# awase-keymap-learn

本クレートは「キー効果の学習」(IMEの状態×キー→効果の表を、注入で少ない押下・少ない待ちで埋める巡回の計画とシミュレータ)で、ADR-176 の「較正UI」(ユーザーがキーを押して効果を確定する)とは別物。製品化では ADR-176 のウィザードから本クレートを呼ぶ。


IMEキー効果の学習(較正)の**巡回プランナ**と**オフラインシミュレータ**(ADR-191)。OS非依存の純粋Rust(Windows API・VKコードを持たない)で、Linuxで `cargo test` が回る。
実機のIMEを「観測できる部分(status: 開閉・変換モード・入力中の有無)と、観測できない隠れ状態(例: 変換中かどうか)を持つMealy機械」とみなし、
(status, キー)→結果 の表を少ない押下・少ない待ちで埋める巡回を計画する。キーは抽象ID(`KeyId`)で表し、実機のVKとの対応は呼び出し側(ドライバ)が持つ。

## 構成

| モジュール | 役割 |
|---|---|
| `model` | 真のモデル(Mealy機械)。状態は `Status` を持ち、同じ `Status` の複数の状態が隠れ状態。分岐の確率で非決定を表す。セルの真の分類(決定的/履歴依存/非決定) |
| `sim` | `SimIme`(実機の代わり): statusは読めるが隠れ状態は返さない。遅延・キー欠落・観測不一致・ドリフト・リセット失敗を注入できる |
| `cost` | 待ちモデル: 固定sleepと、イベント通知を待つ方式(通知が来なければ「変化なし」で確定)。リセットは「任意状態→初期状態」の辺 |
| `anomaly` | 異常の分類(キー未着・観測経路の不一致・想定外の状態・リセット失敗)とリセット段階(Soft/Mode/Hard)・昇格の方針 |
| `graph` | プランナ用グラフ(前回の表から作る)、最短路、**有向CPP**(最小費用流+オイラー閉路)、必須辺が分かれるときの rural 風の連結、観測から辺を直す `learn_edge` |
| `table` | 観測表とセルの分類(決定的/履歴依存/非決定/矛盾)。文脈=直前に押したキー |
| `exec` | 実行器: 押下前後のstatus読み取り(1経路/初回だけ2経路/常に2経路)、キー未着の再試行、リセットの昇格、統計 |
| `strategy` | 戦略 S0〜S9 |
| `metrics` | 指標(時間・押下・リセット・網羅・経路多様性・同期喪失・非決定/履歴依存の検出・精度) |
| `sample_models` | 合成ランダムモデルと、ATOK風モデル |

`cargo run --release -p awase-keymap-learn --example simulate` で下の表を再生成できる(約3分、シード5本の平均)。

## モデルの仮定と限界(重要)

- **ATOK風モデル**(12状態・14キー): 観測層(開閉×変換モード0x19/0x10とモードキーの遷移)は、GJI ATOKプリセットの格子の実測に合わせた。
  **入力中の段階(入力中/変換中〈Space〉/変換中〈変換キー〉/変換中〈無変換〉)の遷移規則は、撤去ブランチの `key_track` を元にした仮定**で、実機で全てを確かめたものではない。
  非決定(入力中のBS、変換中〈Space〉のEsc)の確率(0.25)は、実測の割れ方を元にした近似。セル数は6status×14キー=84(実機の格子は132セル)。
- **合成モデル**: 状態10前後・キー13。隠れ状態と非決定は乱数で入れており、実機の構造とは限らない。
- **待ち・遅延**: 変化の遅延は対数正規(中央値60ms、対数の標準偏差0.5)。現状の固定待ちは押下後2300ms+キー間隔350ms、リセット1300ms。イベント待ちは静止40ms・変化なし150ms・上限700ms。
  いずれも実測に基づく妥当な値だが、CIの実測分布そのものではない(通知遅延の直接実測は未取得)。
- **S0**は「探索で経路を検証済み」の現状の実装を模し、事前モデルの誤りを与えない。S2〜S9は事前モデルに5%の誤りを与え、観測から辺を直しながら進む。
- **注入する異常**: キー欠落2%、観測誤り3%(各観測経路)、ドリフト0.5%/押下(隠れ状態が勝手に飛ぶ)、リセット失敗5%。
- **分類は厳密な一致で行う**(観測が全て同じなら決定的、割れれば非決定/履歴依存/矛盾)。観測誤りがあると「誤検出」(決定的なセルを非決定と宣言)が増える。
  誤りに強い分類(少数派が一定数以上のときだけ非決定と見なす等)は未実装。
- **時間の指標**は、観測誤りで存在しないセルが混じるとやや過大になる。
- 履歴の追跡は、プランナが持つ「status(+疑わしいキーの文脈)」だけで、隠れ状態そのものは持たない。隠れ状態のせいで期待と違う状態に出ることは「同期喪失」として数える。

## 読み取り(この結果が示すこと)

1. **巡回にするだけで、押下より待ちが劇的に減る。** ATOK風モデル(理想)で、現状のS0(毎回リセット+経路再現)は、固定待ちで 15.1 分・リセット 168 回、イベント待ちで 4.8 分。
   有向CPP(S3)は、固定待ちで 8.9 分(約41%減)・リセット 9 回、**イベント待ちで 0.5 分(約90%減)・リセット 1 回**。押下は 168(S0の測定分のみ)→ 197(つなぎ約30)。
   固定待ちのままでは削減は約4割で、**大きく効くのは巡回とイベント待ちの組み合わせ**。
2. **2回ずつの観測では、履歴依存・非決定はほとんど見つからない。** S3/S4/S5/S7 は、非決定セルを見つけた割合が 15〜35%、履歴依存セルは 20〜33% で、
   「決定的」と断定した誤りが 66〜83%(理想条件)。同じ経路の反復や、文脈(直前キー)が同じ観測では区別できない(文献の指摘どおり、文脈数が 2.0 前後)。
3. **部分1-switch(S6)は、少ない追加コストで検出を上げる。** 疑わしいキー(Esc/Space/変換/無変換)の文脈だけを網羅するS6は、イベント待ちで 0.7 分(S3の1.4倍)で、
   非決定検出 60%・履歴検出 53%・誤断定 43%(S3は15%・33%・77%)。矛盾したセルだけを増やすS7は、この分では効かない(矛盾がまだ見えていないため)。
4. **全セルを別経路で12回(S9)は、検出が最も高いがコストが大きい。** イベント待ちで 2.8 分(S0の2回分 4.8 分より短い)で、非決定検出 80%・履歴検出 67%・誤断定 26%。
   固定待ちでは 52 分かかり、現実的でない。ランダムウォーク(S1)は、文脈数が多く検出は高いが、押下が 1,300〜1,900 で、固定待ちでは 60 分を超える。
5. **異常があると、巡回は同期喪失(期待と違う状態に出る)が増え、リセットも増える**が、網羅は 100% を保ち、時間は 0.7〜1.4 分(イベント待ち)。
   観測誤りが加わると、厳密な一致で分類する限り、「決定的なセルを非決定と宣言する」誤検出が 12〜65% に増える(S9で最大)。**誤りに強い分類が要る**。
6. 合成モデル(隠れ状態3・非決定10%)でも同じ傾向。S8(S6+適応)がイベント待ちの異常ありで 3.6 分・非決定検出 93%・履歴検出 80%・誤断定 15%。

## 推奨(暫定)

- **既定の巡回はS6(部分1-switchの有向CPP)**、疑わしいキーの文脈を網羅する。イベント待ちと組み合わせて、1周(各セル2回相当)を1分前後にする。
- **検出を上げる追加の観測は、疑わしいキーのセルにだけ**、別経路で回数を増やす(S9を全セルでなく疑わしいセルに限る形)。矛盾を見つけてから増やす方式(S7)だけでは足りない。
- **分類は誤りに強くする**(少数派が一定数・一定割合以上のときだけ非決定と宣言する等)。実機の観測は、遅延による取りこぼしが起こりうる。
- 計画の実行中は、観測した結果でグラフの辺を直し(`learn_edge`)、想定外の状態に出たら計画を立て直す。想定外が続くときはリセットに昇格する(`anomaly`)。
- リセットは「任意状態→初期状態」の辺として計画に入れる。イベント待ちではリセットが 1 回で済み、現状の 168 回とは桁が違う。
