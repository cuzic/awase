**【ADR-196で置換、M4対応で範囲を精密化（2026-09-23）】本タスクが実装対象4節で定める
「不一致セル数が暫定閾値（例5%）を超えたら学習結果ごと同梱表へフォールバックする」という
**判定内容**は、[ADR-196](../adr/196-keymap-learn-truth-priority.md)決定1b（外部書き込みの
直接観測＋不一致は全件再測定＋大規模不一致のみ「要確認」で既定不採用）に置き換わった。
**加えて、実装対象4の縮退率20%判定を含め、「採否判定をどこで行うか」自体も変わった**——
ADR-196決定1e（`196-...md:133,136`）により、判定（縮退率・突き合わせの両方）は
`awase.exe`の読込時ではなく**学習セッションの末尾（学習プロセス側）**で行う。閾値
（縮退率20%）の値自体は変わらないが、実行場所が本タスクから[ADR196-T2](adr196-t2-mismatch-adjudication.md)
へ移る。本タスク（段階4読込）に残るのは、fs読み取り＋スタンプキャッシュ（実装対象1）と
破損ファイルへの縮退（実装対象2）だけになる。
新しい実装対象は[ADR196-T2](adr196-t2-mismatch-adjudication.md)を参照。**
**既存の実装ブランチ`feat/adr195-t4-runtime-loading`（PR #256、developに未マージ、

書かれているため、ADR-196決定1b・1eへの作り直しが必要。PR #256にコメント済み。
ADR196-T2着手時に、このブランチの担当者と重複作業にならないよう調整すること。**

## 背景

[ADR-195](../adr/195-keymap-learn-productization.md)決定・段階4は、`state/key_effect_predictor.rs`
の予測器を、コンパイル時埋め込みの`key_effect_table.rs`から、実行時に読み込んだ学習結果
（T3の永続化データ）を使う形に変える。**同梱の3種の表は未学習時の既定値として残す**
（ADR-191決定3「表が空にならない」の踏襲）。読み込んだ表は`KeyEffectPredicted`
（belief更新）にのみ使い、actuationの判定（ADR-189の固定セット、ユーザー明示config）
には一切使わない。

## 実装対象（**B-1、round3 Blocker——読めない窓向けの受け入れ基準が本タスクの核心**）

1. **fs読み取り+スタンプ比較キャッシュ**: IPC経由ではなく、T3の永続化ファイルを直接
   読む（`KeymapCache`と同様の方式）。
2. **破損ファイルへの縮退**: スキーマ検証失敗時は同梱の既定表へフォールバック、未知の
   セル・パースできない行は「予測なし」に読み替える、ファイルサイズに上限を設ける。
   スキーマ版不一致も同じフォールバック経路を通す。
3. **(i) 開発者/CI側の一度きりの手法検証**: 学習パイプライン（T0〜T3のロジック）が
   生成する表が、読めない窓（TsfNative）でもblind 0%を保つことを、CIの既存blind構成
   （`ci/e2e-ime.yml`格子ジョブ）で検証する。**合成の`custom_keymap_table`を最低1つ
   CIへ投入**し、カスタムキーマップでも安全であることを確認する（既定キーマップだけの
   検証では不十分）。develop本体のテストコードから行う一度きりの検証であり、学習の
   都度走らせるものではない。
4. ~~**(ii) ユーザー環境で使える代理指標（縮退率・同梱表とのセル突き合わせ）**~~
   **【ADR-196で置換、実行場所ごと[ADR196-T2](adr196-t2-mismatch-adjudication.md)へ移管】**
   縮退率・同梱表とのセル突き合わせという指標そのものはADR196-T2で使うが、判定はもはや
   本タスク（段階4読込）の実装対象ではない。「開ループ連鎖の一致率は指標として使わない」
   （ADR-191実測でぶれが大きいことが判明済み）という注記のみ、そのまま有効。
5. **opt-out（M-b）**: `config.toml`に`use_learned_keymap_table`（既定`true`）を追加。
   awase-settingsのUIチェックボックスでも切り替え可能にする（引き金はユーザー手動）。
   ~~不具合報告（ADR-095/148）の添付内容に「学習表を使用中か」「フィンガープリント
   （T8）」を1項目追加する。~~ **【ADR-196で移管】不具合報告への添付は
   [ADR196-T2](adr196-t2-mismatch-adjudication.md)へ一本化（M6対応）。本タスクでは
   `use_learned_keymap_table`フラグの追加のみ行う。**
