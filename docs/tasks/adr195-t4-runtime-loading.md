# ADR-195 T4: 予測器の実行時読込（段階4）を実装する

状態: 未着手（2026-09-23起票）。[ADR195-T3](adr195-t3-persistence.md)完了後に着手。
着手時は `.claude/rules/worktree-per-session.md` に従い専用 worktree/branch を切ること。

## 背景

[ADR-195](../adr/195-keymap-learn-productization.md)決定・段階4は、`state/key_effect_predictor.rs`
の予測器を、コンパイル時埋め込みの`key_effect_table.rs`から、実行時に読み込んだ学習結果
（T3の永続化データ）を使う形に変える。**同梱の3種の表は未学習時の既定値として残す**
（ADR-191決定3「表が空にならない」の踏襲）。読み込んだ表は`KeyEffectPredicted`
（belief更新）にのみ使い、actuationの判定（ADR-189の固定セット、ユーザー明示config）
には一切使わない。

## 実装対象（**B-1、round3 Blocker——読めない窓向けの受け入れ基準が本タスクの核心**）

1. **fs読み取り+スタンプ比較キャッシュ**: IPC経由ではなく、T3の永続化ファイルを直接
   読む（`KeymapCache`と同様の方式）。
2. **破損ファイルへの縮退**: スキーマ検証失敗時は同梱の既定表へフォールバック、未知の
   セル・パースできない行は「予測なし」に読み替える、ファイルサイズに上限を設ける。
   スキーマ版不一致も同じフォールバック経路を通す。
3. **(i) 開発者/CI側の一度きりの手法検証**: 学習パイプライン（T0〜T3のロジック）が
   生成する表が、読めない窓（TsfNative）でもblind 0%を保つことを、CIの既存blind構成
   （`ci/e2e-ime.yml`格子ジョブ）で検証する。**合成の`custom_keymap_table`を最低1つ
   CIへ投入**し、カスタムキーマップでも安全であることを確認する（既定キーマップだけの
   検証では不十分）。develop本体のテストコードから行う一度きりの検証であり、学習の
   都度走らせるものではない。
4. **(ii) ユーザー環境で使える代理指標（縮退率・同梱表とのセル突き合わせ）**:
   - 縮退率が暫定`20%`を超えていたら、そのファイルを採用せず同梱表へフォールバック
     （`use_learned_keymap_table`は変更しない、通知は設定画面かログで行う）。
   - 検出したキーマップ構成が同梱3種（ATOK/GJI+MS-IMEプリセット/Microsoft IME本体）の
     いずれかと一致する場合、学習表と同梱表をセル単位で突き合わせ、不一致セル数が
     暫定閾値（例5%）を超えたら同様にフォールバックする（`pub(crate)`可視性で足りる）。
   - **開ループ連鎖の一致率は指標として使わない**（ADR-191実測でぶれが大きいことが
     判明済み）。
   - どちらも「読み込み時に採用しない」で統一し、`config.toml`は書き換えない
     （ユーザー所有の設定を勝手に反転させない）。
5. **opt-out（M-b）**: `config.toml`に`use_learned_keymap_table`（既定`true`）を追加。
   awase-settingsのUIチェックボックスでも切り替え可能にする（引き金はユーザー手動）。
   不具合報告（ADR-095/148）の添付内容に「学習表を使用中か」「フィンガープリント
   （T8）」を1項目追加する。

## 完了条件

- 縮退率・セル突き合わせのフォールバック判定のユニットテスト。
