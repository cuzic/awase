# ADR-280: 判定の背景を一様分布からラテン文字の 2 連に替える測定(2026-10-26)

コード変更なしの Python 評価(`tools/lang-detect-eval/eval_latin_bigram.py`)。集計値のみで、評価データ・打鍵列はコミットしない。

## 結論

- **「windows」は拾える**。一様分布(U)では 7 打鍵まで -7.6 で閾値 14・16 に届かず `Undecided`。英語の文字 2 連(E)に替えると -15〜-18(7 打鍵で E_repo -18.1・E_dict -15.4)になり、閾値 14 で 5 打目に `NotJapanese`。多言語 2 連(L)は -15.1 で、日本語の誤判定 1% 以下の閾値(15)で 7 打目に確定する。母音/子音だけの背景(CV)は -12.2 で、`windows` は拾えない。
- **同じ日本語の誤判定率で比べると、背景を替えるだけで英語の決まる率が大きく上がる**。誤判定率 1%: 英文 83.4%(U)→ 94.5%(E_repo)・95.0%(E_dict)・96.6%(L)・92.7%(CV)。0.5%: 76.1 → 92.3 / 93.4 / 93.6 / 87.6%。3 連の効果(#841、+7〜10 ポイント)より大きい。
- **最良は 3 連 + L**(tri-interp+L: 1% で英文 98.2%、0.5% で 97.3%、コード 93.0 / 91.3%)。2 連だけなら L か E(英語の辞書)。CV は言語に依らず最小の背景として、E・L の約 6〜9 割の効果(1% で英文 92.7%)。
- **先頭には効く**: 先頭 3 打以内に英文が決まる率は U 13.8% → E_repo 33.7%・L 29.2%・tri-backoff+L 45.3%(日本語の先頭 3 打の誤判定は 0.4% → 0.3% 前後で増えない)。先頭 1 打は全モデル 0%、2 打は最大 10%。
- **日本語側の注意(重要)**: 背景を替えると llr の尺度が変わる。**英語の背景を使うと `ja_threshold = 4` のままでは非日本語の `Japanese` 誤確定が増える場合がある**(下記 (3)。E_repo・E_dict でコード 5.8%)。L・CV では 0〜0.15% で悪化しない。閾値は絶対値で持ち越さず、日本語誤判定率で再校正が要る(th1 は 12〜17 の範囲)。
- 実装に進む判断材料: 効果は大きい(英語が決まる率 +10〜15 ポイント)。ただし L・E_en は評価データの学習側で作った表なので楽観的(下記限界)。**ライセンスと再生成手順が明らかな E_dict・E_repo でも +11 ポイントあるので、効果は学習データの漏れで出ているものではない**。実装するなら L の元データの確保(辞書+多言語の語彙)と、閾値(`en_threshold`・`eisu_threshold`・`ja_threshold`)の再校正が前提。

## 手順と学習データ

評価の枠組みは #819 以後の判定(`docs/tasks/adr280-trigram-vs-bigram-2026-10-25.md` と同じ。記号は 0 で文脈を切る、親指なし区間、`max_keys = 7`、seed 5)。増分は `ln P_ja(仮名|直前の仮名) − ln P_bg(キー文字|直前のキー文字)`(先頭は `P_bg(c)`)。背景の表は打鍵位置の格子の 44 文字(数字・英字・記号)上の加算平滑(α = 0.5)の 2 連。

| 背景 | 元 | 件数 |
|---|---|---|
| U | 一様 1/N_keys(現行) | - |
| E_repo | このリポジトリの `*.md`・`*.rs`(`tests/fixtures`・`data/` を除く)の ASCII 英字列(camelCase を分割) | 1195 ファイル、7,460,712 キー |
| E_dict | `/usr/share/dict/american-english`(Debian の wamerican、英字のみの語) | 74,585 語、600,318 キー |
| E_en | 評価データの英文の学習側(偶数番) | 300 文 |
| L | 評価データの英文・欧州語 11 言語・マレー語等・コードの学習側 | 657 文、22,296 キー |
| CV | 母音(aeiou)/子音/その他の 3 クラスの遷移確率 × クラス内一様(L の学習側で作る) | 9 パラメータ |
| CV5 | 母音/鼻音(mn)/流音(lr)/破裂音(pbtdkgcq)/他の子音/その他の 6 クラス | 同上 |
| LCV | L と CV の確率の 0.5 : 0.5 混合 | - |

非日本語の文は読み込み順で偶数番を学習側・奇数番を評価側に分け、**全背景の評価を奇数番だけ**に揃えた(英文 900 区間・コード 379・他言語 669、言語別は (5))。日本語側(3247 エピソード)は学習に使っていない。2 連の仮名側に加え、3 連(#841 の tri-backoff・tri-interp)との組み合わせも測った。

## 限界

- 評価データはエージェント生成(出典・ライセンス不明)で、実際の打鍵ではない。固有名詞・略語・パスワード様の列・ローマ字入力の日本語は対象外。日本語は 1400 文×4 開始位置の相関のある標本で、誤判定率 0.5% 未満の差(0.2% 前後など)は数件の違いで有意でない。単一の seed。
- **L・E_en・CV は評価データの学習側(同じ生成器の偶数番の文)から作った**ので、評価側との分布の近さで楽観的になる(文で分けたが語彙・文体は共通)。独立な元の E_dict・E_repo でも効果(1% で英文 +11 ポイント)があるので、効果自体は漏れで出ているものではないが、L の数値(96.6%)は上限寄り。実機に載せるなら L の元を、辞書+複数言語のライセンスの明らかなコーパスに置き換えて再測定する。
- E_repo は Windows のプロジェクトで、`windows` など語そのものを含む。E_dict も `windows` を含む。
- 背景の平滑(α = 0.5)・LCV の混合(0.5)・CV の分類は掃いていない。tri-interp の重みは #841 のまま。
- 仮名側の表は #841 と同じ(3 連は表に無い並びを `floor3` に落とす仮定)。

## 再現手順

```sh
uv run --no-project python -I tools/lang-detect-eval/eval_latin_bigram.py --repo . --data-dir <データのディレクトリ>
```
`--repo` の `git ls-files`(`*.md`・`*.rs`)と `/usr/share/dict/american-english`(wamerican)から E_repo・E_dict を再生成する。評価データは `data_*.jsonl`・`data2_*.jsonl`・`data3_*.jsonl`(2710 行、リポジトリに入れない)。標準出力に (1)〜(5) の全表(閾値 2〜80 の曲線を含む)を出す。
