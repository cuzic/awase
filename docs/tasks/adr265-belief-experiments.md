# ADR-265 belief 接続の設計: 実機実験の手順書(測る前に固定、2026-10-18)

目的: [設計案](../adr265-belief-connection-design.md)(PR #665)と Opus のレビューで出た論点のうち、**実機で確かめられるもの**を測ってから、§9(applied の扱い)と belief 接続の方針を決める。
実機: dragonflyg4(利用者が今すぐ使ってよいと言った)。Mozc Readable は入っていない(`adr265-probe` で確認、インストール済みの製品の一覧が空)ので、入れて、測って、戻す(以前と同じ手順・UAC あり)。
**awase は使わない**(共有メモリを直接読む)。実装していない belief 接続や drift の挙動は、この実験では測れない(下の「測れないもの」)。

## 実験と、結論の基準(測る前に固定)

| # | 問い | 操作 | 記録 | 「成り立つ」の基準 |
| --- | --- | --- | --- | --- |
| E1 | ツールバー(タスクバーのインジケーターのメニュー)で閉じる/開けると、共有メモリは更新されるか | 利用者が、合図(ビープ)のたびに、メニューから「直接入力」「ひらがな」を交互に選ぶ(各 10 回) | 共有メモリの変化(`effective_open/mode`、`tsf_open/mode`、`update_tick_ms`、`seq`)の全時刻。操作の時刻は合図の時刻 | 各操作の合図から 3 秒以内に、`effective_open` が期待の向きに変わる。**10/10 で「追随する」**。1 回でも変わらなければ「追随しない場合がある」とし、原因の場面を記録 |
| E2 | アプリ・外部からの IMM の書き込み(`WM_IME_CONTROL` の `IMC_SETOPENSTATUS`、awase の ImmCross と同じ型)は、共有メモリに反映されるか | スクリプトが Notepad の入力窓のスレッドの `ImmGetDefaultIMEWnd` へ送る。開→閉→開…を 25 往復 | 送信直後からの共有メモリの変化と、送信から変化までの遅れ(ms)。`tsf_open` と `effective_open` が同じ向きに変わるか | 25/25 で反映されれば「反映される」。**遅れの p95 と最大**を出す(§9 の `pending_write` と、M1 の 170ms の窓の判断材料)。反映されない往復が 1 回でもあれば、その型の書き込みは共有メモリで確認できない |
| E3 | キーから共有メモリが変わるまでの遅れの分布 | 注入キー(F2、0x19)を 100 回、通常時と CPU 負荷時(使い切るプロセス 8 つ)で | `SendInput` 完了から `seq` が変わるまで(ms)の分布 | p50/p95/p99/最大を出す。**判断**: 最大が 170ms(`KEY_EFFECT_SETTLE_MS`)未満なら M1 の指摘は実害が小さい。超える回があれば、因果の判定(`update_tick_ms`)が要る |
| E4 | 入力スコープ(パスワード欄)で `tsf_open` と `effective_open` は割れるか | Edge で `<input type=password>` を含むページ(`data:` URL)を開き、通常の欄とパスワード欄を行き来 | 両方の欄で、`effective_open/mode`、`tsf_open/mode` | 割れる(`tsf_open != effective_open`)場面が**あるか**を記録する。ある場合、どちらが入力結果(IME が変換するか)と合うかを、欄に実際に入力して確認する。Edge が使えない・欄にフォーカスできなければ「測れなかった」と書く |

共通: 読むのは `drive_measure.py` の `read_block`(フォーカスのスレッド、`hwndFocus`)。受け入れは従来どおり(magic・version・seq・pid・`active=1`)。
操作の前に、期待の向きを表にして固定してから実行する(結果を見てから期待を変えない)。測定の間、他の操作をしない。

## 測れないもの(この実験の範囲外、結論に混ぜない)

- **awase が High の共有メモリで drift correction を起こして IME を開け直すか(C1)**: belief 接続は未実装。実験できるのは「共有メモリが外からの変化を反映するか」(E1・E2)という前提だけ。C1 はコードの読みでの判定(レビュー)のまま。
- 明示意図の優先(C2)、`most_recent_trusted` の古い値の残り(H2): コードの性質で、実機に依らない。単体テストで固定する。
- スレッド ID の同一プロセス内の再利用、複数窓の物理キー、TsfNative の窓(Chrome 等。実機に Chrome が無い)。

## 後片付け(以前と同じ)

測定後に、入力方式を元に戻し(`adr265-m-ime-restore`)、アンインストール(UAC。`adr265-m-uninstall`)、置いたファイルを削除する。操作の前に、実機の状態(awase のプロセス・入力方式の一覧)を記録して、同じ状態に戻ったかを比べる。
**利用者の通常の awase(pid は `adr265-probe` の時点で 27928)には触れない**(停止・再起動をしない)。
