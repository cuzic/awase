# v2 D1・D3 CI 設計メモ（2026-10-01）

## 構成

D1 は `sc-startup-{gji,msime}-{edit,chrome}-{on,off}` の8構成、各2 run（16ジョブ）。`typing_stress --mode=startup` が対象入力欄を awase より先に作り、0x16/0x1A で状態を設定してから READY を出す。ON は awase.log 検知後（通常モードの10秒待ちはしない）に単打を注入し、起動行から最初の `[engine-input]` が1秒以内、期待かなとの一致を判定する。OFF は3秒待ち、勝手に開かないことを同一プロセス窓では API でも確認し、0x16 後に打てることを判定する。共通で起動後30秒の drift=0、startup-align が状態どおり1件、OFF直後3秒の `[1A, 16]` reinit=0を要求する。安全デフォルト ON は件数のみ。

D3 は `sc-driftrecovery-{gji,msime}-{tsf,chrome}` の4構成、各1 run内で10試行（4ジョブ）。tsf は自前 TsfNative 相当窓の実 IME を `WM_IME_CONTROL` で直接閉じ、+0.5/+2秒と実打鍵を `check_drift_recovery.py` で集計する。Chrome は実 Chrome を同様に閉じ、`check_drift_recovery_chrome.py` が awase.log の観測・drift と実打鍵を集計する。いずれも expect=observe で、観測も補正も0なら `NOT_OBSERVED`、観測したが戻らなければ `NOT_RECOVERED` とする。

追加は12構成・20ジョブ。plan の実コードを `ONLY=sc-*` で展開した結果は80構成・166ジョブで、matrix 上限256以内。D3 は run を増やさず内部10試行にして起動コストを抑えた。

## 実行例

```sh
gh workflow run e2e-ime.yml --ref ci/v2-d1-d3-startup-driftrecovery -f only='sc-startup-*'
gh workflow run e2e-ime.yml --ref ci/v2-d1-d3-startup-driftrecovery -f only='sc-driftrecovery-*'
gh workflow run e2e-ime.yml --ref ci/v2-d1-d3-startup-driftrecovery -f only='sc-startup-gji-chrome-off'
```

`only` は末尾 `*` の前方一致または完全一致で、途中ワイルドカードは使えない。

## CIで代替しない部分

- D1 の人間の体感、実メモ帳、実機固有の Chrome/GJI、MS-IME 互換モードは残る。EDIT はメモ帳相当だが同一物ではない。Chrome の開閉 API は信頼できないため、OFF維持はログと実打鍵を主証拠にする。
- D3 の物理 Ctrl+無変換は SendInput では PHYSICAL_KEY_STATE を作れない。CI は実 IME の直接 close で「ずれ」以降だけを代替する。実機のキー経路と VS Code は残る。
- GitHub-hosted runner のデスクトップ、TIP、Chrome 初回描画は実機と異なる。観測構成は結果を赤ゲートにしない。

## 既知のフレーク要因

WM_TIMER は約64ms刻みで、プロセス起動・前面化・UI Automation 読み戻しも揺れる。注入間隔の根拠は awase.log の `[engine-input] ts=...us` と起動行の時刻で確認する。Chrome は前面化失敗、アクセシビリティツリー再構築、TIP 初期化、`Imm32Unavailable` により INVALID/NOT_OBSERVED になりうる。MS-IME の 0x16 応答、`WM_IME_CONTROL` の見かけの成功も実文字列と一致しない場合があるため、API 値だけで回復としない。
