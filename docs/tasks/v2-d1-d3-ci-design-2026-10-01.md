# v2 D1・D3 CI 設計メモ（2026-10-01）

## 構成

D1 は `sc-startup-{gji,msime}-{edit,chrome}-{on,off}` の8構成、各2 run（16ジョブ）。`typing_stress --mode=startup` が対象入力欄を awase より先に作り、0x16/0x1A で状態を設定してから READY を出す。ON は awase.log 検知後（通常モードの10秒待ちはしない）に単打を注入し、起動行から最初の `[engine-input]` が1秒以内、期待かなとの一致を判定する。OFF は3秒待ち、勝手に開かないことを同一プロセス窓では API でも確認し、0x16 後に打てることを判定する。共通で起動後30秒の drift=0、OFF直後3秒の `[1A, 16]` reinit=0を要求する。startup-align が状態どおり1件であることは EDIT のみ合否に入れる。実 Chrome は Imm32Unavailable で観測が来ず `[startup-align]` が出ないのが正常なので、`form=chromepage` では有無を合否に入れず align 列に記録するだけ（観察項目）にした。安全デフォルト ON は件数のみ。

D3 は `sc-driftrecovery-{gji,msime}-{tsf,chrome}` の4構成、各1 run内で10試行（4ジョブ）。tsf は自前 TsfNative 相当窓の実 IME を `WM_IME_CONTROL` で直接閉じ、+0.5/+2秒と実打鍵を `check_drift_recovery.py` で集計する。Chrome は実 Chrome を同様に閉じ、`check_drift_recovery_chrome.py` が awase.log の観測・drift と実打鍵を集計する。いずれも expect=observe で、観測も補正も0なら `NOT_OBSERVED`、観測したが戻らなければ `NOT_RECOVERED` とする。

追加は12構成・20ジョブ（物理 Ctrl+無変換の変種4構成・4ジョブを後から追加、下記）。plan の実コードを `ONLY=sc-*` で展開した結果は変種込みで84構成・170ジョブで、matrix 上限256以内。D3 は run を増やさず内部10試行にして起動コストを抑えた。

## 実行例

```sh
gh workflow run e2e-ime.yml --ref ci/v2-d1-d3-startup-driftrecovery -f only='sc-startup-*'
gh workflow run e2e-ime.yml --ref ci/v2-d1-d3-startup-driftrecovery -f only='sc-driftrecovery-*'
gh workflow run e2e-ime.yml --ref ci/v2-d1-d3-startup-driftrecovery -f only='sc-startup-gji-chrome-off'
```

`only` は末尾 `*` の前方一致または完全一致で、途中ワイルドカードは使えない。

## CIで代替しない部分

- D1 の人間の体感、実メモ帳、実機固有の Chrome/GJI、MS-IME 互換モードは残る。EDIT はメモ帳相当だが同一物ではない。Chrome の開閉 API は信頼できないため、OFF維持はログと実打鍵を主証拠にする。
- D3 の物理 Ctrl+無変換: 既存4構成は実 IME の直接 close で「ずれ」以降だけを代替する。変種（下記）はマーカー付き注入で物理 Ctrl 扱いにするが、実キーボード経路は残る。実機のキー経路と VS Code は残る。
- GitHub-hosted runner のデスクトップ、TIP、Chrome 初回描画は実機と異なる。観測構成は結果を赤ゲートにしない。

## 既知のフレーク要因

WM_TIMER は約64ms刻みで、プロセス起動・前面化・UI Automation 読み戻しも揺れる。注入間隔の根拠は awase.log の `[engine-input] ts=...us` と起動行の時刻で確認する。Chrome は前面化失敗、アクセシビリティツリー再構築、TIP 初期化、`Imm32Unavailable` により INVALID/NOT_OBSERVED になりうる。MS-IME の 0x16 応答、`WM_IME_CONTROL` の見かけの成功も実文字列と一致しない場合があるため、API 値だけで回復としない。

## D3 変種: 物理 Ctrl+無変換で OFF にする（sc-driftrecovery-ctrlmuhenkan-*）

`sc-driftrecovery-ctrlmuhenkan-{gji,msime}-{tsf,chrome}` の4構成・各1 run（4ジョブ、各10試行）。OFF 操作を実 IME の直接 close ではなく、マーカー付き SendInput の Ctrl↓→無変換(VK 0x1D、scan 0x7B)↓↑→Ctrl↑ で行う（手順書 §9 の既定 OFF キー）。tsf は `typing_stress --mode=drift-on --drift-off-ctrl-muhenkan`、Chrome は `chrome_probe --close-ime=10 --ctrl-muhenkan-off`。

- **物理 Ctrl の再現方法**: debug ビルドの awase は `AWASE_TEST_INJECTION=1` かつ `dwExtraInfo == TEST_INJECTION_MARKER` の注入を物理キー扱い（`PHYSICAL_KEY_STATE` 更新）にする。checker は awase.log の `[engine-input] vk=0x1D KeyDown` が全て `mods(c=true …) phys_ctrl=true` であることを要求し、1件も無い／false が混じれば前提不成立として INVALID にする（phys_ctrl_ok 列）。
- **限界**: OS 側から見れば通常の SendInput であり、実キーボードの HKL・scan=0 の実物・常駐ソフトのフックは再現されない。awase に物理キーと認識させる経路だけを再現する。
- **「ずれ」の定義**: awase の OFF 操作の直後（+50ms）も実 IME が ON のまま。作れた試行が gap_made、OFF が実 IME まで効いたものが gap_not_made（ずれを作れなかった）。ずれ後に ON のままではなくなる（最後のチェックポイントで閉、または実打鍵がかなでない／Chrome は英字 `ka`）が corrected、最後まで ON が not_corrected。verdict は GAP_NOT_MADE / CORRECTED / NOT_CORRECTED / UNDETERMINED / INVALID。expect=observe。
- 流れ: IME ON(0x16) → 物理 Ctrl+無変換 → +0.5/+2秒に実 IME 状態 → 文字キー1つ → 判定。`[drift] correction`・`Blacklist drift correction: apply_ime_open(…)` の有無（drift 列）も記録する。

## 初回 CI 結果（run 36855086091）

- **D1**: `sc-startup-{gji,msime}-edit-{on,off}` は 4/4 PASS。`sc-startup-{gji,msime}-chrome-{on,off}` は全て FAIL だったが、失敗理由は `startup-align=[] (期待 ['true'|'false'])` の1点だけ（drift=0・reinit=0・first_engine_ms 正常。例: `form=chromepage ime=gji initial=on drift=0 align=- reinit=0 first_engine_ms=525`）。実 Chrome は Imm32Unavailable で観測が来ず `[startup-align]` が出ないのが正常で、判定基準の誤り。上記のとおり Chrome では startup-align を合否から外して修正した。
- **D3（実 IME 直接 close の4構成）**: tsf は NOT_OBSERVED（観測0・drift 0・reinit 10）、Chrome は NOT_RECOVERED（観測1・drift 0）。いずれも drift correction だけでは ON に戻らない（ADR-205 / BUG-172 と整合）。
