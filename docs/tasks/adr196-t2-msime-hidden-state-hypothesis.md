# ADR196-T2: MS-IME本体の学習の正答率ばらつきと「隠れ状態」仮説（2026-09-24）

状態: **仮説（原因の切り分けまで。モデル拡張は見送り、下記「決定」参照）**。
windows-latest実機（Microsoft IME本体、`ci/adr196-t2-msime-verify2`、`--trace-walk`）の観測に基づく。
検証ブランチはdevelopへマージしない。関連: [adr196-t2-msime-learning-open-issues.md](adr196-t2-msime-learning-open-issues.md)、
[adr196-t2-mismatch-adjudication.md](adr196-t2-mismatch-adjudication.md)。

## 何が起きたか

MS-IME本体の学習（S6、5モード仮説モデル、PR #294）は完走し、自己検証（独立ランダムウォーク約300歩）の
正答率は実行のたびに動いた。判定は要確認が既定（`UnverifiedMsImeNative`）で、正答率が0.95未満なら不採用。

| 正答率 | 回数 | 備考 |
|---|---|---|
| 0.977〜0.980 | 5 | 要確認 |
| 0.963〜0.970 | 2 | 要確認 |
| 0.950 | 2 | 要確認（閾値ちょうど） |
| 0.920 | 1 | 不採用（`LowAccuracy`） |

（run 35962754810 / 35963160325 / 35963162503 / 35963164667 / 35964552621 / 35964591520 / 35964594663 /
35964596551 / 35964598559 ほか。5モード化前は0.940で不採用、`HighDegeneration`は2モード時）

## 観測（事実）

`--trace-walk`（検証ウォークの1歩ごとに`[verify-step]`行をstderrへ出す、PR参照）で5回分の誤答を集計した。

- **誤答は全て、学習時に決定的（`class=det`）と分類されたセルで起きた。** 学習中の観測が同じ結果ばかりで
  （`n_distinct=1`が多数、観測件数は最大129）、それが検証ウォークでは別の結果になった。
  学習時に結果が割れていたセルの取りこぼし（非決定・履歴依存の見落とし）ではない。
- 誤答は約10セルに集中した。予測と実際の代表例:

| セル（状態・キー） | 予測（学習） | 実際（検証ウォーク） |
|---|---|---|
| 入力中（open, comp=1）+ BS(0x08) | 入力中のまま（Kept） | 破棄されて入力中でなくなる（Discarded） |
| 入力中 + Enter(0x0D)（mode=0x00） | 確定（Committed） | 破棄（Discarded） |
| 開 + 英数(0xF0)（mode=0x09/0x0B） | 半角英数(0x00)へ / 閉 | 全角英数(0x08)へ |
| 閉（open=0, mode=0x00）+ F2/F0/0x19 | ひらがな(0x09)で開く | 直前のモード(0x08/0x0B)で開く |

## 仮説（推測。実機で確かめていない）

誤答は、状態 `(open, conv, composing)` に含まれない**隠れ状態**への依存で説明できる。

1. **入力中の文字数**: BSは、1文字なら入力全体が消えて入力中でなくなり、複数文字なら入力中のまま残る。
   学習は決まった手順（少ない文字数）で測るため決定的に見え、ランダムウォークは長い入力に当たる。Enterも同型。
2. **英数キーの巡回位置**: 押した履歴で半角英数→全角英数のように巡ると考えると、結果が状態だけで決まらない。
3. **閉じる前のモード**: IMEが閉じている間の変換モードは実際の状態を表さない（`open=0`のconvは不安定という
   既存の知見と同じ）。再オープン時は直前のモードへ戻るため、閉状態から開くキーの結果が状態だけで決まらない。

ばらつきの理由: 学習は手順が固定で隠れ状態がたまたま一定、検証ウォークはランダムなので、これらのセルを踏む回数で
正答率が0.92〜0.98に動く。**ランダムなIME/OSの揺らぎは仮定しなくても説明できる**（タイミング・OS内部状態の影響を
完全に否定したわけではない）。

## 決定（2026-09-24）: 現状維持、モデルは拡張しない

| 案 | 内容 | 判断 |
|---|---|---|
| 1 | 現状維持（MS-IME本体は要確認が既定でユーザーが承認する運用） | **採用** |
| 2 | 隠れ状態（入力長・閉じる前のモード・英数の巡回位置）をモデルに足す | 見送り。状態空間と学習時間が増え、仮説の実機確認も要る。効果は要確認の表の精度95→98%程度 |
| 3 | 隠れ状態に依存するセルを予測から外す | 見送り。縮退率（現状5〜7%）が閾値20%へ近づく。どのセルを外すかの基準が未定 |

**再検討する条件**: MS-IME本体の学習を使うユーザーから、不採用や誤予測の報告が出たとき。そのとき本書の
`--trace-walk`で誤答セルを再集計し、案2か案3を選び直す。約1割で不採用になる（0.920が10回中1回）ことは許容している。

## 再現・再測定の手順

- 学習プロセスに`--trace-walk`を付ける（標準出力の`result`行・採点には影響しない）。stderrの`[verify-step]`行は
  `verdict=correct|incorrect|not_in_table|contaminated`、`before`/`actual`/`predicted`（状態）、`class`（学習表側の
  セル分類）、`n_obs`/`n_distinct`（観測件数・結果の種類数）を持つ。
- CIでの走らせ方は`ci/adr196-t2-msime-verify2`のワークフロー（ja-JPのみの言語リスト＋MS-IME TIPを既定にする。
  既存リストへja-JPを足すだけだとen-USが既定のままMS-IMEがアクティブにならない）。
