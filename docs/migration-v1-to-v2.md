# awase v1 → v2 の違いと移行ガイド

v1 は **1.21.1**（2026-09-27）が最後の版です。v2 は、v1.21.0 のあとに積まれた約 1,400 コミット（機能 約 140・修正 約 260）と、
213 番まで採番した設計記録（ADR）の成果です。この文書は **ユーザーが気づく違い** を、設定の移行・新機能・挙動の変更・修正・既知の制限の順にまとめます。
更新履歴は [CHANGELOG.md](../CHANGELOG.md)、設計の根拠は `docs/adr/` にあります。

## 1. v2 の考え方（v1 との一番大きな違い）

awase の難しさは、アプリごとに IME の挙動がまちまちで、IME 自身が自分の状態を偽ることがある点です。v1 は、awase が IME の状態を**推測して先回りで書き込む**ことで合わせていました。
v2 は方針を変えました。

| | v1 | v2 |
|---|---|---|
| IME の状態 | awase の内部状態（belief）を正とし、ずれたら IME へ書いて直す | **IME 自身を正とする**。awase は書かず、観測・予測して追随する（ADR-191） |
| 先回り・補正の書き込み | 確定キーごと・フォーカス変更時・Ctrl を離したとき・エンジン ON/OFF 時などに `VK_IME_ON`/`VK_IME_OFF` を自動送信 | **撤去**（ADR-212/213）。ユーザーの操作を引き金にしない書き込みは行わない |
| キーの役割 | 半角/全角・無変換/変換などを、キーの種類（VK）で決め打ち | **ユーザーの IME キー設定から役割を逆算**する（ADR-199。Google 日本語入力の `config1.db`、MS-IME 本体のレジストリ、学習表） |
| 能動的に書くキー | 多数 | **IME ON/OFF/トグルの役割のキー**と、`keys.ime_on/off` に書いたキーだけ |
| IME キーを押したあと | 内部状態が古いと、押しても変わらないことがある | **押せば必ず合う**: 絶対指定は 1 回、トグルは 2 回以内（ADR-208） |

## 2. 設定ファイル（`config.toml`）の移行

`config.toml` は**そのまま引き継げます**。次の項目は扱いが変わります。

| 項目 | v1 | v2 |
|---|---|---|
| `keys.ime_toggle` | 既定 `VK_KANJI`（半角/全角） | **既定は空**。v1 の旧既定と**ちょうど同じ**値（`["VK_KANJI"]`）は読み込み時に空として扱い、保存で消える。IME 側の設定に従う |
| `keys.ime_detect.on` / `off` | 既定 `IMEオン` / `IMEオフ` | **既定は空**。IMEオン/オフ キー（`VK_IME_ON/OFF`）への追随は指定なしで自動 |
| `keys.engine_on_ime_key` / `engine_off_ime_key` | エンジン ON/OFF 時に IME のモードキーを送る | **撤去**。残っていれば無視し、起動時にトレイで通知。設定画面で保存すると消える |
| `muhenkan_solo_tap_ime_action` / `henkan_solo_tap_ime_action` | 無変換/変換の単独タップで IME 操作 | **撤去**。読み込み時に `keys.ime_*` 相当へ移行して警告（同じキーの設定が既にあれば移行しない）。保存すると消える |
| `confirm_mode` | 複数の値 | **`wait` と `ngram_predictive` の 2 択**。旧値は `wait` 扱い＋警告、保存時に `wait` へ書き換わる |
| キー名の書き方 | 項目ごとに規則が違い、書き方が合わないと**黙って無視** | **全項目で同じ寛容な規則**（前後の空白無視・大文字小文字不問・`VK_` は任意・`Enter` などの一般名・矢印キー）。今まで無視されていた設定が**有効になる**ことがある |
| `[[keymap]]`（旧表記） | 効かなかった | 実際の項目名 `[[keymaps]]` として読まれる（**効き始める**） |
| 設定の誤り | 無視 | **警告**（トレイ通知とログ、設定画面の警告欄）。未知の項目名は近い候補つき |
| 設定画面での保存 | 全体を書き直す | **差分だけ書く**（コメント・未知のキーを保つ。`toml_edit`）。GUI 保存は三者比較で、外部編集を巻き込まない |
| `use_learned_keymap_table` | なし | **新設（既定 true）**。IME キー効果の学習結果を使う（§3） |
| `general.gji_thumb_key_ime_toggle`（設定画面の「GJI の無変換/変換/ひらがな/カタカナキーの状態依存トグルをベストエフォートで追従する（自己責任）」） | opt-in（既定 off） | **撤去**。`true` で残っていれば起動時に通知し、値は無視される（`false` なら何も出ない）。保存で行が消える。同じ目的は、IME のキー設定から役割を逆算する仕組み（ADR-199）が既定で担う |
| `general.dbe_mode_key_policy`（隠し設定。`passthrough` で DBE キーの抑止を外す） | 既定 `suppress` | **撤去**。`passthrough` で残っていれば起動時に通知し、値は無視される（実質効いていなかったため）。保存で行が消える |
| `[[calibration]]` | — | v2 には読み書きがない。残っていても無視される |
| `diagnostics.hook_self_heal` | なし | **新設（既定 true）**。キーボードフックの自己修復。問題があれば `false` で無効化できる |
| `predict_henkan_open_in_unreadable_windows` | なし | **新設**。読めない窓で、GJI の MS-IME プリセットの変換キーによる IME の開きを予測する（ADR-209） |
| `warn_state_dependent_mode_keys` | なし | **新設**。状態依存の IME モードキーを検出して警告する（ADR-192） |

> **v1 の設定画面で保存した `config.toml` には、v1 の既定値が明示的に書かれています**（`keys.ime_toggle = ["VK_KANJI"]`、`keys.ime_detect` の `IMEオン`/`IMEオフ`）。
> v2 は、旧既定と**ちょうど同じ**値を読み込み時に空として扱い、設定画面で保存するとファイルからも消します（旧既定に別のキーを足した設定や、別のキーは尊重します）。
> 撤去された `gji_thumb_key_ime_toggle`・`dbe_mode_key_policy` は、`true`／`passthrough` のまま残っているときだけ起動時にトレイで通知します（既定値なら何も出ません）。設定画面で保存すると行が消えます。

> **心当たりのある再割り当てが、更新しただけで効き始めることがあります。** 昔書いたまま効かなかった `[[keymap]]` や `VK_` なしのキー名などです。更新後に `config.toml` を確認し、起動時ログの「以前は無視されていた設定 N 件が有効になりました」を見てください。

## 3. 新しくできること

- **IME キー効果の学習（`awase-keymap-learn-win.exe`、ZIP・MSI・Scoop に同梱）**（ADR-195/196）: カスタムキー設定の IME でも、キーを押すと IME がどうなるかを実機で学習し、表にして使う。独立プロセスで巡回学習 → 自己検証 → 永続化 → 実行時読込。設定画面の較正パネルに、使用中の表の状態と「採用」「再検証」ボタンがある。学習結果を**内蔵表より優先**する。IME の版が変わると「要再検証」になる。古いカスタム表が残る構成でも約 99 秒で完走する（BUG-178）。
- **打鍵時の予測**（ADR-191・209・211）: 物理のモードキーを押した時点で、表から IME の変化を予測して Engine へ即座に反映する（IME に書かない）。Chrome・Windows Terminal など IME の状態を読めない窓で、変換キーや F13（Google 日本語入力の MS-IME プリセット）で IME が開くのに NICOLA が OFF のまま、が起きなくなる。
- **状態依存の IME モードキーの警告と置き換え**（ADR-192）: 入力中だけ効くなど、状態によって意味が変わるキー割り当てを検出して警告し、設定画面で明示の ON/OFF キーへの置き換えを案内する。
- **キーの役割の逆算**（ADR-199・202）: 半角/全角（0xF3/0xF4）・漢字（0x19）・F13〜F24・無変換/変換が、IME の設定上トグルかどうかを読み取って扱いを決める。MS-IME 本体の無変換/変換が「値 2（トグル）」のときも、役割として扱う（入力中でも切り替わる）。
- **設定の診断**（ADR-201）: 間違いを警告し、キー名を寛容に解釈する（§2）。
- **不具合報告の強化**: 学習表の採否・自己検証・内蔵表との突き合わせ・キーマップ指紋を添付する。実行中プロセス名の一覧をオプトインで添付できる。PowerToys Keyboard Manager/Run を「併用で問題になりうるソフト」の候補に追加。
- **キーボードフックの自己修復**（issue #165）: フックが入力を受けなくなった状態（hook_starved）を検知して自己修復する。
- **アプリ内更新確認が v1/v2 を区別する**: 自分のバージョンを付けて確認し、ラインごとの最新版を返す。

## 4. 挙動が変わるところ

- **IME キーを押したときの保証**（ADR-208）: Ctrl+変換/無変換・かな・半角/全角・漢字などを押すと、awase の内部状態がどうでも、**絶対指定は 1 回、トグルは 2 回以内**で実際の IME がキーの意味に一致する。「何度押しても変わらない」固着をなくした。モードのずれ自体は起こりうるが、押し直せば直る。
- **無変換/変換の単独タップ**（ADR-206）: 設定（Suppress / Passthrough）に従う。Suppress（既定）は IME を動かさない。Passthrough で、IME 側がそのキーを ON/OFF/トグルに割り当てているときは、生キーを抑止して awase が状態に従い絶対指定を **1 回だけ**送る。
- **先回りの書き込みの撤去**（ADR-212/213）: Enter ごとの `VK_IME_ON`、フォーカス変更時・書き込みに随伴する warmup、give-up 後の reinit、Ctrl↑ の再送、エンジン ON/OFF 連動の IME 開閉（ActivationSync）をやめた。半角/全角の OFF→ON は明示の操作として 1 回だけ送る。
- **起動直後**: IME を閉じて起動しても、awase が開けに行かない（BUG-163）。
- **半角英数を検出しても awase が IME を OFF にしない**（BUG-146）。
- **外部から IME を閉じられたとき**（Google 日本語入力 + Chrome など）: 実際の状態に追随する。開け直さない（ADR-205）。
- **MSI のアンインストール**で `config.toml` と配列ファイルを消さない（v1.21.0 から。v2 でも同じ）。

## 6. 開発者向けの違い

- **新しい crate**: `awase-keymap-learn`（学習の核）、`awase-keymap-learn-win`（実機学習プロセス）、`awase-gji-config`（GJI のキー設定の読み取り・役割の逆算）。`awase-windows` は `observer/`・`state/`・`runtime/`・`output/` の層に整理され、IME の belief は Observe → 純粋な `classify_*` → `reduce()` の規律で更新する。
- **検証の方法**: 明示キーの配送を**全列挙テスト**（約 12 万状態 × 12 キー）で固定し、現状の反例を golden に残す（ADR-208）。CI の実機（windows-latest）E2E に、`sc-*`（約 200 構成）・`ts-*`（高速打鍵）・`sc-keymatrix-*`（ずれの作り方 × キー、16 構成）などを追加。
- **ドキュメント**: `docs/adr/` は 1 ADR 1 ファイル・frontmatter つき。`docs/known-bugs/` は 1 バグ 1 ファイル。

## 7. v2 の既知の制限

- **MS-IME 本体 × 実 Chrome の IME オフ**: awase が送る `VK_IME_OFF` が効かないことがある（awase を再起動した直後でも同じ。CI で環境の制約と確認）。英数キーなど MS-IME 自身に届くキーで OFF にする。
- **Windows Terminal + Google 日本語入力（TsfNative）**: 明示キーの保証（ADR-208）は未対応（L3'。単発の `VK_IME_OFF` が「@」を誘発しうるため、実機での A/B が条件）。
- **InputRelay の窓（リモートデスクトップなど）**: 開閉キーを awase が握りつぶさず素通しにする対応は未実装（L4）。
- **MS-IME 本体 × 実 Chrome の起動直後の最初の文字**: 環境により約半数でローマ字になることがあった（CI。再現せず環境依存と判断）。
- **無変換/変換の単独タップ（Windows Terminal + Google 日本語入力）で「@」が出るか**: 実機未確認。

## 8. 検証の状況

CI（GitHub Actions の Windows 実機）で確認済みの範囲は広く、`sc-*` 208 構成・`ts-*`・`sc-keymatrix-*` が通っている。**実機（物理キー・実際の日本語 UI）でしか確認できない項目**は、
Windows Terminal + Google 日本語入力の「@」、MS-IME 本体の設定画面と入力中・変換中の各状態、実際の AutoHotkey による外部操作への追随で、手順は
[docs/tasks/v2-manual-verification-guide-2026-09-29.md](tasks/v2-manual-verification-guide-2026-09-29.md) にある。

## 9. v1 のサポート

v2 のリリースで v1（1.x）は保守を終了する方針です（所有者決定、2026-09-29。日付は未定）。v1 へは重大な不具合だけを個別判断で backport します。
BUG-173 は v1 へ backport せず、v2 への移行を案内します。
