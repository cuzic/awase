# BUG-147: awase起動中のみ、まれに1押下がGJIに反映されない

**発見経緯:** ADR-186の実機E2E（`tools/e2e/ime_key_matrix`、`spike/ime-key-matrix`ブランチ）。**未修正・原因未特定。**

**症状:** 10手順のE2Eを回すと、まれに1手順だけ実IMEが期待どおりに変わらない（例: 半角英数・入力なしで無変換を
押してもIME ONのまま／ひらがなキーでconvが変わらない）。失敗する手順は毎回違う。
GJI単体（awase停止）は5/5で全手順が期待どおり。awase起動中の有効回（フォーカス移動・物理入力の混入なし）は
最新実装（eisu reset抑止なし）で4/8が失敗、Windowsを放置した好条件では連続11回ALL PASS。

**観測（`results/FINAL-noSuppress-s3` STEP2、2026-09-19）:** 失敗した無変換とPASSした同条件のSTEP8で、awaseのログ列が
同一（`[shadow-toggle]…delegate所有→skip`、`Idle`のまま`PassThrough`、`[reinject] vk=0x1d down/up`）。
違いはGJIのI/O（`[gji-io] WRITE`）がSTEP8にだけ出ること。つまりawaseの分岐は失敗の有無に関係せず、
再注入した同じキーにGJIが反応した回としなかった回がある。

**A/B（2026-09-20、実IMEだけの判定、有効12回ずつ、`ab_bug147.sh`）:** GJI単体（awase停止）0/12失敗、
awase起動 6/12失敗。**取りこぼしはawaseを通したときだけ**出る（GJI/E2E側の揺らぎではない）。失敗した押下は
すべてawaseが吸収して`SendInput`で再注入した物理キー（ひらがな0xF2・無変換0x1D）。

**仮説A7（再注入が元のスキャンコードを落とす）:** `lib.rs::RawKeyEventExt::reinject`は`wScan: 0`で再注入する
（物理は0xF2=scan 0x70、0x1D=scan 0x7B）。`wScan`に元のスキャンコードを引き継ぐと再注入が`scan=0x70`になり、
失敗は 2/12 に減った（Fisher正確検定 p=0.19、**有意とは言えない**）。残った失敗は無変換の「半角英数→OFF」のみ。
A7は未マージの実験（`spike/ime-key-matrix`の`ablations/a7-reinject-keep-scan.sh`）で、修正としては採用していない。

**未切り分け:** A7が効いているのか偶然か（N不足）、残る失敗の原因（再注入のタイミング/順序、TSF warmup/cold）。
**次の一手:** A7とベースラインをN≥24で再比較する。差が確定すれば`reinject`の`wScan`引き継ぎを修正として入れ、
`[reinject]`のスキャンコードを検査する回帰テストを足す。差が出なければ、再注入の経路（hook吸収→async実行）自体を疑う。
