# BUG-147: awase起動中のみ、まれに1押下がGJIに反映されない

**発見経緯:** ADR-186の実機E2E（`spike/ime-key-matrix`の`tools/e2e/ime_key_matrix`）。**未修正・原因未確定。**

**症状:** 10手順のE2Eで、まれに1手順だけ実IMEが期待どおり変わらない（無変換で開閉しない／ひらがなでかな⇔半角英数が切り替わらない）。

**A/B（2026-09-20、実IMEだけの判定、有効12回ずつ、`ab_bug147.sh`）:** GJI単体（awase停止）0/12失敗、awase起動 6/12失敗。
ただし**ユーザーの物理入力が混入した回があり**（awaseログの`extra=0x0`のキー。`stat_runs.sh`のINVALID判定はスパイクのログしか
見ず、すり抜けた）、混入回を除くと 5/11。A7（下記）は 2/9。**E2Eの有効回判定はawaseログの物理キーでも行うべき。**

**否定できた仮説（awase/スパイクのログ。失敗8押下 vs 成功202押下）:** awase自身のIME切替（`VK_IME_ON`）が押下近傍にあった＝0件。
再注入の遅延（中央値0.3ms対0.2ms）、経路（passthrough/flush）、直前のGJI I/O、フォーカス変更からの時間、押下前1.5秒のawaseのログ種別に差なし。
物理の保持時間は失敗5件中4件が61〜155msで成功側の分布と重なる（s4 step3の1.5msはスパイクのタイマー遅れの外れ値）。
再注入は失敗した0xF2でもフックが自己注入を観測しており、OSには受理されている（0x1Dは観測ログ対象外で未確認。`send_input_safe`の戻り値も捨てている）。

**Mozc公開ソースの静読（`win32/base/keyevent_handler.cc`、`win32/tip/tip_keyevent_handler.cc`、`data/keymap/atok.tsv`。GJIがMozc派生と同一とは限らない）:**
モードキーはKeyDownだけで効く。scan code・注入フラグ・`dwExtraInfo`・時間閾値は判定に使われない（A7が決定打にならなかったのと整合）。
効くかは、TIPがキャッシュするIME open状態（KeyDownごとに`TipInputModeManager`から読む。更新は非同期のedit session/compartment通知）に依存し、
キャッシュと実状態がずれると先にサーバーが強制ON/OFFされて「押しても変わらない」に見える。**この症状は失敗8件の向き（ON→OFF・OFF→ON・ひらがな）すべてと整合する**（推定・確度高）。

**未確定:** なぜawase起動時だけキャッシュがずれるのか。次の実験で切り分ける: スパイク自身に「LLフックで吸収→即SendInputで再注入」モードを足し、
awaseなしで再注入だけの失敗率を測る（失敗すれば再注入機構が原因、しなければawaseの他の動作＝IME読み取り等が原因）。A7(`wScan`引き継ぎ)は採用していない。
