# BUG-200: IME OFF(実際)× awase ON(認識)で、打った文字が回収の Backspace で消える

**状態(2026-10-12):** 未修正。人工的に再現済み(dragonflyg4 実機、GJI)。**[BUG-074](BUG-074.md)(ADR-227 (i)、CI 検証済み・実機未検証)と同じ構成で、(i) が実機で働いていない証拠かもしれない**(追随が起きない)。原因の切り分けは [ADR-258](../adr/258-raw-tsf-literal-recovery-requires-ime-open-evidence.md) D0'(`GiveUpFollow` の outcome を取る)。TsfNative の窓は [BUG-188](BUG-188.md)(give-up が起きない)で別扱い。

**症状(所有者の報告、2026-10-12):** 「IME OFF・エンジン ON のとき、半角英数を入れると、その英数が消された」。自然発生は再現せず。
同日 22:14(JST)の手動確認(Chrome の入力欄・Windows Terminal)の `awase.log` に、同じ回収の警告が出ていた(13:14:24Z Chrome、13:14:59Z `Windows.UI.Input.InputSite.WindowClass`)。ただし消えた文字の特定はしていない。

**再現(実機、各 n=4):** `typing_stress --form=tsf --mode=drift-on --trials=4`(awase 開発ビルド `7812c9df`、GJI、デバッグ)。
IME を ON にそろえる(awase が ON の意図を持つ)→ ハーネスが awase を経由せず実 IME を閉じる(`WM_IME_CONTROL`)→ 2 秒待っても IME は OFF のまま(`real_ime_open=false`、awase は ON に戻さない)→ NICOLA 単打を1回 → 本文が**空**(`drift_on_typed.text=""`、4/4)。
対照: `--form=edit`(IMM)は同じ手順で本文 `w`(英字が残る、4/4)。TSF の経路だけで消える。

**機序(`awase.log`、13:28:19Z):** `[raw-tsf-literal] cold=4 raw TSF literal suspected → backspace ×1 + re-send "ka" scheduled + mark cold`、以後 `consecutive raw-tsf-literal (count=2..5) → giving up, backs=1 cleanup only (no re-send)`。
`probe_io.rs` の `RawTsfLiteralRecovery` アームは、GJI の書き込み・候補窓などの「IME が動いた証拠」が無いことだけで literal と判定し、Backspace を送る。IME が実際に OFF のときも証拠は出ない。再現した窓は `profile=Imm32Unavailable`(TsfNative ではない)で、ADR-205 の prefetch が別プロセスの開閉を読む設計。ADR-227 (i) がこの読みで追随するはずだが、追随が起きていない(`[external-change]`・`Engine deactivated` が出ない)。

**修正履歴:** なし。関連: ADR-246(回収の宛先照合、PR #557)は宛先の窓の取り違えだけを直した。BUG-170/171(GJI の ESC・Backspace で未確定が消える、別機序)。
