# BUG-229: belief-v2のtrackが明示操作後も古いまま残り、Engineが誤ってOFFになる

**状態(2026-11-10):** [ADR-289](../adr/289-scope-belief-clear-track-on-untracked-mode-claim.md)のD1/D4a/D4b/D5を実装(Opus4ラウンドレビュー済み設計)。実機はdragonflyg4で2026-11-09に1回観測、2026-11-10 17:07-09 JSTの再発報告は確認したが、この回はログ上で矛盾した食い違いの再現は確認できず(真の半角英数利用・ADR-245復元の成功例だった)。実機でのD1-D5の確認は未実施。

**症状:** 利用者が半角英数のまま離れた窓(Chrome)に戻ったとき、「IME ON だが Engine OFF」になった。
期待動作は「IME ON なら Engine ON」(IME OFFの時だけEngine OFF)で、実IMEは`hiragana`のまま
だったにもかかわらずEngineが`reason=Inactive(NotRomajiInput)`で非活性のままになった。

**タイムライン(UTC, awase.log 2026-11-09T13:13:19)**: ADR-245の「戻った窓の最初の打鍵→半角英数
トグルを復元」が発火しbeliefがkanaへ収束・Engine ON(`z=(mode=kana basis=z-observed-high)`)。
その約70μs後、同じ打鍵(Backspace, vk=0x08)の処理中に`[belief-v2]`が`z=(mode=eisu basis=z-explicit)`
へ食い違いを再開、43ms後に届いた`[mozc-shm]`の`"tsf_mode":"hiragana"`(本物の確認)は無視され、
43ms後にEngineが再度OFFに。

**原因:** `scope_belief.rs::on_explicit`は`track`引数が`Some`のときだけ`row.track`を書き換える
(:369-371)。ADR-245の復元(`InputModeApplied{strategy: UserHalfWidthAlnumToggle}`)が作る
`ScopeEvent::Explicit`は`track: None`(:731-741)なので、復元後も`row.track.conv`は窓を離れる前の
`eisu`のまま残る。直後のBackspace(テーブルキー)の予測は`view.track`(=この古いeisu)を入力にして
効果を予測し(`scope_event_of_prediction`:640-657)、`track: Some(prediction.track)`付きで**改めて
eisuをexplicit主張**してしまう。この新しい主張が170msの確定期限(`settle_ms`)を立て、直後に届く
本物の`hiragana`観測を棄却する(`accepts`、:788-789相当)。`on_observed`は受理した観測で
`row.track.conv = None`へ戻す(:541-543)が、`on_explicit`は対応する掃除をしない――この非対称が
原因。`belief_v2`は既定で有効で、EngineはZ(belief-v2)を読むため、古いeisuがそのままEngine停止に
直結した(BUG-192/ADR-244 M-2が「トグルがアクティブな間」だけ対処した近縁の問題の、別の抜け)。

**再現手順:** 半角英数のまま別窓へ切り替え→元の窓(TSF native, GJI系)へ戻り→最初のテーブルキー
(Backspace等、文字キーでなくてよい)を押す。

**古いeisu追跡の出どころ(2026-11-09追記、Opusレビューで確定):** 10秒前の憶測ではなく、コードから
導ける。半角英数トグルが**アクティブな間**、予測の入力からはconvが抜かれる
(`key_pipeline.rs:2045-2047`、`KeyTrack::without_conv_while_half_width_alnum`)が、これは
入力だけを変える処置で、トグル中に押したテーブルキー(Backspace/Enter/Space/Esc等)自身の予測結果
(`after_conv`)は`Some(C10)`のまま`track`に書き戻る(`key_effect_predictor.rs:648`、
`scope_event_of_prediction`:654)。つまり「トグル中にテーブルキーを1回でも押した」窓の行には、
トグルを抜けた後も`C10`が残る。回帰テストはこの手順(トグルON→テーブルキー→トグルOFF→
テーブルキー)で再現させるべきで、`row.track.conv`を手で仕込む必要はない。

**調査:** Opusサブエージェントによるコード読み(commit `6237a0601`)。当初の仮説(言語判定
`ime_on_eisu`のスコアがフォーカス切り替えをまたいで持ち越される)は否定された
(`src/lang_detect.rs`はウィンドウ切替で必ずエピソードを閉じ、非文字キーは「非日本語」の
新規証拠にならない)。2回目のOpusレビュー(ADR-289向け)で、belief-v2の`track.conv`をクリア
するだけでは不十分と判明: 旧belief(`ImeBelief::prev_conversion_mode`)も同じ値のまま残っており、
予測はそちらへフォールバックして同じ`eisu`を再現しうる。詳細はADR-289参照。

**実装(2026-11-10):** D1(`scope_belief.rs::on_explicit`)・D4a(`ime_model.rs`の`InputModeApplied`
受理時)・D4b(`runtime/mod.rs::apply_input_mode_correction`)・D5(`key_pipeline.rs`の
`[focus-conv-check]`書き込みを値スナップショットでガード)をADR-289の確定設計どおり実装。
D1・D4aは`scope_belief.rs`/`ime_model.rs`のユニットテストで確認(Linuxホストで実行可、
`cargo test -p awase-ime-core --lib`)。D4b・D5は、対になる既存の`apply_idle_conv_check`
自身も直接ユニットテストが無い(ハーネス無しでは呼べない)のと同じ理由で直接テストは追加せず、
compile確認・`architecture_guard`(175件)・`golden_scenarios`(24件)・`layer_boundary_guard`の
全パスで代替し、本ファイルへの記録([fix-requires-evidence](../../.claude/rules/fix-requires-evidence.md)
の(b))をもって備える。実機確認は未実施。
