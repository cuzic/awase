# BUG-174: Ctrl↑ で `VK_IME_ON` を再送する eager warmup

**状態(2026-10-04、v2.0.0 時点):** 機構撤去済み(原因かどうかは実機未確定) — Ctrl↑ の `CtrlUp` eager warmup は `889aff2f`(PR #358)で撤去され、さらに ADR-212 P4(`03a7996f`)で eager `VK_IME_ON` warmup の送信元がすべて撤去された(`send_eager_warmup_vk_pair` の定義は現行コードに無く、`architecture_guard.rs` の撤去ガードのみ残る)。実機 A/B(2026-09-29、少数)では撤去前ビルドで「@」が出て撤去後は出なかった。v2.0.0 の CHANGELOG は「原因だったかどうかは…」と留保付きで記載。`WarmupReason::ConfirmKeyDown` は現行コードに無く、確定キー reinject の `VK_IME_ON` warmup も BUG-173 追補2(`dcce6438`)で削除済みのため、下記「未確認・残る被疑」の 2 の2連送経路も現行コードには見当たらない(grep 確認、ログでの再確認はしていない)。

(以下は当時の記述)

**発見経緯:** 不具合報告 `01M3NJYRQ5ZBYTKV55FV06KETP`(v1.21.0、GJI、Windows Terminal + PowerShell、PowerToys 併用)。「Ctrl+Shift の操作で @ が出る」。

**確認できた事実(報告 01M3NJYRQ5ZBYTKV55FV06KETP の log 抜粋 24 秒):**
- `VK_IME_ON`(0x16、scan=0xF2、`self_injected`)の送信は 16 回。内訳は `EmitWarmup(CtrlUp)` 10、`EmitWarmup(ConfirmKeyDown)` 3、reinject の `marking cold + eager warmup` 3。CtrlUp の 10 回は約 11 秒間(03:21:13〜24)に集中。
- 注入は Ctrl↑ を OS へ渡す**前**(フック内)で行われ、10 件すべて `gas_ctrl=true`、うち 3 件は Alt も押下中。アプリへは Ctrl(+Alt) 押下中の `VK_IME_ON` として届く順序だった(フックの処理順と `gas_ctrl` からの推定。GJI・Windows Terminal 側の受信は未観測)。
- 毎回 cold 判定だった理由は GjiFsm が `OffCold` に固着していたため(BUG-170 と同型と推定。修正 `52cd221f` は develop にあり v1.21.0 には無い)。
- 報告の「Ctrl+Shift」は、抜粋では Ctrl+Alt 系の和音が大半で、Shift+Ctrl は 1 回のみ。PowerToys Keyboard Manager の remap で何の物理キーだったかは未確定。
- journal はアプリに出た文字を記録せず、`DumpTruncated`(854/2560 件)でもあるため、「@」の有無は journal から判断できない。log の `[key-output]` に awase が「@」を送った記録は無い。

**導入理由:** `07fc40d7`(2026-05-17)。WezTerm「この→kおの」対策として、「Ctrl 中に GJI の TSF 初期化が中断される」という仮定で Ctrl↑ 起点に warmup と 500ms 待機を再計測。仮定の実測根拠は記録に無い。前提の 500ms 待機は 2026-07-18 に既に撤去済み(`output/vk_send.rs`)。

**修正:** `889aff2f`(PR #358 の squash マージ。squash 前の初回コミット `aa53eb4b` は本文で旧番号 BUG-173 と表記していたが、squash 後の本文は BUG-174。`fix/f2-physical-allow-tsf-gji` の BUG-173〈物理ひらがなキーの Suppress〉とは別件)。`CompositionEvent::CtrlUp` / `WarmupReason::CtrlUp` / `WindowsPlatform::composition_ctrl_up` / executor の `handle_ctrl_up_recovery` を撤去。物理キー(Ctrl)を契機に awase が IME 制御 VK を送る経路をなくす(ADR-179(旧 178)の受動化と整合)。CtrlUp は `MarkCold` / `GjiCompositionReset` を出していなかったので cold/warm の状態遷移は変わらない。

**副作用:** belief が ON のときだけ飛んでいたため、「実 IME は閉じているが belief は ON」の状態では、Ctrl を離すたびに IME を開き直す暗黙の ON actuation として働いていた(ADR-098 / BUG-69)。撤去後は「Ctrl の後に IME が OFF のまま」に見える可能性がある。

**未確認・残る被疑:**
1. **実機 A/B(2026-09-29、dragonflyg4、Windows Terminal + PowerShell、GJI、DEBUG ログ)**: A=`14d162f8`(CtrlUp warmup あり)で Ctrl+Shift を 1 回押すと「@」が 1 個出た。log では Ctrl↓→Shift↓→Ctrl↑ の受信直後に `EmitWarmup (CtrlUp)` → `VK_IME_ON`(scan=0xF2)を SendInput し、その時点で Ctrl と Shift はまだ押されたまま(Ctrl+Shift+`VK_IME_ON` として届く順序)。この和音中に他の awase 出力は無かった。B=`54ffb38c`(撤去後)で Ctrl+Shift を押して「@」は出ず、log に `EmitWarmup (CtrlUp)` も注入も無かった(バイナリに `CtrlUp` が無いことも確認)。n は少数(A・B とも実機の手動操作、A は別途「@」が出た操作が他に 1 回、B は複数回押下で 0 回)。A で `EmitWarmup (CtrlUp)` が発火しても SendInput が出ないケース(14:44:35、14:45:10)があり、送信は状態依存。
2. **確定キー経路が残る**: Enter/Esc は `ConfirmKeyDown`(cold)と reinject(`platform.rs` の `on_reinject_key`)が 1 打鍵あたり 2 回 `VK_IME_ON` を送る。BUG-113 / ADR-167 の「@」の必要条件(連続 2 回以上の SendInput)により近い。本コミットでは触っていない。
3. 修飾キー押下中の注入そのもの(Ctrl+`VK_IME_ON`)の抑止は別コミット・別 BUG で扱う(`send_eager_warmup_vk_pair` の Win 押下スキップ〈BUG-32〉の一般化)。
4. WezTerm「この→kおの」の再発は未検証。ADR-100 F16 は Windows Terminal で eager warmup の全面無効化に問題なし(3 シナリオ、少数)。
5. PowerToys Keyboard Manager の設定(remap、テキストへの remap)を報告者に確認する。
