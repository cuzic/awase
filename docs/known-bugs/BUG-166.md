# BUG-166: MS-IME 起動直後の false 観測で Engine が長く OFF

**症状:** `ts-edit-msime-10ms` で 2/8 回、起動直後に `ime_on=Some(false)` を観測し、Engine が約14秒 OFF のまま。ローマ字が生で入る。打鍵速度に依存しない。

**未修正（原因は絞り込み中）。CI 実測（2026-09-26）:** e2e-ime run [36208885340](https://github.com/cuzic/awase/actions/runs/36208885340)
（`ci/e2e-typing-stress`）の `ts-edit-msime-10ms`（artifact `result-ts-edit-msime-10ms-2`、7日で消える）で再現。単打4試行が全滅（literal=145）、thumb/mixed は PASS。
- 起動直後（24.27s）の `ime_on=Some(false)` は**一過性ではない**。実 IME が約11秒間ずっと閉（`[startup-align] desired=false` は観測どおり）。
  当初の「BUG-163 2段目が一過性の false へ揃えた」仮説は不支持。
- 36.22s: Engine activated（ime=true）→ awase 自身が `engine_decision_async` で `open=true` を書く（`Unwarranted`＝A-1 shadow で would_have_blocked）。
- 38.96s: 観測 false → Engine deactivated → awase 自身が `open=false` を書く（`ImmCross async: open=false`、warranted）。**以後 IME 閉のまま単打が生ローマ字**。
- 52.75s: 最初の thumb 試行の 変換(0x1C) が PassThrough され、`key-effect-predict open=true` → Engine activated → 実 IME も開（52.81s）。この約14秒が「OFF のまま」の正体。
- 通る run は 36.22s の書き込みで IME が開いたままになる（と推定）。書く/書かないの競合が 2/8 の不安定さの候補。
未確認: 36.22s と 38.96s の間で実 IME が閉じた理由（`ime_on=None` の区間 36.3〜37.8s あり）。次の一手は同 artifact の `dist/awase.log` seq=62〜100 周辺の精査と、通った run との差分比較。
