# BUG-224: lang_detect の保持破棄で修飾キーの Up が落ちる

**状態(2026-10-26):** 修正を PR にした。コードレビュー(Opus)で見つけた。実機は未確認。

**症状(想定):** `ime_on`/`ime_on_eisu`、約 3 秒以上の無操作のあと、Shift を押して文字キーを押す。文字キーでエピソードが始まり、その Up と Shift の Up が保持列に入る。`max_ms`(2500ms)以内に別の窓へ切り替えると、保持列が `DiscardHeld` で捨てられ、Shift の Up が OS へ届かない(フックは物理キーをすべて止め、awase が送り直したものだけが届く)。次に Shift を物理的に押すまで、新しい窓の文字が大文字になる。設定の再読み込み(`init_lang_detect` → `on_timer`)も同じ破棄を通る。

**修正:** 保持列の要素に「修飾キーの Up か」を持たせ(`Held`)、破棄のときも Up だけは `Replay` で流す(`discard_held`)。`DiscardHeld` の数には含めない。あわせて、パニックリセットが保持を解放しない件(最大 2.5 秒後にリセット前の打鍵が再生される)も、`lang_detect_release_for_panic_reset` で直した(他の 2 つの保持と同じく、リセットの前に解放)。

**テスト:** `src/lang_detect.rs` の単体テスト 2 本(打鍵による破棄・タイマーによる破棄で、修飾キーの Up が `release` に残る)。パニックリセットの配線は `#[cfg(windows)]` の殻のため、CI の windows-build のコンパイルのみ。

**限界:** 修飾キーの Down がエピソードの中で保持列に入った場合も、Up だけが流れる(OS は対のない Up を無視するので無害)。
