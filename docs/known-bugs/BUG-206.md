# BUG-206: GJI の MS-IME プリセットで、閉からの「開くはず」のキーが開かない(表と実測の食い違い)

**状態(2026-10-18):** 未調査(オフラインの集計のみ)。実機の実害は未確認(記録 0 件)。BUG-204・BUG-205 の機序を検討した Opus レビュー(round 1)の M5 が最初に指摘した(Opus の集計は『開閉が違う 32 件+conv だけ違う 12 件=44 件』)。手元のログで私も集計し、同じ 44 件(38+6)を再現した。

**事実(`--walk=80` の実機ログ、run 39085608032、GJI の MS-IME プリセット × シード 1〜8 の 1 周目。集計スクリプトはセッションのスクラッチ内で、リポジトリには無い):**
- 表(`grid-tables/msime.json`)に当たる打鍵 296 件(`k`・`a` を除く)のうち、**表と実測が食い違うのは 44 件(14.9%)**。開閉が違うもの 38 件、開閉は同じで conv だけ違うもの 6 件。
- 食い違いは**全て押す前が閉**で、キーはひらがな 19・半角/全角 19・無変換 6。例: 表は `off-c19-none|hiragana → ON/0x19` だが実測は `OFF/0x19`。
- 閉からひらがな・半角/全角を押す 65 打鍵のうち、**38 件(58%)が開かない**。直前 1 キー別(開いた/開かなかった): 変換 0/9、ひらがな 0/7、Esc 2/7、a 4/6、k 6/5、無変換 5/2、Enter 1/2、**半角/全角 9/0**。直前 3 キーに変換があると 21/26 が開かない(無しは 17/39)。

**未確定:**
1. 実 IME が本当に閉のまま(表が単に外れている)か、IME は開いているのに読みが `open=0`(読みが嘘をついている)か。後者なら awase の観測が信用できない状態があることになり、影響が大きい。Opus レビューは「A/B/T がそろって `open=0` と読むのに無変換がカタカナとトグルし comp がある」(`open=0` かつ comp ありの『前』が 144 件)と指摘したが、私は検算していない。
2. 原因の仮説(Opus レビュー): 変換=再変換(入力欄の中身に依存)が閉の間の隠れ状態を作る。**入力欄に確定済みの文字がある(`tail`)のは全件で、有無では切り分けられなかった**。

**限界:** `--walk` はランダムな打鍵で、閉の間に変換などを押す人工的な条件。実害の記録が無い。表(格子)は空の入力欄で測っている(`--walk` は文字が溜まる)ので、入力欄の状態の差の可能性もある。

**次の手順(実害の報告があったときに):** `chrome_probe` に「直前に変換キーを押してから、ひらがな/半角全角を押し、`k`,`a` を打つ(`か` なら開いた、`ka` なら閉)」を足して、閉×ひらがなの状態を作って実機で確かめる(IME の開閉は打鍵結果で見る)。入力欄を空にした条件と文字が溜まった条件を分ける。

**修正履歴:** なし。
