# BUG-146: `EngineSync::DirectInput`分岐がIME ONの半角英数をopen軸のOFFとして書く

**発見経緯:** ADR-182の実機ログ解析中、ユーザーの「IME ON・ひらがなから無変換を単独打鍵すると、IME ONのまま
半角英数へ遷移する（GJI ATOKプリセット）。open状態は変化しない」という指摘を受けたopusレビュー
（round3、2026-09-19）で確認。修正は後回し（起票のみ）。

**症状:** `ObservedEisu`検出時（`[idle-conv-check] TsfNative: ObservedEisu 検出 → DirectInput`）、
同一ミリ秒にjournalへ`UserImeSetIntent`（値は`open=false`群からの推定）と`ImeApplyRequested`が
記録され、`apply(open=false)`は`outcome=Unwarranted`（`c8bc1adc`のwarrant）で止まるが、
`desired_open := false`のbelief書き込みは残る（例: 07:35:44.993）。約2分後の07:37:56.711にも
`was_open_before=true last_intent_before=Some(false)`が出ているが、07:37:49.508の再検出を挟むので
同一書き込みの持続とは断定できない。

**根本原因（推定）:** `crates/awase-windows/src/runtime/key_pipeline.rs:1126-1168`の
`EngineSync::DirectInput`分岐が、同じ数行で`OpenBelief { effective_open: true, confident: true }`
（conv英数モードはIME-ONの確証、`state/conv_classify.rs:44-47`）と断定しながら
`handle_engine_set_open(…, false, …)`と`issue_actuation_order(false, …)`を実行する。
`desired_open=false`は`is_eligible_for_ime_force_on()`・`last_user_explicit_off_ms`・
`from_explicit_off_intent`を支えるload-bearingな書き込みというコメントがある。

**未着手:** IME belief（再発ファミリー）で、ADR-178がforce-ONを撤去した直後の前提変化もあるため単独で
評価する。ADR-182では修正案を出していない。
