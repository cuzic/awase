# BUG-183: 入力言語ホットキー経由の言語切替で awase が非活性にならない

**症状:** MS-IME・JIS・PowerToys 併用。左Alt+Shift+3(「入力言語のホットキー」でロシア語に割当)で
日本語→ロシア語に切り替えても awase のアイコンがオレンジ(活性)のまま。左Shift 単独打鍵を2回ほどで
灰色になる(毎回かは不明)。Alt+Shift・Win+Space で切り替えると切替の瞬間に灰色になり、入力に問題はない。

**報告:** `01M4047347WXYWG8RHJDH84F1P`(1.21.1、2026-10-03)。同一ユーザーの前回 `01M31QETZG…`(2026-09-21)は
当時「言語切替時の自動OFFは機能要望」としたが、経路別の差があるため不具合として起票。

**確認できたこと:** app_log に `Engine deactivated (… japanese=false … reason=Inactive(NotJapaneseIme))` が
複数回出ており、非活性化の機構自体は動く。日本語判定は `ime.rs::keyboard_layout_info`(`GetKeyboardLayout`)。

**未確認(仮説):** 入力言語ホットキー経路だけ、レイアウト変化を awase が検知する契機(poll/フォーカス/
`is_japanese_ime` の更新)に乗らない。journal は切詰(`dropped_key_input` 438)で Alt+Shift+3 の `3` が
記録されておらず、どの経路の切替かをログから特定できていない。

**次の一手:** 3経路を実機で再現し、切替直後の `is_japanese_ime` と活性化判定の更新時刻を比較する。
回帰テストは再現後に判定関数へ追加する。

**修正履歴:** なし(未対応)。
