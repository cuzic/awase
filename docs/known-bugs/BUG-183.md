# BUG-183: 入力言語ホットキー経由の言語切替で awase が非活性にならない

**症状:** MS-IME・JIS・PowerToys 併用。左Alt+Shift+3(「入力言語のホットキー」でロシア語に割当)で
日本語→ロシア語に切り替えても awase のアイコンがオレンジ(活性)のまま。左Shift 単独打鍵を2回ほどで
灰色になる(毎回かは不明)。Alt+Shift・Win+Space で切り替えると切替の瞬間に灰色になり、入力に問題はない。

**報告:** `01M4047347WXYWG8RHJDH84F1P`(1.21.1、2026-10-03)。同一ユーザーの前回 `01M31QETZG…`(2026-09-21)は
当時「言語切替時の自動OFFは機能要望」としたが、経路別の差があるため不具合として起票。

**確認できたこと:** app_log に `Engine deactivated (… japanese=false … reason=Inactive(NotJapaneseIme))` が
複数回出ており、非活性化の機構自体は動く。日本語判定の書き込み元は複数あり(ADR-223 の表)、IME の読み取りは `read_ime_state_full`(フォーカススレッド)、フォーカス時の高速読み取りは `keyboard_layout_info`(awase 自身のスレッドの HKL)を使う。

**未確認(仮説):** 入力言語ホットキー経路だけ、レイアウト変化を awase が検知する契機(poll/フォーカス/
`is_japanese_ime` の更新)に乗らない。journal は切詰(`dropped_key_input` 438)で Alt+Shift+3 の `3` が
記録されておらず、どの経路の切替かをログから特定できていない。

**CI 再現(2026-10-04、`ci/bug183-lang-switch`、run 37171454298、windows-latest、MS-IME + ru-RU、`lang_switch_probe`):**
ja→ru を Alt+Shift・Win+Space・入力言語ホットキー(Alt+Shift+3、`ImmSetHotKey`)・`WM_INPUTLANGCHANGEREQUEST` で注入(各 4 試行)。
- どの方法でも言語は 2〜114ms で切り替わるが、**16/16 試行で、14 秒待っても awase は `Engine deactivated` にならなかった**。
- 切替の 1.5 秒後にフォーカスを別窓へ移すと、**8/8 試行で、移動の約 80ms 後に `Inactive(NotJapaneseIme)` になった**。
- awase.log の IME スナップショットは約 6 秒おきで、全て切替前の言語を報告していた。
- 原因の見立て: `runtime/mod.rs` の IME 読み取りの定期予約は、明示意図(`explicit_intent`)があると予約を止める(ADR-187)。
  今回の試行は全て直前に VK_IME_ON(明示意図)を送っているため、言語変更を検知する契機が**フォーカス変更しか無い**状態だった。
  入力言語の変更は意図を捨てる契機になっていない。

**未確認:** 実機の Alt+Shift・Win+Space が「すぐ非活性になる」理由。CI ではこの2方法でも非活性にならなかったので、
実機では切替時の言語表示(フライアウト等)でフォーカスが動き、再判定が走るのでは、という仮説(未検証)。ホットキー経路には表示が無いため、
フォーカスが動かず再判定が来ない、と考えると報告と整合する。明示意図が無い(IME キーを押していない)状態での挙動も未測定。

**次の一手:** [ADR-223](../adr/223-input-language-change-detected-at-key-time.md)(打鍵の時点でフォーカススレッドの HKL を読む。Opus r1 反映済み、r2 待ち)。

**段階 0(2026-10-04、PR #452、ADR-223):** 打鍵時にフォーカス窓のスレッドの入力言語を記録する実装を入れ(記録のみ)、CI で測った(run 37175102765)。
プローブの Win32 窓で、偽陽性 0/40、切替後の 1 打鍵目・2 打鍵目(外部注入を含む)の検知 40/40。Chrome・Windows Terminal・UWP・コンソールは未測定。段階 1(belief の更新)は、その測定の後。
