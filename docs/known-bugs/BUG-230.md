# BUG-230: 半角英数トグル保持中のひらがなキーがtoggle_heldを解除せず、Mozc切替未完了のままローマ字を送る

**状態(2026-11-11):** 原因1(`toggle_held`が解除されない)はADR-290 D1″で修正・developマージ済み
(2026-11-10、PR #933、commit `e2f438871`)。原因2(Mozcの実際の切替完了を待たない)はADR-290 D2として
未着手のまま残る。実機は dragonflyg4 で1回観測(17:09:56-17:10:02 JST、「Excel」を半角英数で
入力した直後)。マージ後の実機で、D1″自体が新しい遅延特性を持つことが分かった
([BUG-231](BUG-231.md)、[ADR-291](../adr/291-mozc-shm-push-notify-and-engine-recheck.md))。

**症状:** 半角英数トグル(左Shift単独タップ)で「Excel」を入力後、ひらがなキー(F2)を押して
日本語入力に戻したつもりが、続けて入力した日本語がローマ字のまま(リテラル)で出力された
(NICOLA変換されなかった)。

**タイムライン(UTC, awase.log 2026-11-10T08:09:56-08:10:02)**:
1. `08:09:56.464` 左Shift単独タップ→`[shift-conv-guard]`半角英数トグルON(`toggle_held=true`)。
2. `08:09:59.859` ひらがなキー(vk=0xF2)押下 → `[mode-key-follow]`がPassThroughとしてOSへ送信、
   20ms後に`KeyEffectPrediction`でbeliefを楽観的に`open=true romaji=true`へ更新・
   `Engine activated (reason=Active)`。
3. `08:09:59.906` 直後の`[mozc-shm]`観測は**まだ`"tsf_mode":"half-ascii"`**(Mozc側は未切替)。
4. `08:09:59.976`〜`08:10:02` `F`キー押下→変換されず→Backspaceで消す、を3回繰り返す
   (NICOLAのローマ字がリテラルのまま出力されたための打ち直し)。
5. `08:10:01.984` ようやく`[mozc-shm]`が`"tsf_mode":"hiragana"`に切り替わる(F2押下から**約2秒後**)。

**原因:** `crates/awase-hook-core/src/state/half_width_alnum.rs`の`toggle_held`フィールドを
`false`に戻す経路は、コード上2箇所(`:430`・`:452`、いずれも「2回目の左Shiftタップ」「右Shift
緊急解除」「ADR-245の窓復帰時の復元」経由の明示的なExit処理)しかない。ひらがなキー(F2)は
`kp_stage_mode_key_follow`(`shadow_action`を持たないモードキー用の汎用PassThrough経路、
ADR-187/ADR-191)を通るが、この経路は`half_width_alnum`の状態を一切見ない・更新しない。
結果として、ひらがなキーを押しても`toggle_held`は`true`のまま残り、`freezes_conv_observation()`
(`is_guard_pending() || is_toggle_active()`)も効き続けて観測による訂正が凍結される。

一方、F2のPassThrough自体は実際にOSへ送られているが、Mozc側が半角英数トグル(`VK_DBE_ALPHANUMERIC`
で入った持続ロック)から実際にひらがなへ切り替わるまで実測で**約2秒**かかっている(ADR-270等が
扱うMozc coldの最初の1打鍵の遅延〈通常16〜32ms〉より大幅に長い)。awase側は`mode-key-follow`の
20ms後にbeliefを即時「成功」とみなすため、この約2秒のギャップの間もNICOLAは正しいローマ字を
生成・送信し続け、まだ半角英数のままのMozcがそれをそのままリテラル文字として出力する。

ADR-270の「Mozc cold最初の送信の確認・回収」はMozc自身のcold start(長時間アイドル後)を対象に
しており、**半角英数トグルからの復帰は「cold」として認識されない**(awase自身の`Engine
activated`は即時成功とみなすため、確認・回収のトリガーが無い)。この点がBUG-229と異なる
——BUG-229は「ADR-245の復元は成功したが古いconv追跡が残っていた」側、BUG-230は「ひらがなキーが
そもそもMozc側の実際の切替を待たない」側。

**再現手順:** 左Shift単独タップで半角英数トグルON→英数テキストを入力→ひらがなキー(F2)で戻す
→直後にNICOLAで日本語を数文字入力する。
