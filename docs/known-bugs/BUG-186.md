# BUG-186: 半角英数持続トグル中の IME 側モードキーで Engine が戻らない(未修正・BUG-149 と同根)

**状態(2026-10-04):** 未修正(CI で再現、原因判明)。報告「ブラウザでの英数入力が不安定」の再現 CI(`sc-table-*`、PR #479)で発見。

**症状:** 実 Chrome × MS-IME 本体(GJI MS-IME プリセットでは変換でローマ字のまま)。左 Shift 単独タップで持続半角英数にしたあと変換・英数・ひらがなを押すと、
IME はかなに戻るが Engine は OFF のままで NICOLA でなく `か` が出る。IME_ON は `kp_restore_kana_from_half_width` に委譲済みで正常。
直接入力・かな・半角英数の 3 状態からは MS-IME 本体は全キーで一致(2 周とも同じ。run 37233715248)。

**原因:** トグル中は OS 読み取りを凍結し belief は `ObservedEisu`。実 Chrome は読み取り経路が無く(`skip_imm_query`)、素通しのモードキーの
読み直しも打鍵中扱い(idle 31ms)で捨てられ、打鍵時点の予測も MS-IME 本体の学習表にこの状態のセルが無く `no prediction`。BUG-149 と同じ「実 Chrome で IME 側のモードキーに追随できない」。

**試して戻した案:** `kp_stage_mode_key_follow` でトグルを OS 書き込みなしで手放す(run 37234927086)。コードには到達したが結果は同じ(`か` のまま)で、
GJI MS-IME プリセットの Shift タップ後の無変換に `ro` が新しく見えたので戻した。直す道は ADR-188(Chrome 向けの遅延 conv 読み取り、ドラフト・未実装)。

**再現:** `only='sc-table-msime-*'` の「Shift単独タップ後」行。
