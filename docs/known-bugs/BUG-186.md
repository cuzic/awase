# BUG-186: 半角英数持続トグル中の IME 側モードキーで Engine が戻らない(修正済み・CI 検証済み・実機未確認)

**状態(2026-10-08):** 修正済み(PR #556、ADR-244)。CI 検証済み・**実機未確認**(BUG-149/150 と同じ扱い)。直接観測(ADR-188)を GJI／同定済み MS-IME 本体へ広げ(本体は英数の軸だけ)、本体で NATIVE の読みへ追随したら持続トグルを OS 書き込みなしで手放す。`sc-table-msime-*` 2 構成とも `PASS=48 FAIL=0 INVALID=0`(修正前は `PASS=42 FAIL=6`)、専用構成 `sc-bug186-msime-shift-toggle-*` が `--strict` で 8/8 PASS(run 37739961689)。ひらがなキーを先に押した後にトグルした場合は、予測の追跡に古い変換モードが残るため、`c289bca7` の D8(BUG-192)も要る。GJI の遷移表は `develop` とセル単位で差分 0。報告「ブラウザでの英数入力が不安定」の再現 CI(`sc-table-*`、PR #479)で発見。

**症状:** 実 Chrome × MS-IME 本体(GJI MS-IME プリセットでは変換でローマ字のまま)。左 Shift 単独タップで持続半角英数にしたあと変換・英数・ひらがなを押すと、
IME はかなに戻るが Engine は OFF のままで NICOLA でなく `か` が出る。IME_ON は `kp_restore_kana_from_half_width` に委譲済みで正常。
直接入力・かな・半角英数の 3 状態からは MS-IME 本体は全キーで一致(2 周とも同じ。run 37233715248)。

**原因(2026-10-07 訂正):** 実 Chrome にも prefetch の読みは来ており、かなへの復帰は約 26〜45ms 後に `conv=0x19` で正しく読めている(run 37704093235)。
それを打鍵中扱い(`TypingActive`、idle 31ms)で捨てている。ADR-188 の直接観測は GJI 限定の述語(`external_change_watch_applies_for`)で、MS-IME 本体では動かない(`[direct-follow]` 0 件)。
トグル中の凍結(`ShiftConvGuard`)はその次の関門。旧記述の「実 Chrome は読み取り経路が無い」は誤り。BUG-149 とは「読みを捨てる」点が近いが、ADR-188 では直らない。

**試して戻した案:** `kp_stage_mode_key_follow` でトグルを OS 書き込みなしで手放す(run 37234927086)。コードには到達したが結果は同じ(`か` のまま。手放した後も同じ読みが打鍵中扱いで捨てられたためと読める、ADR-244)で、
GJI MS-IME プリセットの Shift タップ後の無変換に `ro` が新しく見えたので戻した。根は ADR-244 の a(打鍵中扱いで捨てる)・b(直接観測が GJI 限定)・c(トグル中の凍結)。手放した後も同じ読みが打鍵中扱いで捨てられたため効かなかったと読める。修正は観測された NATIVE の読みを根拠にする点で違う。

**再現:** `only='sc-table-msime-*'` の「Shift単独タップ後」行。

**残る限界:** 変換中にトグルした後の変換キーは直らない(ADR-188 M2)。ひらがなキーを先に押した後のトグルで予測の追跡が残る件は [BUG-192](BUG-192.md)(同じ PR で修正)。
