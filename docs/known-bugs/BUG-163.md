# BUG-163: 起動直後の `desired_open=true` 初期値による強制IME ON

**発見経緯:** 2026-09-24 俯瞰レビュー B-5(起動時の強制ON部分)。BUG-157 が「develop 版CIにも同数ある起動直後の既存の
過渡現象」として切り出したまま、どのBUGにも追跡されていなかった現象。詳細な調査・設計案は
[docs/tasks/review-2026-09-24-05-startup-desired-open-forced-on.md](../tasks/review-2026-09-24-05-startup-desired-open-forced-on.md)。

**症状:** IMEを閉じた状態でawaseを起動すると、起動直後に `[drift] correction: observed=… ≠ desired=true …
set_ime_open(true)` が約11秒間に22件出る(BUG-157 記載。CI run 35620809258 `ci/e2e-drift-fix` の `real-sc-dbe`
awase.log)。awaseがIMEを開けに行く挙動で、ADR-191 決定1(IMEが状態の正、awaseは書かない)に反する。

**原因(コード上の確認、`5877f982` 時点):**
- `state/ime_model.rs:309` `ImeModel::new()` が `desired_open: true`。根拠だった `ImeBelief.ime_on` は現存しない。
- `state/platform_state.rs:1091` `check_drift_correction` の抑止は「観測源が ConvOpenInference/HeuristicDefault かつ
  明示意図なし」と「観測==desired」のみ。起動直後に ImmCrossProbe 等が「閉」を観測すると初期値 true と比較され発火する。
- 送信は `runtime/ime_refresh.rs:645` `ir_apply_drift_correction`。

**未確認:** 22件が再送の結果か(約500ms間隔、推測)、読める窓(ImmCross)の実機で実際にIMEが開くか、
Confirmedで収束するか。CIログ・実機(GJI/MS-IME × メモ帳/Chrome、実打鍵で確認)での確認が必要。

**再現(CI):** run 35620809258 の `real-sc-dbe` で起動〜最初の `VK_IME_OFF` までの `[drift] correction` 件数を数える。

**修正方針(未着手、推奨は代案A):** ADR-187 追補4 の `ModeKeyPassedThrough { align_desired }` と同じ揃え機構を
起動直後(awase未書き込み・明示意図なし)の最初の成功観測にも適用。`desired_open` の型・初期値・
`effective_open()` のフォールバックは変えない。テストは純関数(Linux)と `platform_state`(windows-build CI)の2段。

**追記(2026-09-25、CI実測。現在のdevelopでも再現):** windows-latest・GJI+ATOK、`f2a875cd`（run
[36103384502](https://github.com/cuzic/awase/actions/runs/36103384502)、`baseline`×3・`atok-passthrough-cold`×3。検証専用ブランチ
`ci/verify-05-startup-drift`）。全6回で、起動0.5秒後と約1秒後（回により3件目も）に、明示意図なし（`explicit_intent=None`）の
`[drift] correction: observed=false ≠ desired=true … set_ime_open(true)`（源=ImmCrossProbe/High、`attempts=0,1(,2)`）が出た。
その後は止まり（観測は閉のまま＝書き込みは効かない）、ハーネスの操作後のフォーカス変更で1件再発する。**上の「約11秒に22件」は現在は
再現しない**（旧run 35620809258 の3構成は22/19/22件、観測源は ObserverPoll/Medium、`attempts`は21まで増加）。件数は起動後の観測源の違いで
変わるので、「最大N回」とは書かない。同じ起動直後に awase 自身が `VK_IME_OFF→VK_IME_ON`（`[gji-fsm] Unicode long-cold StartProbe`）を
送る（warmup、例外として維持する経路）ことも確認した。実機での影響は未確認のまま。

**原因調査（2026-09-25、Opus）:** 補正の判定は `desired_open=true` の初期値と最初の観測「閉」で発火する（明示意図なしでも抑止されない）。
現 develop で 2〜3 件で止まるのは収束ではなく、awase 自身の警告ダイアログ（ADR-192）がフォーカスを奪い、古い High 観測が新しい
Medium 観測を隠して 1500ms の鮮度上限（`DRIFT_CORRECTION_OBS_MAX_AGE_MS`）に達するため。ダイアログが出ない普通の起動（旧 run）では、
500ms ごとに続く。**書き込みは送信されていない**（`set_ime_open_ordered` は warrant が下りないと拒否する。ADR-090 A-2）ので、
ImmCross 窓で drift 補正が IME を開けることは無い。二次被害は、無駄な処理、`DriftDetected` による `applied` の `Optimistic(true)` への
偽装、起動約3秒での誤ったバルーン「このアプリではIME状態を確認できません」。IME を開けうる経路は別で、起動後の最初のフォーカス変更時の
`VK_IME_OFF→VK_IME_ON`（GJI warmup、`effective_open()` が観測ゼロで `desired_open=true` にフォールバックする）。

**修正（1段目）:** `ir_apply_drift_correction`（`runtime/ime_refresh.rs`）で、ImmCross の書き込み経路について、`would_have_blocked()` の
授権が下りない補正は「検知」へ進めない（journal・`DriftDetected`・バルーン通知・試行回数の加算より前に return）。
回帰テスト: `architecture_guard.rs::drift_correction_does_not_detect_when_the_warrant_would_block`（順序の固定。実機挙動の確認は
CI e2e の不変条件〔明示意図なしの `[drift] correction` の件数〕で行う）。

**修正（2段目、代案A＋warmup の偽 ON）:** `ImeModel` に `desired_is_placeholder`（`desired_open` が起動時の初期値のまま）を足し、意図・
PanicReset・HWND キャッシュ復元・揃えのどれかが書くと外れる。初期値のままの間は、`desired_open` を awase の意図として扱わない:
- 最初の成功観測へ 1 回だけ揃える（`ImeStateHub::align_placeholder_desired`、reducer は `ModeKeyPassedThrough { align_desired: true }`。
  呼び出しは `ir_align_placeholder_desired`、drift 補正より前）。
- フォーカス時の先同期（`applied` の `record_confirmed(true)` と GJI への ImeOn 通知＝long-cold の `VK_IME_OFF→VK_IME_ON`）は、初期値のままの間は
  行わない。揃えた値が「開」の非 TsfNative だけ、スキップした先同期を行う（`presync_applied_open_on`）。「閉」なら行わない
  ＝IME を閉じて起動したとき awase は開けない。GjiFsm は閉の IME と整合した OffCold のまま。
回帰テスト: 閉ループ `closed_loop_scenarios`（P3、BUG-163 の2本の ignore を外した）、`ime_model` の
`desired_open_is_a_placeholder_until_something_writes_it`、`architecture_guard::startup_placeholder_desired_is_not_treated_as_intent`（配線の固定）。
**未確認（実機・CI）:** 起動直後の `[drift] correction` が 0 件になること、IME を閉じて起動したとき `kanji_marker vk=[1A,16]` の注入が出ないこと、
IME が開いた状態で起動したとき最初の打鍵が欠落しないこと（先同期が最初の観測まで最大約0.5秒遅れる）。GJI × メモ帳/Chrome の実機確認が要る。

**残り:** 古い High が新しい Medium を隠す問題（`most_recent_trusted`）は、代案Aが入ったので別BUGとして扱える
（先に直すと起動直後の補正が無限ループになりうるため、代案Aの後にした）。

**修正履歴:** 1段目 #318（`b6ab8980`）、2段目（代案A＋warmup の偽 ON）は本PR。

**追記（2026-09-25、#321 の CI 確認）:** #321 が入った develop の e2e-ime-smoke（run [36140615943](https://github.com/cuzic/awase/actions/runs/36140615943)、
`baseline`・`atok-passthrough-cold`）で、起動直後の `[drift] correction` は **0 件**になった（修正前 2〜4 件）。
`[startup-align] desired_open を最初の成功観測へ揃えた: desired=false` が起動約 30ms 後に出る。不変条件の上限は 0 に下げた。

**まだ残る（別の経路、未修正）:** CI では起動 0.5 秒後に awase 自身の警告ダイアログ（ADR-192）がフォーカスを奪い、
`Imm32Unavailable entry without trusted cache: 安全デフォルト ON を Low confidence observation として記録` →
`[focus] Imm32Unavailable hard pre-sync applied=true` → GJI の long-cold `VK_IME_OFF→VK_IME_ON`（`kanji_marker vk=[1A,16]`）が
起動 0.5 秒後に出る。初期値の desired ではなく、**キャッシュの無い窓へフォーカスしたときの「安全デフォルト ON」の観測**
（`reset_stale_ime_on_for_imm_broken`）が原因で、実機では Chrome 等の初回フォーカスで起こりうる。IME が実際に閉じていれば
awase が開けるので、ADR-191 決定1に反する。実害の確認（GJI × Chrome/メモ帳、実打鍵）と、別BUGとして起票するかが残る。
