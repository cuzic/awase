# BUG-227: F2 の予測だけで送り、共有メモリが閉じたままのローマ字が素通りする

**状態(2026-11-04):** 実機で再現(dragonflyg4、Mozc 系)。ADR-286 で、送信前に共有メモリで ON を確認する案を起草。未実装。

**症状:** 窓(`Windows.UI.Input.InputSite.WindowClass`)に戻って約 1.6 秒後、F2 のあと「かきの」を打つと `kakino` が出た(2026-11-03 20:45:41Z = 11-04 05:45 JST)。

**ログ(awase-latest の awase.log、UTC):**
- 20:45:39.77 窓に戻る。共有メモリ `tsf_open=false`、Engine は deactivate。
- 20:45:41.37 F2 → `[key-effect-predict] open=Some(true)` で belief ON、Engine activate。
- 20:45:41.75〜42.16 `romaji="ka"`/`"ki"`/`"no"` を送信(`last_write=never`)。`[mozc-compose]` の行は無い。
- 20:45:42.78 `[key-effect-miss] axis=open predicted=true observed=false`。以後 BS ×8、20:45:45.44 の 2 回目の F2 で ON(共有メモリ `tsf_open=true` まで約 43ms)。

**原因:** ADR-270 の確認(`should_check_compose`)は、送信直前の共有メモリが `effective_open == true` のときだけ張る。F2 の直後で `false` のため、送信前も送信後も何も確認せず、予測だけで送った。1 回目の F2 が効かなかった理由は未特定。

**直し方:** ADR-286。
