# BUG-227: Mozc の確認が成功しても連続失敗の数が戻らない

**状態(2026-10-29):** 実機で再現(dragonflyg4、Mozc 系)。修正を PR にした。実機は未確認。

**症状:** 「さいしんか」を打ったつもりが `sあいしんか` になった(2026-10-29 05:02 JST)。

**ログ(2026-10-28 20:02:17Z):** `[mozc-compose] cold=168 no composition 313ms after sending "s" (server ready) → literal`、続けて `[raw-tsf-literal] cold=168 consecutive raw-tsf-literal (count=2) → giving up, no backspace, re-send only the rest "a"`。13 分前の 19:49:15(cold=152、`ko`)でもリテラルが出ていて、そのときは Backspace ×1 + 再送で直った(カウンタ 0→1)。間の約 15 回の cold は `composition confirmed` だった。

**原因:** 連続失敗の数(`consecutive_count`)は、語の最後の VK の確認(`mark_literal_session=true`)かフォーカス変更等の cold 理由でしか 0 に戻らない。Mozc の確認(`mozc_compose_check_fsm.rs`)は最初の 1 キーだけを確かめ、4 箇所とも `mark_literal_session: false` なので、確認が成功しても数えが戻らない。窓の切り替えが無いと 1 が残り、次のリテラルが「連続 2 回目」の諦める分岐(BUG-215/216 の安全弁: Backspace なし・疑いより後ろだけ再送)に入る。

**修正:** `ProbeAction::CompositionConfirmed` に `resets_consecutive` を足し、Mozc の確認(通常の確認と、読み直しの後の `Complete`)で `true` にして、数えだけ戻す。`mark_literal_session`(次の語の確認を飛ばす印)は付けない。Chrome の per-VK(BUG-216)は `false` のまま。テスト: `probe_io.rs::composition_confirmed_with_resets_consecutive_resets_the_count_without_marking_session`、`mozc_compose_check_fsm.rs` の既存テストに `resets_consecutive: true` を追加(windows-build CI)。

**限界:** 戻した後に、残りのキー(`TransmitRest`)の部分リテラル(ADR-284 の安全網)が出ると、再送で最初のキーの確認が再び戻す。Mozc は最初の 1 キーしか確かめず、この安全網は実機で未観測なので、連鎖が起きるかは未確認。連鎖が観測されたら戻す条件を狭める。
