# BUG-152: MS-IME本体でImmCross失敗後のVK_KANJIトグルがIMEを閉じる

**発見経緯:** 2026-09-20、CI実機E2Eに操作シナリオ(`sc-*`)を足して実行(run 35513651096以降)。**修正済み(未マージ)**(設計はADR-190、実機未検証)。

**症状:** Microsoft IME本体(Win32 Edit)で、直接入力からの最初のひらがなキー(0xF2)を押すと、実IMEは閉じたまま(`open=0`)なのにawaseはEngine ON。
その状態の`k`がNICOLAのかな(`き`)として直接入力に出る。awaseなしでは同じキー列でF2はIMEを開く。`sc-dbe/kanji/shift-msime-native`が毎回(3/3)失敗。

**再現(CI):** `e2e-ime`の`ci/e2e-scenarios`ブランチで`sc-dbe-msime-native-suppress`等を実行。2回目以降のひらがなキーは成功する(最初の1回だけ)。

**原因:** 最初のImmCross set-open(`WM_IME_CONTROL 0x0006`)が約150msのタイムアウトで`success=false`→事後読み取りも`None`→`imm_cross_write`が`Failed`→
`ImmCross × MsIme`のチェーンは`[ImmCross, KanjiToggle]`(`MsImeDirect`は`!can_use_imm32_cross_process()`で不適用)→再注入したF2で既に開いたIMEを
`VK_KANJI`(非冪等)が閉じる。

**検証:** KanjiToggleを送らない(a8)で`sc-dbe`/`sc-kanji-msime-native`各3/3 ALL PASS(run 35515406371)。ImmCross失敗後を`MsImeDirect`(冪等`VK_IME_ON/OFF`)に
する(a9)で実IMEが全手順で正しい(run 35516320434)。scan=0のF2でもMS-IME本体は開く(`sc-probe-vk-msime-native`)ので再注入のscan仮説は否定。

**修正履歴:** feb49ffd(ImmCross×MsImeのチェーンを`[ImmCross, MsImeDirect]`に、`KanjiToggle`機構の撤去)、ef2d73a7(到達不能になった`FallbackSent`の削除)、c2163b69(CI判定窓の拡大)。CI実機(run 35545478699)で `sc-dbe/sc-shift-msime-native` 各3/3 PASS(修正前は3/3 FAIL)、`sc-kanji-msime-native` は実IMEが全手順で正しい(1回はスパイク側の`k`が+6.9s遅れた判定窓の問題で、チェッカーを直した)。回帰テスト: `tests/ime_key_sequence_golden.rs`・`state/app_ime_policy.rs`・`state/key_sequence_policy.rs`ほか。
