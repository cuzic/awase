# BUG-132: `hook.rs`の親指キー押下タイムスタンプがDBEキーのDown/Up vk非対称で解除されずラッチしうる（修正済み・実機未検証）

**発見経緯:** BUG-131（`kana_mode_restore_key_down`ラッチの調査）のopus-adversarial-consult
レビュー中に、`hook.rs`に同型のDown/Up vk非対称バグが独立に存在することが判明した。

**症状（未検証、コード読解ベース）:** `hook.rs`の物理キー処理は、KeyDown/KeyUpどちらでも
同じ`vk`（`apply_alt_impersonation`後の値）で`vk == config.left_thumb_vk`
/`vk == config.right_thumb_vk`を判定し、一致すれば`HookState::left_thumb_down_at_us`/
`right_thumb_down_at_us`（`AtomicU64`のタイムスタンプ、ADR-164フェーズ4で`HookState`へ
集約済み。集約前は`LEFT_THUMB_DOWN_AT_US`/`RIGHT_THUMB_DOWN_AT_US`という裸static）を
KeyDownで書き込み・KeyUpで0クリアする（`hook.rs:1254-1271`）。親指キーに
`VK_DBE_HIRAGANA`（設定文字列`"VK_DBE_HIRAGANA"`、`vk.rs::from_name`が受理・
`bootstrap.rs`の`resolve_thumb_key`経由でconfig.tomlから設定可能、実在する構成）を
割り当てた場合、BUG-131と同じ理由でKeyDownは`0xF2`、対応するKeyUpは`0xF0`で届くため、
`vk == config.left_thumb_vk`（0xF2固定）がKeyUp側で常にfalseとなり、タイムスタンプが
0クリアされない。結果、この物理キーを押して離しても「親指キーが押しっぱなし」とawaseが
誤認し続け、NICOLA同時打鍵判定が壊れる（`key_pipeline.rs`の`kp_restore_hiragana_for_
suppressed_mode_key`が持つBUG-115ガード——このVKが親指キー設定時はIMEモードキーとして
扱わない——が存在すること自体、この構成が現実にあることの証拠）。

**下方修正（深刻度）:** タイムスタンプは`hook.rs::set_thumb_vk_codes`（config再読込時に
呼ばれる）で両方とも無条件0クリアされるため、**プロセス生存中ずっと固着するわけではなく、
設定リロード（設定画面での保存等）で自然回復する**。恒久固着ではないが、次に設定を触るまで
NICOLA入力が誤動作し続ける点で実害はある。

**修正（`04c6b35e`）:** BUG-131と同じscan_code一致方式に置き換えた。
`HookState`に`left_thumb_down_scan`/`right_thumb_down_scan`（`AtomicU32`）を追加し、
KeyDownで`scan_code`を記録、KeyUpは`vk`ではなく`scan_code`一致で解除する。既存の全
リセット経路（`reset_physical_key_state`/`clear_hook_latches_for_app_disable`/
`set_thumb_vk_codes`）にも新フィールドのクリアを追加。判定ロジック自体は
`vk.rs::should_release_thumb_latch`（`cfg(windows)`非依存の純粋関数）へ切り出し、
BUG-131が懸念した「NICOLA中核経路への直接変更」を避けつつLinux上でユニットテスト
（4件、DBEキーの非対称ケースを含む）で固定した。

**検証:** `cargo test --lib`（新規4件含む）、`architecture_guard`/`layer_boundary_guard`、
windows targetの`cargo check`/`cargo clippy`はクリーン。実機での`[hook]`ログ確認
（`VK_DBE_HIRAGANA`等を親指キーに割り当てた構成でのチョード判定固着解消）は未実施。

**関連ファイル:** `crates/awase-windows/src/hook.rs`
（`HookState::left_thumb_down_at_us`/`right_thumb_down_at_us`/`left_thumb_down_scan`/
`right_thumb_down_scan`, `set_thumb_vk_codes`）、`crates/awase-windows/src/vk.rs`
（`should_release_thumb_latch`）、`crates/awase-windows/src/runtime/
key_pipeline.rs`（`kp_restore_hiragana_for_suppressed_mode_key`のBUG-115ガード、この
構成が実在することの傍証）
