# BUG-181: 物理ひらがなキーの2回目以降の押下が押下IDを失う

**発見経緯:** 5日分の変更のOpus検証（指摘1）。BUG-131/132と同型のDown/Up vk非対称。

**症状（コード読解ベース、実機未検証）:** 物理「カタカナひらがな」(scan 0x70)はDown=0xF2・
Up=0xF0で届く（BUG-131実測）。`physical_key_state`はVK単位でUpが0xF0の枠しか落とさず、
0xF2の枠が残る。2回目以降のDownは`was_down=true`となり、`assign_press_id`が`None`を返す。
その結果ADR-208の押下ID（applied未知化・`with_press`・L2昇格・L3a）が効かない。
- ひらがなに`keys.ime_on`等を割り当てると、2回目以降は外から閉じられたIMEを開けない固着。
- 親指キー=ひらがな+開閉役割だと、2回目以降は自動リピート扱いで開閉が止まる。
既定構成では実害なし。0xF3/0xF4（半角/全角）はVKが交互に変わるため自然に解消する。

**修正:** `HookState::physical_down_vk_by_identity`（identity=scan+拡張ビット→Down時VK）を追加し、
同じ物理キーのUpでDown側VKの`physical_key_state`/`physical_key_down_at_ms`を落とす
（`vk::stale_down_vk_on_up`・`vk::physical_identity_slot`）。本物の自動リピート（Upなし）は
従来どおり`was_down=true`。scan=0は従来どおり。Down側で「VKが変わった」ことを根拠にした
拡張は実機未測定のため行わない。

**回帰テスト:** `vk.rs`のhostテスト（2回目fresh/F3F4交互8回/自動リピート維持/左右Alt非交差/
scan=0）、`architecture_guard::hook_callback_clears_stale_down_vk_on_up`。

**未検証:** 実機（ひらがなキーにime_on割当）での確認。
