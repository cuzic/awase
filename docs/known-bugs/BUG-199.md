# BUG-199: 通過マークの窓の中の揃えが awase 自身の書き込みを見ない

**状態(2026-10-11 更新):** 経路B(直接観測の窓)で CI 再現。修正案あり(PR #613、[ADR-256](../adr/256-direct-follow-awase-write-in-flight-guard.md)、役割のないキーに限定): 本件 25/30→0/30、回帰セット不変、逆向きの構成は同じ run の比較で差なし。実機未確認。
- 再現(使い捨て `ci/adr247-fkey-intent-ab`、run 38116243509 / 38116609782): tsf 窓(`Imm32Unavailable`)× GJI で物理 Ctrl+無変換(awase が OFF を SendInput)の直後に
  役割の無い F18、GJI の変換サーバを 400ms 停止 → 25/30 で文字が消える(F18 なしは 0/20)。awase の書き込みは窓の arm の 78〜94ms 前で、
  `follow_direct_read_in_scope` の R3(`last_explicit_ime_action_ms >= armed_at`)が守らず、窓内の処理前の「開」で意図を捨てた。
- 修正: SendInput の書き込み(`Applied`)を未確認として控え、書き込みから窓の長さ以内に arm した直接観測の窓へ 1 回だけ引き継ぎ、同じ値を読むまで窓内の読みを採らない。
- 経路A(下の起票時の記述、`drop_decision`)は変えない: 読める窓の awase の書き込みは ImmCross で同期的に IMM を変えるため、同じ再現の edit 窓は閉を読み 0 件。

(以下は起票時の記述)

**状態(2026-10-11):** 未修正・実害の記録なし・要検討。コードを読んで見つけた潜在的な問題(`docs/known-bugs/` に該当なし、報告 journal は未確認)。

**機序(origin/develop `2ba75c68` で確認):**
- `crates/awase-windows-core/src/state/mode_key_pass.rs::ModeKeyPassLatch::drop_decision`(:134-170)は窓の中(`on_expiry == false`)の観測で
  `align = first || !has_last_intent` を返し、`mark.awase_wrote` を見ない。awase_wrote を見るのは窓が切れた後の
  `should_align_after_expired_mode_key_pass`(:248-254、`align_after_expired` が呼ぶ)だけ。
- 最初の破棄で `ModeKeyPassedThrough` が `last_intent` を捨てるため、以後の読み直し(`MODE_KEY_PASS_REREAD_MS` = 60ms ごと)では
  `has_last_intent == false` → `pass_through = true` となり、`platform_state.rs::drop_intents_for_mode_key_pass_in_scope` が
  毎回 `desired_open` を観測値へ揃え直す(`MODE_KEY_PASS_MARK_WINDOW_MS` = 300ms、`tuning.rs:425`)。
- `note_awase_write` は有効なマークにしか記録しないので、arm より前の書き込みは awase_wrote に残らない。後の書き込みも窓の中の揃えは止めない。
- 結果、awase の書き込みが窓(300ms)より遅く IME に届く環境(Chrome の TSF 再初期化は実測 ~114〜~326ms、
  [BUG-002](BUG-002.md)・`.claude/rules/tuning-constants.md`)では、窓の中で読んだ古い観測で `desired_open` が上書きされうる。

**範囲:** `vk::is_followed_mode_key` の全キー(無変換・変換・かな・英数等の IME モードキー、ADR-247 以後は F13〜F24 も)。

**きっかけ:** v2.0.0 以降のレビューで、F13〜F24 追随(ADR-247)の副作用を調べた際に見つけた。
役割の無い F キーで `IntentStore` の明示意図が消える件は別件として CI の A/B で検証中。

**直すときの注意:** mode key 全般の挙動が変わるので、[BUG-157](BUG-157.md)/[BUG-158](BUG-158.md)(通過マークと desired_open の揃え)の
回帰を確かめる。関連 e2e(`.github/workflows/e2e-ime.yml`): `sc-f16-*`、`sc-bug149-chrome-*-passthru`、`sc-adr211-*`、`sc-t1e-*`。
