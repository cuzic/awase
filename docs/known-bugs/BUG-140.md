# BUG-140: `right_thumb_key`と同じキーを`keys.ime_detect.on`に登録すると、変換キー単独タップ毎にIME再適用が暴発し、GJI自身の変換機能と競合+「あ」混入

**症状（report `01M21JQY0PQPE3PQYDKSX8JAZS`、2026-09-08、GJI、`right_thumb_key=変換`）:**
KB232の変換キーをGoogle日本語入力の変換機能に割り当てているが変換が効かず、
トラブル時に未入力の「あ」が混入する。BUG-095「症状1」・GitHub issue #144で
長年真因未確定だった症状と同一。

**原因（journalで実測、確定）:** `config.toml`が

```toml
[general]
right_thumb_key = "変換"
[keys.ime_detect]
on = ["IMEオン", "変換"]
```

のように、`right_thumb_key`と同じVKが`keys.ime_detect.on`（シャドウ追跡キー）にも
登録されていた。`kp_stage_shadow_ime_toggle`で`sync_direction`（`IntentKind::SyncKey`）
が最優先採用されるため、変換キー単独タップのたびに（既にIME ONでも）
`apply_ime_open(true)`が再送される。実機ログで`[shadow-toggle] ... kind=SyncKey
... true→true`の連続発火とGJI変換候補ウィンドウのSHOW/HIDE明滅を確認、これが
GJI自身の変換機能と競合し「効かない」ように見える。初回再適用が誘発する
`[unicode-cold-warmup]`の犠牲キー機構（`VK_IME_ON+VK_A+BS`）が「あ」消し残しの
有力な発火源。

**対応（実装済み）:** `init_ime_sync_keys`（`crates/awase-windows/src/app/mod.rs`）
で`keys.ime_detect.{toggle,on,off}`のVKが`left_thumb_vk`/`right_thumb_vk`と一致
する場合は除外し、起動時診断（トレイバルーン）で警告する。actuation本体には
手を入れず、config読み込み時点で構造的に無効化する方式（`c775bb78`）。回帰テスト
2件追加（`app/mod.rs`、`#[cfg(windows)]`のため実行はCI任せ、Linuxでは
`cargo check --target x86_64-pc-windows-msvc -p awase-windows --tests --lib`で
型検証のみ）。コード変更なしの回避策（`ime_detect.on`から`"変換"`を削除）も
GitHub issue #144へ回答済み。
