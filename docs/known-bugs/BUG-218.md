# BUG-218: 明示 OFF の直後に、古い ON のキャッシュが OFF を上書きする

**状態(2026-10-25):** 修正を PR にした。擬似的な再現は純粋な判定の単体テスト。実機は未確認。

**症状:** Windows Terminal で Ctrl+無変換(IME OFF)を押し、`zoom` と打つと `zotumo` になった(実機 dragonflyg4、Mozc Readable、2026-10-25 16:59 JST)。awase が突然 ON になったように見える。

**ログ(`awase.log` 07:59:10〜11 UTC)で確かめた流れ:**
- 10.97 Ctrl+無変換 → 11.18 awase が IME を OFF にし、判断も OFF(`effective-open-flip → false`)。この時点で awase の追跡中の窓は Zoom のまま(`dwell_ms=28000`)。実際の前面は Windows Terminal。
- 11.19 / 11.31 `Z`、`O` は素通り(`zo`)。
- 11.33 追跡がようやく Terminal への移動を処理(`FocusChange [11352→2228]`)。`[explicit-intent] cleared (focus change)`。
- 11.343 `HwndCache: restore ... ime_on=true (28000ms ago)` → `effective-open-flip → true decided_by=DesiredFallback`、`Engine activated`。28 秒前の ON が、0.16 秒前の明示 OFF を上書きした。
- 11.45 / 12.15 2 つ目の `O` と `M` が NICOLA として変換され `tu`・`mo`。IME は実際には OFF なのでそのまま英字 → `zo`+`tu`+`mo` = `zotumo`。
- 同じ操作の 2 回目(24 秒)は復元が起きず、`zoom` と打てた(間欠)。

**原因:** TsfNative 窓へ入るときのキャッシュの ON 復元(ADR-165 / 35230fd)が、「OFF を押したのが入場先の窓の中だった」場合を区別しない。フォーカスの検出は周期で動くため追跡が実際の前面より遅れ、遅れている間に押された OFF は入場先の窓の中で押されたものになる。窓を離れたときの古い ON(キャッシュ)は、その OFF より古い。時間だけで抑制する案は ADR-165 の案 A として却下済み(35230fd の救済を壊す)。

**修正:** 明示 OFF を押した瞬間の前面プロセスを `ImeStateHub` が記録し(`win32::foreground_scope` を注入)、復元の判断(`focus::tsf_cache_restore::plan_tsf_cache_restore`、純粋)に加える。**OFF がキャッシュより新しく、入場先と同じプロセスで押されていたら復元しない。** OFF が別プロセス(35230fd の「Chrome で OFF → Windows Terminal へ戻る」)なら従来どおり復元する。押した時点のプロセスが不明(pid 0)なら従来どおり。回帰テスト: `tsf_cache_restore.rs` の単体テスト 9 本(Linux で走る)と、`platform_state.rs` の記録・リセットのテスト。

**限界・別件:**
- Mozc が共有メモリで「閉じている」(`tsf_open=false`、High)と報告しても、判断が ON のまま直らなかった。`ime_refresh` が「打鍵中」を理由に観測を飛ばしていた(`Skipping observer/SSOT write: typing active`)。この修正とは別の問題で、未対応。
- 実機の再現は間欠で、Windows Terminal の hosting 窓 → InputSite 子窓のフォーカス移動と、追跡の遅れの組み合わせ。修正後の実機確認は未了。
