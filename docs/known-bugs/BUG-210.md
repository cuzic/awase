# BUG-210: warm パスの literal 検出ベースラインが送信後に取られる

**状態(2026-10-20):** 修正を PR にした(順序の入れ替えとガードテスト)。実害(誤判定)の実機ログは未確認。

**症状(想定):** warm の GJI が送信直後に書いた分がベースラインに入り、write 差分 0 になって composition 成立でも `SuspectedLiteral` になりうる(余計な backspace)。veto(候補ウィンドウ可視)が抑えている可能性があり、実害は未測定。

**原因:** `output/vk_send.rs` の warm パスは `TsfSendPipeline::transmit` の**後**に `LiteralDetectFsm::new` を呼び、その中で `LiteralDetector::new(true)` を作っていた。`LiteralDetector::new` のドキュメントは「ローマ字送信直前に呼ぶこと」、`new_with_pre_send_baseline` のドキュメントは送信後だと当該 write がベースラインに吸収されると明記している。送信前に作った detector は `80756f5c^` 時点で `let _ = (detector,);` と捨てられ、`660ee198`(2026-06-22)以降ずっと送信後の baseline だった。cold パス(`probe_io.rs`)とper-VK は送信前で、warm パスだけが不揃いだった。

**修正:** 送信前に `LiteralDetector::new(true)` を作り、`LiteralDetectFsm::new` に引数で渡す。回帰ガード: `architecture_guard.rs` の `warm_path_takes_literal_baseline_before_transmit`(同時に per-VK・一括送信・フェンス bump の順序も固定: BUG-027/029/030、ADR-140)。ADR-272 段階 B (i)。

**未確認:** 実機で誤判定が起きていたか。`[literal-detect] ... suspected literal` が warm パス(`LiteralDetectFsm`)由来で出たログを探す。
