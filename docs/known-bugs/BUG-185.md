# BUG-185: MS-IME の OFF が、入力中の文字がある間は閉じない(対応しない・Google 日本語入力を案内)

**状態: 対応しない(既知の制限、所有者決定 2026-10-04)。** 利用者への案内は「Chrome で使うなら Google 日本語入力」(CHANGELOG・README・移行ガイド)。

**症状:** MS-IME 本体 × 実 Chrome(`Imm32Unavailable`)/RichEdit の TSF 窓。文字を打って未確定のまま awase の OFF(トグル・無変換単独タップ・Ctrl+無変換)を押すと、
IME は閉じず半角英数(conv 25→16)になる。以後の打鍵は ASCII。ON キーでかなに戻る(10/10)。GJI は影響なし。

**原因(確定):** MS-IME の挙動。未確定の composition が残る間の `VK_IME_OFF` は閉じず conv だけが変わる(awase なしの OS 注入・二重送信でも同じ。入力中の文字が無ければ 10/10 閉じる)。
ADR-208 決定4 例外(a)の「環境の制約」は誤りで、その旨を訂正した。実測は [調査メモ](../tasks/msime-chrome-off-rca-2026-10-04.md)(R1〜R5、n=10)。

**採らなかった案:**
- `IMC_SETOPENSTATUS(0)` の補完: 10/10 閉じるが、TSF 窓では未確定の文字が取り消される(`text_post=''`。BUG-184 の逆)。
- 先に確定してから OFF: Enter/Ctrl+M/Ctrl+Enter なら Chrome で文字が残り OFF も 10/10 閉じる。ただし入力中でないときの副作用(端末で実行・チャットで送信)があり、
  UIA `GetActiveComposition` で判定すれば Chrome では読める(取得失敗約 5/70)。しかし Chrome 以外は未測定で、待ちを含む非同期設計が要り、費用対効果が負。

**再現(CI のみ):** `only='sc-offrca-*'` の `chrome_probe --offrca=1a:typed_nc,ctrl1d:typed_nc`(composition 有り 0/10・無し 10/10)。確定キー探索は `sc-offrca-commit-*`。

**再検討の条件:** Chrome 以外の TSF 窓でも、未確定を安全に確定できる手段(判定と確定キーの副作用がない)が見つかったとき。

**追記(2026-10-04、keymatrix — run 37190693815):** 実 Chrome × MS-IME のトグル行列 `sc-keymatrix-tog-chrome-msime` は `STUCK=4/7`(2 押下以内で一致しない)、絶対キー行列 `abs-chrome-msime` は 9 セル中 7 が 1 押下で一致・1 が 2 押下・1 が GAP_NOT_MADE。edit・tsf では MS-IME も全セル PASS。→ 症状は実 Chrome(読めない窓)に固有。GJI の実 Chrome は `abs`・`tog` とも全 PASS(`e2 fresh` の `1d=off` が 1/10 で 2 押下を要したが、同構成の 3 回再走〈各 10 試行〉は全 PASS でフレーク)。
