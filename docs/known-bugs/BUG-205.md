# BUG-205: 変換中の Esc の後の段階の規則が、予測器と擬似 IME で違い、実測が無い

**状態(2026-10-18):** 未確定。予測器と擬似 IME のどちらが実 IME に近いか分からない。実機の実害は未確認。

**症状(CI の擬似 IME):** ATOK・入力中を観測できない窓で `ime-on → a → 変換 → Esc → カタカナ → 無変換`。擬似 IME は Esc 後を入力中(Typing)とし、無変換は変換中(無変換)になって IME は開いたまま。予測器は段階が None に落ち、無変換で IME が閉じると予測する(想定される実害は Engine の ON/OFF のずれ)。

**再現:** `closed_loop_scenarios.rs::esc_in_conversion_next_key_stage`(`#[ignore]`)。ランダム探索では `known_open_gap`(1 件)と、その連鎖 `after_known_open_gap`(1 件)として件数を固定している。

**原因(読解):** 表には ATOK の `(C19, 変換中, Esc) → 保持` のセルがある(`key_effect_table.rs`)ので、BUG-162 の「セルが無い」分岐は通らない。段階を進める手書きの `next_stage` の Esc の行が、予測器(`key_effect_predictor.rs` は `Esc => None`)と擬似 IME(`pseudo_ime.rs` は `0x1B => Typing`)で違う。表は「保持/破棄/確定」しか持たず、押下後の段階は持たない。

**実測の限界:** `--walk=80` の実機測定(run 39085608032、ci/escctx-probe、3 IME × 8 シード × 2 周)で、変換キー直後の Esc は 5 件。判別できるのは MS-IME 本体の 2 件で 1 対 1(支持 1・反証 1)、ATOK は 0 件。「入力が残った」は、読みに戻る場合と変換中のままの場合のどちらとも合う。同じ歩みの 2 周で Esc の結果(開閉・conv・入力の有無)は 201/201 一致。Opus レビューの再集計では全スナップショットで 7776 中 7769 一致で、差の 7 件は測定器が次のキーの効果を前の打鍵の記録に混ぜる欠陥(MS-IME 本体で 20 打鍵)で説明できるという(私は未検算)。

**次の測定(未実施):** 格子に履歴固定の行 `[k, a, 変換, Esc]` を足し、ATOK × {無変換, カタカナ, ひらがな, 変換, Space, Enter} を各 10 試行、キー間隔 2 通り。結果の開閉・conv が、`typing`・`conv-henkan`・`none` のどの行と一致するかで決める。その後、片方の `next_stage` を直して `#[ignore]` を外す。先に測定器の記録混入(`ime_key_matrix_spike.rs` の `Pending.started_ms`)を直すこと。

**修正履歴:** なし。
