# BUG-154: 再注入(`reinject`)が`wScan=0`でIMEモードキーが効かない

**発見経緯:** 2026-09-21、ADR-191の撤去版を実機（dragonflyg4、MS-IMEプリセットのGJI、ユーザー本番config）でhands-off検証したとき。
awase無し（`adr191-run-noawase`）では、IME OFFから ひらがな(0xF2)/英数(0xF0)/カタカナ(0xF1)/半角全角/漢字 がIMEを開いた（無変換・変換は変化なし）。
撤去版awaseを通すと、`removal-cold-1/2`でひらがなの閉→開が**0/6**（実IMEは閉のまま。awaseは予測どおりEngineをONにしたので「Engine ON/実IME閉」のFAIL 4件）。

**原因:** `PassThrough`は、保留中の効果があると`[relay-defer] PassThrough deferred: pending effects, reinject(...)`で保留し、
`RawKeyEvent::reinject`（`lib.rs`）が`SendInput`で再注入する。この再注入が`wScan: 0`固定で、元の物理キーのスキャンコード（ひらがな=0x70）を捨てていた。
実機のGJIは`wScan=0`のかなキーをモードキーとして扱わない。MS-IME本体は`wScan=0`でも開く（ADR-190、`sc-probe-vk-msime-native`）ので、CIの一貫性検査
（実IMEにEngineが追随するか）では検出できなかった（開かないままEngineも追随してPASSする）。

**修正:** `vk::reinject_scan_code`。IMEモードキー（`is_ime_mode_key_for_ime`）だけ元の`scan_code`を保つ。拡張キー（矢印など）は
`KEYEVENTF_EXTENDEDKEY`無しのscan付き再注入がテンキーに化けうるので従来どおり0。単体テスト（`vk::tests::reinject_keeps_scan_code_only_for_ime_mode_keys`）で固定。

**検証（実機）:** 修正後の撤去版で、`--seq=1A,F2,...`（IME OFF→ひらがなを4回）が**閉→開 4/4**（`removal-f2x4`）。修正前は0/6。
`develop`版は、ひらがなにawase自身の`shadow_action`（TurnOn）があるため、awaseがVK_IME_ONで開いていて、この不具合を隠していた。
無変換・変換（`develop`ではawaseが代行しない）の再注入も、修正前は同じ経路で`wScan=0`だった。
