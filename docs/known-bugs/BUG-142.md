# BUG-142: Windows Terminal + PowerShell + GJI、半角モード中の無変換/変換単独タップ後、物理半角/全角キーがIMEをONから戻せなくなる（「IME ON固着」）

**アプリ:** Windows Terminal（`WindowsTerminal.exe`）+ PowerShell。
**IME:** Google 日本語入力（GJI）。

**症状:** 半角モード（直接入力）中に無変換/変換キーを単独タップすると、直後から
物理半角/全角キーを押しても IME が OFF に戻らなくなる。あわせて「@」の混入
（BUG-113 と同一症状）も観測される。

**再現手順（2026-09-15、dragonflyg4実機）:**
1. Windows Terminal + PowerShell + GJI で awase Engine を有効にする。
2. 半角モード（直接入力）のまま無変換または変換キーを単独タップする。
3. その後、物理半角/全角キーを押しても IME が ON のまま変化しない
   （あるいは「@」が混入する）。

**確認済みの切り分け:** **awase.exe を完全に停止した状態でも両方の症状（「@」・
固着）とも再現する**（ユーザー実機確認）。したがって最終的な加害者は GJI 自身
（無変換/変換の物理押下に対する `ITfKeyEventSink` 等のネイティブ処理）である
可能性が高い——BUG-113 が 2026-09-07 に「無変換キー単独タップの『@』は awase
側のactuation・送信回数とは完全に無関係」と確定した結論と一致する。

**opus-adversarial-consult（ADR-173 round1）による因果連鎖の整理:** awase
稼働時は、物理半角/全角キー自体（`VK_DBE_SBCSCHAR`/`VK_DBE_DBCSCHAR`）は
`transport.rs::PhysicalKeyDisposition::plan`（既定 `dbe_mode_key_policy =
Suppress`）により無条件で Suppress され、そもそも GJI へ届かない。したがって
「半角/全角を押しても戻らない」症状は「GJI が半角/全角キーをどう扱うか」の
問題ではなく、**「無変換/変換の生キーが GJI の TSF 処理を乱した結果、その後
awase が送る `VK_IME_OFF`（半角/全角キー押下に対する awase 自身の応答）を GJI
が無視するようになる」**という間接的な連鎖である可能性が高いと推定される
（未確認、反証可能な仮説として記録）。

**未検討の対立仮説（ADR-172 が指摘）:** ADR-172
（`docs/adr/172-tsfnative-blind-rescue-four-system-consolidation.md`）が
整理した TsfNative の ON 方向救済4系統（force-on/drift correction/warmup/
reassert）のいずれかが、ユーザーの OFF 操作を打ち消す形で再表明している
可能性も排除できていない。特に reassert（`runtime/mod.rs::
reassert_explicit_physical_key`、ADR-121 D1）は物理 IME キー押下そのものが
引き金であり、機序として一致しうる。

**次の調査手順（未着手）:**
1. **awase 稼働状態**で再現させ、半角/全角キー押下前後の journal
   `ActuationDecision` レコードを確認し、awase 自身が ON を再表明していないか
   （ADR-172 の4系統のいずれかが発火していないか）を先に確認する。
2. 上記で awase 側の再表明が確認されなければ、GJI 自身の内部状態破壊
   （無変換/変換の生キー処理由来）という仮説が残る。ADR-173（`AppImeProfile`
   の代わりにプロセス名ベースの `app_overrides.solo_tap_ime_action_apps` で
   無変換/変換の生キーを抑止する変更）を実装後、同じ手順で固着が再現するかを
   確認する。

**注意（ADR-173 round1 の教訓）:** この BUG の解消を ADR-173（無変換/変換の
生キー抑止をアプリ限定にする変更）の成否根拠に**紐づけない**こと。固着が
直っても「無変換/変換の生キー抑止が効いた」と断定する根拠にはならない
（タイミング依存でマスクされた可能性を排除できないため、
`feedback_dont_trust_actuation_outcome_over_observation_events` と同型の罠）。
両者は独立に検証する。

**関連:** BUG-113（「@」の根本原因、GJI自身のTSFキー横取り）、ADR-153
（`muhenkan_solo_tap_ime_action`/`henkan_solo_tap_ime_action` の設計）、
ADR-172（TsfNative ON方向救済4系統の整理）、ADR-173（無変換/変換の生キー
抑止をアプリ限定にする変更、本BUGの調査手順の前提）。
