# BUG-198: 注入された VK_PACKET の文字が awase 経由で消える

**状態(2026-10-10):** 起票。CI で再現済み、原因は仮説(コード読みとログの一致)で、実機報告は無い。

**症状(CI、run 38029357773、`tsx-dict-*-unicode` と `tsx-raw-dict-*-unicode`):** 打鍵の前に他アプリ相当
(`dwExtraInfo=0`)から `KEYEVENTF_UNICODE` で「音声入力テスト」を1文字ずつ注入すると、
awase なしでは全 PASS(edit/rich/tsf × GJI/MS-IME)、awase ありでは全 FAIL。消えるのは注入文だけで、
その後の NICOLA 打鍵は正常(期待 `音声入力テスト…つうほめ…` に対し実際 `つうほめ…`、挿入3回なら21文字が全部消える)。

**原因(仮説):** awase のログでは `vk=0xE7` が `PassThrough` と判定されたあと、`relay-defer`
(出力保留中の後回し)→ `[reinject] vk=0xe7 down/up` に入る。再注入(`crates/awase-windows/src/lib.rs`
`RawKeyEventExt::reinject`)は `wVk=0xE7`・`wScan` は IME モードキー以外では 0・`KEYEVENTF_UNICODE` 無しで
送るため、`wScan` に載っていた文字が失われる。ただし最初の KeyDown が「直接通過」と記録されているのに
全文字が消える点は未説明(未確認)。

**未確認:** どの実アプリが VK_PACKET で注入するか(Spokenly は貼り付け方式で本件ではない、[BUG-197](BUG-197.md))。
PowerToys 等のリマップ・IME 系ツール・リモートデスクトップ・一部の音声入力ツールが該当しうるが、実在確認はしていない。

**修正方針(未決):** (a) `VK_PACKET` は `wScan` と `KEYEVENTF_UNICODE` を保って再注入する、(b) 保留せず素通しにする
(順序の入れ替わりが起きうる)。再発ファミリー(defer/replay キューの解放条件)に触れるため回帰テストを添える。
BUG-197 と同じ CI(`ci/e2e-dictation`)で A/B を取れる。
