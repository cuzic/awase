# BUG-190: MS-IME の一過性の conv=0 を 1 回の観測で「英数モード」と採用して Engine が止まる（機序特定・未修正）

**状態(2026-10-06):** CI で再現(低頻度)。**機序を特定(下記)、未修正**。[BUG-189](BUG-189.md)(古い ImmCrossProbe が優先される件)とは別の機序。BUG-189 の修正後も残る。

**症状:** `Engine deactivated (ime=true, romaji=false, japanese=true, user=true, reason=Inactive(NotRomajiInput))` が出て、次の poll で `conv=0x19` に戻るまで 0.08〜3.2s、Engine が止まる。その間に打鍵があると生のキーが MS-IME に渡り、全角英字が混じる(`おあ。んｈｘｘｔｈ、…`)。

**機序(ログで裏取り):**
1. MS-IME の OS ポーリング(`read_ime_state_full`)が、一過性に `romaji=None conv=Some("0x00000000")` を返す(直前・直後の poll は `romaji=Some(true) conv=0x00000019`)。
2. `ime_observer.rs::classify_ime_snapshot` が `ConvMode::is_eisu_evidence(ime_on, conv)`(`engine/conv.rs`)で、**1 回の観測だけで** `InputModeObserved(ObservedEisu)` を belief に書く。`is_eisu_evidence` は `ime_on == Some(false)` のときだけ conv=0 を無視する(BUG-57)。`ime_on` が `Some(true)`(Flutter・Java AWT)でも `None`(wx、open の読みが 50ms で時間切れ)でも採用される。
3. `input_mode=ObservedEisu` → `Inactive(NotRomajiInput)` で Engine が止まる。回復は次の poll(`ObservedEisu → AssumedRomaji` の stale recovery か、conv が 0x19 に戻ったとき)。

**発生状況(これまでの CI 全 run 約 460 本のうち 5 本):** すべて MS-IME。Flutter(3 本、BUG-189 の修正前の run)、wx 1 本(`tsx-ext-wx-field-msime-20ms`、run 37463797464、修正後で唯一の FAIL、最初の試行だけ崩れた)、Java AWT TextArea 1 本(PASS、止まった期間 1.02s の間に打鍵が無かった)。Flutter の 3 本は、止まる 0.12〜0.26s 前に `[key-effect-predict] vk=0x1C(変換、右親指キー) open=Some(true)` がある(止まった期間 0.08〜0.58s)。wx と Java AWT は直前の予測が 0xF2(IME ON キー)で、5.65s・3.23s 前。**変換キーの処理中(または IME の ON 遷移の直後)に MS-IME が conv を一時的に 0 と返す、と推定(未確認)。**

**訂正:** 以前この BUG の再現として挙げた LibreOffice × MS-IME の最初の試行の失敗(run 37425162897 系)は、`NotRomajiInput` ではなく `ImeOff` の反転(BUG-189 の機序)だった。

**修正の候補(未決、ADR 起票と Opus レビューが先):** (1) conv=0 を ObservedEisu として採るのを、連続 2 回の poll で一致したときだけにする(デバウンス。本物の半角英数への切替は 0.5s 遅れる)。 (2) 直近(例 300ms 以内)に IME キーまたは親指キーを処理していたら、その poll の conv=0 を採らない。 (3) `ime_on` が `None`(open の読みが時間切れ)の poll では Eisu を採らない。(3) は wx の例しか直さないので、(1)(2) が本命。**注意:** ObservedEisu を作る別経路(ユーザーが実際に半角英数へ切り替える)の挙動と、GJI の ObservedEisu stale recovery(`classify_ime_snapshot` の `or_else`)を壊さないこと。journal リプレイに「conv=0 が 1 回だけ挟まる poll 列」を足して、旧は Eisu・新は Romaji のままであることを固定する。

**次の手順:** 修正案の ADR を起票 → opus-adversarial-consult で収束 → 実装と回帰テスト。測定として、`[mrt-shadow]` と同様に、`input_mode` の反転の根拠(どの `InputModeObserved` のソース・信頼度・conv・直前のキー)を 1 行ログする診断を足して、CI の MS-IME 構成で頻度を数える。
