# BUG-190: MS-IME の一過性の conv=0 を 1 回の観測で「英数モード」と採用して Engine が止まる（機序特定・修正方針検討中）

**状態(2026-10-06):** CI で再現(低頻度)。**機序を特定(下記)、未修正**。[BUG-189](BUG-189.md)(古い ImmCrossProbe が優先される件)とは別の機序。BUG-189 の修正後も残る。

**症状:** `Engine deactivated (ime=true, romaji=false, japanese=true, user=true, reason=Inactive(NotRomajiInput))` が出て、次の poll で `conv=0x19` に戻るまで 0.08〜3.2s、Engine が止まる。その間に打鍵があると生のキーが MS-IME に渡り、全角英字が混じる(`おあ。んｈｘｘｔｈ、…`)。

**機序(ログで裏取り、詳細は [ADR-238](../adr/238-single-poll-conv-zero-eisu-adoption.md)):**
1. MS-IME の OS ポーリングが、一過性に `romaji=None conv=Some("0x00000000")` を返す(直前・直後の poll は `conv=0x19`)。
2. `ime_observer.rs::classify_ime_snapshot` が 1 回の観測だけで ObservedEisu を作る。**作る箇所は 2 つ**: `is_eisu_evidence`(`ime_on == Some(false)` 以外は採用)と、else 側の `ConvMode::classify_transition`(前回 0x19・今回 0 で英数遷移)。
3. `input_mode=ObservedEisu` → `Inactive(NotRomajiInput)` で Engine が止まる。回復は次の読み。停止時間は次の読みまでの間隔に依存し、打鍵中は SkipTyping で上限が無い(wx は 3.22s)。
4. **5 件は 2 種類の機序:** (i) 変換/無変換を MS-IME に通した 123〜263ms 後の「モードキー通過の読み直し」で読んだ一過性の値(Flutter 3、BUG-189 の修正前の run)。(ii) 相手の IME 窓の応答が時間切れ寸前のときに読んだ値(wx は open プローブ 50.1ms〈時間切れ〉・conv プローブ 49.5ms、Java は open 16ms と `classify_focus timed out`)。修正後の run で起きたのは (ii) の wx 1 件(修正後の MS-IME 21 本中)。

**発生状況(手元の CI 全 run の `IME snapshot` ログ 599 本):** MS-IME 299 本中 5 本、GJI 292 本中 0 本。5 件とも **前後の poll が 0x19 の孤立した 1 回**で、5 件すべて採用されて NotRomajiInput(`ime_on=Some(true)` 4・`None` 1)。Flutter 3 本(BUG-189 の修正前の run)、wx 1 本(`tsx-ext-wx-field-msime-20ms`、run 37463797464、修正後で唯一の FAIL、最初の試行だけ崩れた)、Java AWT TextArea 1 本(PASS、止まった期間 1.02s の間に打鍵が無かった)。止まった期間は 0.08〜3.2s。Flutter の 3 件は、conv=0 の読みの直前に `[mode-key-follow] mode key PassThrough(vk=0x1C|0x1D)` があり、通過から +263/+165/+123ms の読み直し(打鍵中の除外を外した読み)で読んだ値だった。wx・Java は最後のモードキーから 3〜5s 後で、IME 窓の応答が遅かった。(`key-effect-predict` の行は文字キーにも出るので、直前のモードキーはこの行では分からない。初版の「文字キーと同時」「変換キーとの関係は未確認」という記述は誤り。)

**訂正:** 以前この BUG の再現として挙げた LibreOffice × MS-IME の最初の試行の失敗(run 37425162897 系)は、`NotRomajiInput` ではなく `ImeOff` の反転(BUG-189 の機序)だった。

**修正の検討:** [ADR-238](../adr/238-single-poll-conv-zero-eisu-adoption.md)(起草中)。**候補(未決):** (1) conv=0 を ObservedEisu として採るのを、連続 2 回の poll で一致したときだけにする(デバウンス。本物の半角英数への切替は 0.5s 遅れる)。 (2) 直近(例 300ms 以内)に IME キーまたは親指キーを処理していたら、その poll の conv=0 を採らない。 (3) `ime_on` が `None`(open の読みが時間切れ)の poll では Eisu を採らない。(3) は wx の例しか直さないので、(1)(2) が本命。**注意:** ObservedEisu を作る別経路(ユーザーが実際に半角英数へ切り替える)の挙動と、GJI の ObservedEisu stale recovery(`classify_ime_snapshot` の `or_else`)を壊さないこと。journal リプレイに「conv=0 が 1 回だけ挟まる poll 列」を足して、旧は Eisu・新は Romaji のままであることを固定する。

**次の手順:** 修正案の ADR を起票 → opus-adversarial-consult で収束 → 実装と回帰テスト。測定として、`[mrt-shadow]` と同様に、`input_mode` の反転の根拠(どの `InputModeObserved` のソース・信頼度・conv・直前のキー)を 1 行ログする診断を足して、CI の MS-IME 構成で頻度を数える。
