# BUG-190: MS-IME の一過性の conv=0 を 1 回の観測で「英数モード」と採用して Engine が止まる（修正実装済み・CI 確認中）

**状態(2026-10-06):** CI で再現(低頻度)。**機序を特定(下記)、未修正**。[BUG-189](BUG-189.md)(古い ImmCrossProbe が優先される件)とは別の機序。BUG-189 の修正後も残る。

**症状:** `Engine deactivated (ime=true, romaji=false, japanese=true, user=true, reason=Inactive(NotRomajiInput))` が出て、次の poll で `conv=0x19` に戻るまで 0.08〜3.2s、Engine が止まる。その間に打鍵があると生のキーが MS-IME に渡り、全角英字が混じる(`おあ。んｈｘｘｔｈ、…`)。

**機序(ログで裏取り、詳細は [ADR-238](../adr/238-single-poll-conv-zero-eisu-adoption.md)):**
1. MS-IME の OS ポーリングが、一過性に `romaji=None conv=Some("0x00000000")` を返す(直前・直後の poll は `conv=0x19`)。
2. `ime_observer.rs::classify_ime_snapshot` が 1 回の観測だけで ObservedEisu を作る。**作る箇所は 2 つ**: `is_eisu_evidence`(`ime_on == Some(false)` 以外は採用)と、else 側の `ConvMode::classify_transition`(前回 0x19・今回 0 で英数遷移)。
3. `input_mode=ObservedEisu` → `Inactive(NotRomajiInput)` で Engine が止まる。回復は次の読み。停止時間は次の読みまでの間隔に依存し、打鍵中は SkipTyping で上限が無い(wx は 3.22s)。
4. **5 件は 2 種類の機序:** (i) 変換/無変換を MS-IME に通した 123〜263ms 後の「モードキー通過の読み直し」で読んだ一過性の値(Flutter 3、BUG-189 の修正前の run)。(ii) 相手の IME 窓の応答が時間切れ寸前のときに読んだ値(wx は open プローブ 50.1ms〈時間切れ〉・conv プローブ 49.5ms、Java は open 16ms と `classify_focus timed out`)。修正後の run で起きたのは (ii) の wx 1 件(修正後の MS-IME 21 本中)。

**発生状況(手元の CI の `IME snapshot` 行のある run、MS-IME 約 300・GJI 約 300):** MS-IME で 5 件、GJI は 0 件(LibreOffice の別 artifact に conv=0 が 21 件あるが、すべて `ime_on=Some(false)` で BUG-57 の除外が正しく効く)。5 件とも採用されて NotRomajiInput(`ime_on=Some(true)` 4・`None` 1)。Flutter 3 本(BUG-189 の修正前の run)、wx 1 本(`tsx-ext-wx-field-msime-20ms`、run 37463797464、修正後で唯一の FAIL、最初の試行だけ崩れた)、Java AWT TextArea 1 本(PASS、止まった期間 1.02s の間に打鍵が無かった)。止まった期間は 0.079/0.094/0.58/1.02/3.22s(SkipTyping の回数 0/0/1/1/5 と対応)。**前後の読みが 0x19 の孤立した 1 回と確認できるのは Flutter の 3 件だけ**(wx・Java は間の読みが SkipTyping でログに出ない)。

**訂正:** 以前この BUG の再現として挙げた LibreOffice × MS-IME の最初の試行の失敗(run 37425162897 系)は、`NotRomajiInput` ではなく `ImeOff` の反転(BUG-189 の機序)だった。

**修正方針:** [ADR-238](../adr/238-single-poll-conv-zero-eisu-adoption.md)(設計は収束、Opus round3)。推奨案は F-before(英数の読みを「候補」として持ち確認の読み直しで確定、予測が英数なら即確定)+ B(`ime_on=None` の読みでは採らない)。連続 2 回の一致(A)単独・直近の打鍵での除外(D)は採らない見込み。

**追記(2026-10-06、診断ログ入りの CI):** 打鍵中の除外で捨てられていた読み 5102 件のうち 3 件が単発の `conv=0`(`ime_on=Some(true)`、モードキーの通過なし、前後 0x19)。MS-IME が約 0.06% の読みでモードキーも応答遅延も無いのに単発の conv=0 を返す第 3 の形。打鍵中は SkipTyping が捨てるので無害で、打鍵が止まって通常の poll が走ったときに読むと採用される。

**修正(ADR-238 の F-before + B):** 新たに ObservedEisu へ変わる読みは 1 回目を採らず候補にし(`state/eisu_candidate.rs`)、確認の読み直し(60ms 間隔、寿命 1500ms)でも英数なら確定する。`ime_on=None` の読みは採らない。予測が既に ObservedEisu にしているときは素通し。

**次の手順(旧):** 診断ログ(`[eisu-adopt]`、一過性の値の長さ)を CI の MS-IME 構成で回す → 実装と回帰テスト。
