# BUG-190: MS-IME 起動直後の最初の試行で Engine が NotRomajiInput で止まる（未調査）

**状態(2026-10-06):** CI で再現(低頻度)。**原因は未調査**。BUG-189(古い ImmCrossProbe が優先される件、ADR-233)とは別の機序。

**再現(CI):** `tsx-ext-wx-field-msime-20ms`(wxWidgets、MS-IME)run 37463797464 の 1 回(2 回中)。以前の `tsx-ext-libreoffice-writer-msime-30ms`(run 37425162897 系、14 回中 1 回)も同じ形。どちらも最初の試行(single #0)だけ崩れ、出力が `おあ。んｈｘｘｔｈ、…`(全角英字混じり、loss=2 substitute=23)。

**ログ:** `Engine deactivated (ime=true, romaji=false, japanese=true, user=true, reason=Inactive(NotRomajiInput))` が ready 確認(12:34:51.96)の直前に出て、約 3.2s 後(12:34:54.96)に `Engine activated` で戻る。その間の打鍵が生のまま MS-IME に渡る。直前の OS ポーリングは `romaji=Some(true) conv=0x19` を返していた。`input_mode` の観測(`InputModeObserved`)が一時的に ROMAJI でない値になったと推定(未確認)。

**手がかり・次の手順:** 診断ログ `[effective-open-flip]` は ime_on の反転だけを出す。`input_mode` の反転の根拠(どの `InputModeObserved` のソース・信頼度か)を同様に出して、起動直後の MS-IME のモード観測を見る。ハーネス側の起動直後の状態(MS-IME を有効化した直後)の影響の切り分けも要る。
