# BUG-225: Mozc の cold 最初の送信で先頭の文字だけ素通りし、確認済みとして見逃される

**状態(2026-10-28):** 実機で再現(dragonflyg4、Mozc Readable、ime=GJI 分類)。修正を PR にした(ADR-284)。実機は未確認。

**症状:** フォーカス移動(別の窓へ)のあと、ひらがなキー(F2)→R(こ)で「こちら」と打つと `kおちら` になる。手で `k` を消して打ち直すしかない。2026-10-21 の「`dえ`・`kおちら`」と同じ型(先頭だけ素通り。記録: memory dragonflyg4-first-key-literal)。

**ログ(2026-10-28 00:33:38 UTC):** `FocusChange`(cold) → F2 → R。`ko` を送信。`[mozc-compose] cold=199 composition confirmed after 15ms (sent 2 chars, key_seq 330→331)`、`settled +30ms: key_seq delta at confirm 1, settled 1`。TIP は 2 打のうち 1 打(`o`)しか見ておらず、`k` は素の英字で文書へ入った。`ti`・`ra` は正常。

**原因:** `judge_compose` は `phase >= 1`(入力中の文字ができた)で `Confirmed` とする。`o` だけでも入力中の文字ができるので確認済みになり、`key_seq` の進みが送った文字数より少ない事実は 10-21 からログに出していたが、判断に使っていなかった(ADR-270 の既知の限界「部分的なリテラルは検出できない」)。

**修正(ADR-284):** 確認の時点で進みが足りなければ `Done` にせず 30ms 待って読み直し、まだ足りなければ足りない分が文書へ素通りしたと判断し、Escape(入力中の文字を捨てる)+ Backspace ×足りない文字数 + 全体の再送。揃えば通常の確認。判断は `state/mozc_shm.rs::judge_settled`。

**テスト:** `judge_settled` の単体テスト 3 本(Linux)。FSM の `settle_step` の単体テスト 4 本は `#[cfg(windows)]` のためコンパイルのみ(windows-build CI)。

**限界:** 欠落が先頭の文字だと仮定する(`ko` なら `k`)。末尾の文字の欠落(`k` だけ入力中)では、文書の順序が違うため、Escape + Backspace で直らない可能性がある。実機で測る(ADR-284 の未確認事項)。
