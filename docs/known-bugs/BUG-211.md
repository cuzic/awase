# BUG-211: 入力中の BS の後、追跡の段階が Typing のまま残る

**状態(2026-10-22):** 未修正(所有者の判断待ち)。擬似 IME の全列挙(ADR-277 の仕分け)で発見。実機の実害は未確認。

**症状(擬似 IME、実測の格子が根拠):** 最短の列(開・ひらがな 0x19 から)。
- ATOK: `a → BS → 変換`。格子 `on-c19-typing|bs`=`ON/0x19/破棄`(2/2)・`on-c19-none|henkan`=`OFF/0x19`(2/2)で IME は閉じるが、予測器は(入力中, 変換)=保持を引き「開のまま」。無変換も同じ(予測は開・半角英数、実 IME は閉)。
- MS-IME 本体: `a → BS → 英数`。格子 `on-c19-typing|bs`=破棄・`on-c19-none|eisu`=`OFF/0x10` で閉じるが、予測は(入力中, 英数)=保持の「開・半角英数」。0x1B・0x13 でも同じ(`closed_loop_scenarios.rs` の `EXPECTED_MSIME_NATIVE_1B_EISU_GAP` の 2 件はこれ)。半角/全角・IME OFF(0x1A)も同じ。
- GJI の MS-IME プリセットも、入力中の BS は表から除外されている(同じ機序が起こりうる)。

**原因:** 入力中の BS のセルは、未確定文字の文字数で破棄/保持が割れるので表から除外され(ADR-210 M2、`key_effect_table.rs` の生成の注記)、`predict_in_table` は `None` を返す。`None` のとき `ImeModel` の `key_track` は更新されず `Stage::Typing` が残る。Esc には「セルが無いときの段階」の規則(`esc_stage_without_cell`、BUG-162)があるが BS には無い。読める窓では TSF の `composing=false` が来ているが、`predict_in_table` は `composing` を「None→Typing」の昇格にしか使わず、追跡の Typing を下げない。

**想定される実害:** 1 文字打って消した直後のモードキーで、belief の開閉が実 IME と逆になる。読める窓は次の観測(柵 170ms の後)で直る。読めない窓(実 Chrome 等)では予測が主な証拠なので残り、Engine が閉じた IME へローマ字を送る(リテラル)/開いた IME で止まる、のどちらかになりうる。

**回帰の検出:** `crates/awase-windows/tests/pseudo_ime_exhaustive.rs` の `TRIAGE`「段階のずれ 起点=0x08」と golden `pseudo_ime_prediction_mismatches.txt`(件数)。

**本来あるべき動作:** 入力中を観測できる窓(TSF の composing が読める)では、観測(入力中の文字は無い)に従い段階を None にするのが正しい(ADR-191 決定3 は観測を正とする。予測器の注記も「読めるアプリでは composing が入力中を決める」)。観測できない窓では、格子は 1 文字の入力中しか測っておらず、2 文字以上なら予測器(入力中のまま)が正しいので、本来の動作は**所有者の判断待ち**(ADR-277 の仕分けの節)。

**直し方の候補(未決定):** (1) 読める窓で `composing=false` なら Typing を None に下げる、(2) BS の予測なしでは段階を「不明」にして次のモードキーの予測を止める。どちらも予測を減らす側。
