# BUG-192: ひらがなキー直後の持続半角英数 → 無変換で入力が空になる(修正済み・CI 検証待ち・実機未確認)

**状態(2026-10-08):** 原因判明、BUG-186 の PR #556 に同梱して修正(CI 検証は PR に記録)。`develop` でも再現していた。

**症状:** 実 Chrome × MS-IME 本体。かな入力の状態からひらがなキー(0xF2)を 1 回押し、左 Shift 単独タップで持続半角英数(`ka` が出る)にしたあと、無変換を押すと `ka` が入力されず文字が空(`text=""`、2 回目の確認も空)。直後のケースは前提が崩れ(持続トグルが残る)、`持続半角英数にならなかった`(INVALID)が続く。変換キーを先に押した場合は影響しない。

**原因:** 予測付きのモードキー(ひらがな)で打鍵時点の予測の追跡 `track.conv` が `Some(C19)` になる。トグル開始は awase 自身が `conv=0x0000` を書く(`InputModeApplied`)が、reducer は `input_mode` だけを書いて追跡に触れないので、トグル中も `Some(C19)` が残る。トグル中の無変換・ひらがなに予測が付き(`(open, C19)` の行)、belief を「開・ローマ字」へ動かす——実 IME は閉じる／半角英数のままなので Engine だけが ON になり、閉じた IME へ打って空になる。予測が付いた打鍵では直接観測(ADR-188)が見送られ、持続トグルも手放されない(Opus レビュー M-A、`sc-bug186-pre-F2-*` の awase.log で確認)。

**修正:** トグル中は古い追跡の変換モードを捨てる(`KeyTrack::without_conv_while_half_width_alnum`、`kp_predict_key_effect`)。トグル中の 変換・無変換・英数・ひらがな は、追跡が空の場合と同じく「予測なし」になる。

**再現・回帰:** `sc-bug186-pre-F2-{suppress,passthru}`(`--strict`、`chrome_probe --table-pre=F2`)。修正前の `develop` の本体(run 37737446039)は `PASS=2 FAIL=3 INVALID=3`。
