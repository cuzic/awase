# BUG-192: ひらがなキー直後の持続半角英数 → 無変換で入力が空になる(未調査・develop でも再現)

**状態(2026-10-08):** 未調査(CI で再現、`develop` でも同じ)。BUG-186(PR #556)の確認中に見つかった別の不具合。

**症状:** 実 Chrome × MS-IME 本体。かな入力の状態からひらがなキー(0xF2)を 1 回押し、左 Shift 単独タップで持続半角英数(`ka` が出る)にしたあと、無変換を押すと `ka` が入力されず文字が空(`text=""`、2 回目の確認も空)。直後のケースは前提が崩れ、`IME_ON後: ローマ字のまま` や `持続半角英数にならなかった`(INVALID)が続く。ひらがなキーの代わりに変換キーを先に押した場合は全 PASS。

**再現:** `only='sc-bug186-pre-F2-*'`(観測のみ、`chrome_probe --table --table-state=shift --table-keys=1C,1D,F0,F2 --table-pre=F2`)。
- `develop` の本体(`sc-bug186-pre-*` を回すための probe と構成だけ足した版、run 37737446039): `PASS=2 FAIL=3 INVALID=3`(2 構成とも、FAIL は変換 1 件〈BUG-186〉と無変換 2 件〈空〉)。
- BUG-186 の修正を入れた版(run 37737146770): `PASS=3 FAIL=2 INVALID=3`。無変換の FAIL(空)2 件と INVALID 3 件は修正の前後で同じ。

**未調査:** 無変換でなぜ入力が空になるか(IME が閉じて `ka` が打てないのか、フォーカスが外れるのか)。ひらがなキーの予測の追跡(`track.conv`)が持続トグルの開始後も残る、という機序(PR #556 の Opus レビュー M-2)は、変換キーを先に押す場合では再現しなかった(8/8 PASS)ため、この症状の原因とは限らない。
