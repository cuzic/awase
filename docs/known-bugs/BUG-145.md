# BUG-145: チョードの親指が閾値超過で単独タップ扱いになり、生の無変換がGJIへ届く（ADR-182）

**発見経緯:** ADR-179 Passthrough実験（`muhenkan_solo_tap_always_suppress=false`）の実機ログ
（2026-09-19、GJI+ATOKキーマップ、Windows Terminal）解析。ユーザーはチョードのつもりで打鍵していた。

**症状:** 文字を押して閾値（基準100msをn-gramで調整、実効80〜120ms）付近で無変換を押すと、
文字が単独確定（`て`等）し、無変換が単独タップとして`[Key(29), KeyUp(29)]`を送出→GJIが
IME ONのまま半角英数へ遷移し、awaseのエンジンも非活性になる。文字先押しと親指先押しの両方で発生:
- 文字先押し（`PendingChar→PendingThumb`）: 間隔90.1〜108.8ms（元ログ4件）、80.7/87.3/92.6ms
  （検証3件、重なり87/88/46ms）。
- 親指先押し（`step_pending_thumb_char`）: 検証で間隔58.9ms（`な`のn-gram調整後閾値が約58.8ms）、
  `[Key(29), Char('な')]`。

**根本原因:** 入口ゲート`is_simultaneous`（押下間隔）は「これから何ms重なるか」を知り得ず、落ちた親指は
通常のPendingThumbと区別されず、`resolve_pending_thumb_as_single`が優先順位4（Passthrough）で生VKを
出す。親指先押しでは、時間超過分岐が`consume_thumb`を呼ばないため、再ディスパッチされた文字が
`reduce_active_thumb`で親指面のかなを出して初めて親指を消費し、同じ押下がsolo tapとshiftの両方に
使われる（BUG-46型の二重使用）。

**修正（ADR-182）:** 決定1（`f2eb1efe`）: 時間超過で文字が単独確定された直後の親指は
`PendingThumbData.after_char_flush`を持ち、優先順位3・4（delegate/Passthrough）を抑止。決定1b
（`17890b87`）: 親指先押しで到着文字に親指面のかなが存在するとき、生の親指VKを抑止（かなは不変）。
回帰テスト: `src/engine/tests.rs`の`char_then_thumb_after_threshold_*`、`thumb_then_char_*`。
**未修正の残り:** タイマー経路（無変換を100ms超押したまま文字→`timeout_pending_thumb`が生VKを
先に送出）はADR-182決定1cで別途対応。割れたかな自体（通常面で確定）は修復しない（決定2、実測後）。
