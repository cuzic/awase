# BUG-201: 英数を押しても入力モードのずれが解消しない(逆位相の固定)

**状態(2026-10-15):** ADR-260(B1o + B3)を実装中。**報告の一太郎(観測の無い窓)には効かない**。

**症状(報告 `01M4QSFH1B02DQ9B8AXBYVRQ39`、GJI・一太郎、issue #623):** 「タスクバーは IME OFF なのに入力は全角。IME ON にするとローマ字。ちょうど逆転している」。
他のアプリで IME ON にして戻ると直ることが多い。

**再現(GitHub Actions、スパイク `exp/mode-key-recheck`・ブランチ `ci/e2e-eisu-composite` の `sc-eisu-km-*`):** GJI の MS-IME/ATOK プリセットで、英数(0xF0)を belief とずれた状態
(`close`=awase が ON を書いた後に外から閉じる / `fresh` / `sync` / `open`)で押し、かな単打の結果を読む。読める窓(`tsf`)は 132/180、実 Chrome は 75/180 がずれる。

**原因:** 開状態の英数は、かな↔半角英数を入れ替えるトグル。belief が実機と逆位相だと、打鍵時点の予測も実機も同じ向きに反転し続け、逆位相が固定される。
窓内の読みは実 conv を読んでいるのに、直接観測は「予測が付いたキーは読みを軸を問わず採らない」(ADR-188 追記6)ので採られない。

**修正(ADR-260):** (1) 窓内の読みが効く窓(GJI の直接観測の窓・現在のスコープで読みが成功済み・学習済みの IMM 能力が Unavailable でない)の開状態の英数トグルは、入力モードを予測せず追跡も捨てる(B1o)。
(2) 直接観測の予測ガードを、今回の打鍵の予測が値を持つ軸だけにする(B3、GJI のみ)。スパイクの結果: 読める窓の 6 セルがすべて 0(従来 132/180・実 Chrome 75/180)。

**残る穴:** 観測の無い窓(報告の一太郎。`ImmGetDefaultIMEWnd`=NULL)には効かない(従来の予測のまま)。入口(別アプリで OFF にして戻ると、古い ON を `HwndCache` から復元する)は別の問題(ADR-260 の Y、未検証)。
MS-IME 本体への B3、追記6 の遅い IME の構成は未測定。実機の確認は未実施。
