# BUG-135: ADR-121のVK_IME_ON冪等再送、即時パスがpending_explicit_reassertラッチを解除せず冗長送信しうる

**症状（コード監査で発見、実機未確認）:** ADR-121 D1（PR #188）は、
belief一致でno-opになった物理`VK_DBE_HIRAGANA`のTurnOnに対し
`VK_IME_ON`を冪等に追加再送する。フォーカス遷移settling中は
`pending_explicit_reassert`ラッチ（`ScopedOneShot<ForegroundScope,
bool>`）に載せてタイマーで遅延実行し、settling外なら即時実行する
（`key_pipeline.rs::kp_stage_shadow_ime_toggle`のD1ブロック）。

**根本原因:** `disarm_pending_explicit_reassert()`の呼び出しは
`message_handlers.rs`のタイマー消費パス1箇所のみで、`key_pipeline.rs`
の即時パス（`self.reassert_explicit_physical_key(new_val, tick_ms)`）
では呼ばれていない。1回目のVK_DBE_HIRAGANA打鍵がsettling中でラッチを
立てタイマーを予約した後、settlingが自然終了し2回目の打鍵（自動
リピートまたはユーザーの再試行）が即時パスを通ると、1回目のラッチは
解除されないまま残る。その後1回目のタイマーが発火すると、フォーカス
スコープが一致していれば`reassert_explicit_physical_key`が再度呼ばれ、
2回目の打鍵で既に送った`VK_IME_ON`に対する冗長な追加送信が起きる。

**影響の見積もり:** 冪等キー（`VK_IME_ON`）の重複送信であり、ADR-149/
BUG-113のような「@」誘発の再現条件（短時間の連続SendInputでGJIの
TSF composition追跡が乱れる）に該当する可能性はあるが、未検証。

**対応:** 未修正。即時パス（`key_pipeline.rs`のD1即時分岐）でも
`self.disarm_pending_explicit_reassert()`を呼ぶ。

**関連ファイル:** `crates/awase-windows/src/runtime/key_pipeline.rs`
（D1ブロック）、`crates/awase-windows/src/runtime/mod.rs::
disarm_pending_explicit_reassert`、`crates/awase-windows/src/runtime/
message_handlers.rs`（タイマー消費パス）。
