# BUG-155: 観測失敗カウントの復帰で通過マークの追随が止まる

**発見経緯:** 2026-09-21、ADR-191の撤去版を実機（MS-IMEプリセットのGJI、`custom_keymap_table`175行）でhands-off検証（`removal-cold-2`）。ひらがな押下の予測（`open=Some(true)`）で
Engineが有効になり、約12秒間ONのまま実IMEの`open`フラグ（0）に追随しなかった。1回目の同じ押下は約150ms後に訂正された（`[key-effect-miss]`）。

**切り分け:** 実IMEの`open`フラグは、この環境では**awase無しでも**閉（0）のまま、変換モード変化と未確定文字列（`comp="ｋ"`）が起きる（`noawase-cold`）。
つまりフラグ判定（cold検査器の「open=0ならEngine OFF」）は不正確で、Engine ONが誤りと断定はできない（原因(a)）。**ただし** awase側には別の実バグがあった: 
`ir_stage_observe`の`OsPoll`後は`detect_miss_count() == miss_before`のときだけ意図を破棄して`MODE_KEY_PASS_REREAD_MS`(60ms)間隔の読み直しを続けるが、
直前の読み取りが失敗（`ime_on=None`、カウント1）していて今回成功（カウントが0へリセット）すると等しくならず、追随が黙って止まる。最初の観測がfence
（`KEY_EFFECT_SETTLE_MS`=100ms）内で`stale observation ignored`になった予測は、以後の打鍵中（typing-idleガード、`Skipping observer/SSOT write: typing active`）に
読み取りの機会が無く、TTLまで残る（2回目は`[mode-key-follow] observation arrived`が1件も出ていない）。

**修正:** `state::force_guard::poll_counted_no_new_miss(before, after) = after <= before`（1トークンの条件変更＋純関数化）。復帰（減少）でも追随を続ける。
新しい型・フィールド・通過マークの追加は無い。単体テスト`poll_counted_no_new_miss_continues_follow_after_recovery`（Linux）で固定。

**検証:** CI（`ci/e2e-misprediction`）で`cal-verify-{obs,blind}`を確認（結果は本ファイル末尾に追記）。実機固有（`custom_keymap_table`、cold）は、`open`フラグの不正確さが
残るため、修正後のawaseは実IMEの`open`フラグ（0）に従ってEngineを約150msで戻す（`develop`版はawaseが強制的に開閉してフラグを一致させていた）。
