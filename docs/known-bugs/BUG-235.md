# BUG-235: focus-restore sameproc で MS-IME 本体だけ固着する

**状態(2026-11-16):** CI実測で再現を確認。原因未調査・修正未着手。

**経緯:** [ADR-245](../adr/245-half-width-alnum-restore-on-return.md) Q4(79行目)が
「同一プロセス内の窓移動は ADR の範囲外とするが、CI に `sc-focusrestore-sameproc` を
observe で足して実 IME が窓ごとかを測り、結果次第で BUG を起票する」と明記していたが、
実測後に BUG を起票するフォローアップが漏れていた(`until='2026-11-08'` の期限切れ棚卸しで発覚)。

**再現(CI、run `39129301176`、branch `feat/adr245-r2-resume-hold`、2026-10-18):**
`sc-focusrestore-{ime}-sameproc` を5試行ずつ回した結果、IME ごとに非対称:

- `sc-focusrestore-msime-sameproc`(MS-IME 本体): **5/5 で失敗**。`typed` がリテラル `'w'` の
  まま固着し、2打鍵目の `typed2` でも `'か'` に確定しない。
- `sc-focusrestore-gji-sameproc`(GJI・ATOKプリセット): 5/5 で成功。`'か'` が即時に出る。
- `sc-focusrestore-gjimsime-sameproc`(GJI・MS-IMEプリセット): 5/5 で成功。`'か'` が即時に出る。

同一プロセス内の窓移動(`process_changed` が偽、`ir_notify_focus_changed` も世代 bump も
走らない)という同じ条件で、GJI 系は追随できるのに MS-IME 本体だけ戻ってきても復元が
働かない。ADR-245 本体の半角英数トグル復元ロジックが MS-IME 本体の経路のどこかで
同一プロセス内の窓移動を正しく検知できていない可能性がある(未調査)。

**次の調査**: `runtime/resume_hold.rs`/`state/half_width_resume_hold.rs` が MS-IME 本体
固有の経路(`ime_profile`/`AppKind`判定)でこの `sameproc` ケースを早期に取りこぼしていないか、
実機(dragonflyg4)で同一プロセス内の窓移動(例: 同じエディタの別タブ/別ペイン)を再現できるかを
確認する。
