# BUG-168: StaleConfirm 2連続 → chrome-reinit が未確定文字を破棄する

**状態(2026-10-04、v2.0.0 時点):** 解決済み(CI検証済み・実機未確認) — `bc12ce95`(ADR-200 決定1: StaleConfirm は reinit の否定的証拠に数えない)が develop 済み。`tsf/probe.rs` に BUG-168 参照が現存。CI(run 36235067738・36262147901・36543501335)で実 Chrome×GJI 2ms の消失 0、`reinit withheld: negative_evidence=0 < 2` の実ログも確認。C2 残課題(1)(候補窓が残る条件での回復低下は合成条件で再現)は別途 ADR-205 の結果で再判定の提案が残る。実機での確認記録は無い。

**発見経緯:** 2026-09-26。「GJI で Chrome のアドレスバー/フォームに超高速打鍵すると取りこぼす」報告の切り分けで、`ci/e2e-typing-stress` に実 Chrome(`--form=chromebar|chromepage`)を足し windows-latest で計測。awase あり 4,200試行(取得済み artifact 分)中8件失敗(2〜10ms間隔)。うち本件は2件: run 36222195067(ページ内 textarea・2ms、40文字中35文字消失)と run 36225188542(アドレスバー・2ms、先頭23文字消失)。BUG-036(実機、2026-07-23)と同じ連鎖の再発。

**原因(ログで確認済み):**
1. 直前の deferred 一括送出(63 VK/38 VK)で GJI が詰まり、GJI I/O が223ms以上止まる(`[gji-io] WRITE` 52.959→53.182)。その間に次の語を per-VK 確認し、`visible_fencing_verdict` が StaleConfirm を2連続で返す(猶予20msを延ばしても両方 Stale になる)。
2. StaleConfirm は否定的証拠を持たない(BUG-075)のに、`probe_io.rs` の give-up 分岐は SuspectedLiteral と同じ `consecutive` に数え、2連続で `schedule_chrome_gji_reinit` する。
3. reinit の VK_IME_OFF→ON は入力中の preedit を破棄する。awase なしの対照(GJI、raw 20ms、各フォーム12試行、CI の GJI): `off_on` 24/24 で全消失、何も送らない対照は 0/24。ただし BUG-036 の実機観測は「commit されて literal が残った」で食い違う(CI の GJI 版・タイミング差の可能性、未解明)。

**切り分け済みの別件:** StaleConfirm 1回による romaji 再送の文字重複(1件、BUG-075 の系統。10ms・20秒アイドル後のアドレスバー)、起動直後の IME モード不整合(全角英数など、2件、awase なしでも1件)、awase 主スレッド約7秒停止(1件・2試行、`[slow-stage]` 計測は以降未発生)、読み戻しが GJI 処理完了前だった疑い(1件)。

**修正:** `bc12ce95`(ADR-200 決定1: reinit は SuspectedLiteral の否定的証拠が累計2回そろったときだけ。StaleConfirm は数えない)。[ADR-200](../adr/200-reinit-must-not-run-during-live-composition.md)。回帰テストは `probe_io.rs`/`tsf/probe.rs`(windows-build CI)。**CI 確認(run 36235067738、修正入り、GJI・実 Chrome・2ms):** アドレスバー 720 試行・ページ内フォーム 720 試行で失敗 0(修正前は同条件で 2/4,200)。新経路が通った回のログ: chromebar-23 で「S→U(StaleConfirm)の give-up」が `reinit withheld: negative_evidence=1 < 2` で reinit を見送り PASS、chromebar-29 では S,S の give-up が従来どおり `chrome-reinit` を送った(BUG-033 の回復は維持)。ただし修正前の発生率(約0.05%)では前後差の統計的検出はできない。**未確認:** 実機での確認、残る romaji 再送の誤り(BUG-075 系)、実機での reinit 破壊性(BUG-036 の観測と食い違い)。

**最新 develop での再確認(2026-09-26、run 36262147901、`ci/verify-latest-develop`、GJI・実 Chrome・2ms):** アドレスバー/ページ内 textarea 各 720 試行で文字の消失 0 件。修正の経路が通った実ログあり(chromepage-28: StaleConfirm 2連続の give-up が `reinit withheld: negative_evidence=0 < 2` で reinit を見送り。修正前ならここで VK_IME_OFF→ON が送られ未確定文字が全消失していた場面)。失敗2件(各1試行、0.14%)は消失ではなく文字重複で、**StaleConfirm 1回の romaji 再送(BUG-075系、ADR-200 決定2で変更しない範囲)**: chromebar-25 は2つ目の「あ」の probe が既表示の候補窓を「confirm だが GJI I/O が猶予に間に合わない」と stale 判定し、実際は入力済みの `a` を再送して「あああ」。chromepage-28 は `de` が cold=26 で同判定→再送、cold=27 も stale で give-up し「べでる」→「べっｄる」(`d` 重複で「っ」+`d`、`e` 欠落と推測、再送の詳細は未追跡)。人間の速度では起きにくいため対処は保留。**未確認:** 実機での確認は未実施のまま。

**C2 残課題5項目の再現確認(2026-09-29、`ci/c2-tschrome-repro`〔develop 2c4d48b2 + `ci/e2e-typing-stress` のChrome用ts-*構成 + `--reinit-after=esc`/`--close-ime-at`〕、GJI・実 Chrome):** 観測はすべて awase.log の `literal detect` 行と `[raw-tsf-literal]` 行。
- **run 36543501335(修正入り develop、通常打鍵)**: chromebar/chromepage 2ms 各720試行+idle3/idle20 各72試行+chromebar 10ms idle20 72試行、計1,584試行で失敗0。試行中の StaleConfirm 0・SuspectedLiteral 0・give-up 0・chrome-reinit 0。StaleConfirm 4件は全て ready 段階(cold=1、`ka` 再送、PASS)。
- **(1) 候補窓が残ったまま GJI OFF での回復低下: 再現した(合成条件)。** `--close-ime-at`(10文字目後の停止中に前面 Chrome の実 IME を `WM_IME_CONTROL` で閉じる)。chromepage で run 36545712575(ADR-200 あり): StaleConfirm 551+155件が全て give-up(`consecutive` が54まで増え続ける)、`reinit withheld` 273+75件、reinit 0。閉じた後の試行(n≥1)50試行で kana 化0文字。run 36546679858(`bc12ce95` を revert、修正前の reinit): chrome-reinit 67件×2構成、n≥1 の45試行中18試行で部分的に kana 化(180文字)。ただし完全回復はせず全試行 FAIL は同じ。chromebar は awase が状態を観測せず(StaleConfirm/give-up 0)判定不能。**限界:** 閉じ方が外部 IME 閉止(BUG-172 型)で、候補窓が実際に見えていたかは未確認。実利用での発生頻度は不明。
- **(2) StaleConfirm の romaji 再送重複: 強制シナリオで試行中に3回入り、重複0(判定は限定的)。** 試行ごとに OFF→ON する `--reopen-before-trial`(192試行)では試行中の StaleConfirm 0件で状態に入れず。`--cold --awase-settle-ms=1000`(awase 起動1秒後に最初の打鍵、chromebar 6ジョブ)で2件入り(最初の2文字目の VK で stale→ESC→romaji 再送)、本文は期待どおり(重複なし)。run 36548417600。入った件数が少なく、0.14% 級の重複は否定も肯定もできない。
- **(3) Escape 経路: awase 経由で2回発火、消失なし。** 上の2件で `escape=true backspace ×0` が出て、直前の1文字(preedit)を ESC で消し romaji を再送した結果、全文一致。awase なしの対照(24/24全消失)と違い、再送で補われるため消失に至らなかった。再送が先行文字を含まない経路(ESC 対象が複数文字)は今回入らず未確認。
- **(4) 他の reinit 呼び出し元(`platform.rs:187` Unicode long-cold): Chrome では入らない。** 入る条件は `InjectionMode::Unicode`(hint が Default かつ AppKind が TsfNative でない)で、Chrome_WidgetWin_1 は TsfNative のため Vk。CI 全ラン(約200ジョブ)で Chrome 上の long-cold StartProbe は全て Vk、`Unicode long-cold` ログ0件。フォーカス復帰直後を狙った `--idle=12000 --switch-focus --start-delay=0` 8ジョブ・long-cold 開始27回も、別窓=Unicode → Chrome 復帰の FocusChange で約500ms前に Vk へ更新済みで、Unicode 経路には入らず。AppKind の誤分類(BUG-18 型)が起きた場合だけ到達。
- **(5) 起動直後の不整合/7秒停止: どちらも再現せず(観測はした)。** 起動1秒後/3秒後の最初の打鍵(`--cold`)は chromebar/chromepage 各6ジョブ、計24ジョブで全 PASS(うち StaleConfirm 2件・SuspectedLiteral→give-up→chrome-reinit 1件を含むが本文は一致)。主スレッド停止の代理指標: `[slow-stage]` 0件、awase.log のログ間隔が4秒超の15箇所は全て無打鍵区間。`run_with_timeout` の300ms超過は約200ジョブで19件(11件が起動5秒以内、8件がアイドル後のフォーカス切替時)で、いずれも1回300ms止まり、7秒級はなし。起動時は2連続(約600ms)の主スレッド待ちがあり得る。
