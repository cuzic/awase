# BUG-168: StaleConfirm 2連続 → chrome-reinit が未確定文字を破棄する

**発見経緯:** 2026-09-26。「GJI で Chrome のアドレスバー/フォームに超高速打鍵すると取りこぼす」報告を受け、`ci/e2e-typing-stress` に実 Chrome(`--form=chromebar|chromepage`)を足して windows-latest で計測。awase あり約4,700試行中8件失敗(2〜10ms間隔、再現率 約0.2〜0.7%)。定常の連続打鍵は失敗ゼロ。

**症状:** ページ内 textarea・2ms で 40文字中35文字が消えた(run 36222195067)。10ms・20秒アイドル後のアドレスバーでは先頭の「い」が二重になった(run 36226778637、BUG-075 と同型)。

**原因(実証済み):**
1. `visible_fencing_verdict` が「候補窓は可視だが GJI I/O が猶予 `EPOCH_FENCE_GRACE_MS`(20ms)に追いつかない」を StaleConfirm と断定する。CI 実測で CompositionConfirmed の `since_vk_sent_ms` は p50=16/p90=32/p99=63ms なので、20ms は遅い正常系を切る。全ログ約1,430判定中 StaleConfirm 11件(0.8%)、30ms間隔でも発生。
2. StaleConfirm は否定的証拠を持たない(BUG-075)のに、`probe_io.rs` の give-up 分岐は SuspectedLiteral と同じ `consecutive` に数え、2連続で `schedule_chrome_gji_reinit` する。
3. reinit(VK_IME_OFF→ON)は入力中の preedit を破棄する。**awase なしの対照実験**(`--reinit-after`、GJI、アドレスバー/ページ各12試行): off_on 12/12・off 12/12・VK_DBE_HIRAGANA 6/12 で全文字消失、何も送らない対照は 0/12。BUG-36 のコメント(「commit される」)と逆。
実例のログ: cold=9,10 で stale → `[chrome-reinit] cold=10` → 直前の35文字が消え、後続の deferred 5文字だけ残った。

**別件(本件と切り分け済み):** 起動直後の最初の試行の失敗(ready が3回目で通った直後。awase なしでも発生)、awase 主スレッド約7秒停止1件(`[slow-stage]` 計測は以降未発生)。いずれも未解明。

**修正:** 未着手。[ADR-200](../adr/200-reinit-must-not-run-during-live-composition.md) 参照。回帰テストは ADR-200 決定3。
