# BUG-180: 保留の `StartComposition` が IME OFF・フォーカス変更をまたいで残る

**症状:** `[gji-fsm] StartComposition while engine off — ignored`(OffCold での警告、不変条件 i4)。
OnCold/OnWarm の状態では、存在しない composition で `OnComposing` に入りうる(BUG-170 型、コード読みからの推論で実ログ未確認)。

**再現(ADR-213 P2b の CI、run 36836062803):** `sc-follow-chrome-atok-eisu`・`sc-follow-chrome-msime-hankaku` の run 1。
最後の送信の後に候補窓 SHOW が来て latch が立つ(drain の機会なし)→ IME OFF で OffCold → 次の文字 K の drain で約1秒前の SHOW が配られる。

**原因:** `pending_start_composition`/`pending_end_composition` は `advance_tsf_probe`・`send_keys`・WM_DRAIN 後処理でしか drain されず、
`gji_on_ime_off`・`gji_on_focus_change` では捨てられない。develop にも以前からあった潜在バグ。P2b で起動時の `VK_IME_ON` が無くなり
GJI 変換プロセスの接続が遅れて probe が1 tick で終わるため、顕在化しやすくなった。

**修正:** `gji_on_ime_off`・`gji_on_focus_change` の先頭で保留 latch を捨てる(`observer::discard_pending_composition_events`)。単体テスト追加(windows-gated)。
