# BUG-195: アクティブ TIP の誤同定(GJI → MS-IME)

**状態(2026-10-09):** 起票。原因は仮説のみ(未検証)。報告 `01M4FJV2M52W30VG98YNBETMK8`(v2.0.0、[bug-reports-triage.md](../bug-reports-triage.md))。

**症状:** Windows Terminal で「のと」を打つと「noと」。所有者が GJI 使用を確認。

**証拠(報告のログ・journal):**
- awase の同定は約3.3時間ずっと MS-IME: `GjiFsmTransition` 1246件すべて `MsImeStrategy`、`ActuationDecision` は `kind=MsIme`、`FocusProbe` は `ime=MicrosoftIme`、`ime_product_name` は `Microsoft IME`。
- 実際は GJI: `[gji-obs] candidate SHOW`(クラス `GoogleJapaneseInputCandidateWindow`)が40件。
- 症状の経路: 物理ひらがなキー(0xF2)PassThrough の約0.93秒後に `[msime-ready] IME mode 未確認 → defer` → 16ms 後に conv の NATIVE を確認して `"no"` を送信([BUG-172](BUG-172.md) 型)。GJI として扱えば別の戦略(literal 検出 → GJI reinit)になる。

**仮説(未検証):** `tip_detector.rs::query_active_kind` は監視スレッド(`gji-io-monitor`)の `GetActiveProfile` で種別を決める。
「入力設定をアプリ ウィンドウごとに異なる値にする」(`SPI_GETTHREADLOCALINPUTSETTINGS`)が有効だと、監視スレッドが見るプロファイルは前面窓の IME と食い違いうる。報告にこの設定値は無い。

**未確認:** 報告者の設定値、起動時の `[tip-detect] EnumProfiles(JA)` / `initial IME kind`(ログ抜粋に無い)、他の GJI ユーザーでの再現頻度。

**修正方針(未着手):** 種別の同定を前面窓のスレッドの HKL/TIP から取るか、`GoogleJapaneseInputCandidateWindow` の表示を GJI 稼働の独立証拠として照合する。
`fix-requires-evidence`(IME belief / キー選択ファミリー)により、修正時は回帰テスト(判断表の単体テストか CI)を添える。
