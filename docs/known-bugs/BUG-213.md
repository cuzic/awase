# BUG-213: 押下 ID の無い ON が applied で省かれる

**状態(2026-10-22):** 修正を PR にした。実害は GitHub の Windows CI(実 Chrome × GJI)で再現。実利用の頻度は未確認。ECRS DD5-03 の検証で発見。

**症状(CI、`ci/dd503-repro`、run 39806707217・39801179398):**
- `hkfresh`: awase を再起動して実 IME が閉じた状態から、フォーカス往復 → ホットキー OFF → ホットキー ON。有効 3 試行すべてで実 IME が閉じたまま残った。`applied=true` はフォーカス時の写し(`presync_applied_open_on`)だけで付き、OFF は `Unwarranted`、ON は `AlreadyMatched`。
- `hkcl`(OFF の後で実 IME を外から閉じる)5/5、`hkclnr`(フォーカス往復なしの対照)6/6 も固着した。写しの全廃では直らない(`hkclnr`)。
- Engine ON コンボ(押下 ID が付く)は安全(run 39797924449、24 試行すべて 1 押下で ON)。

**原因:** `toggle_engine`(トレイ・`general.engine_toggle_hotkey`)と `force_engine_on`(トレイの「状態をリセット」)の `SetOpen` は `press=None` で、`explicit_press_applied_pair`(押下に由来する ON は `applied` を未知にする、ADR-208 D1)が効かない。`gji_direct_already_matches` が古い `applied` で ON を省く。

**修正:** 2 つの経路で `hook::allocate_command_press_id()`(押下と同じカウンタ)の押下 ID を `SetOpen` に載せる。`PressLedger`(1 押下 1 書き込み)と `applied` の未知化がそのまま効く。drift correction や自動リピートの `press=None` は従来どおり省略する。回帰の検出は `architecture_guard::user_commands_without_a_physical_key_stamp_a_command_press` と、`sc-keymatrix-dd503-chrome-hk-*`(CI)。

**未確認:** 実利用の journal での件数、MS-IME・Edge、トレイメニュー操作そのもの(ホットキーは同じ `toggle_engine`)。
