# BUG-171: 途中の語で StaleConfirm→ESC が直前の未確定文字を巻き込む（未修正）

**状態(2026-10-04、v2.0.0 時点):** 未修正(現行コードに残存を確認) — `crates/awase-windows/src/tsf/warmup/literal_detect_fsm.rs:89` の `per_vk_recovery_params(is_stale, failed_idx)` は 2 引数のままで、「途中の語」を区別する引数は無く、`escape_composition = failed_idx > 0` も変わっていない。BUG-170 の修正(`52cd221f`、ADR-203)は OffCold 固着の防止と、OnComposing 中の Reopen を no-op にする部分(`gji_fsm.rs` のテスト `reopen_while_composing_is_a_no_op`)のみで、本バグの方針(語頭で未確定文字の有無を記録して ESC を抑止)は未実装。README・移行ガイド・`docs/tasks/v2-e2-v1-backport-inventory-2026-09-29.md` も「v2 でも未修正」と記載し、`d97e612e` で v2.0.0 の CHANGELOG/移行ガイドから「修正済み」を外している。

(以下は当時の記述)

**発見経緯:** [BUG-170](BUG-170.md) の調査（report `01M3NBQA8KH2JN6S1PYHP8DJRF`、Opus レビュー）。BUG-168 追記・BUG-075 系と同根。

**症状:** 「これ」を未確定のまま「で」を打つと、「で」の per-VK が StaleConfirm になり `escape=true` の `VK_ESCAPE` で「これ」ごと消える（journal 上 per-VK 約26セッション中4回）。

**原因:** `per_vk_recovery_params(true, idx=1) → (0, true)`（`tsf/warmup/literal_detect_fsm.rs`）は「IME セッション最初の1文字専用」の前提で、ESC の破壊範囲は pending composition 内に閉じるとしている。
しかし「pending composition = この語」ではない。途中の語では候補窓が既に可視で、per-VK の可視ショートカットが Stale に倒れやすい。
ADR-203 で GjiFsm の OffCold 固着を直しても、OnComposing 中の CompositionReset+gji_idle≥7000ms（OnCold(Medium)）や `WarmupAborted→AbortedCold`、
1語目の probe が `StartComposition` より前に Stale で終わって `OnCold(kind, NotStarted)` に戻る経路で再発する。

**方針（未着手）:** 語の最初の VK を送る時点で「未確定文字が既に存在したか」（候補窓可視・`ime_composition_active_now()`・GjiFsm が OnComposing か）を記録し、存在したら `escape_composition=false`
（または途中の語の Stale は confirm 扱い）。`per_vk_recovery_params` に引数を足して全組合せを単体テストする。`docs/windows-api-constraints.md §1-2` に「pending composition = この語ではない」を追記する。

**状態（2026-09-29）:** 未着手・未修正。[BUG-170](BUG-170.md) の残作業と独立に着手できる（BUG-170 の実機検証で消失が0件でも本バグは残りうる）。
