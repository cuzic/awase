# BUG-177: 学習プロセスが自分の注入を汚染と誤判定する(JIS 実機)

**状態(2026-10-04、v2.0.0 時点):** 解決済み(実機確認済み) — 修正 `ef4f24f4`(PR #390 のマージ `c4d3dd72`、`awase-keymap-learn/src/external_write.rs::classify_injection` と回帰テスト `own_marker_without_injected_flag_is_self_injected` が現存)。同じ JIS 実機(dragonflyg4)で修正を含む develop `b9ae1bac`(`ef4f24f4` の子孫であることを確認)から学習を回し、[BUG-178](BUG-178.md) の記録のとおり interference なく 98.7 秒で `status=success` になった(2026-09-30)。なお本文「未確認」の学習表で Engine が追随するかは別論点(v2 実機確認の追跡項目)。

(以下は当時の記述)

**発見経緯:** 2026-09-30、v2 実機確認(dragonflyg4、JIS キーボード、GJI、Windows 11)。「変換単独で Engine が追随しない」の原因が未学習と分かり、
`awase-keymap-learn-win` を実機で回したところ、3回とも 14 押下・6 セルで `result status=failure … contaminated_trials=4 reason=interference`
(`press: 汚染を検出(物理入力)` ×4)で終了した(`keymap-learn-table.json` は書かれない)。PowerToys.KeyboardManagerEngine を止めても、画面を起こす処理の入力を止めても同じ。

**原因(独立した低レベルフックで観測):** 学習プロセスが注入した `VK 0xF3`/`0xF4` のうち、**キーアップだけ**が `injected=False`(`LLKHF_INJECTED` なし)で届く。
`dwExtraInfo` は自分の目印 `0x4C524E4D`("LRNM")のまま。`classify_injection` は「注入フラグが無ければ、目印が自分のものでも物理入力」としていた
(旧テスト `physical_input_has_no_injected_flag` がその前提を固定)ため、4回の汚染=無効化上限で学習が打ち切られた。CI(windows-latest)では起きない。

**修正:** 自分の目印が付いていれば、注入フラグの有無によらず `SelfInjected` にする(`external_write.rs::classify_injection`)。物理キーの `extra_info` は通常 0 で自分の目印にならない。
回帰テスト: `own_marker_without_injected_flag_is_self_injected`(旧テストの前提を入れ替え)。

**未確認:** 修正版の学習プロセスで実機の学習が完走するか、学習表で Engine が追随するか(検証中)。
