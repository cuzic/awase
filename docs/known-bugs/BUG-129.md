# BUG-129: 【解決済み・仕様と判定】`flush_pending`の`PendingCharThumb`腕が`ComposingHint`（現`ThumbRawVkEmission`）を参照しない件、根本原因はコード見落としではなく型名が実態より広い意味を名乗っていたこと

**発見経緯:** 全数決定表（`nicola_fsm.rs::tests::run_flush_matrix`）で
`PendingCharThumb`だけが`ComposingHint::Unknown`を無視すると判明。当初は
`e3041be6`が全flush経路への適用を意図していたのに`PendingThumb`の腕にしか
実装しなかった**見落とし**と判定したが、Opusに再検討させ判定を訂正した。

**訂正後の根本原因:** `composing`値を消費するのは`PendingThumb`の腕
（生の機能VK=Space/無変換/変換の送出可否）のみ。`PendingCharThumb`/
`PendingChar`はかなの`KeyAction`のみを返し生VKを送出しないため対象外。
`e3041be6`のdiffでは変更**前**の`PendingThumb`腕が常に生VK抑止で、同コミットは
「composing中でも生VKを撃てるようにする」**緩和**を追加しただけだった。
`Unknown`はこの緩和の適用除外（従来挙動維持）であり、「flush全体の安全
ガード」ではない——`PendingCharThumb`は緩和の対象外なので除外条項を書く
相手がそもそも無かった。

**「無条件suppressに直す」が誤答である理由:** フォーカス検出は500ms周期
ティックのみだが`PendingCharThumb`滞在は数十ms——`FocusChanged`のflushが
掴む保留キーは切替**後**（現在のウィンドウ宛て）の可能性の方が高く、
suppressするとユーザーが見ているウィンドウの入力を黙って消す。
`PendingChar`も同様にかなを出すのに suppress していない非対称も生む。

**対応:** 挙動は変えない。`ComposingHint`（`Trusted(bool)`/`Unknown`）→
`ThumbRawVkEmission`（`Allowed(bool)`/`Denied`）に改名し、`PendingChar`/
`PendingCharThumb`の腕に「参照しないのは意図的」と明記した。

**テスト:** `flush_pending_char_thumb_ignores_raw_vk_emission_by_design`が
invariantとして固定。`flush_pending_thumb_suppresses_raw_vk_when_denied`が対照。

**再検討条件:** 「FocusChangedのflushが非Idle状態を掴んだ実回数」を記録し
有意な頻度が出て、かつ実機で誤注入報告が出た場合のみ。

**関連ファイル:** `src/engine/nicola_fsm.rs::flush_pending`、
`src/engine/fsm_types.rs`（`ThumbRawVkEmission`）。関連コミット: `e3041be6`、
`0edf8e84`（`PendingCharThumb`導入）。
