# BUG-173: GJI + TSFネイティブで物理ひらがなキーが握りつぶされ、カタカナから戻れない

**状態(2026-10-04、v2.0.0 時点):** 解決済み(コード確認のみ・実機未確認) — 物理ひらがなキー(F2)を常に Allow にする修正(PR #359、`state/physical_disposition.rs` に旧 `f2_warmup_owned` Suppress を廃した旨のコメントとコード)は develop 経由で v2.0.0 に含まれ、CHANGELOG「修正」・移行ガイド(`docs/migration-v1-to-v2.md`)にも記載。回帰テスト(`transport.rs::plan_tests::f2_is_always_allowed_down_and_up`、`key_effect_runtime::keyup_latch_tests`、`architecture_guard::bug173_*`)あり。「実機検証項目(未検証)」(i)〜(v)は `docs/tasks/bug173-remaining-work-2026-09-29.md` に残り、実機確認の記録は見当たらない。最初にカタカナへ入った契機は未特定のまま。v1 へは backport しない(所有者決定 2026-09-29)。追補2・3(`dcce6438`・`094c0bfb`、`CompositionFsm` 解体・ConvOpenInference の drift 撤去)も develop に入っている(`CompositionFsm` は現行コードに実体なし、`tsf/gji_fsm.rs` のコメントのみ)。

(以下は当時の記述)

**症状:** 報告 `01M3NJ784NKMH120HM6QGKF7W7`（v1.21.0、GJI、Windows Terminal/msedge/explorer間でフォーカス往復）。
「なぜかカタカナに切り替わり、ひらがなを押しても戻らない」。journalでconv 0x19→0x1B後、物理ひらがなキー約25回が全て `Suppress(tsf-f2)`。

**原因（確定）:** `PhysicalKeyDisposition::plan` は `is_tsf_mode && f2_warmup_owned`（GJI戦略、既定true・IMEの実状態を見ない）で物理F2を
Suppressしていた。「awaseがwarmupとして物理F2の代わりにF2を再送する」契約が前提だったが、ADR-100決定2（2026-08-22）でwarmupが`VK_IME_ON`
単発（open軸のみ）に変わり契約が崩れ、conv軸（カタカナ→ひらがな）へ効く代替が無かった。埋め合わせ（`kp_restore_hiragana_for_suppressed_mode_key`、
ADR-137 M-6）は `effective_open` 等が必須で、報告ログでは `composition_warm=false`（BUG-170）で全て見送られていた。`handle_reinject` も
deferred F2 をTSFモードで握りつぶしていた。**未解明:** 最初にカタカナへ入った契機（journalは850/2560件に切り詰め、BUG-050原因2と同様）。

**修正:** 物理F2を常にAllow（`plan()`）。`handle_reinject`の握りつぶしを撤去。F2に併走していた`VK_IME_ON` warmupと`ConsumeF2`を削除
（F2+`VK_IME_ON`の2連送はADR-149/BUG-113の「@」の必要条件。cold化とGjiFsm通知は残す）。到達不能になった埋め合わせ機構・`plan()`の
`is_tsf_mode`/`f2_warmup_owned`引数を撤去。確定キーD段の二重warmup（Enter1回で`VK_IME_ON`2発）を撤去。Ctrl↑ warmupはBUG-174を取り込み。

**KeyUp非対称（追補）:** `plan()`は非ImmCrossのIME系キー（`VK_IME_ON/OFF`・`VK_KANJI`等）のKeyUpを常にSuppressしDown=Allow・Up=Suppressの
非対称（BUG-131/132型）があった。`key_effect_runtime::keyup_follows_keydown`（純粋関数）で、KeyUpをscan_codeで引いた最初のKeyDownの配送に揃える
（`GateStore::shadow_key_down_disposition`、フォーカス変更・無効化遷移でクリア）。無変換/変換・role F13〜F24・注入は別の所有者が揃えるため対象外。

**Opusレビュー A1への回答:** 物理F2はSuppress有無に関係なく`kp_stage_key_effect_track`→`apply_key_effect_prediction`（ADR-191決定3）を通り、
journalでもF2押下直後に`KeyEffectPredicted{open:true}`、直後の半角/全角(0xF4)が`ShadowToggle open=false Applied`（belief ONからのトグル）。
報告スナップショットの`effective_open=false`は、このF2より後の0xF4でOFFにした結果で矛盾しない。よって別のfollow機構は足さない。

**回帰テスト:** `transport.rs::plan_tests::f2_is_always_allowed_down_and_up`・`injected_f2_is_allowed`（Windows）、
`key_effect_runtime::keyup_latch_tests`（Linux 9件）、`architecture_guard::bug173_...`（F2 Allow・reinject握りつぶし禁止・ラッチ順序）。

**実機検証項目（未検証）:** (i) belief OFF＋実IMEカタカナで物理F2→ひらがなに戻りEngineも追従するか（`[key-effect-miss]`が出ないか）。
(ii) 未確定「か」でF2→文字欠落・余計なBSが無いか。(iii) NICOLA pending中にF2→到達順。(iv) cold状態のF2/Enter直後の1文字目がリテラル化しないか
（`[gji-coro] transmit-plan gji_settled= confirm_key_tsf_hint=`を前後で比較）。(v) `VK_IME_ON/OFF`等の物理キーでDown/Upとも届くか。
