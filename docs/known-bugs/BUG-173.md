# BUG-173: GJI + TSFネイティブで物理ひらがなキーが握りつぶされ、カタカナから戻れない

**症状:** 報告 `01M3NJ784NKMH120HM6QGKF7W7`（v1.21.0、GJI、Windows Terminal/msedge/explorer間でフォーカス往復）。
「なぜかカタカナに切り替わり、ひらがなを押しても戻らない」。journalでconv 0x19→0x1B（カタカナ）後、
物理ひらがなキー約25回が全て `Suppress(tsf-f2)`。この間 belief は `effective_open=false`。

**原因（確定）:** `PhysicalKeyDisposition::plan` は `is_tsf_mode && f2_warmup_owned`（GJI戦略、既定true・
IMEの実状態を見ない）で物理F2をSuppressしていた。この設計は「awaseがwarmupとして物理F2の代わりにF2を
再送する」契約が前提だったが、ADR-100決定2（2026-08-22）でwarmupが`VK_IME_ON`単発（open軸のみ）に変わり
契約が崩れていた。物理F2は消えるのにconv軸（カタカナ→ひらがな）へ効く代替が無く、埋め合わせ
（`kp_restore_hiragana_for_suppressed_mode_key`）は `effective_open==true` 必須のため、beliefがOFFの
ときは完全に無反応になる（ADR-137 M-6の残存）。`executor.rs::handle_reinject` も deferred F2 をTSFモードで
握りつぶしていた。

**未解明:** 最初にカタカナへ入った契機（journalは850/2560件に切り詰められ直前の入力が残らない。BUG-050原因2と同様）。

**修正:** 物理F2を常にAllow、`handle_reinject`のTSF F2握りつぶしも撤去。cold化・eager warmup（`VK_IME_ON`）は
`kp_stage_execute`の`composition_native_f2_down`が従来どおり実行。`kp_restore_hiragana_for_suppressed_mode_key`は
F2がSuppressされなくなり到達しない（別コミットで整理可）。

**追補（KeyUp非対称）:** `plan()`は非ImmCrossのIME系キー（`VK_IME_ON/OFF`・`VK_KANJI`等、`shadow_action`あり）のKeyUpを
KeyDownの結果と無関係に常にSuppressしており、Down=Allow・Up=Suppressの非対称（BUG-131/132型）があった。
`key_effect_runtime::keyup_follows_keydown`（純粋関数、Linuxで単体テスト）で、KeyUpをscan_codeで引いた最初のKeyDownの配送（Allow/Suppress両方）に揃える
（`GateStore::shadow_key_down_disposition`）。無変換/変換・role F13〜F24・注入イベントは別の所有者が揃えるため対象外。

**追補2（発火削減、Opus戦略相談）:** journalで自己注入`VK_IME_ON`が約200秒で46発（物理F2併走22・確定キー22〈Enter1回で2発〉・Ctrl↑推定2）。
物理F2は素通しになったのでF2併走のwarmupを削除（`eager_warmup_sent_ms`の基準点だけlatch）。確定キーはD段(passthrough後処理)とreinject段の
二重発火だったのでD段を撤去し、さらにreinject段の`VK_IME_ON`送信も削除（cold化とGjiFsm resetは残す）。Ctrl↑ warmupはBUG-174で撤去済みを取り込み。
`CompositionFsm`は役割が物理F2のcold化だけになったため解体し`composition_native_f2_down`へインライン化。残る warmup 送信元は FocusChange と IME ON 適用直後のみ。

**追補3（D4、VK_IME_OFFの重複送信）:** `ConvOpenInference`（conv のNATIVEビットからの間接推測）を drift correction の根拠から外した
（`state/drift_correction.rs::check_drift_correction`）。GJI×TsfNativeでは IME を閉じても conv の NATIVE が残り、推測が「開」と誤って
`VK_IME_OFF` を送っても収束しない（BUG-172と同型、conv を actuation のゲートに使わない方針にも反する）。報告 journal ではユーザー自身の
Ctrl+無変換（`VK_IME_OFF`）の106ms後に同じ `VK_IME_OFF` を重ねて送っていた。撤去: `decide_conv_inference_drift`・`ConvDriftEpisode`・
`ConvDriftDecision`・`Runtime::conv_drift_latch`。開閉を読む手段が無い環境で最初のOFFが失われても自動再送はしない（ユーザーの押し直し）。
回帰: `closed_loop_scenarios.rs::conv_inference_alone_does_not_fire_drift_correction_despite_explicit_off`（修正を外すと失敗することを確認済み）。

**回帰テスト:** `transport.rs::plan_tests::f2_tsf_mode_gji_strategy_allows_down_and_up`、
`injected_f2_is_allowed_even_when_tsf_warmup_owns_f2`、`hiragana_in_tsf_mode_has_no_suppress_reason`（Windows実行）。

**Opusレビューへの回答（A1）:** 「物理F2にbelief追従が無い」という指摘は、journalで反証できた。物理F2はSuppress有無に関係なく
`kp_stage_key_effect_track`→`apply_key_effect_prediction`（ADR-191決定3）を通り、報告journalでもF2押下直後に
`KeyEffectPredicted{open:true}`が記録され、直後の半角/全角(0xF4)が`ShadowToggle open=false Applied`（=belief ONからのトグル）になっている。
よって別のfollow機構は追加しない（新規機構の積み増しを避ける）。ただし予測は観測との照合で外れうるため実機で確認する。

**実機検証項目（未検証）:**
(i) belief OFF＋実IMEカタカナの状態で物理F2→ひらがなに戻り、Engineも追従して親指シフトが効くか（`[key-effect-miss]`が出ないか）。
(ii) 未確定「か」の状態でF2→文字欠落・余計なBSが出ないか。(iii) NICOLA pending中にF2→到達順。
(iv) F2直後の一文字目がリテラル化しないか・cold probeがgiving upしないか（物理F2+warmup VK_IME_ONの併送は未測定）。
(v) VK_IME_ON/OFF等の物理キーをbelief一致状態で押したときDown/Upとも届くか（KeyUpラッチ）。

**実機未検証。** GJI+Windows Terminalでカタカナ状態から物理ひらがなキーで戻ること、warmup直後の二重発火が無いことの確認が必要。
