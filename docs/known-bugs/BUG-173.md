# BUG-173: Ctrl↑ で `VK_IME_ON` を再送する eager warmup

**発見経緯:** 不具合報告 `01M3NJYRQ5ZBYTKV55FV06KETP`(v1.21.0、GJI、Windows Terminal + PowerShell、PowerToys 併用)。「Ctrl+Shift の操作で @ が出る」。トリアージは [docs/bug-reports-triage.md](../bug-reports-triage.md)。

**確認できた事実(journal / log):** Ctrl を離すたびに `[composition-fsm] EmitWarmup (CtrlUp)` → `tsf_marker_warmup` → `VK_IME_ON`(0x16、scan=0xF2、`self_injected`)が SendInput された。報告の約 60 秒で 10 回。GJI FSM は `OffCold` のままで、毎回 cold と判定されて再送された。**「@」の出力そのものは journal に残っておらず、因果は未確認。**

**導入理由:** `07fc40d7`(2026-05-17)。WezTerm で「この→kおの」対策として、「Ctrl 中に GJI の TSF 初期化が中断される」という仮定のもと、Ctrl↑ 起点で warmup と 500ms 待機を再計測した。仮定の実測根拠は記録に無い。

**修正:** `CompositionEvent::CtrlUp` / `WarmupReason::CtrlUp` / `WindowsPlatform::composition_ctrl_up` / executor の `handle_ctrl_up_recovery` を撤去。物理キー入力(Ctrl)を契機に awase が IME 制御 VK を送る経路をなくす(ADR-178 の受動化と整合)。同じファイルの `ConfirmKeyUp` には「warmup VK が確定直後に `@` としてリテラル漏れした」ため送信を止めた前例(2026-08-22)がある。

**未確認・リスク:** (1) 実機で「Ctrl+Shift で @ が消えるか」の A/B は未実施。(2) 撤去により WezTerm の「この→kおの」が再発しないかは未確認。再発した場合は、Ctrl↑ ではなく実際に冷えた契機(probe の起点)で扱うこと([tuning-constants](../../.claude/rules/tuning-constants.md) の前例を参照)。
