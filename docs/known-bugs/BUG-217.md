# BUG-217: Zoom のチャットで注入キーの一部(主に母音)が落ちる

**状態(2026-10-24):** 修正を PR にした(Zoom のチャット窓のときだけ、キーを 1 つずつ順に、↓のあと 10ms 待ってから↑を送る。1 回の送信で 20 キーまで)。次の課題は、メッセージループを止めない、ペース付き送信(別の PR)。

**症状:** Zoom のチャット入力欄で「かくにんをおねがいします」と打つと、「かｋにんをんぎします。」のように、一部の母音が落ちる。落ちる場所は毎回違う。BUG-215(リテラル化の誤判定で Backspace が出る)を直した後でも残った。

**切り分け(実機 dragonflyg4、GJI):**
- awase のログでは、想定どおりのローマ字を送っていた(`ka`・`ku`・`ni`・`nn`・`wo`・`o`・`ne`・`ga`・`i`・`si`・`ma`・`su`)。疑い・回収・諦めは 0 件。
- ユーザーの実際の打鍵(`awase.log` から取り出した 36 イベント)を、awase を通して同じタイミングで再生すると、同じ症状が出た(落ちる母音は毎回違う = タイミングの競合)。
- 入力欄を「Shift+Enter で確定 → 全選択 → コピー」で読んで、自動で各 8 回比べた。IME が OFF の状態の試行でも英字の母音が落ちたので、IME の手前(Zoom がキーを受ける段階)で落ちている。

| 送り方(一致 = 期待の文字列または変換後 `確認をお願いします。`) | 一致 |
|---|---|
| 従来(全キーの↓を送ってから↑、1 回の SendInput) | 0/8 |
| キーを 1 つずつ順に(待ち 0ms) | 0/8 |
| 順に、↓↑の後に 2ms | 0/8 |
| 順に、押している時間 5ms | 2/8 |
| **順に、押している時間 10ms** | **8/8**(別の日も 8/8、目視 2/2) |
| 全キーの↓ → 10ms → 全キーの↑(重ねる) | 0/8 |
| 順に、↑の後だけ 10ms | 6/8 |

**原因:** awase の注入キーは「↓から↑まで」がほぼ 0 秒で、キーが重なる場合もある。Zoom のチャット入力欄は、それを一部取りこぼす。人間の打鍵は押している時間が数十 ms あるので起きない。

**修正:** `class_names::needs_key_hold_window`(Zoom のチャット 2 クラス)のときだけ、`KeyInjector::send_vk_run_batch` と `send_vk_pair` が、キーを 1 つずつ順に「↓ → `tuning::ZOOM_KEY_HOLD_MS`(10ms)待つ → ↑」で送る。ほかの窓は変えない。

**本番の修正だけを入れたビルドでの確認(環境変数なし、2026-10-24):** 自動の比較 7/8(従来 0/8)。失敗の 1 回は、IME が OFF の状態の試行で `a` が 1 つ落ちた(`kakuninnwoonegaisimsu.`)。IME が OFF の状態で、なぜ落ちるかは未調査。

**限界:**
- 押している時間を空けるキーは、1 回の送信につき `tuning::ZOOM_KEY_HOLD_MAX_KEYS`(20 キー、約 200ms のブロック)まで。超えた分は空けずに送る(取りこぼしうる)。測定値ではなく、設計上の選択。
- 10ms が最小とは言えない(6〜9ms は未測定)。測定は、ユーザーの 1 つの文(13 音)の再生。
- メッセージループを 1 キーあたり 10ms ブロックする(1 つの音で約 20ms)。保留したキーを一度に出すときは、キー数に比例して長くなる。非ブロックにする(タイマーで↑を後から送る)のは、別の課題。
- 窓のクラスで判定している。ポップアップのチャット窓での再測定は未了。
