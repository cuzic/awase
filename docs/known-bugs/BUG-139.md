# BUG-139: ADR-163のActuationDecisionRecord診断が、with_app再入時のskipカウンタ二重加算と一部同期記録点のcaller未設定を持っていた

**症状（/code-reviewで発見、修正済み・実機未検証）:** ADR-163 Part D（PR #201）
が追加したactuation decision記録・163-T6カウンタに2件の診断精度バグが
あった。いずれも実actuation（IME ON/OFF送信）自体には影響しない。

**1. `ACTUATION_DECISION_RECORD_SKIPPED`の二重加算:**
`runtime/open_chain.rs::run_open_chain_async`で`with_app`がgateチェック時に
`None`（再入）を返すと、その場で`record_actuation_decision_skipped(site)`を
呼んだ直後、`is_input_relay`が常にfalseになるため必ず関数末尾の
`if let Some(gate_inputs) = .. else { record_actuation_decision_skipped(site) }`
にも到達し、同一イベントに対してカウンタが2回加算されていた。163-T6が
測ろうとしている「with_app再入で記録が失われる頻度」が実際の2倍に
見えていた。

**2. 6箇所ある同期記録点のうち3箇所が`caller`未設定:**
`ActuationDecisionRecord.caller`はPR #201のB-2で「`site=Sync`の記録が
どの呼び出し元由来か区別できない」問題を解消するために追加されたが、
`runtime/mod.rs`の2箇所と`runtime/executor.rs::dispatch_ime_set_open`の
1箇所にしか配線されておらず、`key_pipeline.rs`の`shadow_toggle_off`
同期分岐・`idle_conv_check_direct_input`・`runtime/ime_refresh.rs`の
blacklist drift correctionの3箇所は`caller=None`のまま残っていた。
`caller`導入の目的（`site=Sync`記録の呼び出し元判別）が半分の箇所でしか
達成されていなかった。

**修正（2026-09-12）:** (1) gateチェック時点の`record_actuation_decision_skipped`
呼び出しを削除し、末尾の1箇所のみでカウントするようにした。(2) 残る3箇所に
`DecisionSite::ShadowToggleOff`/新設した`DecisionSite::IdleConvCheckDirectInput`/
`DecisionSite::BlacklistDriftCorrection`をそれぞれ`caller`として設定した。

**実機ソーク未実施:** 診断専用の変更のため、windows-build CIのコンパイル・
既存golden/architecture_guardテスト（cargo nextest run -p awase-windows
--test architecture_guard --test layer_boundary_guard --test golden_scenarios、
123件）通過で検証済み。実actuationの送信内容・タイミングには影響しない
変更のため実機ソークは対象外と判断。

**関連ファイル:** `crates/awase-windows/src/runtime/open_chain.rs`、
`crates/awase-windows/src/runtime/key_pipeline.rs`、
`crates/awase-windows/src/runtime/ime_refresh.rs`、
`crates/awase-windows/src/state/ime_actuation_decision.rs`、
`crates/awase-windows/src/state/actuation_decision_record.rs`、
`crates/awase-windows/src/journal.rs`。
