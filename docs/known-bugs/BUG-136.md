# BUG-136: ADR-121のVK_IME_ON冪等再送ゲートがVK_DBE_HIRAGANA限定で、対称のはずのKatakana/Henkan/Muhenkanが対象外

**症状（コード監査で発見、実機未確認）:** `key_pipeline.rs::
kp_stage_shadow_ime_toggle`は、9行上（`turn_on_direction`計算、ADR-141
「無変換/変換もHiragana/Katakanaと対称に」）でHiragana/Katakana/Henkan
（VK_CONVERT）/Muhenkan（VK_NONCONVERT）の4キーを対称に扱っているが、
その直後にあるADR-121 D1（VK_IME_ON冪等再送、BUG-37部分対策）のゲート
条件は`event.vk_code == crate::vk::VK_DBE_HIRAGANA`のみで、他の3キーは
対象外。

**根本原因:** D1が対象にする「belief一致でno-opになった物理TurnOnに
対しVK_IME_ONを追加再送する」というno-op検出自体は、`effective_open()
== current`という共通条件で4キーとも同一の分岐に到達するが、追加再送の
発火条件だけがHiragana限定になっている。コメントには「BUG-37部分対策」
と明記されており意図的な範囲限定だが、対称化すべき理由（ADR-141）と
矛盾する。

**影響の見積もり:** BUG-37が対象にしていたのと同じ「belief一致だが
実IME状態が乖離」というBlacklistプロファイル限定の症状が、Katakana/
Henkan/Muhenkanの物理キーでは今も未対策のまま残る。

**対応:** 未修正。D1のゲート条件を`vk_code == VK_DBE_HIRAGANA`から
`turn_on_direction`（4キー共通で既に計算済み）ベースの判定に置き換える。

**関連ファイル:** `crates/awase-windows/src/runtime/key_pipeline.rs`
（D1ゲート、`turn_on_direction`計算）。
