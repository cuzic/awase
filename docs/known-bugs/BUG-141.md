# BUG-141: Ctrl+無変換で「Applied」記録されたIME OFF後も、GJI候補ウィンドウが実際に再表示され英字入力が変換され続ける（msedge.exe/Imm32Unavailable/GjiDirect）

**症状（report `01M2D8HS5SBWSZ221P240Z4ZXE`、2026-09-13、GJI、msedge.exe/`Chrome_WidgetWin_1`/`profile=Imm32Unavailable`）:**
「Ctrl + 無変換 で IME OFF になってほしいのにならなかった」。

**初回調査の誤り**: journalの`ActuationDecision{mechanism:GjiDirect, outcome:Applied}`
と`GjiFsmTransition{OnCold(Long)→OffCold}`だけを見て「OFFは成功している、
再現していない」と誤って報告した。ユーザー指摘を受けて`GjiFsmTransition
{StartComposition(candidate SHOW)}`（`observer.rs`の`EVENT_OBJECT_SHOW`＝
GJI候補ウィンドウの実際の表示イベント、キー入力の解釈ではなく実OS UI）を
見落としていた。

**実際の経過（elapsed_ms、すべて同一msedge.exeフォーカス中）:**
1. `6128805`: Ctrl+無変換 1回目 → `Applied`、`OffCold`へ遷移（内部beliefはOFF）
2. `6130242`〜: ユーザーが`C`,`H`,`A`を入力（`PassThrough`で素通し扱い）
3. `6130462`: **GJI候補ウィンドウが実際に表示**（`StartComposition`、
   `gji_fsm.rs:885-887`の`"while engine off — ignored"`分岐で内部状態は
   保持されるが、GJI側の候補ウィンドウそのものは閉じない）
4. Backspace×2で訂正 → Ctrl+無変換 2回目（`6131393`、`AlreadyMatched`）
5. `C`,`H`,`A`再入力 → `6131714`で**再び候補ウィンドウ表示**（同一パターン再現）
6. Backspace×2 → 物理半角/全角キー相当イベント（`vk=0xF3/0xF4`）→
   Ctrl+無変換 3回目（`6135090`、`AlreadyMatched`）
7. `C`,`H`,`A`4回目の入力（`6135583`〜）で候補ウィンドウは表示されず、
   Enter確定 → ここでようやく実際にOFFへ収束

**原因（作業仮説、未確定）**: `ActuationDecision`の`outcome:Applied`/
`AlreadyMatched`は「awase→GJIへのコマンド送信が成功した」ことしか示さず、
GJI側が実際に候補ウィンドウ（TSF composition）を閉じたかどうかを検証しない。
`gji_fsm.rs`の`StartComposition while engine off`分岐は「awase自身の
belief破壊を防ぐ」設計だが、GJI実体への訂正コマンド（再度のOFF送信や
候補キャンセル）を発行しない受動的な無視であり、実際に2回連続でGJIが
composition再開したことを止める機構になっていない。

**対応状況**: 未対応（原因未確定）。まず`StartComposition`ignore分岐に
実測（頻度・再現条件）に基づく訂正アクション（例: OFF再送、`EndComposition`
相当の明示キャンセル）を追加する設計が必要。次に同一症状が再現した際は、
`GjiFsmTransition{StartComposition}`の有無を最初に確認すること
（`ActuationDecision`の`outcome`だけでは判断できない）。
