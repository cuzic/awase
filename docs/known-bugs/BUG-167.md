# BUG-167: `engine_toggle_hotkey` の `VK_` 二重付与で無言に無効化される

**発見経緯:** 2026-09-21 の不具合報告 `01M31QETZG5K23E8E4SDE5M54Q`(v1.21.0、MS-IME。同一内容の重複 `01M31QMJAPFB2YCE1T4NY1CYXN`)。「Ctrl+Shift+F12 でエンジンを無効化できない」。報告者はロシア語入力への切替後に気づいたが、切替前から効いていなかった可能性が高い(推測。journal に残る F12 押下2回はどちらも `toggle_engine` を呼んでいない)。トリアージは [docs/bug-reports-triage.md](../bug-reports-triage.md)。

**症状:** 設定 GUI でホットキーを設定する(または config に `Ctrl+Shift+VK_F12` と書く)と、`RegisterHotKey` が呼ばれずホットキーが効かない。手書きの `Ctrl+Shift+F12` なら動く。

**原因(コードで確認):**
- 設定 GUI の `format_combo` は、メインキーの内部名 `VK_F12` をそのまま連結して `Ctrl+Shift+VK_F12` を書き出す。
- `vk::parse_hotkey`(`crates/awase-windows/src/vk.rs`)は末尾トークンに `VK_` を無条件で付けるため `VK_VK_F12` となり、`VkCode::from_name` が `None`。
- `HotKeyGuard::register_toggle`(`app/bootstrap.rs`)が「Invalid toggle hotkey format」で失敗するが、呼び出し側が `tracing::warn!` を出して `.ok()` で握りつぶすため、利用者には何も見えない。
- `keymap::warn_on_engine_hotkey_collision` も同様に `VK_` を機械的に補っており、同じ二重付与で衝突検出が常に空振りしていた(同じ関数内に同型)。

**修正:** `vk::with_vk_prefix`(ungated の純粋関数)を追加し、`VK_` で始まるキー名にはそのまま、そうでなければ補う。`parse_hotkey` と `warn_on_engine_hotkey_collision` の両方がこれを使う(正規化を1か所に)。
回帰テスト: `vk::tests::with_vk_prefix_accepts_both_spellings` / `both_hotkey_spellings_resolve_to_the_same_vk`(Linux で走る)、`parse_hotkey_accepts_gui_and_handwritten_spellings`(`#[cfg(windows)]`、windows-build CI で走る)。

**追補 ([ADR-201](../adr/201-config-key-resolution-and-load-diagnostics.md) 段階1、PR #336):** 局所修正の `with_vk_prefix` を削除し、`from_name` を唯一の寛容な解決関数にした(前後空白・大文字小文字・`VK_` 任意・中立名の別名)。修飾キー解釈は `vk::interpret_combo`(コアの `split_combo` を使用)1関数に集約し、`parse_hotkey`・`parse_key_combo`・GUI の `parse_combo_str` が共用する。これでホットキーに `変換`/`無変換`/`かな`/`漢字`(GUI 候補の内部名は `VK_` 無し)を選んでも登録できる(修正前は `VK_変換` になり失敗)。回帰: awase-settings `key_acceptance_tests`(GUI 候補×読み手)、awase-windows `config_key_resolution_tests`、`vk::tests::from_name_resolves_every_legacy_name_to_the_same_vk`。

**追補 ([ADR-201](../adr/201-config-key-resolution-and-load-diagnostics.md) 段階2、PR #337):** ホットキーの登録失敗(名前の解決の失敗と `RegisterHotKey` の失敗の両方)を `StartupDiagnostics::warn`(ログ+トレイ通知)へ流すようにした(`app/bootstrap.rs::install_hooks_and_hotkeys_validated`)。同型の無言の握りつぶし (a)〜(d)(`post_bypass`・`[[keymaps]]` の from/to・`engine_on/off_ime_key`・`muhenkan_solo_tap_dedicated_fn_key`)も診断に流した。読み込みの入口は `AppConfig::from_toml_str` に一本化(未知キーの検出と `[[keymap]]` の合流を含む)。

**未対応(分離):** (1) ~~ホットキー登録失敗を利用者に見える形で通知しない~~ は段階2で解消。(2) ~~設定 GUI の `parse_combo_str` が手書き形式を照合できない~~ は段階1で修飾キー解釈を共通化して解消(主キーの表示名の照合は今も完全一致のため、`F12` のような `VK_` 無しの主キーは GUI の候補と照合できない可能性が残る。未確認)。
