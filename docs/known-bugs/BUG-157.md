# BUG-157: `desired_open` が古いまま、drift correction がユーザーのモードキーを打ち消す

**発見経緯:** 2026-09-21、PR #240 の Opus コードレビュー担当A(Blocker 2)。実機/CI の awase.log で確認:
起動直後、awase の開始時の想定(desired=true)と実IME(閉)の乖離で `[drift] correction ... set_ime_open(true)` が約11秒間×22件出るのは
**develop 版のCIにも同数ある(起動直後の既存の過渡現象、本件ではない)**。本件はその後の 2〜3 件:
CIの `real-sc-dbe`(撤去版)で、起動時のVK_IME_OFF(desired=false)の後、ユーザーのひらがな(F2)で実IMEが開いた1264ms後に
`[drift] correction: observed=true ≠ desired=false ... set_ime_open(false)`(源=ImmCrossProbe High)が発火し、開いたIMEを閉じ直す。develop 版は 22 件(起動直後の分だけ)、撤去版は 24 件(+2)。

**原因:** 撤去で静的な `shadow_action`(ひらがな等=TurnOn)を外したので、ユーザーのモードキーは通過するだけで `desired_open` を更新しない。
`ModeKeyPassedThrough`(ADR-187)は `last_intent` を捨てるだけで、`check_drift_correction`(`desired_open` と最新の信頼できる観測を比べる)は古い `desired_open` を「awase の意図」として実IMEへ書き戻す。
ADR-191 決定1(IMEが状態の正、awase は書かない)の逆。`check_consistency`/`--drift` は「実IMEが戻ればEngineも戻る」ので不可視。

**修正:** `ModeKeyPassedThrough` の reducer が、`last_intent` を捨てるのに加えて、観測から導ける開閉(`observations.derive_any`、`effective_open` と同じ導出)があれば `desired_open` をそれへ揃える。
通過マークの窓の間は観測が届くたびに送る(最初の観測はGJIがキーを処理する前の古い状態のことがある)。ただし通過より後に記録された明示意図(`last_intent`)は2回目以降で捨てない。
観測が無い窓(読めない窓)では `desired_open` に触れない。awase が書いた意図(通過マーク無し)が実IMEに届かなかった場合の drift correction は従来どおり(テストで固定)。

**検証:** 単体テスト3件(通過後にdesiredが揃いdrift補正が発火しない/観測が無ければdesiredを書かない/awaseの書き込みの乖離は従来どおり補正)+reducerの既存テスト更新。
CI(`ci/e2e-drift-fix`、run 35620809258、実機と同じ custom keymap の `real-*` と `cal-verify-*`): 起動後(最初のVK_IME_OFF以降)の `[drift] correction` は全ランで0件、`real-sc-dbe/kanji/shift/f2x4` の総件数は修正前の24→22(develop 版と同数=起動直後の既存の過渡現象のみ)、`real-cold` は全ランALL PASS。
Engineずれ: 観測あり 400ms以降 0%(seed1・2)、読めない条件 0%/1.0%(残る1件は別件: ADR-189トグルONの `UserImeOnEisuReset` が GJI の変換モード保持と食い違う、BUG-157とは無関係)、`[key-effect-miss]` 0件。
