# BUG-150: ATOK+パススルーで無変換/変換のIME開閉にEngineが追随しない

**状態(2026-10-04、v2.0.0 時点):** 一部解決(IMM で読める窓は CI 検証済み・実 Chrome の素通し設定では再現、2026-10-04) — ADR-187 follow 方式は ADR-191 決定2 で全IMEモードキーへ一般化され(`c949ba33`、HEAD 含む)、通過マーク機構(`state/mode_key_pass.rs`・`ModeKeyPassedThrough`)が現存。本文の ADR-187 時点CI(`atok-passthrough` 各3/3)に加え、ADR-191 の CI 記録で MS-IME 全25構成 rc=0。適用範囲外(TsfNative/Imm32Unavailable)は BUG-149 参照。

(以下は当時の記述)

**発見経緯:** ADR-186のCI実機E2E(`--walk`、`check_consistency.py`)で、`atok-passthrough`各3/3が再現。

**症状:** ATOKプリセットのGJI(既定=opt-in無し)で、かなON中に無変換/変換を押すと実IMEはOFFになるが、Engineは残ったままONで、
直接入力にNICOLA変換が効く。

**原因(3層):** (1)通過後に読み直す契機が無い(`may_change_ime`は無変換/変換を含まず、親指キーのKeyDownはFSMがConsume)。
(2)直前の明示意図(`IntentStore`と`ImeModel::last_intent`)が`effective_open()`を固定し、観測が入っても`ctx.ime_on`が動かない。
(3)20ms後の再読み取りがtyping-idleガードで`SkipTyping`になる。詳細はADR-187。

**修正:** follow方式(ADR-187)。生キー通過点(FSMの`SendKeys`と、Engine OFF時の`PassThrough`)で通過マーク+20ms再読み取り
(typing-idleバイパス)を予約し、観測が成功した直後に対象hwndの`IntentStore`と`last_intent`を捨てる(`ImeEvent::ModeKeyPassedThrough`)。
回帰: CIの`atok-passthrough(-henkan)`と`-cold`(各3/3追随)、`ime_model`/`platform_state`の単体テスト、`architecture_guard`の出現数固定。

**適用範囲:** IMMで開閉を読めるアプリ。TsfNative/Imm32Unavailable(メモ帳・Windows Terminal・Chrome/Edge)は未検証([BUG-149](BUG-149.md)参照)。

**追記(2026-09-23、未検証):** 上記「修正」節のfollow方式(ADR-187個別実装)は、その後より広範な
[ADR-191](../adr/191-ime-is-source-of-truth-observe-not-write.md)(IMEを状態の正とし観測・予測に追随する設計転換、
PR #240でdevelop統合済み)の通過マーク機構(`ModeKeyPassMark`/`ModeKeyPassLatch`等)に置き換わっている可能性が高い。
`fix_commits`が空のままなのは、ADR-187個別実装からADR-191統合後の機構への移行を裏取りできていないため。
着手する場合はまずATOKパススルー構成のCI/実機再検証で現行developでの再現有無を確認すること。

**追記(2026-10-04、実 Chrome の CI 再現 — `sc-bug149-chrome-{atok,msime}-passthru`、run 37188439753):** 無変換/変換の単独タップを素通し(`muhenkan_solo_tap_always_suppress = false`・`henkan_solo_tap_always_suppress = false`)にして、実 Chrome(TsfNative、読めない窓)で「かな→無変換/変換/Shift+無変換」を各 3 周測った。
- **ATOK プリセット**: 3 ケースとも 3/3 FAIL。実 IME は閉じる(`k`,`a` が `ka` のローマ字のまま)のに Engine は ON のまま = 本 BUG の症状。awase なしの対照は全 PASS。
- **既定設定(Suppress)では同じ操作で IME が動かない**(ADR-206 決定1どおり。awase.log: 無変換 KeyDown→`PendingThumb`→100ms タイマーで `Idle`、再注入なし)。この場合の「Engine ON のまま」は設計どおりで、本 BUG とは別。
- MS-IME プリセットは awase なしの対照も崩れて判定できない(ケースの前提が GJI のキー割り当てと合わない)。
→ IMM で読めない窓(Chrome/Edge/Windows Terminal)で素通し設定のユーザーには、BUG-150 の症状が残る。ADR-209 の予測は「開く」方向(変換)だけで、閉じる方向の追随は無い。

**追記(2026-10-04、開く方向の追随 — `sc-follow-chrome-*`、run 37190644852):** 実 Chrome で IME 閉状態から各キーを 1 回押す。ATOK プリセットは 0x16・変換・無変換・半角/全角で IME が開き Engine が追随(PASS)、MS-IME プリセットは 0x16・変換・半角/全角・英数(0xF0)・ひらがな・F13 で追随。**「IME だけ開いて Engine OFF(`か`)」は 32 ケース中 0 件**(開かないキー=`ka` はそのキーが IME を開かない割り当てで、BUG ではない)。→ 開く方向の追随は問題なし。閉じる方向は上の追記のとおり残る。
