# BUG-159: GJIの閉→開でモードが保持されるのに、`UserImeOnEisuReset` が英数をひらがなに直す

**発見経緯:** 2026-09-21、ADR-191 撤去ブランチの CI `cal-verify-blind` seed 2（1.0%→14.3%）の切り分けで、誤判定14押下のうち #58 は
「半角/全角 OFF/英数 → ON/英数」の押下だった（読めない窓。#82 以降の連鎖は別原因＝表の履歴依存セル）。

**原因:** ADR-189 の半角/全角トグルの OFF→ON 経路（`kp_stage_shadow_ime_toggle`）は、`eisu_reset_on_ime_on`（Edge のデッドロック対策）で
「IME ON はひらがなで再開する」と仮定して `ObservedEisu` を `AssumedRomaji` へ直す。GJI は同じスレッド内で閉じても変換モードを保持する
（Mozc `Composer::ResetInputMode` は comeback モードへ戻す。CI 実測: ATOK 0x10→閉→開=0x10、`docs/adr/191-gji-state-scope-spec.md` §2.1）ので、
開き直すと実IMEは英数（0x10）のまま。awase の Engine だけが ON になり NICOLA のかなが出ない。Microsoft IME 本体は閉→開で 0x19 へ戻るので現行のリセットが正しい。

**修正:** `eisu_reset_on_ime_on` に `mode_retained` を足し、純関数 `gji_retains_tracked_eisu(ime, tracked_conv)`（`state/eisu_recovery.rs`）で判定する。
GJI かつ追跡中の変換モード（`KeyTrack::conv`）が英数（C10）と既知のときだけリセットしない。追跡が不明（新しいスレッド・観測で追跡を捨てた直後・未検出）や
MS-IME 本体では従来どおりリセットする（Edge のデッドロック対策は追跡不明のとき効き続ける）。新しい状態は持たない。単体テスト4本（`eisu_recovery::tests`）。
Decision 経由の `PostSetOpenEisuReset` 経路は未変更（GJI の VK_KANJI 送信後の挙動は実測未確認のため）。

**検証（CI `ci/e2e-major-fix`、run 35664202440）:** `cal-verify-blind` s2（押下 #58 を含む seed 2）が **1.0%→0.0%**、s1 0.0%、`cal-verify-obs` 0.0%、`real-sc-*`/`real-cold` は悪化なし。MS-IME 本体（`sc-*-msime-native`）も全 PASS。
