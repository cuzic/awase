# BUG-204: 初期値の ObservedRomaji が閉→開で残る

**状態(2026-10-18):** 未修正。閉ループのランダム探索(PR #634)で再現。実機の実害は未確認(記録 0 件)。フォーカス移動の件は読解のみで未再現。**機序は 3 回書き直した**(下記)。

**症状(CI の擬似 IME):** ATOK で IME が閉・半角英数(conv 0x10)で始まり、閉のまま開くまでは、belief の入力モードが初期値の `ObservedRomaji` のまま。IME を開く打鍵は `mode: None`(変えない)なので、`ObservedRomaji`(かな入力と確認済み)が残り、実 IME は 0x10 で開く。想定される実害は、半角英数で開いた IME に NICOLA のローマ字が送られること。

**機序(Opus レビューで訂正、`ime_model.rs`・`harness.rs` を読んで確認):** `ImeModel::new()` の `input_mode` の初期値は `ObservedRomaji`(`ime_model.rs:325`)。`input_mode` への書き込みは reduce の 3 箇所(`InputModeObserved`・`InputModeApplied`・`KeyEffectPredicted`)だけで、`Unknown` を流す経路は本番にも無い。閉の間は入力モードを観測しない(BUG-57 / ADR-239。ハーネスも開いているときだけ観測する)。ATOK の閉のセルは全て `after_conv=None` で `mode: None`。よって閉で始まると、開くまで初期値が残る。`predict_in_table` の `seeded`(`input.mode == Unknown`)の経路は本番では到達しない。**最初の版は「`Unknown` のとき最初の打鍵で既定のかなの種が入る」と書いたが、誤り**(CI の『Unknown の種 0 件』の意味を取り違え、「実測では」と書いたのは推測だった)。

**再現:** `closed_loop_scenarios.rs::random_key_walks_keep_predictions_consistent_with_truth` の `EXPECTED_INITIAL_MODE_GAP`(32 件 / 2878 打鍵。ATOK・閉・半角英数で始まる 16 シード × 窓 2 通り)。その時点の `input_mode == ObservedRomaji` を検査している。

**実測(格子):** 閉→開は ATOK 10/10・GJI の MS-IME プリセット 18/18 で閉じる前の変換モードを復元。MS-IME 本体は 閉 c10 から開くと 0x19(格子の 7 キー)。試行は各セル 2 回以下(MS-IME 本体は 227 セル中 206 が 1 回)。

**方針(ADR-266、未決):** 初期値を `ObservedRomaji` から「観測済みと名乗らない値」(`AssumedRomaji`)にしても、本番の挙動は変わらない見込み(`is_romaji_capable` が同じ扱い)。ただし閉のキーは `mode: None` なので、食い違いは減らない。減るのは閉の間のモードの証拠源(ADR-261 字形・ADR-264 メニュー)が入ったとき。種として `Unknown` を返す案は、`Unknown` が `is_romaji_capable` で偽のため Engine が止まり、逆効果。

**関連(未再現、読解のみ):** フォーカス移動の `input_mode` は `reduce_focus_changed` が消さず、主に(1) hwnd キャッシュの復元(`apply_hwnd_cache_restore`、(pid, class) で最大 1 時間、`input_mode` を無条件に上書き。`ObservedEisu` は `AssumedRomaji` に倒す)と、(2) 新しいスレッドを閉とみなす経路(`assume_closed_for_new_thread`、開閉だけを Low で記録し `input_mode` に触れない)で決まる。前の窓が `ObservedEisu` で、起動後に作られたスレッドの読めない窓へ移り、実 IME は閉×ひらがなで表の予測で開くと、`ObservedEisu` のまま開いて Engine が `NotRomajiInput` で止まる可能性(`eisu_recovery` の冒頭のデッドロックと同型)。BUG-204 の食い違い(ローマ字が半角英数に送られる)より実害が大きい可能性がある。ハーネスの `focus_change()` は擬似 IME をスレッドごとに持たない(状態は共有)ので現状では再現できない。

**修正履歴:** なし。
