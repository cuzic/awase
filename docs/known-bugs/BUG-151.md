# BUG-151: cold状態のひらがなキー後、20ms再読み取りがSkipTypingで半角英数に追随しない

**発見経緯:** ADR-187/189のPR #230(develop向け)のe2e-ime再確認(run 35504455792)で、`atok-passthrough-cold`の3回中1回が失敗した。
**修正: ADR-191 決定2**（`c949ba33`、round2 レビュー A-N8）。当初は「未修正・原因は推測」の記録のみだった。

**症状:** ATOKのGJI(Win32 Edit、ImmCross)で、先頭にひらがなを押さない構成(`--walk --cold`、awaseがIMEを一度も書き込んでいない)で、
ひらがなキーによるかな→半角英数(conv 0x19→0x10、開閉は不変)の後も、Engineが半角英数に追随せずONのまま(step 5・11、step 6も残る)。
`k`を打つとNICOLAがかなを送る。無変換/変換の追随(ADR-187)は成功しており、失敗しているのはひらがなキーの後の追随。

**ログの根拠(run 2):** ひらがな(0xF2)押下の29ms後の再読み取りが`strategy=SkipTyping ... typing active (idle=32ms)`でスキップされた
(`explicit_intent=Some(true)`はあるのに)。成功したrun 1では読まれる。run 2は`ime open applied`が1件(run 1は5件)。

**原因(推測):** typing-idleガードのバイパス`explicit_verify`(`runtime/ime_refresh.rs::ir_decide_read_strategy`)は、明示意図に加えて
`applied != Unknown`を要求する。coldではawaseが一度もactuateしておらず`applied`がUnknownのまま、バイパスが効かない可能性がある。
ADR-186決定3(ひらがなキー後の20ms再読み取りは必須、実験E5)の機構の脆さ。BUG-149(Chromeで同じ「モードキー後の再読み取りがSkipTyping」)と同型。

**頻度:** cold系の実行でひらがな型の失敗は約26回中1回(約4%)。他の構成(baseline/opt-in/パススルー/MS-IMEキーマップ/リセット/半角全角)は失敗なし。
ADR-187(follow)・撤去(revert)・developとの統合の変更とは無関係(失敗したのはfollowの対象外のひらがなキー)。

**方針候補(未決定):** (1)モードキー通過後の再読み取りで`applied`がUnknownでもバイパスする(`explicit_verify`の条件変更、BUG-34/113系の再発ファミリー、
実機での影響確認と敵対的レビューが先)。(2)BUG-149のADR-188(遅延conv読み取り)と統合して設計する。CI側で期待を緩めるのは問題を隠すので避ける。

**追記(2026-09-20): 決定的な再現と原因の裏づけ。** スパイク`--exp`(`spike/ime-effect-learning`のコミット`91f17341`、`tools/e2e/ime_key_matrix/results/elw8/exp-B/`)で
**12/12再現**(CIの約4%ではなく決定的)。手順: awaseを`AWASE_TEST_INJECTION=1`で**起動直後(cold)**に、`ime_key_matrix_spike --exp=70:n:12 --activate-gji`
(GJIをアクティブ化、ON・かなでひらがな0xF2→0.9秒後に`a`)。結果は全12回で実IMEが半角英数(conv 0x10)なのに、次の`a`が`う`(NICOLAのUnicode注入)。
GJI×ATOK×Win32 Editでawase起動なし(A')/素通し(A)は12/12で半角の`a`(Mozc `atok.tsv`のPrecomposition `Kana`=ToggleAlphanumericModeどおり)。
**原因の裏づけ(awase完全ログ):** 全12回が`[shadow-toggle] no-op: ... effective_open は既に true → apply-ime 見送り`(actuationなし)→`ime open applied`は実行全体で2件
(warmのelw2/B2は43件)→`applied`がUnknownのまま`explicit_verify`が偽になり、20ms後の再読み取りが毎回`Skipping observer/SSOT write: typing active (idle=31〜47ms)`で捨てられ、
`Explicit intent: bypassing`は0件。上の推測(`applied != Unknown`要求)と一致。warm(applied既知)では同条件でもスキップは稀(elw2/B2で1件)。
**訂正(2026-09-20): 上の追記の測定ビルド。** 12/12の再現に使ったawaseは`e2e/ablation`(コミット5f11a872、ADR-186＋実験用の変更)で、ADR-187(follow)・ADR-188・ADR-189の実装を含まない。
ただしdevelopの`kp_stage_mode_key_follow`(ADR-187)も対象は無変換/変換だけでひらがな(0xF2)は対象外なので、ひらがなの経路(原因の①②③)はdevelopでも同じはず。**developビルドでの再現(頻度がCIの約4%か、cold条件で12/12か)は未確認。**

**修正と検証(2026-09-21、ADR-191 決定2):** 生キー通過後の追随(ADR-187 follow)を、無変換/変換だけでなく全IMEモードキー(ひらがな0xF2を含む)へ一般化した(`is_followed_mode_key`、`c949ba33`)。
通過マークが立つと `explicit_verify` が `mode_key_pass_live` でタイピング中ガードをバイパスし、20ms後の再読み取りが `applied` の有無に依らず実行される。
CI: `real-cold`(cold、MS-IMEプリセットのGJI、`--walk --cold`)3/3 PASS(`ci/e2e-major-fix`、run 35664202440)。**スパイクの `--exp=70:n:12` による決定的な再検証は未実施**（現行のCI道具に `--exp` は無い）。
