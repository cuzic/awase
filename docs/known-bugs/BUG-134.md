# BUG-134: tray.rs::restart_self()がBUG-79と同型のos error 50で失敗しうる(修正済み・実機未検証)

**症状（コード監査で発見、実機未確認）:** BUG-79(PR #190)は「稼働中の
`awase.exe`から`std::process::Command::spawn()`を呼ぶと`CreateProcessW`が
`ERROR_NOT_SUPPORTED`（os error 50）で失敗する」問題を
`launch_settings_with_args`（設定画面起動）でだけ修正した
（`.stdin/.stdout/.stderr(Stdio::null())`を追加）。

**根本原因:** 同じ「稼働中のawase.exeからCommand::spawn()を呼ぶ」形の
呼び出しが`crates/awase-windows/src/tray.rs::restart_self()`（トレイ
メニューの「再起動」に接続、`runtime/message_handlers.rs`経由）にも
存在するが、こちらは修正時に見落とされ、今もstdioリダイレクトなしの
まま:

```rust
match std::process::Command::new(&exe).spawn() {
```

BUG-79の診断（`docs/known-bugs/BUG-079.md`参照）が正しければ、この
経路も100%再現するはず。失敗時は`Err`分岐で`tracing::error!`を出す
だけで、プロセスは再起動もexitもしない——ユーザーから見ると「再起動」
を押しても何も起きない。

**対応（`4ea89e93`）:** BUG-79の修正を`restart_self()`にも適用
（`.stdin/.stdout/.stderr(Stdio::null())`を追加）。両呼び出しの共有
ヘルパーへの統合は行わず、既存の`launch_settings_with_args`と同じ
インラインパターンを踏襲した（差分最小化）。

**検証:** `cargo check --target x86_64-pc-windows-msvc -p awase-windows`
でクリーン確認済み。実機でのos error 50再現・解消確認は未実施
（BUG-79側も同様にLinuxサンドボックスでは検証不能な領域）。

**関連ファイル:** `crates/awase-windows/src/tray.rs::restart_self`、
`crates/awase-windows/src/app/mod.rs::launch_settings_with_args`（先行修正側）。
