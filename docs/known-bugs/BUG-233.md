# BUG-233: KeyEffectPredictionのみで開を信じた送信にADR-270確認が張られずリテラル化

**状態(2026-11-12):** 原因確定。修正は[ADR-292](../adr/292-key-effect-prediction-vs-observation-priority.md)
のG3(settle起点の修正)・P(未照合中の物理キー保持)として[PR #936](https://github.com/cuzic/awase/pull/936)
(`6439bc7d2`)でdevelopへマージ済み。「観測が閉と確定したとき何をするか」(R6)は(iv)
(belief修正+流し直し+警告ログ)がデフォルトとして実装済み、(i)開き直しはモードキーが効か
なかった原因特定待ちで未実装。マージ後のround5 Opusレビューで、**Pには既知の限界がある**
ことが判明: cold Mozcがモードキーを処理してから`tsf_open`を共有メモリへ公開するまで
settle_ms(170ms)+読みの周期より遅れる場面で、Pは保持していた打鍵を即座にqwerty生文字として
再生してしまい、後から開いたMozcがそれをローマ字として誤変換する(BUG-233本来の`kore,`型
リテラルとは逆の症状。詳細はADR-292「決定」節)。実機確認(dragonflyg4)は同機が現在オフライン
のため未着手。

**症状:** dragonflyg4、`herdr-app.exe`(class=`Zed::Window`)で「これ、」と入力しようとして
`kore,`とリテラルに出た(2026-11-12 20:24:20〜23 JST)。

**タイムライン(UTC, awase.log)概要:** `20.671`モードキー押下→予測だけでbeliefが開に倒れる
(mozc-shmはまだopen=false)→`20.989`〜`21.526`ローマ字`ko`/`re`/`,`がリテラルのまま出力→
Backspace×6→`23.142`(モードキーから+2471ms)mozc-shmの実測がようやく追いつき訂正。

**原因(確定):**

1. `ImeModel::resolve_open_at`の170msフェンス(ADR-191決定3の意図的設計)は本件の送信
   (モードキーから318ms後)には無関係(フェンスは20.841で終了済み)。
2. 訂正の遅延(2471ms)は`decide_use`(ADR-268 D3、一部ADR-291 D5)がbelief食い違い時に
   要求するsettle無条件待ちの起点が、全物理キー(Backspace含む)で押し戻されるローリング値
   だったこと。**ユーザーが誤りを消すために打つBackspaceそのものが訂正を遅らせる悪循環**。
   ADR-291 D5への帰属はCI(`tickchurn --closed`、実機確認)で確定した(ADR-292 D1b参照)。
3. ADR-270の安全網(`should_check_compose`)は前提条件の問題があるが、`judge_compose`が
   `!effective_open`で即座にSkipを返す既存ロジックのため、前提条件を外すだけでは機能しない。

詳細・修正候補の比較・Pの既知の限界はいずれも[ADR-292](../adr/292-key-effect-prediction-vs-observation-priority.md)参照。

**未解決:** R6(i)「開き直す」は未実装(モードキーがZedでMozcを開けなかった理由が未解明の
ため)。Pの既知の限界(上記)の是正(`KEY_EFFECT_SETTLE_MS`の見直し等)は実測待ち。
