# BUG-169: `None` を保存できない `Option` 項目（`general.ngram_file`）

**状態(2026-10-04、v2.0.0 時点):** 未修正(CI の特性テストで再現、2026-10-04) — `src/config.rs` の `ngram_file` 既定値は今も `Some("data/ngram_hiragana.csv.gz")`、GUI(`crates/awase-settings/src/main.rs`)は空欄を `None` にするが、保存すると既定値へ戻る制約を `src/config_save.rs` の回帰テスト(`ngram_file = None` の保存→読込で既定値)が現状仕様として固定している。修正は記録のみで未着手。

**発見経緯:** 2026-09-26、ADR-201 決定3 の実装（`toml_edit` 保存、段階3）の調査。ADR-201 round4 R4-3 で指摘済みの、今もある制約。

**症状:** GUI の n-gram ファイル欄（`crates/awase-settings/src/main.rs` の `ngram_file` 欄）を空にして「適用」しても、次に config.toml を読むと既定のファイルに戻る（n-gram を無効にできない）。

**原因:** `GeneralConfig` は構造体単位の `#[serde(default)]` を持ち、キーが無いと `Default` の値が入る。`ngram_file` は既定値が `Some`。TOML に null が無いので `None` はキーの削除でしか表せず、削除すると読み込み時に既定値の `Some` に戻る（`toml::to_string_pretty` の全体保存でも同じ。ADR-201 の `toml_edit` 保存でも同じで、`src/config_save.rs` の先頭コメントとテスト `none_cannot_be_saved_for_items_whose_default_is_some` で明記）。同型: `keys.engine_off_solo_repeat` は空文字 `Some("")` を「無効」の意味に使って回避している（`bootstrap.rs` の `.filter(|s| !s.is_empty())`）。

**直し方の候補（別件）:** `ngram_file` も空文字を「無効」とし、読み手で `.filter(|s| !s.is_empty())` する。または既定値を `None` にする（互換性の確認が要る）。

**修正:** なし（記録のみ）。

**追記(2026-10-04、CI 再現 — 特性テスト `config_save::tests::bug169_ngram_file_none_comes_back_as_default_after_save_and_reload`、PR #457):** `save_edit`(GUI と同じ保存経路)で `ngram_file = None` を保存し `AppConfig::load` し直すと、既定値(`Some("data/ngram_hiragana.csv.gz")`)に戻ることを、windows-latest を含む CI の `test` ジョブで確認した(テストは現状の挙動を固定している。直したら期待値を `None` のままへ書き換える)。
