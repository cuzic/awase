# BUG-234: settle窓(170ms)がMozc自身の非同期切替完了より短く、明示OFFを外部変化と誤認する

**状態(2026-11-13):** 原因確定(ログ+mozc-readableフォークのソース照合)。修正は未着手。

**症状:** dragonflyg4(Zed::Window、GoogleJapaneseInput)で「svg」と入力しようとして
「sfuse」のような出力になった(2026-11-13 16:33〜35 JST)。`s`は正しく半角英数で出たが、
続く`v`/`g`がかな変換に飲まれた。

**タイムライン(UTC, awase.log 2026-11-13T07:35:11〜07:35:16):**
1. `11.995` 明示的な「IME OFF (key combo)」→`[effective-open-flip] → false
   decided_by=ExplicitIntent`。
2. `12.635`(**640ms後**) `[mozc-shm] follow external change open=true effective_was=false
   desired_was=false` — `z-observed-high`(新鮮な観測、キャッシュの読み違いではない)。
   外部トリガー(ひらがなキー等)は直前に無い。
3. `12.655` `[effective-open-flip] → true decided_by=DeriveHigh(MozcShm)` → Engine再活性、
   直後の`G`/`V`キーがかな変換される。
4. `15.894` 2回目の明示OFFでも同じパターンが**239ms後**(`16.133`)に再現。

**原因:** `KEY_EFFECT_SETTLE_MS = 170ms`(`tuning.rs:479`)は、`GLYPH_KEY_FENCE_MS`のコメント
(同ファイル488〜491行)が明記するとおり「予測と**同期的な**観測(IMMの読み)の遅れ」用に測った
値であり、Mozc自身の**非同期な**開閉切替完了(`TURN_OFF_IME`/`TURN_ON_IME`の
mozc_serverラウンドトリップ、mozc-readableフォーク`session.cc`)には短すぎる。[BUG-230](BUG-230.md)
が既に実測済み(原因2、未着手)のとおり、この種の切替完了は最大約2秒かかる場合がある。
[ADR-291](../adr/291-mozc-shm-push-notify-and-engine-recheck.md)/[ADR-292](../adr/292-key-effect-prediction-vs-observation-priority.md)
(BUG-232/233)の「食い違いがsettle_msを過ぎたら外部変化として信頼する」設計は、この170msが
そもそも別の遅延種別用に測られた値であることを踏まえておらず、**awase自身が送った明示OFFを
Mozcがまだ処理し終えていないだけの状態**を外部からの変化と誤認し、`desired_open`まで
観測側へ揃えてしまう(`report_mozc_shm`→`pass_through_observed(align_desired=true)`)。

OSの「かな入力ロック」(`VK_KANA`)は無関係と確認済み: mozc-readableフォーク
(`src/win32/base/keyevent_handler.cc`)は`UnlockKanaLock()`を`ImeProcessKey`/`ImeToAsciiEx`の
先頭で毎打鍵呼び、`ConvertToKeyEventMain`も実際のVK_KANAビットを使わず`behavior.prefer_kana_input`
から独自に期待値を作っている。

**BUG-230との関係:** 原因2(「Mozcの実際の切替完了を待たない」)と同根。BUG-230は
`KeyEffectPrediction`の楽観的成功判定(待たずに進む側)、本件は`decide_use`のsettle窓
(待った後に誤って信じる側)という別経路での同じ現れ。

**未解決:** 固定のsettle時間をさらに延ばす対症療法は`tuning-constants.md`が禁じる盲目的
エスカレーション(Mozcがそれより遅い場面で再発する)。恒久修正は、awase自身の送信した
開閉要求の完了を推測せず確認する閉ループ(`exp/mozc-direct-actuation`・mozc-readable
`exp/direct-actuation-channel`のnonce/ack機構)を仕上げること。
