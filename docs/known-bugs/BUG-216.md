# BUG-216: per-VK の 2 番目以降の疑いが ESC + 全体の再送を連鎖させる

**状態(2026-10-24):** 修正を PR にした(擬似窓で再現・確認。実機は未確認)。Zoom のチャットは BUG-215 の修正(2 番目以降の疑いを信用しない窓)で先に止めてあった。

**症状(擬似窓):** `Profile::SECOND_KEY_WEAK`(子音は閾値を超え、母音の書き込みが 150B)で `ki` を 1 語入れると、ESC + 再送が 8 回(暴走ガード)連鎖し、入力中の文字が毎回破棄されて何も残らない(`escapes: 8, resends: 8`)。

**機序(コードで確認):** `run_per_vk_confirm` は、2 番目以降の VK が `SuspectedLiteral` になると `per_vk_recovery_params` で `backs=0, escape=true`(ESC のみ)の回収に入り、`consecutive==0` なら全体を再送する。再送した 1 番目の VK は確認できて `reset_consecutive_count` で連続カウントが 0 に戻るため、2 番目でまた疑われると同じ回収に入る。止まるのは 1 番目の VK も疑われた時(`consecutive` が増える)だけ。

**実機での観測:** Zoom のチャット(修正前)で 1 打鍵に `ki` が最大 6 回再送された(`awase.log` の `[raw-tsf-literal]`、2026-10-24)。Zoom 以外の窓で起きたかは未確認。

**修正:** (1) 連続カウントは、語の最後の VK まで確認できた時(`mark_literal_session`)だけ 0 に戻す。途中の VK の確認では戻さない(`output/probe_io.rs` の `CompositionConfirmed` の処理)。(2) 「諦める」分岐は ESC を送らない(入力中の文字を破棄しない)。回帰テスト(擬似窓): `bug_216_weak_second_key_in_an_untrusted_window_recovers_once_and_keeps_text`、`bug_216_weak_second_key_window_does_not_escape_again_on_later_words`。

**確認が要ること:** 実機の Chrome × GJI で、部分リテラルの回収(`escape_composition` の元の用途)が壊れていないか。この変更は、語の途中で疑いが出た後の「連続カウント」の戻り方を変える。Chrome の通常の入力(全 VK が確認できる語)は最後に戻るので変わらない。
