# BUG-158: 通過マークの観測が失敗すると意図が捨てられず、ポーリングが止まる

CI経緯・run別の数値・ログ原文は補助資料 [191-calibration-experiments.md](../adr/191-calibration-experiments.md) 末尾の付録に移した（30行目安のため、round2 レビュー C-N6）。

**症状・原因:** MS-IME本体で、F2 直後の `[mode-key-follow]` の20ms追随読み取りが `ime_on=None`(IMMクロスプロセスprobeの空振り)。ADR-187 は意図の破棄を「観測が成功したとき」だけにしていたので、
古い `explicit_intent` が残り、`reschedule_ime_refresh` が早期returnしてポーリングが止まる(BUG-151 原因③)。develop 版は F2 を awase が書く(`shadow_action`)ので通過マーク自体が立たず顕在化しなかった。
CI(`ci/e2e-msime-native-b`): 撤去版だけ `msime-native`/`sc-dbe`/`sc-kanji`/`sc-shift` 各3/3 FAIL、`sc-shift` で約18秒Engineが動かない。

**修正(通過マークの意味に立ち返る):**
1. 窓(300ms)の間は、観測の成否によらず `reschedule_ime_refresh` が読み直しを予約。直前の読み取りが失敗なら窓の終了時の1回だけ(`mode_key_pass_next_read_ms`。60msごとだとprobeが重なり降格する)。
2. `ir_stage_notify` で、窓が切れても観測が一度も成功していない通過マークの古い明示意図を捨てる(`expire_mode_key_pass_mark`)。ただし**通過を立てた時点で読めない窓**は捨てない
   (`ModeKeyPassMark::readable_at_arm`。読めない窓では意図がbeliefの唯一の手がかり。捨てると blind のずれが 0%→23%。立てた時点で読めた窓は途中で降格しても捨てる=round2 A-N2)。
3. 窓の終了時の破棄は `desired_open` を書かない(`ModeKeyPassedThrough { align_desired: false }`=round2 A-N1)。窓が切れた後の最初の成功観測では1回だけ揃える(`align_after_expired_mode_key_pass`、`aligned`/`awase_wrote` の2つのbool)。
4. 学習側: `imm-learning`(3回連続の空振りで `Unavailable`)が、MS-IME本体のCIで50msの時間切れを「IMM不可」と誤学習した。**個別の `SendMessageTimeout` の時間切れ(b)だけ**を miss に数えない
   (`ImeSnapshot::probe_timed_out`、`send_failure_is_timeout`: `ERROR_TIMEOUT` か `elapsed >= 宣言timeout`)。即時の拒否とワーカー全体の300msタイムアウト(d)は従来どおり数える(応答しない窓の降格を残す、round2 A-N4)。
   閾値(3)・probe のタイムアウト(50ms)は不変。実測: probe は二峰性(成功は最大50ms、時間切れは最小50ms、n=7183で p99=59.5ms)。
   本当にIMM不可のアプリ(`DirectUIHWND`/`TframeMainFunMenu`、ユーザー実機)の降格は INFO ログで `elapsed` が無く、時間切れか即時拒否かは判別不能(未確認)。

**検証:** 純関数 `should_drop_intents_for_mode_key_pass`・`mode_key_pass_next_read_ms`・`should_align_after_expired_mode_key_pass`・`timeouts_are_not_imm_evidence_but_immediate_refusals_are` をLinuxで固定
(`platform_state` のテストは `#[cfg(windows)]` でwindows-buildで実行)。CI: MS-IME本体(round1 後 run 35664202440)は `sc-dbe/kanji/shift-msime-native` 各3/3 PASS・降格0件・起動後の `[drift] correction` 0〜3件(develop 水準)、
GJI側は `cal-verify-obs` 0.0%・`cal-verify-blind` 0.0%/0.0%・`real-*` 悪化なし。
