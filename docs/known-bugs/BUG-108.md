# BUG-108: タスクトレイの「学習キャッシュをクリア」メニュー項目が完全な no-op になっている

**症状（BUG-107 の調査中にコード読解で確定）:** 右クリックメニューの「学習キャッシュをクリア」を
選んでも何も起きない。`tray.rs`（`IDM_CLEAR_IMM_CACHE` → `TrayCommand::ClearImmCache`）から
`runtime/message_handlers.rs` の `Some(TrayCommand::ClearImmCache) | None => {}` に到達し、
`ImmCapabilityStore`（`cache.toml` の `[imm_capability]`）に触れなかった。

**影響:** BUG-56・BUG-107 は誤学習した IMM32 能力の回復手段として「クリア」を案内していたが、
機能しないため `cache.toml` の手編集しかなかった。1.19.0 のリリースノートは「修正」と書いたが、
実際は未修正だった（リリースノートに訂正注記済み）。

**修正（2026-09-28）:** `ImmCapabilityStore::clear()` を新設し、メモリ上のキャッシュ・確定前の
疑いカウント・`[imm_capability]` を空にする（`FocusTracker` → `Platform` 経由でトレイから呼ぶ）。
メニュー名は学習表と区別するため「IME 制御の学習キャッシュをクリア」に変更。実行するとバルーンで件数を通知する。
- **消さないもの**: `cache.toml` の他セクション（`[injection_mode]`）、学習表 `keymap-learn-table.json`（ADR-198 決定5）。
- `cache.toml` が読めない・壊れている・書けないときは `save_section` が上書きせず警告する
  （ADR-198 決定5）ので、メモリだけが空になる。この場合バルーンは成功と伝えず、
  「cache.toml に反映できず、再起動で元に戻る」と知らせる（Codex レビュー指摘で追加）。
- テスト: `focus/classifier.rs::clear_empties_imm_capability_section_and_keeps_other_sections`
  と `clear_reports_failure_when_cache_toml_is_unwritable`
  （`#[cfg(windows)]` のため Linux では実行されず、windows-build CI で実行）。
- 未確認: Windows 実機でのメニュー操作（誤学習させた状態でクリア→次回フォーカスで再学習されること）。

**関連:** BUG-56・BUG-107。
