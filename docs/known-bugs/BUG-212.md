# BUG-212: 半角カタカナ(0x13)の英数キーを予測器が逆に予測する

**状態(2026-10-22):** 未修正(所有者の判断待ち)。擬似 IME の全列挙(ADR-277 の仕分け)で発見。実機の実害は未確認。

**症状(擬似 IME、実測の格子 `msime.json` が根拠、各セル 2/2):** 開・ひらがな(0x19)から `無変換 → 無変換 → 英数`。`on-c19-none|muhenkan`=`ON/0x1B`、`on-c1B-none|muhenkan`=`ON/0x13`、`on-c13-none|eisu`=`ON/0x19`。予測器は最後の英数を(C19, 英数)=`C10` の行で引き、入力モードを `ObservedEisu` と予測する(実 IME はひらがな)。入力中・変換中(Space/変換/無変換)の 0x13 の英数も同じ。MS-IME 本体の格子では 0x13 と 0x19 の結果が全キーで一致するので起きない。

**原因:** `Conv` は `C10`・`C19`・`C1B` の 3 つだけで、`Conv::from_raw(0x13)` は `None`。`predict_in_table` は追跡の conv → 観測の conv → 入力モード の順に決めるので、0x13 は入力モード(かな系)から `C19` になる。ADR-191(決定・`Conv` の doc)は「MS-IME プリセットで 0x13 は到達不能、表現できない値は追わない(予測なし)」とするが、第 3 版の格子では無変換 2 回で到達し、実装も「予測なし」ではなく `C19` の行で予測している。(C1B, 無変換)のセルは `after_conv=None`(表の生成が 0x13 を捨てた)で、追跡の conv は消える。

**想定される実害:** 半角カタカナから英数キーで、belief が英数になり Engine が止まるが、実 IME はひらがな。読める窓は次の観測(柵 170ms の後)で直る。読めない窓では残り、NICOLA が効かずローマ字かなになる。

**本来あるべき動作:** 実 IME(ひらがなへ移る)に従うか、少なくとも予測しない(ADR-191 は表せない conv を「予測なし」とする)。「半角英数へ」は格子にも ADR の意図にも根拠が無く、Engine を止める側に外れる。

**回帰の検出:** `crates/awase-windows/tests/pseudo_ime_exhaustive.rs` の `TRIAGE`「変換モード 0x13 を予測器が表せない」と golden `pseudo_ime_prediction_mismatches.txt`(件数)。

**直し方の候補(未決定):** (1) `from_raw` が `None` の観測 conv では入力モードへ落とさず予測なしにする(ADR-191 の意図どおり)、(2) `Conv` に 0x13 を足して表を再生成する。
