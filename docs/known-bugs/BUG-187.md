# BUG-187: GJI(ATOK)の外部エコー VK_DBE_HIRAGANA が IME OFF を巻き戻す(疑い・現行機序は未確認)

**状態(2026-10-05):** 保留・再現待ち(現行機序未確認)。ADR-181 の症状を ADR 棚卸しで起票したが、Opus レビューで「現行コードでは本文の機序が成り立たない」と判明した。所有者判断(既知の制限扱い)は誤った前提の上のため再確認待ち。

**症状(ADR-181、ADR-179 の Passthrough 実験の実機 A/B で発見):** GJI(ATOK プリセット)が VK_DBE_HIRAGANA(0xF2)を
`injected=false` で 0.4〜28 秒間隔に送ってくる。当時は IME OFF 直後に VK_IME_ON が再送され IME が ON に戻った。

**現状のコード(2026-10-05 Opus レビューで確認):** `kp_stage_shadow_ime_toggle`(`runtime/key_pipeline.rs`)は injected=false の 0xF2 を先へ進めるが、
意図へ昇格する `select_shadow_intent`(`state/explicit_press.rs`)は `shadow_action` か `sync_direction` を要する。0xF2 は
静的にも(`vk.rs` の `shadow_effect` は `DbeHiragana` で None)、役割由来にも(`ROLE_CANDIDATE_VK_NAMES` に無い)持たず、
`keys.ime_detect` 既定は空(ADR-207)。当時の機序(`delegate_to_open_axis`)は ADR-191 で撤去済み。したがって
shadow-toggle 経由の VK_IME_ON 再送は既定設定では起きない。

**残る近い経路(未再現):** 0xF2 は `kp_stage_key_effect_track` → `kp_predict_key_effect` へ届き、学習表・同梱表が「開く」と予測すれば
`apply_key_effect_prediction` が belief を開へ寄せる。IME へは書かないが「IME 閉なのに Engine ON」と見えうる。

**修正時の注意:** 存在しない shadow-toggle 経路を塞ぐ変更は無意味で、foreign-injected キー遮断は他アプリの機能的注入を壊す(BUG-14)。
