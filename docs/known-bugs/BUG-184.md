# BUG-184: 英数キーによる IME OFF で未確定文字が消える(MS-IME)

**症状(GitHub issue #138 と同一):** MS-IME・TSF アプリ(Chrome)。文字未確定のまま英数キーを押すと未確定文字が消える。
確定したうえで OFF にしてほしい(報告者の要望)。

**報告:** `01M3VCRSS2BEXGPKH2S8BYCX30`(1.21.0、2026-10-01)。

**確認できたこと(journal、Opus r1 の指摘で訂正):** OFF の経路は混在している。経過 2222779ms の OFF は秀丸
(Win32/ImmCross)。報告直前の Edge(TSF/`Imm32Unavailable`)では `VK_IME_OFF`(0x1A)が 2 回ずつ送られており
(2146130ms、2155092ms)、これが再現操作とみられる。英数は報告者自身が `keys.ime_off` に設定しており、エンジンが
Consume している。IME を閉じる前に未確定文字を確定する処理はコード全体に無い(`CPS_COMPLETE` 等0件)。

**未確認(原因は特定済みではなく仮説):** `ImmSetOpenStatus(FALSE)` で未確定文字が実際に破棄されること(MS-IME で未測定。
ADR-117 が同じ理由で挙動変更を見送った)。`composition_active` は全 OFF で false で、ADR-117 の予告どおり
MS-IME では信号として使えない。BUG-168/170/171 は GJI 側の別機序。

**次の一手:** [ADR-221](../adr/221-msime-ime-off-composition-loss-measure-first.md) D1 の実測(素の英数・VK_IME_OFF・
ImmSetOpenStatus(FALSE) × composing)。結果で修正案(OFF 前の確定/英数を Suppress しない/対応不要)を選ぶ。

**修正履歴:** なし(未対応)。

**実測(2026-10-04、ADR-221):** 現行機構(VK_IME_OFF、英数、ImmCross 相当の IMC)では、Chrome・MS-IME 本体の EDIT のどちらでも
未確定文字は消えなかった(Chrome は残る、EDIT は残るか確定)。再現せず・要追加情報。ただし別セッションの試作(VK_IME_OFF の後に
IMC 補完)は TSF の Chrome で未確定文字を取り消す(`text_post=''`、10/10)ので、本番化の際は BUG-184 型の副作用に注意。
