# BUG-179: CI の MS-IME 構成で新規 Chrome の初回入力が `kiu` になる

**症状:** awase 起動後に起動した実 Chrome へ、IME 操作なしで `k,a` を打つと
`kiu` になる。belief は ON、実 IME は閉。awase なしの対照は `ka` 5/5。

**再現:** CI run 36803095123 と最終 head の run 36805640317 の `sc-p2-initial-chrome-msime`（observe）は各 0/5。
`sc-p2-initial-chrome-msime-noawase` を対照にする。

**原因:** Chrome の TSF-native 経路では開閉を読めず、belief が ON の placeholder のまま残る。PR #406 の
新スレッド=閉は GJI または同定済み MS-IME 本体が条件だが、CI 構成の TIP は
`MicrosoftIme (Other)`（IMM32 HKL）と同定されるため適用されない。

**修正:** 未修正。GJI 経路は PR #406 の `fix(ADR-212 P2)` で修正済み。

**残作業:** CI の MS-IME 構成が `Other` になる理由を調査する。`table_ime_kind` を使う
ADR-189 の半角/全角 belief トグル等の CI カバレッジへの影響は未確認。
`sc-hz-msime-native` が observe である理由が同じ原因かも未確認。
