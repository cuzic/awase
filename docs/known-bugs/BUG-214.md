# BUG-214: 窓切替直後の最初の打鍵が前の窓の状態で処理される

**状態(2026-10-23):** 修正を PR にした(窓切替直後の短い保持、`state/focus_switch_hold.rs`)。CI で再現・確認。実機は未確認。

**症状(CI `e2e-ime` `tsx-sw809-b-*`、run 39952236830、`docs/tasks/mech-ecrs-2026-10-21/verify-809-unconfirmed-result.md`):**
窓 B(IME OFF)から A(IME ON)へ戻り、前面になってから 0〜30ms に打った最初の 1 打鍵がエンジン非活性(B の belief)のまま
素通しになる(`ふほうほしく` → `ｖほうほしく`)。60ms 以降は 0 件。#809 の前(TsfGate あり)は 0 件。実 Windows Terminal・WezTerm × GJI
では最初の打鍵が右親指(変換)だと、変換キーが GJI に届いて閉じ、読めない窓なので belief とのずれが直らず、以後の試行が全てローマ字(12/32)。

**原因:** フォーカス変更(`[focus-sync]`)から refresh が新しい窓を反映する(`[notify-refresh]`)まで CI で中央 67ms・最大 228ms(n=1,564)。
その間の打鍵は前の窓の分類・belief・Engine の活性で処理される。#809 で撤去した TsfGate(フォーカス直後のキー保留)がこの間を覆っていた。

**修正:** フォーカス変更から `FOCUS_SWITCH_HOLD_MAX_MS`(250ms)以内かつ refresh 前に届いた、文字・親指の修飾なしの物理 KeyDown、
または IME のモードキー(親指でない変換・半角/全角など)から保持を始め(V2)、保持中の打鍵が使った修飾キーの離しも保持に足し(V1)、spawn 時の世代がフォーカス変更以後の refresh の完了で `INPUT_DEFER` へ再生する(期限 250ms、上限 8 Down)。全窓で同じ。
回帰: `focus_switch_hold` の単体テスト、擬似 IME の閉ループ網羅 `tests/focus_switch_hold_closed_loop.rs`(PR #818 から)、`architecture_guard::focus_switch_hold_wiring_m1`、CI `tsx-sw809-b-*`。

**未確認:** 実機(dragonflyg4)のフォーカス検出〜refresh の時間、Alt+Tab・マウスでの切替、250ms を超える窓。

**既知の制限(直さない、所有者判断 2026-10-23。閉ループ検証 PR #818):** V3 上限 8 Down での解放は refresh を待たず古い文脈で再生し、
待機に戻らない(6ms 間隔の注入・音声入力など機械の速さの入力だけ)。V4 保持中に別の窓へ切り替えると、前の窓で打った打鍵が次の窓に届く。
V5 フォーカスからちょうど 250ms の打鍵が同時刻の refresh の完了より先に処理されると古い文脈になる。古い世代の refresh が新しい世代の後に
完了すると文脈が戻る(保持とは別の既存の並び)。
