# BUG-194: RAW_TSF_LITERAL に focus 世代ガードが無い(構造は残存・実環境では未観測)

**状態(2026-10-08):** 構造は残存・実害は未観測。特性テストで構造を固定した(ブランチ `ci/e2e-focus-restore-13-17` の `9afe8fac`、`develop` へは未マージ。Windows CI の `windows-build` で PASS、run 37779407207)。

**事実(`git grep -n RAW_TSF_LITERAL`、`origin/develop` `5ed1d151` と調査ブランチ `9afe8fac` で同じ):** 書き込みは `output/mod.rs:1258-1262` の `record_raw_tsf_literal` だけ。読み出しは `1095-1099`・`1275`・`tsf/output.rs:166-167` の swap/take だけ。`cancel_probe`(`output/mod.rs:1177`、FocusChange 等で発火)は deferred を破棄するが `RAW_TSF_LITERAL` に触れない。過去の `discard_raw_recovery_if_focus_stale`(`3a763c4d` で導入、`0a7f9067` で削除)は reinit 予約が Scheduled のときだけが対象で、通常の回収(consecutive==0)には最初からガードが無い。

**割り込み経路:** `RawTsfLiteralRecovery` と `Done` は同一の `step_probe` 内で同期に処理され、`WM_DRAIN_OUTPUT_QUEUE` は PostMessage で届く(`tsf/probe_bridge.rs:133-148`)。その時点でキュー済みの FocusChange(WinEvent)が先に処理されれば、残った backs/romaji/escape が新しい前面窓に送られる。当初は「窓は投函 1 回分」と書いたが誤り。record は literal 検出の 300〜500ms 後に走り、warm 経路の `LiteralDetectFsm` は FocusChange で止まらないので、窓はもっと広い(ADR-246)。

**未確認:** 実環境で起きるか。Chrome の cold-start リテラルは CI で起こせない(ADR-193、BUG-002)ので再現は試みていない。
**修正(2026-10-08、ADR-246):** 段の開始時(`Output::install_pending_tsf`)に `(focus 世代, 前景窓)` を採り、`flush_raw_tsf_literal_recovery` の先頭で `state::raw_recovery_plan::plan_raw_recovery` により照合する(主な物差しは前景窓。世代は前景が取れないときだけ。世代は debounce で遅れ、窓切替直後の段を誤って捨てるため)。違えば ESC/BS/romaji と旧窓の `pending_deferred` を送らず捨て、journal に `DiscardedStale` を残す。初版(record 時に世代だけ刻む)は、検出時の刻印が遅い・世代が前景変化より遅れる・deferred が新窓へ送られる、の3点で Opus レビューに却下され改訂した。前景が一瞬別窓になる場面(ダイアログ、Alt+Tab 等)では回収を捨ててリテラルが残る側に倒れる。同じ最上位窓の中の移動(Chrome のアドレスバー等)は捉えない(ADR-246 Q3)。テスト: `plan_raw_recovery` の単体(Linux)、`output/mod.rs::raw_tsf_literal_and_deferred_are_discarded_when_foreground_changed_before_flush`(Windows CI のみ)、`architecture_guard::raw_tsf_literal_recovery_is_guarded_by_stage_origin`。

**訂正:** 上の「割り込み経路」で `cancel_probe` が FocusChange で発火するかのように読める記述は、record から flush までの窓では成り立たない(probe_id が段末で抜かれ GjiFsm も NotStarted のため `CancelProbe` が出ない)。詳細は ADR-246。
