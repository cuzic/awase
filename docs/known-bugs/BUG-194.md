# BUG-194: RAW_TSF_LITERAL に focus 世代ガードが無い(構造は残存・実環境では未観測)

**状態(2026-10-08):** 構造は残存・実害は未観測。特性テストで構造を固定した(ブランチ `ci/e2e-focus-restore-13-17` の `9afe8fac`、`develop` へは未マージ。Windows CI の `windows-build` で PASS、run 37779407207)。

**事実(`git grep -n RAW_TSF_LITERAL`、`origin/develop` `5ed1d151` と調査ブランチ `9afe8fac` で同じ):** 書き込みは `output/mod.rs:1258-1262` の `record_raw_tsf_literal` だけ。読み出しは `1095-1099`・`1275`・`tsf/output.rs:166-167` の swap/take だけ。`cancel_probe`(`output/mod.rs:1177`、FocusChange 等で発火)は deferred を破棄するが `RAW_TSF_LITERAL` に触れない。過去の `discard_raw_recovery_if_focus_stale`(`3a763c4d` で導入、`0a7f9067` で削除)は reinit 予約が Scheduled のときだけが対象で、通常の回収(consecutive==0)には最初からガードが無い。

**割り込み経路:** `RawTsfLiteralRecovery` と `Done` は同一の `step_probe` 内で同期に処理され、`WM_DRAIN_OUTPUT_QUEUE` は PostMessage で届く(`tsf/probe_bridge.rs:133-148`)。その時点でキュー済みの FocusChange(WinEvent)が先に処理されれば、残った backs/romaji/escape が新しい前面窓に送られる。窓は投函 1 回分と狭い。

**未確認:** 実環境で起きるか。Chrome の cold-start リテラルは CI で起こせない(ADR-193、BUG-002)ので再現は試みていない。
**修正(2026-10-08):** `Output::raw_literal_focus_gen` に record 時の `ime_mode_focus_gen` を刻み、`flush_raw_tsf_literal_recovery` の先頭 `discard_raw_recovery_if_focus_stale` で照合して、違えば backs/ESC/romaji を送らず捨てる。読み出し口は flush の1本だけなので照合も1箇所(deferred は `cancel_probe` が破棄済み)。疑似 FocusChange でも世代は進むため、その場合は回収を捨てて literal が残る側に倒れる(別窓へ BS が飛ぶよりよい)。テスト: `output/mod.rs::raw_tsf_literal_is_discarded_when_focus_changed_before_flush`(Windows CI のみ)、`architecture_guard::raw_tsf_literal_recovery_is_guarded_by_focus_gen`。関連: [BUG-193](BUG-193.md)。
