# BUG-203: IME を閉じた直後の GJI の I/O を「ON の証拠」と読んで、Engine を有効化する

**状態(2026-10-17):** 未修正。CI(windows-latest、awase debug)で観測の無い窓の近似(自前の TSF text store の窓、`cache.toml` で unavailable)に限って確認。実機・実アプリでの頻度は未確認。

**症状(ログ):** 入力インジケーターの右クリックメニューで **Direct Input(IME 閉)を選ぶ**と、約 9 ms 後に GJI が I/O を起こし(`[gji-io] WRITE: w_ops=+1`)、約 0.4 秒後の定期観測で
`[gji-poll] GJI I/O observed 406ms ago … → observer_poll=true` → `[effective-open-flip] → true decided_by=DeriveMedium { first: ObserverPoll }` → `Engine activated (ime=true …)` → `[startup-align] desired_open … desired=true`。
実際の IME は**閉**(メニューを再度開くと `Item 10`=Direct Input が選ばれている)なのに、awase は ON と判断して Engine を有効にする。

**再現(CI):** ブランチ `ci/indicator-menu-verify`、run 39081235242、成果物 `result-gji-full` の `gji-tsf-hover/awase.log`(選択は `events.log` の `POPUPEND` 00:06:38.602、上のログは 00:06:38.611〜39.016)。
run 39079041821(`result-gji` の `gji-tsf-awase`)でも、選択の約 3.3 秒後に同じ向きの `effective-open-flip → true` が出た。MS-IME の同条件では出ない。GJI の通常の窓(IMM が読める)では選択後に `true→false` で実状態と一致した。

**影響(想定。未確認):** 利用者がずれに気づいてメニューから「直接入力」を選ぶと、次の打鍵が NICOLA のローマ字として送られ、直接入力の窓にローマ字が出る。
メニューに限らず、**GJI が I/O を起こす操作全般**(設定の書き込みなど)の直後、IME が閉でも ON と推論しうる(GJI の I/O 推論が「開いている間の I/O」と「閉じる操作に伴う I/O」を区別しない)。

**原因(読解):** `gji_observer` は「直近の GJI プロセス I/O」を ON の証拠(Medium)として扱う。IME を閉じる操作そのものが I/O を起こすため、閉じた直後の I/O が ON の証拠に見える。

**方針案:** 利用者の明示の閉じる操作(物理キー・メニュー選択)の直後の一定時間は、GJI の I/O を開閉の証拠にしない。メニュー選択は [ADR-264](../adr/264-indicator-menu-mode-evidence.md) の証拠(選択後の状態)で上書きする。
`state/`・`observer/gji_observer.rs` は再発ファミリー([fix-requires-evidence](../../.claude/rules/fix-requires-evidence.md)、IME belief)なので、直す際は golden か journal のテストを足す。観測の無い窓の近似以外(実アプリ)で出るかを先に確かめる。

**修正履歴:** なし。
