# BUG-197: 注入された Ctrl+V の V が NICOLA の文字キーとして変換される

**状態(2026-10-10):** 起票。原因はログで確定。ADR-249 案 A' を実装(PR は fix_commits 参照)。CI: 貼り付けは全構成 36/36(run 38041351075)、KeyUp 欠落後に物理相当の打鍵が通常どおり変換されることを run 38046806775(コミット 7a2b0e2b、3bfd87ca を含む)で観測(ADR-252、S1 は c=false・6/6)。0x11 は LL フックに 0xA2 scan=29 として届く。実機は未確認。実機確認は報告者のみ。

**症状(報告 `01M4J72G985T0FFT6XPN0SWCQQ`、GJI、awase 2.0.0):** awase を起動したまま Spokenly で音声入力すると
「ふ」1文字だけが入る。awase を止める、またはやまぶきR に替えると正常に貼り付く。

**原因(journal で確認):** Spokenly は貼り付けで挿入する。注入キー(`injected=True`)の列は
左Ctrl↓(scan 29)→V↓(scan 47)→V↑→約100ms 後に左Ctrl↑。awase の `hook.rs` は物理押下状態
(`physical_key_state`)を非注入のイベントだけで更新するため、注入された Ctrl は押下として数えず、
V は `ctrl=false` の `Char` として NICOLA 変換(V=「ふ」)され Consume される(`PendingChar(0x56)`→出力3件)。
貼り付けは起きず、「ふ」が出る。この Ctrl 非計上は `8351bcf9`(2026-06-06)で入れたもの:
X サーバーが注入した Ctrl の KeyUp を送らず終了すると stuck modifier が残る問題への対策([BUG-023](BUG-023.md) と同系統)。

**補足(Opus レビューで判明):** 報告では両方の貼り付けの 約 0.77〜0.91 秒前に物理の右 Ctrl の長押しがある(Spokenly の押して話すホットキーと思われる、未確認)。ホットキーを押したまま貼り付けが走る設定では物理 Ctrl が重なり、現状でも成立しうる。設定により症状が出る/出ないが分かれる可能性がある。

**CI での裏取り:** `ci/e2e-dictation` の `tsx-dict-*-paste`(run 38029357773)で、注入 Ctrl+V に対し
`[engine-input] vk=0x56 KeyDown mods(c=false …)` → `PendingChar(vk=0x56)` と同じ判定になった。
当時の模擬は PowerShell がフォーカスを奪い(全試行 `focus_ok=False`)無効だった。`bc479aa6` で Win32 直呼びに直した run 38038031488 では、edit・rich の paste で awase あり 0/36(実際 `ふふふつうほめ…`、貼り付け文が消え V が「ふ」)、awase なし 36/36 一致。GJI・MS-IME とも同じ。tsf の paste は貼り付け文が消えるだけで「ふ」は出ない(未調査)。

**修正方針:** [ADR-249](../adr/249-foreign-injected-modifier-ttl.md)(案 A': 注入された打鍵の `modifier_snapshot` にだけ、注入 Ctrl↓ の期限内 ctrl を足す。Ctrl のみ、物理打鍵には効かせない)。
再発ファミリー(物理キー押下ラッチ)なので回帰テストを添える。

**別件(同じ CI で判明、未修正):** `KEYEVENTF_UNICODE`(`VK_PACKET`=0xE7)の注入が awase ありだと丸ごと消える
(awase なし全 PASS、`tsx-dict-*-unicode`)。保留→再注入(`RawKeyEvent::reinject`)で文字(`wScan`)が失われる疑い。Spokenly は貼り付け方式のため本件の原因ではない。
