(修正前の状態)未修正。調査用 CI(`sc-focusrestore-{msime,gji}`、observe)で MS-IME 本体・GJI とも有効 5/5 試行で再現。実機・実アプリ(Chrome 等)は未確認。調査ブランチ `ci/e2e-focus-restore-13-17`(先頭 `c629db6b`、`develop` へは未マージ)。

**症状:** 窓 A で左 Shift 単独タップ(持続半角英数、ADR-107)にしたまま別プロセスの窓 B へ移り、A へ戻ると、A の conv は 0x10 のまま(かなに戻らない)。戻してから打つと期待の文字が出ない(`w`)。awase のトグルフラグは強制解除で下りているので、A で左 Shift をもう一度タップしても変わらない。
同一プロセス内の窓移動では `ir_notify_focus_changed` が呼ばれず、この経路に入らない。

**原因(コードで確定):** `ir_notify_focus_changed` が `kp_restore_kana_from_half_width(false)` を起案し `owner_gen`/`focus_gen` を捕獲して `spawn_local` する(`key_pipeline.rs:2299,2308`)。同じ同期呼び出しの後半で `gji_on_focus_change` → `on_ime_mode_focus_changed` が両世代を進める(`ime_refresh.rs:694`、`platform.rs:632`)。タスク先頭の `extend_confirm_gate_override(owner_gen)` は必ず false になり、`復元リトライ #0 ... 中断`。**IMC 書き込みは一度も行われない。**
MS-IME の F2 注入は SendInput で前面窓(= 移動先 B)に届く。`effective_open()` は B の belief を見る。B が閉ならスキップ(`VK_DBE_HIRAGANA 注入をスキップ`、GJI も `Exit をスキップ`)、B が開なら B に届く(B の conv が動いたのは GJI の 2/5 回のみ、MS-IME は動かず)。旧窓 A を戻す経路は無い。

**対照:** B へ移さない構成では 2 回目のタップで A が 0x19 に戻る(通常の復元経路は単体で動く)。

**未確認:** 窓 A が 0x0 → 0x10 に変わる遷移の主体(awase のログに出ない)。実 Chrome・UWP を B にした場合。
**修正方針:** 決定済み([ADR-245](../adr/245-half-width-alnum-restore-on-return.md)、案 B: 戻ったときに復元)。関連: [BUG-194](BUG-194.md)、観測起点の書き込みの棚卸し `docs/tasks/observation-driven-writes-inventory-2026-10-08.md`。
