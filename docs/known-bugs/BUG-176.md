# BUG-176: 外部注入の IME キーで IME が閉じないのに awase が OFF へ追随する(偽 OFF)

**発見経緯:** 2026-09-30、v2 実機確認 X5(BUG-172 の実機検証)。dragonflyg4、GJI、Edge の `<textarea>`(`Chrome_WidgetWin_1`、`Imm32Unavailable`)、develop `1ec078ef`。
注入は PowerShell の `SendInput`(目印なし、VK_IME_OFF=0x1A、scan は `MapVirtualKey`)。3 秒後に `z` を注入して、入力欄の文字で IME の実状態を見た。

**症状(判定は入力欄の文字: `z`=IME 閉+追随 / `．`(U+FF0E)=awase が追随せず Engine ON で NICOLA 変換 / `ｚ`(U+FF5A、未確定)=IME 開):**

| 条件 | 注入 0x1A の 3 秒後の `z` |
|---|---|
| awase 停止 | `z`(IME は閉じる) |
| 利用者の元の awase(未コミット変更入りの e174c6f6 系ビルド) | `z` |
| **develop 先端(ADR-205 入り)** | **`ｚ`(IME は開いたまま)** |
| e174c6f6 の素のビルド(ADR-205 なし) | `．`(追随せず Engine ON。修正前の BUG-172 症状) |

**awase.log(develop 先端、注入 05:21:21.039Z、debug):** 注入を `injected=true scan=0xF1` で検出 → `[relay-passthrough] direct OS pass-through` と `[reinject] vk=0x1a`(自己注入マーカー付きの再注入)
→ +49ms `[external-change] 監視窓の中で開閉の読みが変わった → 実状態 open=false へ追随` → `Engine deactivated`。追随後に awase が IME を開け直した形跡は無い
(VK_IME_ON/F2 の送信なし。`apply-ime open=false → AlreadyMatched`)。読みの出どころは `read_ime_state_full` の `WM_IME_CONTROL`(cmd=0x0005/0x0001)の先読み(`ir_follow_external_change`)。

**確認したこと:** キー注入は入力欄に届く(`z` 単独の注入で確認)。awase を止めると同じ注入で IME は閉じる。CI(windows-latest、GJI × 実 Chrome)では 10/10 で正しく閉じて追随した(PR #377)ので、**実機の Edge だけ**で起きる。

**追跡結果(2026-09-30、同日):** #377 の前後・先端を3状態(`z`=IME 閉+追随 / `．`=追随せず Engine ON / `ｚ`=IME 開)で自動判定した(入力欄の値を UI Automation で読み、注入の前後の差分で分類):
`89f5e63f`(#377 の直前)=`．`×3(BUG-172 の元の症状)、`a4022ba9`(#377 のマージ)=`z`×3、develop 先端=`z`×3。ON の準備を変えても develop 先端は `z`×9
(注入 VK_IME_ON 1.5秒後 / 目印付き注入=物理キー扱い 1.5秒後・25秒アイドル後)。新しく起動した awase での手動(Ctrl+変換で ON)も `z`。**#377 の効果は実機でも確認できた。**
偽 OFF/無変化は、**最初に起動した awase での手動の連続試行(3回)にだけ**出た。そのとき awase は前の試行で `desired=false` のまま、IME はマウス等で ON に戻されていた
(`[drift] correction: observed=true ≠ desired=false … Unwarranted` が続いていた)。再現条件は未特定(ON にしたキーの記録が無い)。F2 単独・変換単独で ON にした場合は未確認。

**未解明(初回セッションの異常について):** (1) awase が「閉じた」と読んだのに IME が開いたままなのは、読みの誤りか、閉じてから開き直されたのか。(2) awase 稼働中だと閉じないのは、通過+再注入の経路が絡むのか(awase 停止だと閉じる)。
実 IME の状態を awase とは独立に読む手段が無い(トレイのインジケーターは名前に状態が出ない)。3 状態(`z`/`．`/`ｚ`)で #377 の前後を判定し直す予定。

**影響(初回の異常が実在するなら):** 追随が「正しい」を装って Engine を OFF にするので、注入元(他のキーリマッパ等)の操作の後、利用者は IME が ON なのに NICOLA が効かなくなる。
**残作業:** 再現条件の特定(F2 単独・変換単独・マウスで ON にした後、awase の belief が OFF のまま残った状態からの注入。`x5-auto-phys-*` の自動判定で試せる)。再現しなければ観察継続として閉じる。
