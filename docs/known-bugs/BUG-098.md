# BUG-098: 非同期 shadow toggle の完了と focus epoch ゲート

**状態(2026-10-06 訂正): 主な窓は `cf48bc67`(ADR-213 P2a、PR #408 の Opus M-3)で閉じた。残りは小さな窓で、実害の記録は無い。コードは変えない(案 D)。**
旧記述(「`generation=None` のまま epoch ゲートを通らず、残存を確認」)は、M-3 の照合に触れておらず、部分的に古かった。

**症状(元の指摘、ADR-108 決定6):** shadow toggle の ImmCross 非同期経路(`runtime/key_pipeline.rs` の `spawn_local`)は、`run_open_chain_async(..).await` の後に `on_ime_apply_complete(open, outcome, None, ..)` を WM で投函する。待機中に Alt+Tab で別プロセスへ移ると、旧ウィンドウ宛ての完了が新ウィンドウの `applied` に `Confirmed` を書く恐れがあった。

**いまの状態(コードで確認):** spawn 内の「書き込み後の `ime_mode_focus_gen` 照合」(`key_pipeline.rs:1351-1359` 付近)で、フォーカスのプロセスが変わっていれば `UnsafeToToggle` に落とす。世代は**プロセス変更のときだけ**進み、`applied` のリセットと同じ refresh の呼び出しの中で進む(同一プロセス内の hwnd 変更では進まない。Opus のレビューで訂正)。

**残る窓(いずれも小さく、実害の記録なし):** (G1) 照合から WM を取り出すまでの窓(キューで前に focus 系のメッセージがあるとき)。(G2) `with_app` 再入時の「一致扱い」(fail-open、B-1 の設計。`with_app` は再入時に warn を出す)。(G3) OFF が宛先を捕獲していない(`Untargeted`)ことは、`applied` の記録としては無害。書き込み先の捕獲は別件。

**実害を測る手順:** (i) 不具合報告の journal で、`ActuationDecision`(caller が shadow toggle)の後に `FocusTransition`(プロセス変更)があり、その後に `ImeOpenApplied { reason: ShadowToggle }` が outcome ≠ `UnsafeToToggle` で来る並びを数える(G1 の実例)。(ii) `with_app re-entry detected` の warn の件数(G2 の上限)。

**再開の条件:** (i) が 1 件以上、または G2 の warn が shadow toggle の直後に出ていたら、案 A(完了ハンドラ `handle_wm_async_ime_apply_complete` で、spawn 時の `focus_gen` を WM に載せて照合し、不一致なら `UnsafeToToggle` に落とす。新しい世代は作らない=ADR-229 F-D5-2。64bit 前提は `const _: () = assert!(size_of::<isize>() == 8);` で固定。outcome を書き換えると journal が「送っていない」と誤読されない形にする)を入れる。設計: `docs/adr/review/` の BUG-098 設計(本作業の調査)と Opus レビュー。

**修正履歴:** `cf48bc67`(M-3 の書き込み後の世代照合)。ADR-108 決定6 は「意図的に未修正」としていたが、その後 M-3 で主な窓は閉じた。
**関連:** ADR-108 決定6、ADR-110、ADR-213 P2a、ADR-229 F-D5-2。`crates/awase-windows/src/runtime/key_pipeline.rs`、`runtime/message_handlers.rs`(`handle_wm_async_ime_apply_complete`)、`state/platform_state.rs`。
