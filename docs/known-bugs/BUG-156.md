# BUG-156: 予測でbeliefが動いたのに`applied`が古いまま、書き込みが省かれる

**発見経緯:** 2026-09-21、ADR-191の撤去ブランチのCI `cal-verify-blind`（Editを`Imm32Unavailable`へ降格した読めない条件）のずれが 0%→10〜15% に悪化。
復元を外した版(`ci/e2e-blind-b`)は0%に戻るので、原因はADR-189の半角/全角トグルの復元。半角/全角の押下で実IMEの開閉が変わった割合は 復元あり 5/8・6/10、なし 8/8・10/10。

**原因（実IMEが変わらなかった7押下の分類）:** A（5件）beliefは実IMEと一致(ON)でトグル(true→false)を決めたが、`apply_mechanism`が
`[apply-ime] GJI direct: shadow already OFF (open=false), skip`で`VK_IME_OFF`を省く。GjiDirectのalready-matched判定（`ControlLog.shadow_on`＝`ImeModel.applied`）は
「awaseが最後に書いた結果」を根拠にするが、その後に予測（`KeyEffectPredicted`、変換キーの`open=Some(true)`等）がbeliefだけをONへ動かしていた。`applied`は実状態の証拠でなくなったのに残り、
物理キーはSuppress済みなので誰も実IMEを動かさない。C（2件）はAの連鎖（書き込みが飛んだ後にbeliefだけがトグル済みで向きが逆）。

**設計原則:** 「送信を省略してよいか」は**陽性の確認済み証拠**にのみ基づく（`AppliedImeState::applied_open`のdoc、ADR-098決定1-b、BUG-113、fix-requires-evidenceの`shadow_on`の行）。
書き込み以外の源でbeliefが開閉を動かしたなら、`applied`はもう証拠ではない。

**修正（根本、ガードではない）:** `ImeModel::reduce`の`KeyEffectPredicted`で、予測が開閉を動かし、かつ`applied`が予測と食い違う向きなら`applied`を`Unknown`へ落とす（1箇所、新しい型・フィールド無し）。
すると`applied_pair()`/`ControlLog.shadow_on`が`None`になり、GjiDirectのalready-matched判定（`None`は該当しない、BUG-113）が書き込みを省かず、beliefトグルの書き込みが行われる。
同じ向きの予測や追跡だけの予測は`applied`を保つ。単体テスト`prediction_that_contradicts_applied_drops_it_to_unknown`、`architecture_guard`の`.applied = `件数(5→6)を更新。
（最初に入れた対症のガード〈`applied`と`belief`が食い違うときトグルしない〉は、ユーザー判断で撤回し、この根本修正に置き換えた。）

**未対応:** 観測（`ObserverReported`）がbeliefだけを動かした場合の`applied`の扱い（読める窓は観測が`applied`の食い違いを解消するため、CI obsでは0%）。`VK_KANJI`(0x19)の静的Toggle経路も同じ`applied`を見る（本修正で同様に恩恵を受ける）。
