# BUG-148: フォーカス未確定（current_focus=None）のままだと明示意図が記録されず委譲SetOpenが不発になる

**発見経緯:** ADR-186のE2EをGitHub Actions（`ci/e2e-ime`、run 35484080057）で回した際の切り分け。**未修正。CIで再現・実機未確認。**

**症状:** 実機ではALL PASSする無変換（`delegate_to_open_axis`、IME ON→OFF）が、CIでは手順5で必ず失敗する。
awaseは`IME open axis delegated ... → false`まで出すが、`[apply-ime] outcome=Unwarranted`（`attempts_len=0`）で
書き込みが1回も行われず、物理の無変換もFSMが`Consume`するのでGJIに届かない（IME ONのまま）。

**原因（一時ログ`[warrant-diag]`で確定）:** `target=HwndId(0) intent=None`。`ImeModel::current_focus`は
`ImeEvent::FocusChanged`のreducerでしか設定されず、そのイベントは**プロセスが変わったとき**
（`runtime/focus_tracking.rs::on_focus_process_changed`）にしか発行されない。awase起動時に既に対象アプリが前面にあると
一度も設定されず、`record_explicit_intent`（`current_focus()`が`None`だと何もしない）が空振り→
`issue_open_warrant` Step 1が外れ、Step 3の観測（実IME=ON）が要求OFFと不一致で`None`（Unwarranted）になる。

**再現（CI）:** awase起動後にフォーカスを別プロセスへ一度も移さずスパイクで無変換を押す。
notepadを起動→終了して1回フォーカス移動させると全手順PASS（run 35484314507）。

**実機での影響（推測、未確認）:** awaseを起動した直後、アプリを切り替える前の最初のIMEモードキー操作。
[BUG-147](BUG-147.md)（実機での取りこぼし）とは別の機序（実機のE2Eはスパイク起動＝プロセス変更を必ず挟む）。

**修正案:** 起動時の初期フォーカスでも`FocusChanged`相当を1回発行して`current_focus`を設定する、
または`record_explicit_intent`/`issue_actuation_order`が`current_focus`ではなくフォアグラウンドHWNDを直接使う。
回帰テストは`current_focus=None`でのwarrant発行を固定する（`state/open_warrant.rs`の純関数テスト）。
