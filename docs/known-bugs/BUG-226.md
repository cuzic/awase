# BUG-226: LINE では Mozc の cold 最初の送信の確認が張られない

**状態(2026-10-28):** 実機で再現(dragonflyg4、Mozc 系、LINE)。ADR-285(PR #904)で、確認を張る窓を反転(Chrome 系と空以外のすべて)し、最初の 1 キーだけ送って確認する per-VK 化も入れた。実機は未確認。

**症状:** LINE で 70 秒ほど空いたあとの最初の「こちらのけん」が `kおちらのけん` になる。BUG-225 の修正(ADR-284)を含むビルド(`528d4a70`)で起きた。

**ログ(2026-10-28 07:41:55 UTC、16:41 JST):** `[focus-sync]` で `Qt663QWindowIcon` に移った 5 秒後、物理 F2 → R・U。`[vk-send] romaji="ko" warm=false prepend_f2_warmup=true`、`[h1-window] cold=184 class=Qt663QWindowIcon`、`idle_at_cold=70875ms`。ChromeProbe は 16ms で終わった。**`[mozc-compose]` の行が無い**。同じ時間帯の Windows Terminal の `ko`(07:42:22)は `[mozc-compose] ... confirmed` が出て正常に入った。

**原因:** `is_mozc_compose_check_window`(`awase-windows-base/src/focus/class_names.rs`)が Windows Terminal・WezTerm だけを対象にしており、LINE は `mozc_compose_precheck` の前段で `None` になる。ADR-284 の回収は確認の FSM の中にあるので、LINE では働かない。

**修正(ADR-285):** (1) `is_mozc_compose_check_window` を Chrome 系と空のクラス以外すべてで真にする(許可リストから除外リストへ)。(2) 張るときの最初の送信を最初の 1 キーだけにし、確認できてから残りを送る(`TransmitRest`)。リテラルは Backspace ×1 + 全体の再送。テスト: `class_names.rs` の判断表、`mozc_shm.rs::split_first_key`(Linux)、`probe_io.rs`・`mozc_compose_check_fsm.rs` の単体テスト(windows-build CI)。

**限界:** 漏れたこと自体は画面の `kおちら` からの推定で、ログに直接の証拠は無い。LINE で共有メモリの `key_seq` が読めるか、`confirmed after Nms` の分布は未測定。Qt のバージョンが変わるとクラス名(`Qt663`)が変わる。
