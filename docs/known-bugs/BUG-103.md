# BUG-103: `[[post_bypass]]` は `reload_config()` で反映されない（設定変更に再起動が必要）

**状態(2026-10-04):** 修正済み(PR #471 で develop にマージ。実 awase.exe の CI で B-3〈リロード後に追加したルールが効く〉が PASS。実機未検証。`PostBypassEntry::compile_all` を bootstrap と `apply_config_update` の唯一の構築点にした。回帰ゲートは `bug103-verify.yml` の B-3 が PASS すること) — 修正前の状況: `post_bypass_rules` は `app/bootstrap.rs:721` の起動時構築のみで、`runtime/mod.rs::apply_config_update` は `post_bypass` に一切触れない(runtime 内の読み取りは `message_handlers.rs:435` のみ)。CHANGELOG 2.0.0 の `[[post_bypass]]` 言及は診断通知であり reload 反映の修正ではない。

**症状:** `config.toml` の `[[post_bypass]]` セクションを変更して設定を保存
（reload）しても、変更が反映されない。awase を再起動して初めて新しい
`[[post_bypass]]` ルールが有効になる。

**原因:** `Runtime::post_bypass_rules`（コンパイル済み `[[post_bypass]]`
ルール一覧）は `bootstrap.rs` でのみ構築され、`apply_config_update`
（`runtime/mod.rs`、`reload_config()` から呼ばれる）は一切この値に触れない。
`[[keymap]]` も ADR-114 実装前は同じギャップを抱えていたが、ADR-114 決定8
（`Runtime::all_keymaps`/`recompute_active_keymaps()`）で解消済み。
`[[post_bypass]]` 側は本 ADR のスコープ外として意図的に対象外にした
（[[keymap]] のギャップ解消が優先度が高いと判断したため）。

**再現手順:**
1. `[[post_bypass]]` ルールが未設定の状態で awase を起動する。
2. 設定画面（またはトレイの「設定リロード」）から `config.toml` に
   `[[post_bypass]]` セクションを追加して保存・reload する。
3. 対象のキーコンボを押しても、ルールが有効になっていない
   （追加前と同じ挙動のまま）。
4. awase を再起動すると、追加したルールが有効になる。

**修正方針（未実装）:** `apply_config_update` に `[[post_bypass]]` のコンパイル
（`bootstrap.rs` の `post_bypass_rules` 構築ロジックと同等）を追加し、
`Runtime::post_bypass_rules` を差し替える。`[[keymap]]` の
`recompute_active_keymaps()` と同様、書き込み点が複数に増えないよう
1箇所に集約すること。

**状態:** 未修正。`[[keymap]]` 側（ADR-114）の実装と同時に発見・記録した。

**関連ファイル:** `crates/awase-windows/src/app/bootstrap.rs`（`post_bypass_rules`
構築）, `crates/awase-windows/src/runtime/mod.rs`（`apply_config_update`,
`post_bypass_rules` フィールド）, `crates/awase-windows/src/app/mod.rs`
（`reload_config`）。関連: ADR-114（`[[keymap]]` 側の同種ギャップの解消）,
ADR-037（`[[post_bypass]]`/`[[keymap]]` 共通の「アプリ+キースコープの横取り」
形状）。

**追記(2026-10-04、実 awase.exe での CI 再現 — `bug103-verify.yml`、run 37199776558):** windows-latest の debug ビルド awase に、目印付き SendInput で Ctrl+P を物理 Ctrl 扱いで注入し(`config_verify_probe --mode=caret`)、`[ctrl-bypass] post_bypass armed`(ルールに一致した Ctrl+キーでだけ出る)を数えた。`tools/e2e/config_verify/reload_post_bypass.py`。
- 対照A(起動時の config に `[[post_bypass]] key = "Ctrl+P"`): armed 1 件 → 検証は成り立つ。
- B(ルールなしで起動 → armed 0 件 → config.toml にルールを足して `awase_tray_window` へ `WM_RELOAD_CONFIG` を投げる): ログに `Config reload requested via WM_RELOAD_CONFIG` が出てリロード自体は走るが、**その後の Ctrl+P で armed は 0 件のまま**(`[ctrl-check] vk=0x50` は出ている=キーは届いている)。→ **BUG-103 を再現。再起動するまで `[[post_bypass]]` の追加は反映されない。**

**修正(2026-10-04):** `runtime/mod.rs::PostBypassEntry::compile_all` を新設し、`app/bootstrap.rs` と `Runtime::apply_config_update` の両方から呼ぶ(警告は呼び出し側が診断へ流す)。再武装中の `gate.post_bypass` latch はルール参照を持たず短時間で失効するためリロード時の disarm は入れていない。
