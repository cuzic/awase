# BUG-161: 旧UI「IMEオン/オフ」トグル（コード`CE`）は無変換/変換キーの実IME挙動を変えない

**発見経緯:** 2026-09-23、[ADR-197](../adr/197-msime-legacy-custom-keymap-runtime-warning.md)
（`msime_legacy_keymap.rs`が検出する旧UIのキー割当てを実行時警告に配線する設計）のOpus
敵対的レビューround1が、2026-09-07の元の実機確認（変換キーでIME ONになった）はNATURAL既定
挙動と区別できない観測だった可能性を指摘。裏取りのためGitHub Actions CI（windows-latest）で
無変換キーを対象に7パターンの実機的検証（互換モードON/OFF・コード`CE`/`CA`〈ひらがなキー
自身が使う機能〉・再読込タイミング2種・MS-IME初回有効化前の書き込み）を行ったが、**いずれも
無変換キーはIME OFFのまま変化しなかった**。ユーザー本人もdragonflyg4実機で無変換キーを
物理的に押して同じ結果を直接確認した。

**訂正の範囲（過度な一般化に注意）:** 「旧UIのキー割当てとawaseが競合する事象自体が存在
しない」わけではない（ユーザー指摘）。確認できたのは「本モジュールが検出対象にしている
コード`CE`（『IMEオン/オフ』トグル機能）は無変換キーには効かない」という狭い事実のみ。
他のプリセット・コード・実際の設定ツール（`IMJPUEX.EXE`）経由で作成されたキーマップに
ついては未解明のまま残る。

**最終的な教訓（ユーザー方針）:** 7パターンすべてで否定的だった一貫性は、`StyleList\
<style>\key`レジストリの記述内容を「そのキーが実際にどう動くかの真実」として扱うこと自体が
構造的に不適切であることを示す実例と位置づける。将来この種の実効果を確認したくなった場合、
正しい手法はレジストリの静的解読ではなく、[ADR-195](../adr/195-keymap-learn-productization.md)/
[ADR-196](../adr/196-keymap-learn-truth-priority.md)が採用する学習（キャリブレーション、
実際にキーを注入し実IME状態の変化を観測する）である。

**対応:** `msime_legacy_keymap.rs`のmodule doc・`LegacyMsImeToggleAssignment`のdoc・
`BugReportLegacyMsImeKeymapSummary`のdocを訂正（「実機確認済み」→「レジストリにこの割当てが
存在するかの事実のみ、実効性は未確認」）。ADR-197の実行時警告（決定1〜3）は撤回、検出機構
自体は不具合報告への添付（ADR-148 Phase 2、診断専用）としてのみ残す。
