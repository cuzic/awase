# BUG-178: 学習プロセスが到達できないセルで回り続け、完走しない(実機)

**発見経緯:** 2026-09-30、v2 実機確認(dragonflyg4、JIS、GJI `session_keymap=2` + `custom_keymap_table` 191 行が残る、Windows 11)。BUG-177(自分の注入を物理入力と誤判定する)の修正後に、
`awase-keymap-learn-win`(引数なし、develop `ef4f24f4` 相当)を実機で回した。PowerToys の KeyboardManagerEngine は停止、awase は停止、画面はスリープ抑止(入力なし)。

**症状:** 1段目の格子学習が約 20 秒で `progress cell=73 total=84` に達した後、**`cell=73` のまま 22 分間(1344 秒)進まず**、`eta_ms` は 117 秒 → 196 秒と**伸び続けた**
(約 1.7 秒/10押下のペースで押下し続け、progress 行は約 1160 行)。「非決定的なセルがあるため学習をもう一度実行します(やり直し・1回まで)」の警告が stderr に1回出ている。
手で止めるまで終了しなかった。`keymap-learn-table.json`・`keymap-learn-last-attempt.json` は書かれない。`--trace-walk` 付きで 75 秒回した記録は空(2段目の自己検証ウォークには入っていない)。

**推測(未確認):** この構成では到達できない(状態 × キー)の組み合わせが残り 11 セルにあり、1段目の探索が、押下数の上限に達するまで(または上限なく)そのセルへの到達を試み続ける。
`main.rs` に「縮退が激しい表は予測300歩に固定回数では届かない」旨の上限 `VERIFICATION_WALK_MAX_STEPS=1500` はあるが、1段目(格子)の到達不能セルに対する打ち切りは確認できていない
(CI の windows-latest GJI ATOK では 80 セル × 20 回=1600 件の到達所要押下数の上限があり完走している)。

**影響:** 実機で学習表が作れず、v2 の設計思想(学習して IME ON の効果を持つキーを追随)がこの構成では使えない。学習中は実機の入力を占有する(22 分間、入力不能)。

**残作業:** (1) 1段目の押下数・時間の上限と、到達不能セルの打ち切り(理由をログに出す)の確認と実装。(2) どの11セルが未到達か(`--trace-walk` ではなく格子の記録)を出す診断。
(3) 「表が不完全でも、到達できたセルだけで暫定採用する」経路が要るか(ADR-196 の採否条件との関係)。実測は 2026-09-30 の実機ログ(`learn.out.keep`、実機の `C:\Users\cuzic\`)。
