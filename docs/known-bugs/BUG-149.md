# BUG-149: TsfNative(Chrome)でconvだけ変わるモードキーにEngineが追随しない

**発見経緯:** ADR-186の未検証だったTsfNativeを、`chrome_probe`（`spike/ime-key-matrix`、Chrome専用プロファイル+検証ページ+
`SendInput`、打った文字で状態を判定）で測定（2026-09-20）。**未修正・原因は一部のみ特定。**

**症状:** 実IMEがかな→半角英数(conv 0x19→0x10、開閉は不変)になっても、awaseのEngineはONのまま。`k`,`a`を打つと
NICOLAが`き`,`う`のromajiを送り、半角英数のIMEにそのまま`kiu`と入る（期待は`ka`）。要件「英数=Engine OFF」に反する。
**再現:** awase起動中のChromeで、かなONから (a)ひらがなキー(0xF2) または (b)Shift+無変換 を押し、0.5秒後に`k`,`a`。

**測定（Chrome、awase起動、8ケース×3周=24）:** 無変換/変換のON/OFF（かな→OFF、OFF→かな）とShift+無変換のOFF中は全18件PASS。
**かな→半角英数の2ケースだけ、3周とも3/3失敗**（計6/6）。awase停止の対照は24/24 PASS（GJI自身はChromeで正しく半角英数になる）。
待ちを2秒に延ばしても2/2失敗×2ケース(4/4)で、時間経過では直らない。

**awaseログでの観測:** ひらがな押下の29ms後の再読み取りは`[stage-observe] strategy=SkipTyping ... typing active (idle=32ms)`で
スキップされ、`explicit_intent=Some(true)`が記録される。2秒後の最初の打鍵で、`idle-conv-check`(`src/engine/idle_check.rs`の
ガード条件は満たすはず)の読み取り・`Engine deactivated`は**ログに出ない**（Chromeのconvは`[cold-diag] pre-send conv=`で
読めているので、読み取り自体は可能）。なぜ`idle-conv-check`が走らないかは未確認。

**否定できた仮説:** 「明示IME操作の抑止窓(`EXPLICIT_IME_SUPPRESS_MS`=1500ms)を過ぎれば`idle-conv-check`が追随する」（2秒待っても不変）。
**Win32 EDITでは同じ操作で追随する**（IMM再読み取りが効く）。差はTsfNative側の再読み取り経路。

**方針候補（未決定、設計判断）:** (1) convを変えるキー(0xF2、Shift+無変換)の後に、抑止窓と無関係な遅延再読み取りを1回足す、
(2) ADR-186決定3(予測反転)。ADR-184の反省（型・フィールドを積まず最小の配線変更で）に沿い、まず`idle-conv-check`が
Chromeで走らない理由を特定するのが先。
