# BUG-149: TsfNative(Chrome)でconvだけ変わるモードキーにEngineが追随しない

**状態(2026-10-04、v2.0.0 時点):** 未修正(CI で再現、2026-10-04) — 症状側の修正は未確認。ADR-188(遅延conv読み取り、Chrome向け)は status が「ドラフト・未実装」のまま、`is_effectively_tsf_native`/`is_tsf_native_window`(Chromeを含まない)の入口も現存。ADR-191 の `is_followed_mode_key`(`vk.rs`)による通過後追随がChromeのかな→半角英数にも効くかは、ADR-191 status が TsfNative(Chrome)を「実機未確認」とする通り裏取りできていない。`chrome_probe` での現行 develop 再測定が必要。

(以下は当時の記述)

**発見経緯:** ADR-186の未検証だったTsfNativeを、`chrome_probe`（`spike/ime-key-matrix`、Chrome専用プロファイル+検証ページ+
`SendInput`、打った文字で状態を判定）で測定（2026-09-20）。**未修正・原因は一部のみ特定。**

**症状:** 実IMEがかな→半角英数(conv 0x19→0x10、開閉は不変)になっても、awaseのEngineはONのまま。`k`,`a`を打つと
NICOLAが`き`,`う`のromajiを送り、半角英数のIMEにそのまま`kiu`と入る（期待は`ka`）。要件「英数=Engine OFF」に反する。
**再現:** awase起動中のChromeで、かなONから (a)ひらがなキー(0xF2) または (b)Shift+無変換 を押し、0.5秒後に`k`,`a`。

**測定（Chrome、awase起動、8ケース×3周=24）:** 無変換/変換のON/OFF（かな→OFF、OFF→かな）とShift+無変換のOFF中は全18件PASS。
**かな→半角英数の2ケースだけ、3周とも3/3失敗**（計6/6）。awase停止の対照は24/24 PASS（GJI自身はChromeで正しく半角英数になる）。
待ちを2秒に延ばしても2/2失敗×2ケース(4/4)で、時間経過では直らない。

**原因(特定済み):** Chromeは`profile=Imm32Unavailable`(`Chrome_WidgetWin_1`)で、`idle-conv-check`の入口
`should_run_idle_conv_check`のガード2(`is_tsf_native`、`AppImeProfile::is_effectively_tsf_native`)は、Imm32Unavailableでは
`is_tsf_native_window(class_name)`(WezTerm/Windows Terminal/XAML系の5クラスのみ、`focus/class_names.rs:51`)に委ねる。
Chromeは含まれず、**黙ってfalse**(このガードにデバッグログは無い)。検証ログ全体で`[idle-conv-check]`は0件
(出ているのは別経路の`idle-conv-check-diag`=`ime.rs:425`のみ)。加えて、ひらがな押下の29ms後の再読み取りは
`strategy=SkipTyping ... typing active (idle=32ms)`でスキップされる(押したモードキー自身が「入力中」を成立させる)。
つまり**Chromeでは、convだけを変えるキーの後にconvを読みに行く経路が1本も無い**。ただしChromeのconvは読める
(`[cold-diag] pre-send conv=0x00000019`)。待ち2秒でも直らなかったのは、この入口で弾かれるため。

**方針候補（未決定、設計判断）:** (F1) モードキー押下後の再読み取り(20ms)を、押したキー自身による「入力中」判定で
スキップさせない(Imm32Unavailableでもconvを読む)、(F2) `idle-conv-check`のガード2をImm32Unavailableにも広げる
(ただし次の打鍵で読む方式なので最初の1〜2打鍵はEngine ONのまま)、(F3) ADR-186決定3(予測反転)。いずれもChrome全般の
挙動変更(クロスプロセス読み取り、BUG-34/113/33/37の再発ファミリー)で、ADR-184の反省どおり、実機で効果を確かめる
最小のアブレーション実験と敵対的レビューが先。

**追記(2026-09-23、未検証):** 本BUGの核心は「convだけを変えるモードキー(ひらがなキー/Shift+無変換)の後、
Engineが実IME(conv)の変化に追随しない」こと。[ADR-191](../adr/191-ime-is-source-of-truth-observe-not-write.md)
(IMEを状態の正とし、開閉のみに作用するキー以外はawaseが書かず観測・予測に追随する設計転換、PR #240で
develop統合済み)は、まさにこの種のモードキー追随を狙った変更であり、本BUGの症状が既に解消している可能性がある。
ただしADR-191の実機検証範囲はGJI(MS-IMEプリセット)中心で、TsfNative(Chrome)は「未確認」と明記されている
(ADR-191 status節)。着手する場合は先に`chrome_probe`で現行developへの再現確認を行うこと。

**追記(2026-10-04、CI 再現 — `sc-bug149-chrome-*`、run 37187579784):** v2.0.0 相当の develop(c54ddb6d)で、実 Chrome(GJI、awase 起動)に対し chrome_probe 既定の 8 ケース×3 周を測った。awase なしの対照(`-noawase`)は ATOK 24/24 PASS。
- **Shift+無変換(かな→半角英数)**: ATOK・MS-IME 両プリセットで 3/3 FAIL(`k`,`a` が NICOLA 文字=Engine ON のまま)。対照は PASS なので awase 起因。→ BUG-149 は v2.0.0 でも残る。
- **ひらがなキー(かな→半角英数)**: ATOK は 3/3 PASS(元の報告より改善)。MS-IME プリセットは awase の有無に関わらず `か`(GJI 自身が英数にしない)で、判定対象外。
- **別件の疑い**: ATOK でも「かな→無変換=IME OFF」「かな→変換=IME OFF」が 3/3 FAIL(Engine ON のまま、対照は PASS)。BUG-150 を「CI 検証済み」としていたが、実 Chrome の閉じる方向は未解決の可能性(要確認)。
