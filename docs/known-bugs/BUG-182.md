# BUG-182: パニックリセットが非 Imm32 窓で実 IME を開かない

**症状:** IME 関連キー連打のパニックリセット（「状態をリセットしました」通知）後も、Chrome/Edge
（Imm32Unavailable）と TsfNative の窓では実 IME が閉じたままで、`ka` がローマ字のまま入る（BUG-179 と同じ見え方）。

**再現（実機未検証）:** 非 Imm32 窓で belief=ON・実 IME=閉の状態にし、パニックリセットを発動 → `k,a` を打つ。

**原因:** `runtime/mod.rs::panic_reset` の OFF→ON 直列書き込みは `can_use_imm32_cross_process()` の窓だけ。
非 Imm32 窓では belief（`desired_open=true`、`ForceGuard::PanicReset`）を戻すだけで何も書かなかった。
撤去前は、パニック前に Engine が非活性だった場合に限り、次の打鍵の非活性→活性遷移が出す ActivationSync の
SetOpen(true) が（PanicReset ガードの SafetyValve 授権で）実 IME を開いていた。ADR-213 P2b/P2c でそれが
無くなり、また `ImeEvent::PanicReset` が `applied` に触らないため、`applied=Some(true)` が残ると
続く SetOpen(true) も already-matched で省略されうる。Engine が既に活性だった場合は撤去前から直っていなかった。

**修正:** (1) `PanicReset` の reducer で `applied` を未知に落とす。(2) `panic_reset` の非 Imm32 分岐で
`ImeEffect::SetOpen{open:true, press:None}` を `execute_decision`（既存 executor 経路、
`dispatch_ime_set_open`）へ積む。新しい order 起案口・`apply_ime_open_with_view` 呼び出し元は増やさない。
Imm32 窓の OFF→ON 直列実行は残す。

**回帰テスト:** `ime_model.rs::panic_reset_demotes_applied_to_unknown`、
`architecture_guard.rs::panic_reset_non_imm32_branch_queues_set_open`。

**残課題:** `ForceGuard::PanicReset` は期限切れにならない（ADR-213 P6）。ガードが残る間、押下 ID のない OFF
（drift correction 等）は Unwarranted になる。明示操作はガードを消すので影響しない。実機未検証。
