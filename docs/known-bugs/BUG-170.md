# BUG-170: GjiFsm の OffCold 固着 → 毎打鍵 per-VK → StaleConfirm → ESC で「これ」が消える

**症状（report `01M3NBQA8KH2JN6S1PYHP8DJRF`、2026-09-29、GJI、msedge.exe/`Chrome_WidgetWin_1`/`Imm32Unavailable`、Google Meet）:** 「これでいい」→「でいい」。「時々消える」。
報告は `app_version 1.21.0` だが journal に `ImeOpenOutcome::Unwarranted` があり develop 系ビルド。

**原因（journal/awase.log で確認）:**
1. 回帰の起点 `c8bc1adc`（ADR-090 A-2 warrant 強制、v1.21.0 に無い）。物理キーで開いた後の engine `SetOpen` が `Unwarranted` → `NotSent` となり
   `drives_composition_side_effects()` が false で `on_ime_applied` に届かず、`GjiFsmSync::OnImeOn/OnImeOff` が発行されない。
2. 固着の起点は Windows Terminal での物理 F2（193002、予測 ON+Unwarranted）。以後 `StartComposition(candidate SHOW)` が OffCold のまま観測される（実 GJI は ON）。
3. OffCold は `is_warm()==false` なので全打鍵が cold 経路（`prepend_f2_warmup=true` 13回・`false` 0回、cold_seq 53→78）を通る。**cold-start 保護が効かなかったのではなく毎打鍵かかっていた。**
4. 報告された消失は4回目（215324〜）: 「で」で StaleConfirm（`per_vk_recovery_params(true, idx=1)→escape=true`、log 723/735/737）→ `VK_ESCAPE` が未確定の「これ」まで取り消す。
別経路として `sync_ime_kind_from_observation` が GjiFsm を作り直す（OffCold）ときも同じ固着が起きうる（applied がほぼ更新されないため）。

**修正（ADR-203、実機未検証）:**
- (i) `WindowsPlatform::send_keys` の冒頭で、ローマ字を送るのに GjiFsm が OffCold なら belief 起点で ON 同期（`needs_belief_sync_on`。Unicode モード・probe/recovery 実行中は除外）。
- (ii) 物理キー予測 ON・shadow toggle ON・`sync_direction` の on キーで `GjiEvent::Reopen`（OffCold→ImeOn、OnWarm→OnCold、OnCold/OnComposing は何もしない、候補窓可視なら出さない）。OFF は同期しない。
- 同期由来の StartProbe では Unicode long-cold の reinit を行わない（`GjiSyncOrigin::BeliefSync`）。

**回帰テスト:** `gji_fsm.rs`（Reopen 遷移表・固着の再現）、`state/gji_direct_mechanism.rs`（`needs_belief_sync_on` 全数・`reopen_obligation`）、
`architecture_guard::gji_fsm_sync_entry_points_are_accounted_for`（入口件数固定）・`user_ime_on_paths_are_paired_with_gji_reopen`。windows-latest の e2e は未整備（ADR-203 検証方針）。

**残る別バグ:** StaleConfirm→ESC が途中の語で既存の未確定文字を消す問題は GjiFsm を直しても残る → [BUG-171](BUG-171.md)。

**PR #354 の Opus コードレビュー（2026-09-29）での追補**（M1/M2/L1〜L5 は同日のフォローアップ PR で修正、M3/M4 は下記の既知の穴として残す）:
- 修正済み: (i) の送信判定が `KeySequence`（全角記号 `，` `－`）と `Sequence` の中身を見ていなかった(M1、`send_carries_romaji`)。Unicode モードで Reopen すると long-idle 後に awase 起点の VK_IME_ON poke が出る(M2、推測)。**対応を一度入れたが取り下げた**:
  e2e-ime-smoke の baseline/atok-passthrough-cold は Unicode モードで動き、Unicode で Reopen を出さないと GjiFsm が OffCold に固着して I4 が FAIL した(PR #357 の CI、baseline 2 件・atok-passthrough-cold 7 件)。
  poke は Unicode long-cold の既存設計で、同期が正常なら元から起きる挙動。trigger 名を入口別に(L1: `predict`/`shadow-noop`/`shadow-toggle`)、再帰で origin を捨てていた(L4)、`debug_assert!` が FSM 更新後にあった(L5)。
- **残る既知の穴(M3)**: 予測経路の Reopen は `PredictedEffect.open` が「変化するときだけ `Some`」なので、belief が既に ON の ON キー(0x16/0xF2 等)では出ない。OFF が belief にも GjiFsm にも届かなかった後の
  予測経路キーでの ON は、GjiFsm が OnWarm のまま最初の1語が warm 経路で即送信される(BUG-002 型のリテラル化の余地)。shadow toggle の no-op 分岐(`TurnOn`)では Reopen が出る。実機で問題が出たら、予測に
  セルの `after_open` を持たせて拾う。
- **残る既知の穴(M4、推測・実機未確認)**: 「入力中」の判定が候補窓の可視性だけ。GJI のサジェスト窓を出さない設定のユーザーでは、入力中に shadow toggle の `TurnOn` キーで Reopen が走り、次のモーラが
  per-VK→StaleConfirm→ESC で未確定文字を消す(BUG-171 型)可能性がある。`ime_composition_active_now()` や `key_track().stage` を OR で足すのが候補(実機で `EVENT_OBJECT_IME_SHOW` の有無を確認してから)。

## 実機検証（2026-09-30、dragonflyg4、GJI、Windows Terminal/Chrome、develop `a0ac0def`）

修正前ビルド(`e174c6f6`)で同じ固着を再現（Ctrl+無変換で IME OFF → 物理 F2 で開始 → `[apply-ime] open=true → Unwarranted` → 以後の語ごとに `StartComposition while engine off — ignored`、`stale confirm 検出 … escape=true` で入力途中の文字列が消え、打ち直しで「っ」等が混入。不具合報告の提出は無く、利用者の口頭報告と実機 awase.log による）。`a0ac0def` に差し替えて Ctrl+無変換→F2 を 12 組、連続打鍵 273 キー出力で確認: OFF/F2 の各組で `Reopen from OffCold … → Short|Long` が1回ずつ出て、`while engine off`・`stale confirm 検出`・`raw-tsf-literal`・`cold パスだが GjiFsm に Authorized probe が無い` はいずれも 0 件。物理 F2 直後の `Unwarranted`（20件）は従来どおり出るが、固着しなくなった。**消失は BUG-171 の経路（StaleConfirm→ESC）で起きていたため、本バグ修正で止まったのは引き金の固着のみ**（下記）。
