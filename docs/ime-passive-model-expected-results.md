# 受動モデルの期待結果（設計から導く、撤去の合否基準）

[ADR-191](adr/191-ime-is-source-of-truth-observe-not-write.md)（IMEを状態の正とし、awaseは書き込まず観測に追随する）へ
設計を転換している最中なので、撤去の合否を「**撤去前と同じ挙動か**」で決めてはいけない。旧挙動には、
ADR-191 が誤りとして測定した部分（awase 経由で仕様から外れた31件）が含まれ、そこは**変わるのが正しい**。
本書は、設計から「この操作をしたらこうなるはず」を導いた期待結果と、その測り方を定める。
検証の手段（CI・実機・純粋テスト）は [teardown-verification-guide.md](teardown-verification-guide.md) を参照。

**位置づけ**: ADR-191 は草案（opus敵対レビュー round3 待ち）。ADR が変わったら本書を追随させる。
実機で確かめていない行には「（未確認）」を付けた。期待が実測とずれたときの扱いは §6。諦める範囲は §4。

## 1. 合否の3つの基準

| 基準 | 内容 | 旧挙動との関係 |
|---|---|---|
| A. 設計の不変条件 | ADR-191 の決定から導いた、常に成り立つべき性質（§2） | 旧挙動に依らない |
| B. IME単体との一致（透過性） | awase 有りの実IMEの推移が、awase 無し（同じキー列）と一致する | 旧挙動に依らない。**仕様そのものが正解** |
| C. 意図した変更 | 旧挙動から**変わるべき**点と、変わった後の期待（§3） | 変わることが合格 |

既存の判定器は、`check_consistency.py`（実IMEのかな=Engine ON、英数・直接入力=Engine OFF）と `check_toggle.py` が
基準 A、`check.py` の `EXPECT`（ATOK前提の期待表）が旧設計（ADR-186）の期待である。**撤去後は `EXPECT` を基準に使わない**（§8）。

## 2. 不変条件（基準A）

適用範囲は原則として「IMEの状態をIMMで読めるアプリ」（ADR-191 決定1）。TsfNative は INV-7 で別に扱う。

| # | 不変条件 | 根拠 | 測り方 | 判定器 |
|---|---|---|---|---|
| INV-1 | **透過性**: 例外キー（INV-4）を除き、awase 有りの実IME（開閉・conv・入力中）の推移は、awase 無しと一致する | 決定1 実測2（Bで仕様から外れたのは awase の書き込みのため） | 同じ `--seq`/`--walk` を `awase=true` と `awase=false`（`*-noawase`）で回し、押下ごとの実IMEを比べる | **空白**（`*-noawase` は `observe` で表に出すだけ。比較器は `effect_learning.py --compare`（未マージ）に近いものがある） |
| INV-2 | **追随**: 実IMEのかな=Engine ON、英数・直接入力=Engine OFF。各押下の後、一定時間（下記）以内に成り立つ。**ただし、表が「IME内部状態に依存する」と判定したキーは除く（§4）** | 決定1・3 | 押下の700ms後に打つ `k` の扱い（`PassThrough`=OFF）で Engine を読む | `check_consistency.py`（既存） |
| INV-3 | **書き込みの最小性**: 例外キー以外の打鍵で、awase は IME 状態を変える送信をしない | 決定1（書いてよいのは開閉のみに作用するキー）・決定5 | awase.log の `[shadow-send]` 行（`channel=ImeControl`、および `channel=SendInput` の actuation 種別）を、押下ごとに数える | **空白**（ログは出ているが、数える判定器が無い） |
| INV-4 | **例外の限定**: awase が書いてよいのは、①冪等な `VK_IME_ON`/`VK_IME_OFF`（`keys.ime_on/off`、単独打鍵の `"on"`/`"off"`）、②トグルキー（ADR-189: 0x19/0xF3/0xF4、`keys.ime_toggle`）だけ | 決定1 | INV-3 の送信の内訳が①②に収まること | INV-3 と同じ（空白） |
| INV-5 | **打鍵を失わない**: 物理キーを Suppress したなら、同じ効果の書き込みが必ず伴う。belief が低信頼（`applied` が Unknown）のときは Suppress せず素通し | 決定1 書き込みの規則 | Suppress した押下について、同じ押下に `[shadow-send]` があるか。低信頼状態から押して、実IMEが変化するか | **空白** |
| INV-6 | **フォーカス**: 新しい窓のフォーカス直後、awase はその窓の IME へ書かない。belief は観測で新しい窓の実状態へ追随する | 決定1、決定5 P1 | 2窓を用意し、片方を IME ON にしてから他方へ移り、`[shadow-send]` が出ないことと、Engine が実IMEへ追随するまでの時間を測る | **空白**（シナリオ自体が無い） |
| INV-7 | **TsfNative**: 状態を読まないので INV-2 は要求しない。代わりに、①トグルキーは書き込みで反転しEngineが追随、②強制ON/OFF打鍵（`keys.ime_on/off`）で実IMEとEngineが同期する | 決定1（ADR-189 は残す）、TsfNative 節 | ADR-193 の RichEdit スーパークラスの入力先（TsfNative 扱い）で押す | **空白**（CI未配線） |

**INV-2 の待ち時間**: 現行の判定は各押下の +1500ms で実IMEを読み、700ms 後の `k` で Engine を読む。ADR-191 の
「観測に追随」がどれだけ速く成立すべきかは、まだ決めていない（compartment 通知は 2〜5ms、ADR-193 のプローブで実測）。
**決めずに 1500ms を維持し、遅い追随が見えたら値ではなく原因を調べる**（`tuning-constants` と同じ考え方）。

## 3. 旧挙動から変わるべき点（基準C）

ADR-191 実測5の「Bで仕様から外れた31件」は、撤去後は**仕様どおり**になるべき。旧設計の期待表は、ここで書き換わる。

| 旧挙動（awase の書き込みで決まっていた） | 撤去後の期待（IME仕様どおり） | 撤去する機構 |
|---|---|---|
| ひらがな(0xF2)を IME OFF で押すと ON になる（11件、`0xF2 => Activate`固定） | **GJI(ATOK)**: DirectInput では何も起きない（OFFのまま）。**MS-IME プリセット**: 開く。awase の書き込みは 0 件 | `shadow_effect` の静的決め打ち |
| 入力中の無変換/変換で IME が OFF になり未確定が消える（9件、単独タップ代行） | **ATOK**: 入力中の無変換は IME の仕様どおり（半角英数トグル／変換）。未確定は残る。書き込み 0 件 | 単独タップ代行（`*_delegate_to_open_axis`） |
| 半角/全角を ON・英数で押しても閉じない（7件、方向固定） | ADR-189 のトグルで**反転**する（develop では直っている見込み、要再測定） | 方向固定（ただしトグル自体は**残す**） |
| 入力中（英数）の Esc/無変換が仕様どおりにならない（4件） | 変わらない。IME側（Conversion/Suggestion/Prediction の状態）の挙動で、awase 無しでも出る。**期待に含めない（`observe`）** | — |
| モードキー直後の20ms再読み取りが typing-idle ガードで読まれず、Engine が追随しない（BUG-151） | 追随する。cold（awase が一度も書いていない）でも成立する | `shadow_action` を持つキーだけを追随対象から外す条件 |

## 4. 諦めること（表が決める）

「諦めるキー」と「諦めないキー」は、キー名や VK で**決め打ちしない**。**GJI の設定の取得フェーズ（表S）と学習フェーズ（表L）が決める**
（ADR-191 決定1・3・4、ADR-192 決定1）。**IME 内部状態が要らずに効果を決定できるキーは、諦めない。**
諦めるのは、決定できないキーだけで、その操作ではモードずれ（実IMEと Engine の不一致）が起こりうる。**諦めるのは「100% の保証」であって、追う努力ではない**（§4.6 の第2段階）。この領域のテストが失敗しても、直ちには撤去の不合格とは扱わない（§4.7）。

### 4.1 判定の基準

- **IME 内部状態**: 入力中（Composition）・変換中（Conversion）・サジェスト/予測の候補窓（Suggestion/Prediction）。awase が確実には知れない状態。
  awase が belief として持つ（開閉・かな/英数）は含めない。
- **決定できる**: キーの効果が（開閉・かな/英数）だけで決まる。内部状態が要らないので、awase は結果を予測でき、**諦めない**。
- **決定できない**: キーの効果が内部状態で変わる。awase は押下前に結果を確定できない。**諦める**（追随は試みるが保証しない）。

### 4.2 どう決まるか

1. **取得フェーズ（表S）**: `config1.db`（`session_keymap`・`custom_keymap_table`・`overlay_keymaps`）と Mozc の公開キーマップを、**全 status**
   （DirectInput/Precomposition/Composition/Conversion/Suggestion/Prediction）へ展開する。全ての開状態で同じコマンドなら「内部状態に依らない」。
   1つでも状態で違う・未割当があれば「依存」（2状態だけ見て判定しない。ADR-191 の状態完備の教訓）。
   MS-IME 本体は公開キーマップが無く、レジストリで判定できる範囲だけ。
2. **学習フェーズ（表L）**: awase を完全にバイパスした注入で（状態, キー）→効果を測る。状態に**入力中**を含める。セルが決定的で、入力中の有無で効果が変わらなければ「決定できる」。
   非決定のセルや、入力中で効果が変わるセルは「依存」。
3. **突き合わせ**: S と L が一致すれば採用する。食い違えば**実測（L）を採り、諦める側（書かず追随）に倒す**（ADR-191 決定1）。
   S が作れない・L が未実施・未知のセルも、諦める側に倒す（疑わしきは決定できるとしない）。

判定は**設定ごと・ユーザーごと**に変わる。同じ「無変換」でも、カスタムキーマップで全 status に `IMEOff` を割り当てていれば諦めない。

### 4.3 判定の結果（キーの判定 × アプリ）

| キーの判定 | IMM で読めるアプリ | 観測できないアプリ（TsfNative 等） |
|---|---|---|
| 決定できる・開閉のみ・**Set型**（冪等） | 諦めない。awase が書く。INV-2 が成り立つ | 諦めない。書き込みで成り立つ（INV-7 の②） |
| 決定できる・開閉のみ・**トグル** | 諦めない。belief に基づいて書く（低信頼なら素通し） | 諦めない。同じ（ADR-189、観測に依存しない。INV-7 の①） |
| 決定できる・**入力モードを変える**（ひらがな等） | 諦めない。書かず、生キーを通して表の予測と観測で追随する | 表の予測で追随（ADR-188 の範囲）。**（未確認）** |
| **内部状態に依存する** | **諦める**。観測で追随を試みるが保証しない | **諦める**。保証しない。強制ON/OFF打鍵で同期する |

表に依らず、**アプリ側の理由で諦める**ものが1つある: 観測できないアプリで、窓を切り替えた直後の初期 belief（窓ごとの IME 状態を読めない。
最初のずれを受け入れ、強制ON/OFF打鍵で同期する。ADR-191「窓を切り替えた直後の初期belief」）。

### 4.5 諦めた結果のユーザー側の回避

回避は「内部状態に依るキーを、依らないキーに置き換える」こと。

- 親指キーの単独打鍵の挙動を awase 側で決める（既存の `muhenkan_solo_tap_ime_action` / `henkan_solo_tap_ime_action`、`keys.ime_on/off/toggle`。ADR-153・ADR-192 決定3）。
  awase が物理キーを消費し、冪等な `VK_IME_ON`/`VK_IME_OFF`（トグルは belief 基づき）で書くので、IME 側の状態依存の割り当ては届かない。
- IME 側のキーマップを冪等なキー（変換=IME ON、無変換=IME OFF など）へ変更する。awase は `config1.db`・レジストリを書き換えない（ADR-192 決定4）。

**後続の作業（今は作らない）**。撤去が頭打ちになってから別 ADR で扱う（ADR-191 決定5: 追加は撤去と対）。

1. **設定 UI での親指キー挙動の上書き**: awase-settings から、無変換/変換の単独打鍵の挙動（IME ON/OFF/トグル）を awase 側で上書きできるようにする。
   既存の設定項目を UI から書くだけで、新機構は作らない（ADR-192 決定3の具体化）。
2. **doctor ボタン**: 押したときに、「どの設定をどう直さないとモードずれが起きるか」を診断して表示する。
   **表示の中身は、§4.2 の判定で「決定できない」とされたキーの一覧そのもの**にする。判定の源は ADR-192 決定1（状態依存の検出）と同じ表S・Lから引く
   （実装を1つにするかは後続で決める）。ADR-192 の警告（決定2）は起動時・設定リロード時に一度だけ出す形で、オンデマンドの診断は現行 ADR-192 に無い。
   **ADR-192 への追記（または別 ADR）が要る**。出す内容の案: 該当キー、IME プリセット、（状態→コマンド）の対応、ずれが起きる具体的な操作、推奨する置き換え、影響するアプリ種別。
   検証は ADR-192 の検証計画（GJI の各キーマップの TSV と検出結果の突き合わせ、Linux で走る単体テスト）に従う。

### 4.6 保証の2段階（100% と、一定以上）

キーの判定（§4.2）に応じて、テストの厳しさを2段階に分ける。

| 段階 | 対象 | 予測に使うもの | 保証 | テスト | 実行場所 |
|---|---|---|---|---|---|
| **第1段階** | 「決定できる」キー（諦めない領域） | awase が持つ状態（開閉・かな/英数）・キー・プリセットだけ。**純粋関数** | **100%**。1セルでも外れたら実装のバグ | 状態×キー×プリセットの**全セルを列挙する網羅テスト**。実機ログもリプレイも要らない | Linux |
| **第2段階** | 「決定できない」キーのうち、入力中・変換中を**打鍵履歴から追う**領域（`KeyTrack`） | 上に加えて、履歴から推定した隠れ状態（入力中の段階） | **一定以上**。100% は要求しない | 実IME の観測に対する**リプレイ**で、一段予測の正答率が閾値以上 | Linux |

第2段階で追っても決まらないセル（履歴を追っても非決定）は、**予測しない（`None`）**とし、観測に任せる。追跡の対象外なので、率の分母に入れない（ただし、そのセルの数は網羅の状況として記録する）。

**第1段階の網羅テストの中身**:
- 全セルで、`predict` の結果が表の値と一致すること。「決定できる」セルで `None` を返さないこと。
- 表S（Mozc の公開キーマップ）と表L（学習結果）を全セルで突き合わせ、一致したセルだけが第1段階に入ること。食い違うセルは、実測（L）を採って第2段階以下に落ちること（§4.2 の3）。この落とすロジック自体をテストする。
- awase の belief 更新（`ImeModel` の `reduce`）が、予測・観測の各イベントで正しく遷移すること（これも純粋関数の単体テスト）。

**第2段階のリプレイテストの中身**:
- フィクスチャ: awase 無し（A'）の `--walk` で取った、プリセット、キー列、押下ごとの実IME（開閉・conv・入力中の有無）。正解は**実IMEの観測**（旧 awase の挙動ではない）。
  **表の学習に使っていない別シードのラン**を使う（同じデータでは、表が元データを再現することしか言えない）。
- 指標は**一段予測の正答率**（押下前の実状態を与えて、押下後の開閉・conv・入力中の有無を当てる）。ADR-191 実測2の未見データでの先例は 98.5%（仕様モデル、`atok.tsv` の転記）と、
  学習表の既知セルで 95.2〜98.8%（いずれも第2段階に限った値ではない）。**開ループ（最初の状態だけ与えて連鎖させる）は指標にしない**
  （連鎖の再同期の回数に強く依存し、条件間で単調でないと ADR-191 が判定している）。
- **閾値の決め方**: 値を先に決めない。まず未見データで実測し、「`KeyTrack` を使わない（`None` で観測任せ）場合」との差を出す。
  実効標本はセル数（約40）に近く小さいので、**絶対値の目標より、記録した値を下回らない（ラチェット）**を主にする。
  `KeyTrack` が上回る幅が小さいなら、その機構は撤去の候補になる（ADR-191 決定5）。
- リプレイの入力は、既存の `ConvClassifyFixture` と同じ形式の新しいフィクスチャ（キー効果用）を足す。既存の `journal_replay`・`actuation_decision` コーパスは使えない
  （前者は conv ビットの分類だけ、後者は記録値をそのまま残す characterization corpus で、正解データではない）。

**I/O 側はこの2段階の外**: Suppress/Allow の判断（`transport.rs::plan`）と実際の書き込み、追随のタイミングは、CI 実機E2E（INV-2/3/5）の担当。
論理は第1段階で網羅済みなので、実機は代表ケースの確認で足りる。

### 4.7 テストでの扱い

- **期待は表の判定から引く**。表が「決定できる」としたキーは INV-2 を満たすこと（`expect=pass`）、「決定できない」としたキーは `expect=observe`（ずれの回数を記録するだけ。第2段階のリプレイが率を見る）。
  構成の期待を手で決め打ちしない。較正基盤（未マージ）で表から生成できるようになるまでは、手で `pass`/`observe` を付け、根拠の表の行を構成の横に書く。
- 対にして、**回避設定を入れた構成は `expect=pass`** で固定する。例: 「決定できない」と判定された ATOK の親指キーの構成と、同じプリセットで `*_solo_tap_ime_action` を設定した構成。
  「諦めた範囲」と「回避すれば満たせること」が両方 CI で見える。
- 現状 `pass` の構成（`atok-passthrough*`）を `observe` へ緩めるのは、撤去した機構が担っていた追随が実際に失われた場合に限る。先に緩めない（撤去の副作用を見逃すため）。

## 5. 期待結果の例（IMEの状態 × キー）

「実IME」は IME 単体の仕様（Mozc の公開キーマップ、`atok.tsv`/`ms-ime.tsv` と実測）、「書き込み」は awase.log の
`[shadow-send]` の件数（INV-3）。Engine は INV-2 から決まる（かな=ON、それ以外=OFF）。

| プリセット | 状態 | キー | 実IME（期待） | awase の書き込み | 備考 |
|---|---|---|---|---|---|
| ATOK | 直接入力 | ひらがな 0xF2 | 変化なし | 0 | 仕様上未定義。Engine OFFのまま |
| ATOK | ON・かな | ひらがな 0xF2 | ON のまま半角英数へ | 0 | `ToggleAlphanumericMode`。Engine は OFF へ追随 |
| MS-IME | 直接入力 | ひらがな 0xF2 | 開く（かな） | 0 | Engine は ON へ追随 |
| MS-IME | ON・かな | ひらがな 0xF2 | 閉じる | 0 | Engine は OFF へ追随 |
| ATOK | 入力中 | 無変換 | IME仕様どおり（**未確定を破棄・OFFにしない**） | 0 | Mozc の Composition 状態のバインド。**（未確認: Conversion 系は `observe`）**。ATOK の親指キー（無変換/変換）の単独打鍵は、§4.4 のとおり表で「内部状態に依存」と判定される見込みで、Engine の追随は諦める範囲 |

**1行ずつ「期待」を先に決めておくのが目的**で、この表が実測とずれたときの扱いは §6。行の追加・変更は ADR-191 と一緒に行う。

## 6. 期待が実測とずれたとき

どちらが間違いかは、**awase 無しの結果**で決める（IME単体の仕様が正解）。

1. awase 無しでも期待とずれる → **期待表が間違い**（IMEの仕様の読み違い）。表を直す。ADR-191 実測の「Conversion/Suggestion/Prediction の
   状態を持たない仕様モデルの限界」は、この型（表に `observe` を付けて保留）。
2. awase 無しでは期待どおりで、有りだとずれる（INV-1違反） → **実装がバグ**。awase が書き込んでいるか、追随が遅れている。
   `[shadow-send]` の有無で切り分ける（書き込みが有れば INV-3/4 違反、無ければ観測の追随不良）。
3. 期待表も実装も正しいが、設計が想定していなかった状態がある → **ADR-191 を更新**（TsfNative の「観測できないアプリのずれは受け入れる」など）。
   期待表の変更は、必ず ADR とセットで行う。

## 7. 撤去候補ごとの「撤去後の期待」

| 撤去候補 | 撤去後の期待 | 合否の測り方 |
|---|---|---|
| フォーカス変更時の強制OFF | フォーカス直後に `[shadow-send]` が出ない。belief が OFF で新しい窓の実IMEが ON のとき、Engine は観測で ON へ追随する | INV-6 のシナリオ（**要新設**）。追随に要する時間を測り、上限を決める |
| `shadow_effect`/`shadow_action` の決め打ち | §3 の3行が仕様どおり。INV-1/3 が成り立つ | `sc-*`・`atok-*`・`msime*` に INV-1/3 の判定を足す |
| 単独タップ代行 | 入力中の無変換で未確定が消えない。書き込み 0 件 | `atok-optin` 系。旧設定 `gji_thumb_key_ime_toggle` は構成ごと削除 |
| `dbe_mode_key_policy` | 設定の意味は「素通し（IMEに任せる）」に一本化されるか、設定ごと消える | ブランチの決定（設定UIの撤去が未実装）に従い、`sc-dbe-*` の suppress/passthrough を整理 |
| `ir_apply_drift_correction` | 設計が定まっていない。撤去するなら「TsfNative のずれは受け入れ、強制ON/OFF打鍵で同期する」が期待（ADR-191 TsfNative 節） | INV-7 の②。**撤去するか残すかの判断が先** |
| idle-conv-check・eisu reset | Win32 では使われず、Win32 の期待は変わらない | Win32 では測れない。TsfNative 相当の入力先（INV-7）が要る |

## 8. 既存の判定・構成の見直し

撤去が進むと、旧設計を前提にした判定・構成が**壊れるのではなく意味を失う**。撤去コミットと同時に見直す。

- **`check.py` の `EXPECT`**: step 5 の `delegate_false`（単独タップ代行が false を送る）や、step 1/7 の「Engine が 300ms 以内に
  deactivated」は旧設計の期待。撤去後は使わず、`check_consistency.py`（INV-2）に一本化する。
- **`e2e-ime.yml` の `mutator` 構成（a1〜a7）と `e7-toggle-false`**: ミューテーターは撤去箇所の文字列を探して置換し、
  見つからないとワークフローが失敗する（コードが動いた合図）。対象コードが撤去されたら**構成ごと削除**し、
  必要性の確認は INV の判定に置き換える。削除した行数は撤去量に数える。
- **`expect=fail` の意味**: 旧設計では「この機構を消すと壊れる」（必要性の固定）だった。受動モデルでは、機構を消すこと自体が目的なので、
  `fail` は「消してはいけない例外」（ADR-189 のトグルなど）にだけ残る。
- **`*-noawase`**: `observe` のままにせず、INV-1 の比較の**片側**として使う。

## 9. 用意すべき判定器（追加の順）

撤去量が主目的（ADR-191 決定5）なので、判定器は最小にする。

1. **第1段階の網羅テスト（§4.6）**: `predict` と belief 更新を全セルで検証する純粋関数のテスト。実機もフィクスチャも不要で、最も安く、100% を要求できる。
2. **第2段階のリプレイテスト（§4.6）**: 未見データの A' walk をフィクスチャにし、一段予測の正答率がラチェットを下回らないことを見る。`KeyTrack` の効果は、追跡なしとの差で示す。
3. **書き込み数の判定（INV-3/4/5）**: awase.log の `[shadow-send]` を押下ごとに数え、許可リスト（例外キー）と突き合わせる。
   スパイクの押下時刻と同じ時計で取れるので、`check_consistency.py` の `parse_engine` と同じ形で足せる見込み。
4. **透過性の比較（INV-1）**: `awase=true` と `awase=false` の同じ列の実IME推移を比べる。
5. **フォーカス切替シナリオ（INV-6）**: teardown-verification-guide §8-1 と同じ。
6. **TsfNative 相当の入力先（INV-7）**: ADR-193 の RichEdit スーパークラスの CI 配線。
