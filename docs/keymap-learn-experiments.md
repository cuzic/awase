# 学習(awase-keymap-learn)の実験ログ

キー効果の学習(ADR-195/196、`crates/awase-keymap-learn`・`crates/awase-keymap-learn-win`)の
速度と精度を上げる試行の記録。[experiments.md](experiments.md)(IME 制御まわり)と同じ目的で、
**一度捨てた案を別のセッションで盲目的に再試行しない**ために、採用・却下の両方を実測つきで残す。

- 環境の表記: 「GJI ATOK」「GJI MS-IME」= Google 日本語入力のキーマッププリセット(session_keymap 1 / 2)、
  「MS-IME 本体」= Microsoft IME(TIP)。実機はすべて GitHub Actions の windows-latest。
- 精度は独立ウォークの自己検証(ADR-195 段階2)。**同じ設定でも実行間で 0.94〜0.99 動く**ので、
  2〜4 回ずつの精度差は参考程度。割れるセル数・押下数・時間のほうが信頼できる。
- 診断の再現方法: `--trace-features`(押下ごとの特徴量)と `KEYMAP_LEARN_DEBUG_TOUR=1`(同期喪失・未達セル)、
  分析は [tools/keymap-learn/analyze_features.py](../tools/keymap-learn/analyze_features.py)、
  実機は `ci/keymap-learn-trace-*` ブランチへの push で `keymap-learn-trace-{gji,native}.yml` が走る。

## 教訓

- **同じデータで特徴量を選んで同じデータで評価しない。** 学習中の押下だけで表を作り、検証ウォークで採点する(実際の採否と同じ条件)。「予測できた割合」も併せて見る(直前キーを足すと、正答率は上がるが予測できる押下が半分になる)。
- **待ち時間を変える実験は、待ちの位置と通知の猶予窓に注意。** 待ちを押下前の状態を読む前に置かないと表が古い状態で汚れ、遅れて届いた通知が「外部書き込み」と数えられて確かめたい押下ほど捨てられる。
- **精度の実行間ばらつき(0.94〜0.99)は改善幅より大きいことがある。** 割れるセルの数・押下数・時間で判断し、精度は複数回の平均とばらつきで報告する。
