# ADR-262: 観測の無い窓で、親指シフトの打鍵を意図の証拠にして IME ON を明示する

## ステータス

起草(2026-10-16)。実装なし。測定もまだ無い。

## 背景

- 報告(一太郎・GJI、issue #623)では、窓内の IMM が読めない窓(`ImmCapability::Unavailable` と学習された窓)で、別アプリで IME OFF にして一太郎へ移ると
  `HwndCache` の古い ON が復元され、belief が実機とずれる。読めないので、ずれを証拠で直す手段が無い。
- [ADR-260](260-eisu-toggle-no-mode-prediction-when-observable.md) は読みが効く窓にしか効かない。[ADR-261](261-taskbar-indicator-glyph-observation-for-unreadable-windows.md) は
  タスクバーの字形で状態を読む案だが、一太郎でインジケーターが実状態を映すかが未測定で、go/no-go が立っていない。
- 一太郎での追随失敗の根本原因は分かっていない(belief が違うのか、書き込みが届かないのか)。所有者は一太郎を持っていない。

## 着想

状態が読めないなら、打つ人の意図を使う。親指シフトで打つ人は、無変換/変換(親指キー)を含む同時打鍵をする。英数で打つ人はしない。
最初の同時打鍵が成立した時点で、「この人は親指シフトで打つつもりだ」と確実に言える。7 打鍵や 2.5 秒の統計を待つ必要は無い(待つ案は所有者が撤回済み)。

## 決定

### D1: 証拠は「親指キーを含む同時打鍵の成立」だけにする

- 親指キーが無いことは英数の証拠にしない。統計(キー位置のバイグラム等)は使わない。判定の誤りで英語を打つ人の IME を ON にする害を避けるため、非対称にする。
- 親指キーを含まない単打(NICOLA にもある)は証拠にしない。既存の同時打鍵待ちの窓を超えて保持しない。
- 証拠は、プラットフォーム層が分類したイベントとして core に渡す(core で生の VK を見ない。`docs/layer-boundaries.md`)。

### D2: 動くのは次の全部を満たすときだけ

1. 観測の無い窓であること。具体的には `ImmCapability::Unavailable` と学習された窓。**TSF ネイティブの窓すべてではない**
   (ADR-260 の実測では、`tsf` フォームと実 Chrome は `[direct-follow]` で約 25ms で追随する。読める窓に動かすと、ADR-208 の押下 ID と二重になる)。
2. 窓切替直後、または無操作が続いたあとの、最初の証拠であること(エピソードごとに 1 回だけ。ラッチ)。閾値は段階 0 のログから決める(今は決めない。`tuning.rs` の定数は実測を添える)。
3. 利用者が直前に明示の IME キーを押していないこと(押したなら意図は明示されている)。

### D3: 証拠は観測ではなく意図なので、belief に入れない

`.claude/rules/ime-belief-architecture.md` の「禁止パターン 2: 観測を偽装した内部補正」に当たらないよう、`ObservationSource` に新しいバリアントを足さない。
`GjiIoInference`(「変換動作が見えた」という間接観測、一方通行)とは性質が違う。本 ADR の証拠は IME の状態についての情報ではなく、打つ人の意図についての情報である。
動作は「IME ON を明示する order の起案」で、既存の入口 `state/sync_actuation.rs::dispatch_set_open` を再利用する(新しい order 起案入口を増やさない。
増やすなら押下 ID の 3 点〔`claim_press_write`・`with_press`・`explicit_press_applied_pair`〕と `RESTRICTED_CALLS` の許可呼び出し元が要る。複雑性予算制は未発効だが方向は同じ)。

### D4: 書いたあとの扱い

- 書いた結果は読めないので、確認しない。再送もしない(drift correction のループを作らない)。
- 書いても効かなかった場合は、今と同じ挙動に戻るだけで、悪化させない。これが本 ADR の下限。
- 書く前に保持するのは、既存の同時打鍵待ちの打鍵だけ。書き込み完了または短い期限で解放する(期限は段階 0 で実測してから決める)。

## 段階

- **段階 0(挙動を変えない)**: 観測の無い窓で証拠が出たとき、次をログと journal に出す。窓切替からの経過 ms、無操作の ms、そのときの belief(open/mode と観測元)、プロセス名・クラス名。
  合格の目安は、報告者の journal で「証拠が出たとき belief が OFF だった」件数が 0 でないこと。0 なら、そもそも直す対象が無い。
- **段階 1(設定で有効化、既定は無効)**: D2 を満たしたとき `dispatch_set_open(ON)` を 1 回起案する。報告者の実機で、直前のずれが減るかを確かめる。
- 段階 1 に進む条件は、段階 0 の報告に、ずれていた実例があること。

## 未決事項

- Q1: 範囲を `ImmCapability::Unavailable` の窓に絞ってよいか。TSF ネイティブでも読めない窓があるなら含める。
- Q2: 明示の「IME ON」は一太郎で効くか。IME ON 専用のキー(冪等)が効くか、トグルしかないか。ここが効かなければ本 ADR は無意味になる。**一太郎を持つ報告者の実機確認が要る**。
  読めない窓を模した CI の窓で骨格だけ確かめられるが、一太郎固有の挙動は再現するか分からない。
- Q3: 無操作の閾値と、窓切替直後の窓の長さ(段階 0 のログから実測して決める)。
- Q4: ADR-261 と同時に入った場合、字形が「OFF」を示し、親指シフトの証拠が「ON」を示したときの優先順位。ADR-261 が先に go になるかで変わる。

## やらないこと

- 常時の判定(v3 構想の断念と同じ理由。調査の結論は `research-private/` にある)。
- 英数側の統計判定。
- 新しい `ObservationSource` の追加。
