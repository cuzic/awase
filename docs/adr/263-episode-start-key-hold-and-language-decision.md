# ADR-263: エピソード先頭の打鍵を保持して、日本語入力と判定できたときだけひらがなキーを送る

## ステータス

実装済み(2026-10-18 更新)。マージ済み: PR 1(#630)・PR 2a(#632)・PR 2b(#633)・設定画面(#635)。**既定は `observe`**。実機未確認。測定は人工データのオフライン評価のみ(実ジャーナルは未)。

## 実装との差分(2026-10-18 に本文へ反映)

round 2 までの本文から、実装で変えた点:

1. **書き込みはひらがなキー単独**(旧: `VK_IME_ON`。D5)。所有者判断。報告が「ON・全角英数」の可能性があり、`VK_IME_ON` は既に開いていれば何も変えないため。
2. **対象の窓に `scope`**(`unobserved` 既定 / `all`)。`all` は読める窓でも判定・書き込みをする(利用者の責任)。TSF ネイティブ窓と入力中継ツールの窓は `all` でも対象外。
3. **英数側の動作 `ime_on_eisu`**(旧: 範囲外・IME OFF)。IME OFF ではなく**半角英数トグルに入る**。IME OFF は belief を動かさないと Engine が止まらず、授権も通らないため断念した(D5 の理由は維持)。
4. **書き込み前の確認**: Alt/Win が押されていたら書かない(Ctrl/Shift は送信口が一時解放する)。Alt を押したままひらがなを送る選択肢は作らない(所有者判断)。
5. **設定は 5 択に集約**(D6)。数値・アプリ指定は折りたたみの「詳細」。

## 背景

- **#623 の実状態は未確定**: 報告文の「タスクバーは OFF なのに**入力は全角ローマ字**」は、実 IME が OFF(半角の英字が直接入る)ではなく「ON かつ全角英数」を示唆する(全角の英字が出るのは ON の全角英数のとき)。
  その場合 `VK_IME_ON` は既に開いているので何もせず、本 ADR の ON の書き込みは #623 を直さない(本題は「ON かつ ひらがな」)。app log の belief の値からの「belief ON・実 OFF」は推定で、観測ではない。
  PR 2b の前に報告者の実機で「一太郎で、タスクバーが OFF のとき、awase なしで英字を打つと半角か全角か」を確かめる(ADR-261 の D0-2 と同じ依頼にまとめる)。`observe`(PR 2a)のジャーナルも手掛かりになる。
- issue #623(一太郎・GJI): 窓内の IMM が読めない窓(`ImmCapability::Unavailable` と学習された窓)では、belief(ON)と実 IME(OFF)がずれる。報告は「タスクバーは OFF なのに入力は全角ローマ字」「英数を押してもずれが直らない」。
  読んで直す手段が無い(ADR-261 は字形で読む案、ADR-262 は最初の同時打鍵を契機に ON を書く案)。
- 所有者の着想(2026-10-17): 窓切替直後・長い無操作のあとだけ、最大 2.5 秒・7 打鍵の打鍵列から入力が英数か親指シフトかを統計的に判定し、日本語なら IME を ON にしてから注入を始める。
  反映が少し遅れる副作用より、ずれが直る利益が大きい。打鍵の時刻は使わない。英語専用のモデルは作らない(コーディング・他言語併用のため)。
- 所有者判断(2026-10-17): 既定は「日本語のときの IME ON だけ」。OFF の書き込みは取り下げ(授権が通らない。下記)。保持中に前面窓が変わったら、保持した打鍵は捨てる。

## 評価(オフライン、人工データ。詳細は `research-private/2026-10-17-v3-eval-first-run.md`、非公開)

- 日本語 約 1,800 件(読みは LLM 生成、目視で未検証)、非日本語 約 1,700 件(英語・マレー語/インドネシア語・欧州ほか 11 言語・コード)。文の途中開始と打ち間違い 3% を含む。dev/test はジャンルまたは言語群で分離。スペースは数えていない。
- **採る設計(逐次判定・一様背景)の数字**: 「日本語を英数と誤る」は 5〜9%(逐次の閾値 (A,B)=(4,8)〜(6,10)、平均 2.4〜2.8 打鍵で決まる)。固定 k 打鍵で背景を一様にすると k=5 で 2.5%、他言語プールの 2 連を背景にすると 1.5%(学習した重ね合わせは 0.6% だが未知の言語で悪化するため不採用)。
  未知の言語を日本語と誤る率は約 1%(群により 0〜3%)。「親指なし→英数」とだけ決めた場合の日本語の誤りは k=5 で 4.5%。
- **この設計では誤りの害が小さい**: 日本語を英数と誤判定した場合は、保持した打鍵を今までと同じ流れに戻すだけ(ひらがなキーを書かない)。つまり**今の挙動に戻る**だけで、遅れが加わる。英数を日本語と誤判定しても、belief が ON の窓では Engine が既に英字をローマ字に変換して送っているので、ひらがなキーを書いても悪化しない。
- 限界(楽観側): 閾値を人工データで校正、日本語標本が少ない k、英語以外の標本が小さい、日英混在・記号・大文字・Space の親指・実ジャーナルは未検証。

## 決定

### D1: 対象とエピソード

- **対象の窓**: 既定(`scope = "unobserved"`)は観測の無い窓(`FocusTracker::demoted_by_learning`。実測学習で `Standard` から降格された窓。静的リスト由来の `Imm32Unavailable`〔Chrome/Edge/UWP〕・TsfNative・InputRelay は含まない)で、かつ **Engine が活性**のエピソードだけ(`compute_active`。IME ON かつローマ字入力と見られること)。
  Engine が非活性の窓は保持しても何も変わらない(保持しない)。`scope = "all"` は読める窓も対象にする(**利用者の責任**。読める窓では belief が実状態に追随するので、書き込みの結果が次の観測で揃うまで食い違いうる)。実質 TSF ネイティブの窓(Windows Terminal 等)と入力中継ツールの窓は `all` でも対象外。
- **エピソードの開始**: 前面窓(`ForegroundScope` の hwnd)が変わった直後、または最後のフック打鍵から長い無操作のあとの最初の Down。hwnd 単位にする(一太郎の複数文書の窓の切替は `focus_epoch`〔プロセス単位〕では拾えない)。
  無操作の長さは `deliver_key_event` が `last_hook_activity_ms` を上書きする**前**に読む。無操作の閾値は新しい定数として `#[measured]` と実測を添える(`LONG_IDLE_MS` は GJI の cold 判定用で意味が違うので流用しない)。
- **保持を始めるのは判定の材料になる打鍵だけ**: 文字キー(`Char`)・親指・Shift の Down。矢印・Tab・Delete・F キー・Home/End 等の Down で始まるエピソードは保持しない(無操作のあとのカーソル移動が止まる)。
- **保持を始めない場合**: 変換中(`tsf::observer::ime_composition_active_now()`。未確定文字列に QWERTY を足すと取り返しがつかない)、`FocusKind::NonText`、IME キー、修飾付き(Ctrl/Alt/Win。ただし Alt なりすましの親指は `impersonated` を見て対象にする)、awase の注入、`exclude_apps` のアプリ。

### D2: 保持

- **保持するのはエピソードの全打鍵(Down も Up も、判定の対象外の打鍵も)**。判定の入力に使うのは文字キー(`Char`)と親指(`LeftThumb`/`RightThumb`)の Down/Up だけ。Space・Shift・矢印・リピート・保持の開始前に押されていたキーの Up を、保持中に先に流さない(順序が崩れ、Shift が抜けて大文字が小文字になる)。
  自動リピートの Down は保持するが、7 打鍵には数えない(`press_id.is_some()` の Down を 1 打鍵と数える)。
- **打ち切りの打鍵も保持列の後ろに積む**: 打ち切り(下記)の契機になった打鍵を `process_key_event` へその場で流すと、非同期の `WM_DRAIN_OUTPUT_QUEUE` で再生される保持列を追い越す。契機の打鍵は保持列の最後に `INPUT_DEFER.replay_later` で積んでから解放する。
- **場所と器**: `runtime/message_handlers.rs::deliver_key_event` の `consume_post_bypass` の後、`process_key_event` の前(`[[keymap]]` の latch より後なので Down/Up の非対称にならない)。器は `timed-fsm` の `HoldingGate<新しい状態機械, RawKeyEvent>`、置き場所は `PlatformState`/`Runtime` のフィールド(裸の `static` を作らない)。
  解放は `INPUT_DEFER.replay_later(held)`(TsfGate と同じ経路。`take_all` が timestamp 昇順に並べ替える)。2.5 秒のタイマーは新しいタイマー ID(TsfGate の `TIMER_TSF_GATE` と同じ形)。
- **再保持の防止は出所ではなく印で行う**: 再生された打鍵は `KeyOrigin::DeferredReplay` で届くが、窓切替直後の最初の打鍵は `FOCUS_RESYNC`/`OUTPUT_GATE` 経由でも `DeferredReplay` として届く(`app/mod.rs:643-663`)ので、出所で見ると最初の打鍵を保持し損ねる。エピソードの状態機械が「このエピソードで保持した打鍵の `press_id`」と「判定済み」を持つ。
- **フォーカス追跡の遅れ**: Alt+Tab 直後の最初の打鍵では、awase のフォーカス追跡(`demoted_by_learning`・belief)が前の窓の値のことがある(フォーカスの検出は WinEvent/500ms のリフレッシュ)。対象の判定(観測の無い窓かつ belief ON)は**解放(判定の確定)の時点でやり直し**、保持の開始時は「前面窓の hwnd が `FocusTracker` の現在の hwnd と一致しないなら、追跡が追いつくまで保持する(上限内)」とする。
- **打ち切り(保持を即解放して通常処理)**: 判定の材料でない Down(矢印・Tab・Delete・F キー・Space〔親指でないとき〕・Esc/BackSpace/Enter 等。契機の打鍵は保持列の最後に積む)、IME キー、修飾付き打鍵、7 打鍵、2.5 秒、判定の確定。
  **すべての解放点(判定の確定・打ち切りの打鍵・2.5 秒のタイマー)で、保持の開始時の `ForegroundScope` と今の前面窓(`win32::foreground_scope()`)を照合し、違えば捨てる**。**前面窓が変わっていたら、保持した打鍵は捨てる**(元の窓の打鍵が新しい窓、チャット欄やアドレス欄へ入る誤送信を避ける。捨てた件数は journal に残す。所有者判断)。マウス操作はフックで見えないので、前面窓の変化(`ForegroundScope`)で補う。

### D3: 判定(純粋、ルートの `awase` crate)

- 入力は分類済みの値だけ: `PhysicalPos` の列と、親指と文字の重なり(下記)。生の VK は見ない(ADR-019)。
- **日本語の確定**: 親指キーと文字キーの**重なり**が出たこと(親指の Down と文字の Down の間にどちらの Up も無い、または文字の Down の後でその Up の前に親指の Down が来る)。Down/Up の順序だけで決まり、打鍵時刻は使わない。
  親指の単独タップ(重なりなし)は証拠にしない。**ただし Space を親指キーにした構成(`keyboard_layout = "us"` の現実的な代替〔`config.rs:186-188`〕)では、英文のロールオーバー(`e` Down→Space Down→`e` Up、Space Down→`q` Down→Space Up)で重なりが成立してしまう。重なりを証拠にせず、エピソードを対象外にする**(述語: `left_thumb_key`/`right_thumb_key` の解決結果が `VK_SPACE`。ADR-255 と同じ扱い)。無変換/変換・F13〜F24・Alt なりすましは英文の打鍵に現れないので、重なりは使える。`observe` で Space 親指の利用者の誤判定率を実測する。
  `[[keymaps]]` に `ime = "off"` で親指キー(無変換/変換/`left/right_thumb_key`)を Space に写す規則がある構成では、エピソードを対象外にする(ADR-255 の述語は ADR-262 D2-5 と同じ)。
- **逐次判定**: 重なりが出ない間は、打鍵ごとに `LLR = log P_ja(仮名列) − log P_bg(キー列)` を更新し、`LLR ≥ A` で日本語、`LLR ≤ −B` で「英数」、7 打鍵/2.5 秒で未決なら「決めない」。**「英数」と「決めない」は同じ扱い**(今の流れに戻す)。英数と決めても害は「早く流す」だけなので、A(日本語の確信)は ON を慎重にするため大きめ、B(英数の解放)は英数側を早く流すため小さめにするのが向きだが、B を小さくするほど親指がまだ出ていない日本語を取り逃す(日本語の確定が減る)。
  **評価(2026-10-17、人工データ)**: A=4 で他言語の誤確定 0.2%。B ごとの(日本語の確定, 他言語の保持の平均打鍵)は 4: (79.6%, 1.9)、8: (91.9%, 2.9)、14: (95.1%, 4.0)、100: (98.2%, 6.7)。**既定は A=4・B=8**(取り逃し 8% と英数側の保持 3 打鍵弱の折り合い)。
  **日本語の確定のほぼ全部は親指の重なりで決まり、尤度比は日本語の確定を増やさない**(重なりのみ A=1000 でも 98.1%)。尤度比は『英数側を早く流す』ために効く。実ジャーナルで再校正する。
  - `P_ja`: 未シフト面(`YabLayout.normal` の `YabFace::get(PhysicalPos)`、`kana` が `Some` のもの)でデコードした仮名列。`data/ngram_hiragana` の 2 連(3 連は任意)。
    **`NgramModel::frequency_score` は使えない**(未知の組で `0.0` を返すが、表の値は `log10`〔最大 0〕なので未知が最頻の組と同じ点になり、行和も取れない)。表の生の値を読む口を足すか、判定器用に別にロードして `10^score` と下限で条件付き確率を作る(評価の `eval5.py` と同じ)。
  - `P_bg`: 初版は一様(言語非依存)。将来は多言語プール、または利用者自身の IME OFF 打鍵からの適応学習。**英語専用のモデルは作らない**。
- 判定器は OS・時刻を持たない純粋関数(Linux でテストが走る)。

### D4: 判定後の動作

- **日本語と確定**: 保持した打鍵を流す**前に**、ひらがなキーを 1 回送る(D5)。流したあとは通常どおり Engine が処理する。
- **英数と確定 かつ `mode = "ime_on_eisu"`**: 保持した打鍵を流す前に、**半角英数トグルに入る**(左Shift単独タップと同じ入口。GJI は `VK_DBE_ALPHANUMERIC`、MS-IME は IMC への conv 書き込み。ADR-107・ADR-245)。IME は ON のまま、入力モードの belief が半角英数になり、Engine は非活性になるので、保持した打鍵はそのまま OS へ流れる。IME の開閉の belief は動かさない。
  戻り方は Shift 単独タップと同じ(左Shift の再タップ・右Shift・IME キー。窓を離れたときは戻り待ちに積み、戻った窓の最初の打鍵で復元)。日本語を英数と誤判定しても Shift のタップで戻れる。半角英数トグルの設定が entry を許さないとき(`half_width_alnum_toggle` が無効)・すでにトグル中・戻り待ちがあるときは入らない(journal に理由を残す)。
  英数と確定する確信度は、日本語でないことの尤度比 `eisu_threshold`(既定 14.0)。評価(人工データ)で日本語を英数と誤判定する率は B=14 で 3.7%。
- **それ以外(`ime_on` の英数・決めない・打ち切り)**: 保持した打鍵を、今までと同じ流れ(`process_key_event`)で順序どおりに流す。IME に書かない。素通しにもしない。

### D5: ひらがなキーの書き込み(ADR-212 の例外。ADR-262 の機構を引き継ぐ)

- 所有者判断(2026-10-17): 判定を契機にした書き込みを、利用者が設定で選んだときだけ認める(ADR-262 の例外を、契機を「最初の同時打鍵」から「判定」に置き換える)。IME OFF の書き込みは**取り下げ**(下記)。
- **送るのはひらがなキー(`VK_DBE_HIRAGANA`)単独**。`send_ime_mode_key` を使い、scan=0 で送る。『ON かつ ひらがな』を 1 キーで作る(`VK_IME_ON` は前回のモードを復元するので、前回が半角英数だと開いても半角英数のまま。報告の『英数を押してもずれが直らない』の一因)。
  **BUG-015 追補7(『実 IME が確実に ON でない限りモードキーを注入しない』)への例外**: 所有者判断(2026-10-17、利用者が設定で選んだときだけ)。Alt/Win を確かめ、scan 無しで送ることでハザードを避ける。
  MS-IME(TSF)は scan 無しのモードキーを処理しないという実機の記録がある(`kp_restore_kana_from_half_width` 付近)ので、効かない構成がありうる。実機で確かめる(Q5)。
- 送った**あと**: `platform.on_ime_applied(true, Applied)`(composition を cold に・MS-IME のモード FSM の未確認化)と `kp_reopen_gji_fsm(ReopenSource::LangDetect)`(GjiFsm の OFF→ON〔cold〕。無操作のエピソードで GjiFsm が `OnWarm` のままだと、開いた直後の最初のローマ字をリテラル化する。BUG-002 系)。
  `applied` は書き換えない・`Confirmed` を記録しない(ADR-262 D3)。`apply_ime_open_with_view` は使わず(件数ガードは増やさない)、送信口は `send_hiragana_key()` の 1 箇所で、`architecture_guard` が『書き込みの判断 → 送信 → 送信後の同期』の順を固定する。
- **書き込み前の確認(送信の直前にやり直す)**: `hiragana_write_skip_reason`(純粋)が次のどれかなら送らず、理由を journal に残す。順序が優先順位。
  Engine が活性でない・対象の窓でない・NonText・フォーカス追跡が前面窓に追いついていない・利用者が直近に明示的に IME OFF を選んでいる(その意図を尊重)・**Alt/Win が押されている**。
  **Alt を押したままひらがなを送る選択肢は作らない**(所有者判断)。かなロックへの遷移は Alt との同時押しで発火する(BUG-008)。Ctrl/Shift は送信口が一時解放する。判断は `ime_mode_key_injection_blocked_by_modifier`(フック時点の修飾キーの状態)。
  エピソードは Alt+Tab の直後に始まることが多く、書き込みは判定の確定(数打鍵後)に行うので、確定の時点でも確認をやり直す。
  半角英数トグルに入る側(D4)は `eisu_write_skip_reason` で、逆向きの明示意図は『明示 ON』。
- 授権: `issue_open_warrant` は通さない(ひらがなキーは開閉の order ではなくモードキーの送信で、belief の `desired_open` も動かさない)。代わりに上の書き込み前の確認(利用者の明示 OFF の尊重・Alt/Win)と、設定で利用者が選んだときだけ働くこと、が ADR-212 の例外の条件。
- **IME OFF の書き込みを取り下げる理由**: D1 は belief を動かさない。英数と判定したとき `desired_open` は ON のままで、Step 4c の `finalize(requested=false, resolved=true)` は不一致の `None` になり、OFF は必ず `Unwarranted` で送られない。通すには新しい `WarrantBasis`(ADR-087 の授権の原則の変更)か belief を OFF に動かす新しいイベントが要る。belief を OFF に寄せても `effective_open()` は打鍵時予測・観測を優先するので Engine は止まらず(実装中に確認)、専用の素通しも試したが、半角英数トグル(D4)のほうが戻り方が既存の操作と揃うため置き換えた。
- **入力モード(ひらがな)について**: ひらがなキーは開閉と入力モードを同時に作る(上記)ので、書くのは 1 キーで足りる。conv の force-write は ADR-094 で撤去済み。
  残る問題は BUG-050: ひらがなキーは『IME を開く』と『ひらがなに強制する』を 1 つの副作用に束ねており、MS-IME で一度カタカナに入ると IME-ON コンボで戻れなくなるデッドロックの前提になった(`7fcb89aa` で MS-IME の ON キーを `VK_IME_ON` に変更して根治)。本機能は MS-IME のカタカナの窓でひらがなに戻す側に働くので悪化しない見込みだが、GJI での副作用は未確認(ADR-098 決定 3-c・`docs/experiments.md` エントリ 16)。実機で確かめる。

### D6: 設定

```toml
[auto_detect]
mode = "observe"      # "off" | "observe"(既定。保持せず、同じ打鍵列で判定器を影として走らせ journal に残す。挙動は変えない)
                      # | "ime_on"(保持+日本語のときひらがなキー) | "ime_on_eisu"(ime_on に加えて、英数と判定したら半角英数トグルに入る。利用者の責任)
scope = "unobserved"  # "unobserved"(観測の無い窓だけ。既定) | "all"(読める窓も。利用者の責任。TSF ネイティブ窓・入力中継ツールの窓は対象外)
idle_ms = 3000        # この時間以上の無操作のあとの最初の打鍵でも判定を始める(窓切替でも始まる)
max_ms = 2500
max_keys = 7
ja_threshold = 4.0    # 日本語と確定する確信度(A)
en_threshold = 8.0    # 日本語でないと判断して早く流す確信度(B)
eisu_threshold = 14.0 # ime_on_eisu で半角英数に入る確信度
include_apps = []     # プロセス名。空なら対象の窓すべて。指定した場合はその窓だけ
exclude_apps = []     # 対象外のプロセス名(ゲーム・リモートデスクトップ等)
```

**設定画面は 5 択に集約**する(軸を並べない): 無効 / 記録のみ(既定) / 読めない窓で、日本語ならひらがな / すべての窓で、日本語ならひらがな / すべての窓で、日本語ならひらがな・英数なら半角英数。数値とアプリ指定は折りたたみの「詳細」に置く。プリセットに当たらない組み合わせは「カスタム」と表示する。
既定は `observe` で、実ジャーナルで確かめてから `ime_on` への既定の変更を判断する(所有者の判断を再確認する)。起動時に保持の前提を満たさない構成(親指キーが Space・`[[keymaps]]` の `ime = "off"`)では、`ime_on` 系でも保持しない(`observe` に落とす)。

### D7: 観測(journal)

境界で 1 エピソード 1 件を記録する: 窓の種別、無操作の長さ、決めた打鍵数、判定(日本語/英数/未決)、**打鍵ごとの LLR の増分の列**、**重なりが初めて出た打鍵の位置**、エピソード内の訂正(BackSpace の連打・明示の IME キー)の位置、打ち切りの理由、捨てた打鍵数、書き込みの有無と結果(`hiragana-sent`・`half-width-alnum-entered`・`skipped-*` の理由。`LangDetectRecord`)、belief、`applied`。
保持はメモリ上だけで、中身は journal に出さない(パスワード欄を含む。ブラウザのパスワード欄は学習降格の窓ではないので対象外の見込み)。**キー位置の列は記録しない**(ADR-250 の方式。核が理由つき Plan を返し、殻が境界で記録)。「エピソード内で後に重なりが出た = 日本語」をラベルにして、中身なしで閾値を再校正できる。`observe` はこれで閾値の再校正に使う。

## revert 条件

実機(一太郎・GJI 等)で、(a) 保持の遅れが体感で不快(遅れの予算: 保持と書き込み後の待ちの合計。実測してから ms を決める)、(b) 保持した打鍵の順序の乱れ・消失(窓切替時の件数が多い)、(c) 日本語の判定が外れて ON が書かれる回数が `observe` のログの想定を超える、(d) ON の直後に最初の文字がリテラル化する、のいずれかが見られたら `mode` の既定を戻すか機能ごと取り下げ、失敗条件(アプリ・IME・症状)を `docs/experiments.md` に残す。
