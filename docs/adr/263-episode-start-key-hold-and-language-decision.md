# ADR-263: エピソード先頭の打鍵を保持して、日本語/英数を判定してから流す

## ステータス

起草(2026-10-17)。実装なし。測定は人工データのオフライン評価のみ(実機・実ジャーナルは未)。

## 背景

- issue #623(一太郎・GJI): 窓内の IMM が読めない窓では、belief(ON)と実 IME(OFF)がずれる。読んで直す手段が無い(ADR-261 は字形で読む案、ADR-262 は最初の同時打鍵を契機に ON を書く案)。
- **出発点(所有者、2026-10-17 再確認)**: 一太郎の**モードずれの解消**。ADR-262 は開閉軸だけを扱い、報告の「英数を押してもモードずれが解消しない」(問題 2)を範囲外にしていた。本 ADR は両方を対象に戻す。
- 所有者の着想(2026-10-17): 窓切替直後・長い無操作のあとだけ、最大 2.5 秒・7 打鍵の打鍵列から入力が英数か親指シフトかを統計的に判定し、判定が終わってから IME OFF/ON を切り替えて注入を始める。
  反映が少し遅れる副作用より、モードずれが直る利益が大きい。打鍵の時刻は使わない。英語専用のモデルは作らない(コーディング・他言語〔マレー語等〕と併用するため)。
- 先行する調査は 2026-10-16 に断念した v3 構想(常時の保持と最尤選択)。本 ADR は「エピソード先頭だけ・判定後は保持しない」に絞る点が違う(常時ではない)。

## 評価(オフライン、人工データ。詳細は `research-private/2026-10-17-v3-eval-first-run.md`、非公開)

- 日本語 約 1,800 件(読みは LLM 生成、目視で未検証)、非日本語 約 1,700 件(英語・マレー語/インドネシア語・欧州ほか 11 言語・コード)。文の途中開始と打ち間違い 3% を含む。dev/test はジャンルまたは言語群で分離。
- 親指キーが出れば日本語で確定。出ない間のみ尤度比で判別: 日本語側は `data/ngram_hiragana` の仮名 2 連(未シフト面でデコード)、背景は言語非依存(一様)または多言語プールの 2 連。
- 結果(k 打鍵目まで親指なし、日本語全体に対する誤り): k=4 で約 4%、k=5 で約 1.6%、k=6 で約 0.7%(「親指なし→英数」とだけ決めると、それぞれ 8.5%・4.5%・2.7%)。
  未知の言語を日本語と誤る率は約 1%(0〜3%)。3 連は k=4 で約 1 ポイント改善、k=5 以上はほぼ差なし。6 連は構造的に効きにくい。
- 学習した特徴の重ね合わせ(行の分布等)は日本語側を改善するが、未知の言語・コードで悪化する(コード 9%)ため、固定の重ね合わせは採らない。
- 限界(楽観側): 閾値を人工データで校正、日本語標本が少ない k、英語以外の言語の標本が小さい、日英混在・記号・大文字・実ジャーナルは未検証。

## 決定

### D1: エピソードと保持

- **エピソードの開始**: 前面窓(`ForegroundScope` の hwnd)が変わった直後、または最後のフック打鍵から長い無操作(閾値は既存の idle 判定を再利用。新しい定数を足すなら `#[measured]` と実測を添える)のあとの最初の Down。
  無操作の長さは `deliver_key_event` が `last_hook_activity_ms` を上書きする**前**に読む。
- **対象の打鍵**: 修飾なし(Ctrl/Alt/Win なし)、awase の注入でない、IME キー(`shadow_action`/`is_ime_mode_key`/`is_sync_key`)でない、`KeyClassification` が `Char`/`LeftThumb`/`RightThumb` の Down と、保持した Down に対応する Up。
  リピート(`was_down`)は数えない(`press_id.is_some()` の Down を 1 打鍵と数える)。
- **保持の場所**: `runtime/message_handlers.rs::deliver_key_event` の `consume_post_bypass` の後、`process_key_event` の前。`KeyOrigin` が見えるので、再生された打鍵を再保持しない。`[[keymap]]` の latch より後なので Down/Up の非対称にならない。
  器は `timed-fsm` の `HoldingGate<新しい状態機械, RawKeyEvent>`(TsfGate と同じ)。置き場所は `PlatformState`/`Runtime` のフィールド(裸の `static` を作らない。ガード `:5470-`)。
- **解放**: 判定・期限・打ち切りのどれでも `INPUT_DEFER.replay_later(held)`(TsfGate と同じ経路。`take_all` が timestamp 昇順に並べ替え、`deliver_key_event(.., KeyOrigin::DeferredReplay)` で再生する)。保持中に来た新しい打鍵は INPUT_DEFER の後ろに付く(`app/mod.rs:658-663`)。
  新しい状態機械は「判定済み」を持つ(再保持の防止)。
- **打ち切り(保持を即解放して通常処理)**: IME キー、修飾付き打鍵、Esc/BackSpace/Enter、前面窓の再変更、7 打鍵、2.5 秒。フォーカス再変更では TsfGate のように `held` を**捨てない**(打鍵が消えるため)。解放してから新しいエピソードを始める。
- **同時打鍵の判定は保たれる**: NicolaFsm は `event.timestamp` で同時性を判定するので、まとめて再生しても判定は変わらない(確定のタイマーは再生時刻から待つ)。

### D2: 判定(純粋、ルートの `awase` crate)

- 入力は分類済みの値だけ: `PhysicalPos` の列と、親指キーの有無。生の VK は見ない(ADR-019)。
- 親指キー(`LeftThumb`/`RightThumb`)が出たら日本語で確定(確信 100%)。
- 親指が出ない間は、打鍵ごとに対数尤度比 `LLR = log P_ja(仮名列) − log P_bg(キー列)` を更新する。
  - `P_ja`: 未シフト面(`YabLayout.normal` の `YabFace::get(PhysicalPos)`、`kana` が `Some` のもの)でデコードした仮名列に、`data/ngram_hiragana` の 2 連(3 連は任意)を使う。
    表は正規化されていない(`NgramModel::frequency_score`、未知=0)ので、条件付き確率に直す。判定器用にモデルをもう 1 つロードするか、Engine から借りる口を足す。
  - `P_bg`(言語非依存): 初版は一様(キー数で割る)。将来は多言語プール、または利用者自身の IME OFF 打鍵からの適応学習。**英語専用のモデルは作らない**。
- 決める規則(逐次判定): `LLR ≥ A` で日本語、`LLR ≤ −B` で英数。7 打鍵/2.5 秒で未決なら**決めない**(現状の挙動のまま流す。IME に書かない)。閾値 A・B は評価で校正した値で、実機のジャーナルで再校正する。
- 判定器は OS・時刻を持たない純粋関数(`tests` は Linux で走る)。

### D3: 判定の適用

- **日本語**: 保持した打鍵を Engine へ流す(belief が既に ON なら Engine が処理する)。実 IME の開閉・モードが日本語入力になっているかは読めないので、書き込みで揃える。設定が `ime_on`/`ime_on_off` かつ観測の無い窓なら、流す**前に**「IME ON かつ ひらがな」を作る書き込みを 1 回行う(D4)。
- **英数**: そのエピソードの間(前面窓が同じ間、または明示の IME キー・無操作・窓切替まで)、Engine を通さず素通しにする(`consume_post_bypass` を 1 打鍵限りからエピソードに伸ばした分岐を `deliver_key_event` に足す。`enqueue_reinject`)。belief は動かさない。
  設定が `ime_on_off` かつ観測の無い窓なら、流す前に IME OFF を 1 回送る(D4)。素通しした打鍵の Up も素通しにする。

### D4: IME への書き込み(ADR-212 の例外の拡張)

- 所有者判断(2026-10-17): 「モードずれもありうるので、判定の場合に限って IME ON/OFF を書いてよい。設定で ON のみか ON/OFF か、どの窓でするかを選べるようにする」。ADR-262 の例外(ON のみ・同時打鍵契機)を、判定契機の ON/OFF に広げる。他の窓・他の契機への拡張は認めない。
- **書き込みの目標は(開閉, 入力モード)の組**: 日本語と判定したら「IME ON かつ ひらがな」、英数と判定したら「IME OFF」(半角英数モードは目標にしない。`VK_DBE_ALPHANUMERIC` は IME ON のまま半角英数になるだけで直接入力ではない、と `docs/experiments.md` エントリ 01 が記録している)。
  GJI の `VK_IME_ON` は**前回のモードを復元する**ので、前回が半角英数だと ON を書いても半角英数のままになる(問題 2 の原因の一つ)。日本語の書き込みは ON だけでなく、ひらがなへ戻す手段が要る。
  ただし次の履歴がある(キー選択は再発ファミリー)。ON のキーは 2026-08-06 に `VK_DBE_HIRAGANA` から変えた(BUG-50)。`conv_mode_policy = force`(conv の force-write)は ADR-094 で撤去された。
  どのキー・どの順序で「ON かつ ひらがな」を作るかは、`ime_controller.rs::characterize_strategy` の戦略表と ADR-191/196 の学習済みキー効果表(`keys.ime_on` 等)から実装前に決める(Q7)。
- 書き込みは ADR-262 D3 の機構を使う: `press=None` の order を `platform.apply_ime_open_with_view` 経由で起案する(`issue_actuation_order`)。`applied` は書き換えない・`Confirmed` を記録しない(`record_ime_apply_result` を呼ばない)・`on_ime_applied` は呼ぶ。`RESTRICTED_CALLS`・件数ガード(1→2)に登録する。
  GjiFsm の OFF→ON は ADR-262 の段階 A(presync 停止)後は level 突合(ADR-203)が覆う。
- **書き込みは観測の無い窓(`FocusTracker::demoted_by_learning`)に限る**。読める窓では belief と drift correction が衝突する(判定で OFF を書いても belief は ON のまま、drift correction が ON に戻す)。
  読める窓の設定 `scope = "all"` は、保持・判定・素通しとログだけを行い、IME には書かない。
- 授権は `issue_open_warrant` の通常経路(一太郎は `FEEDBACK_BLIND` なので `OwnSsot`)。TTL 内の明示 OFF の意図があれば ON は止まる(利用者の意図を尊重する正しい挙動)。OFF の書き込みの授権は実装前に確認する(Q3)。

### D5: 設定

```toml
[auto_detect]
mode = "off"          # "off" | "observe"(保持・判定・ログだけ、素通しもしない) | "passthrough"(英数の素通しまで) | "ime_on"(+日本語で ON) | "ime_on_off"(+英数で OFF)
scope = "unobserved"  # "unobserved"(観測の無い窓。書き込みはここだけ) | "all"(読める窓も。書き込みなし)
include_apps = []     # プロセス名。空なら scope に従う。指定した場合はその窓だけ
exclude_apps = []     # 対象外のプロセス名(ゲーム・リモートデスクトップ等)
max_keys = 7
max_ms = 2500
```

既定は `mode = "off"`(段階 1 のリリースでは `observe`)。

### D6: 観測(journal)

境界で 1 エピソード 1 件を記録する: 窓の種別、無操作の長さ、決めた打鍵数、判定(日本語/英数/未決)、LLR の最終値、打ち切りの理由、書き込みの有無、belief、`applied`。**打鍵の中身(キー位置の列)は記録しない**(ADR-250 の方式。核が理由つき Plan を返し、殻が境界で記録)。

## 段階

1. **PR 1(core、Linux で検証)**: 判定の純粋関数(仮名 2 連・一様背景・逐次判定)、仮名条件付き確率への変換、単体テスト、評価データでの回帰(人工データ数十件を `tests/` に)。`tuning` の定数は `#[measured]` と評価の実測を添える。
2. **PR 2(shell、`mode = observe`/`passthrough`)**: `HoldingGate` と状態機械、`deliver_key_event` への保持・再生・素通し分岐、journal、設定、ガードテスト更新(`architecture_guard` の `process_key_event` 1 件・`enqueue_reinject` の件数・保持の再保持防止)。書き込みなし。
3. **PR 3(`ime_on`/`ime_on_off`)**: D4 の書き込み(開閉とモードの両方。Q7 の決着が前提)。ADR-262 段階 A(presync 停止)が前提。回帰テストと `docs/known-bugs/` の記録、`docs/experiments.md` の行、revert 条件。
各 PR で Opus の敵対的レビューを通す。実機は CI の読めない窓の模擬(ADR-261 の TSF のみの窓)と報告者の実機。

## revert 条件

実機(一太郎・GJI 等)で、(a) 判定が外れて日本語入力が英数のまま素通しされる、(b) 英数入力の IME が誤って ON になる、(c) 保持の遅れが体感で不快、のいずれかが `observe` のログと比べて見られたら `mode` の既定を戻すか機能ごと取り下げ、失敗条件(アプリ・IME・症状)を `docs/experiments.md` に残す。

## 範囲外・未決

- 範囲外: 日英混在の行内切替、打鍵の時刻を使う判定、常時の判定、読める窓での IME 書き込み。
- Q1: 背景モデルの初版は一様でよいか(多言語プール・利用者適応は後)。
- Q2: 7 打鍵・2.5 秒・無操作の閾値の実測(`tuning.rs` の `#[measured]`)。
- Q3: IME OFF の書き込みの授権(`WarrantBasis`)と、`ImmCapability::Unavailable` の窓での OFF の実効性(GjiDirect の OFF が効くか)。
- Q4: マウス操作は保持中に検出できない(2.5 秒の保持中にクリック→打鍵が別の位置に入りうる)。受け入れるか、フォーカスの検出で補うか。
- Q5: パスワード欄・`FocusKind::NonText` では保持しない(既存の素通しに任せる)ことの確認。
- Q7: 「IME ON かつ ひらがな」を作るキーと順序(GJI の ON キーは前回モードの復元。半角英数のまま ON になる問題の対処)。MS-IME/GJI/ATOK で別か。学習済みキー効果表から引けるか。実機(一太郎・GJI)で確かめる前に決めない。
- Q6: 判定器用に `NgramModel` をもう 1 つロードする(メモリ)か、Engine から借りるか。
