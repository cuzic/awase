## Should-fix

### S13. 「他ツールが1件足されても解除できる」は、from 重複のときだけ成り立たない(B4 の取りこぼし)

- 決定3(削除は常に通る)は「他ツールが1件足されても、awase が書いた入れ替えを awase から解除できる」と言い切っている。
  しかし分類表の「同じ from が2件 → 重複したエントリだけ Unclaimed」と組み合わせると、次の場合に成り立たない。
- 失敗シナリオ: awase の `A→B`, `B→A` のあとに、手動 regedit などで `A→Z` が追記される。from=A が2件なので、`A→B` と `A→Z` が
  Unclaimed になる。残った `B→A` は相方が無いので Unclaimed(単独)。結果、Caps⇄LCtrl に当たるペアが UI から消え、解除できない。
  現行の `current_preset`(包含判定)なら Swap と検出され、from=0x3A/0x1D の全件を消すので**今は解除できる**。
- 修正案(表の1行を直すだけ): 「`A→B`, `B→A` がそろっていて、さらに同じ from の別エントリ(`A→Z`)がある」場合は、
  `A⇄B` を **Pair(警告つき)**、`A→Z` を Unclaimed(理由: from 重複)にする。削除は `A→B`, `B→A` の2件だけを消す。
  削除後に `A→Z` が新たに効くようになる可能性はあるが、それは他ツールが書いた値そのもので、多対一も from 重複も新たには作らない
  (「悪くならない」規則と整合する)。UI の警告文で「削除すると `A→Z` が効くようになります」と出せば足りる。

## Note

- **N13. 未確認の節に英数が残っている**: 「押しっぱなしにできないキー(決定2): 半角/全角・かな・**英数**と Ctrl/Alt/Shift の入れ替えで…」。
  決定2 は仮説の対象から英数を外したので、ここも「半角/全角・かな」にそろえること(英数を念のため測ること自体は害が無いが、
  文書の中で対象が食い違うと、次の読み手が「英数の組は禁止か」を判断できない)。
- **N14. プロパティテストの入力範囲**: 等式「`unclaimed` = `existing` の Unclaimed − `displaced`」は、ペアの削除で他のエントリの分類が
  変わる入力(S13 の from 重複、`C→A` と交わる警告つきペアの削除で `C→A` だけが残る等)では、Unclaimed の**理由**が変わりうる。
  比べるのはエントリの集合だけにし、理由は比べないと書いておくこと。生成器が from 重複を含む入力を作るかどうかも明記する。
- **N15. 現行のテストの引き継ぎ**: `third_party_left_ctrl_remap_to_unrelated_key_survives_caps_extra_ctrl_enable_and_disable`
  (`scancode_map.rs:488-501`、CapsAsExtraCtrl と他ツールの `0x1D→0x99` の共存)は、新しい分類でも `0x3A→0x1D` 単独 → CapsAsExtraCtrl、
  `0x1D→0x99` → Unclaimed で成り立つ。ambiguous テストと同様に「引き継ぐ」と1行書いておくと、実装時に消されずに済む。
  また、旧 UI では Swap → CapsAsExtraCtrl の切り替えが UAC 1回で済んだ(ADR-126 決定5)。新 UI でも「`Caps⇄LCtrl` ペアの削除と
  チェックボックスのオン」を1回の適用で書ける(`compute_swap_write` の1回の呼び出しで両方を扱う)ことを確認しておくこと。
  今の決定3 の引数で可能なので、記述の追加だけでよい。
