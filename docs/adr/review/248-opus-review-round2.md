## Blocker

### B5. `Locked` の位置を含む awase の入れ替えは、図からは個別に解除できない。今の行の「削除」より後退する

- 根拠: 決定5 :81-86。`Locked` は「ドラッグ元にもドロップ先にもできない」。③は「他ツールのエントリの to に現れる機能の位置」、④は「from が重複している位置」。
  「この位置を戻す」(:90)が `Locked` の位置で使えるかは書かれていない。個別に消せる一覧は「許可リスト外の位置を含む入れ替え」(:79-80)と
  「他のツールの設定」(:86)だけ。
- ADR-230 決定3 の表で、警告つきの Pair は2種類ある: `A⇄B` に他ツールの `C→A` が交わる場合(A の機能が他ツールの to → ③)と、`A⇄B` に `A→Z` が
  追記された場合(A が from 重複 → ④)。どちらも ADR-230 が「削除は常に許す」「awase が書いた入れ替えを awase から解除できる」(round2 B4・round3 S13)と
  決めた対象そのもの。
- 失敗シナリオ: awase で `無変換⇄左 Alt` と `変換⇄スペース` を書いた後、他ツールが `0x003B〈F1〉→無変換` を足した。図では「無変換」の機能(左 Alt の位置に
  出ている)が③で `Locked`、`無変換⇄左 Alt` の2位置ともドラッグもドロップもできない。消す方法は「すべて解除」だけで、関係の無い `変換⇄スペース`
  まで消える。今の画面(`main.rs:5049` の行ごとの「削除」)なら `無変換⇄左 Alt` だけを消せる。
- 推奨修正: `Locked` を2つに分ける。「動かせない(ドラッグ・ドロップ不可)」と「解除はできる」は別の性質。awase の編集できる入れ替え(Pair/循環、
  警告つきを含む)に属する位置は、`Locked` でも「この位置を戻す」(=その入れ替えを解除。核では削除なので常に通る)を出す。
  `PositionState::Locked{label, reason, releasable: bool}` のようにし、「入力 → 図の表示」の表(:87)に警告つき Pair の2行(③・④)を必須ケースで足す。
  あわせて、決定3〜5 の段階で行の一覧(ドロップダウン)を撤去するのかを決める(S1)。撤去しないなら、この Blocker は行の「削除」で回避できるが、
  その場合は図と行の2つの編集口が同じ状態を持つことになる。

## Should-fix

### S1. 図(段階2)が行・ドロップダウンの編集 UI を置き換えるのか、併存するのかが書かれていない

- 根拠: 決定3 :72「ドロップダウンの表記を統一する」、決定4 :73「他の行で使用中」は行の UI を前提にしている。決定5 は図を足すが、行の UI の扱いが無い。
- 併存なら、図の「ドロップ = P と h を含むペアを解いてから P⇄h」(:88)と、行の「候補から使用中のキーを除く」(`scancode_editor.rs:202-233`)で
  同じ状態への操作の規則が2通りになる。行の UI は「片方しか選んでいない行」(`has_incomplete`)を持つが、図にはその状態が無い。
  図でドロップした結果を行にどう反映するか(行の順序、未完成の行の扱い)も要る。決定6 の後は、行は循環を表せない。
- 推奨修正: 段階2 で図に置き換え、行の UI は撤去する(許可リスト外を含む入れ替えの一覧と「解除」だけ残す)、と決定5 に書く。決定3・4 の「行」「ドロップダウン」の
  記述は段階1 だけのものと注記する。

### S2. 置換の核のときのドロップの定義「P と h の中身を入れ替える」は誤り。h ではなく、ドラッグ元の位置 s と入れ替える

- 根拠: 決定5 :89「核が置換になった後(決定6)は、P と h の中身を入れ替える(置換に互換を掛ける)」。h は「機能 F の元の位置」(:88)。
- F がいま出ている位置 s は、入れ替え済みなら h と違う。σ(s) = F、σ(h) ≠ F。P と h の中身を入れ替えると、P に来るのは σ(h) で、F ではない。
  例: `無変換⇄左 Alt` がある状態で、左 Alt の位置に出ている「無変換」を変換の位置へ落とす。h = 無変換の位置。P(変換)と h(無変換)の中身を
  入れ替えると、変換の位置は「左 Alt」を出し、無変換の位置は「変換」を出す。利用者が落とした「無変換」は左 Alt の位置に残ったまま。
- 推奨修正: 「ドラッグ元の位置 s と P の中身を入れ替える(σ' = σ∘(s P))」と書く。round1 で示した「ラベルを入れ替える」はこれ。ペアの核の間の
  「解いてから P⇄h」と、置換の核の「s と P を入れ替える」は、入れ替え済みの位置からドラッグしたときに結果が違う(前者は s が恒等に戻り、
  後者は s に P の機能が来る)。段階2 で利用者が覚えた操作の結果が、段階3 で変わる。決定6 の費用(:109-113)にこの非互換を書き、段階3 に進むときに
  所有者へ示すこと。

### S3. 質問(3)への回答: 「解いてから作る」は ADR-230 決定3 の規則と矛盾しないが、条件が3つ要る

ADR-230 の `compute_swap_write` は「編集後のペア集合の全体」を受け取るので、1回のドロップは「消すペア(解く)+作るペア(P⇄h)」を1回の計算で表せる。
解く部分は削除なので常に通り(「削除は常に許可」)、作る部分だけが新規作成の検査(許可リスト・Caps 追加 Ctrl・他ツールの to)を受ける。
「悪くならない」もこの分け方で保たれる。ただし、ADR に次の3つが無い。

1. **ドロップは全体で1つの操作**: 作る部分が検査に落ちたら、解く部分も行わない(図の状態を変えない)。部分的に「解いただけ」の状態にすると、
   利用者は落としたつもりで、関係の無いペアが消えている。
2. **「落とせない位置は無い(Locked を除く)」(:89)は誤り**: P = h(元の位置へ戻す)は `SelfPair` になる。これは「この位置を戻す」と同じ意味
   (h を含むペアを解くだけ)と定義する。また US 配列で表示される JIS 専用キー(S4)・許可リスト外の位置を含む入れ替え(S5)へのドロップは
   `NotAllowed` か候補外になる。「置ける/置けないは核の検査で決める」(:85)と一致するよう、この文は「`Locked` と検査に落ちる位置を除く」に直す。
3. **解く側の副作用の可視化**: P または h を含むペアを解くと、利用者が触っていない位置(P の元の相手、h の元の相手)が恒等に戻る。差分の常時表示(:129)に
   載るが、ドロップの最中(`dnd_hover_payload` の段階)に「この位置も元に戻ります」と出すと誤操作が減る。解くペアが警告つきの場合は、`revealed` の
   警告も出す(ADR-230 決定3 の「全ての経路で警告」)。

### S4. US 配列で表示に戻した JIS 専用キーの位置へのドロップが、新規に JIS 専用キーのペアを作れてしまう

- 根拠: 決定5 :77-78(いまの入れ替えに含まれる JIS 専用キーは US でも描く)。ADR-230 決定2(230:70-71)は JIS 専用キーを「JIS 配列のときだけ候補に出す」、
  `quick_available` は US で JIS 専用キーを含むものを無効にする(`scancode_editor.rs:163-170`、理由は「US 配列にその物理キーは無く、スペースなどが
  入力できなくなる」)。
- 失敗シナリオ: US 配列の利用者の画面に、JIS 利用者が書いた `無変換⇄左 Alt` のため「無変換」の位置が描かれる。利用者がそこへ「スペース」を落とすと、
  解いてから「スペース⇄無変換」を作る。US キーボードに無変換の物理キーは無いので、スペースが打てなくなる(S9 の注意は「右 Alt・かな・英数」だけで
  無変換を含まない)。
- 推奨修正: B3 の修正で表示に戻した位置は「戻す(解除)専用」にし、ドロップ先にもドラッグ元にもしない(`Locked{releasable: true}`、B5 と同じ型)。
  配列で候補から外れるキーへの新規作成を禁じる規則は、行の UI(`candidates`)と同じ関数で決める。

### S5. ⑤の「許可リスト外を含む混在循環」が決定6 と食い違う。awase の編集できる混在ペアの図での扱いが無い

- 根拠: 決定5 :84「⑤他ツールの片方向・許可リスト外を含む混在循環に関わる位置」は Locked。決定6 :115「完全な循環は許可リストに関係なく編集できる」、
  決定5 :79「許可リスト外の位置を含む編集できる入れ替えは図の下の一覧に」。
- 混在した完全な循環(例 `無変換⇄0x0010`)は決定6 では「他ツールのもの」ではなく編集できる入れ替え。図の「無変換」の位置にはラベル `0x0010` 相当が出る。
  ⑤は「他ツールの」と書くので、この位置が Locked かどうかが読めない。Editable にすると、ラベルを他の位置へ落とせば `to = 0x0010` の新規エントリになり
  `NotAllowed`。
- 推奨修正: ⑤を「他ツールの片方向」と「許可リスト外を含む編集できる入れ替えに関わる位置(`Locked{releasable: true}`、解除は図の下の一覧と同じ)」に
  分ける。

### S6. 機種に無いキーの注意に「英数」を入れると、いちばんよく使うワンクリックが毎回注意を出す

- 根拠: 決定5 :99-101(スペース・左 Ctrl・左 Alt の機能を右 Alt・かな・英数へ移すとき注意)。ワンクリック「英数/Caps ⇄ 左 Ctrl」(:105)は
  左 Ctrl の機能を英数の位置へ移す。
- 英数/CapsLock の位置のキーは JIS・US のどちらのフルキーボードにもノート PC にも通常ある(round1 S9 で私が英数を挙げたのは、ADR-230 :92-93 の
  「この機種には英数キーが無く」の一文に引きずられたため。あの文は「英数の位置を Ctrl に置き換えて使っている」機種の話で、物理キーが無いのではない
  と読むのが自然。私の誤り)。毎回出る注意は、決定6 :128 が避けたい「読まずに押す」を作る。
- 推奨修正: 英数を対象から外し、右 Alt・かなに絞る。US 配列では JIS 専用キー(S4)も対象。ADR-230 :92-93 の文意は、ADR-230 の実機確認(段階5)で
  確かめて直す。

### S7. 段階の順序: Q2 を段階1 全体の前提にすると、Q2 に関係ない文面の改善まで実機待ちで止まる。逆に Q3 は前提に入っていない

- 根拠: 段階 :152-155(段階0 に Q2、段階1 に決定1〜4・7の一部・8・9)。決定7 :138「確認できた手順だけを書く」、Q3(:170-171)は段階のどこにも入っていない。

  再起動していなければ、まだ効いていません」(:62-63)で出せると ADR 自身が書いている。
- 決定7 の手順(1)〜(3)は Q3 の項目(画面キーボード・WinRE のパス)を含むが、段階2 で出す。「確認できた手順だけ」と食い違う。

  段階1 の「7 の『元に戻す』整理」は「復旧はすべて解除」と画面に書くが、「すべて解除」は段階2 なので、段階1 ではその1文を出さない。

## Nit

- **N10. 図に描く位置の書き方**: :77-78「いまの入れ替えに含まれる位置」と非目標 :186「いまの入れ替えに含まれる位置だけ」は、許可リスト外の位置も
  図に描くと読める。:79-80 の意図(許可リスト外は一覧)に合わせ、「いまの入れ替えに含まれる、許可リスト内の位置」と書く。
- **N11. 「すべて解除」は他ツールが書いた完全な入れ替えも消す**: :132「他ツールのエントリは残す」の「他ツールのエントリ」は ADR-230 の定義どおり
  Unclaimed のことで、SharpKeys などが書いた完全な入れ替え(Pair として読まれる)は消える。利用者には「他のツール」と読めるので、
  「他のツールの設定(一覧に出ているもの)は残します。入れ替えの形の設定は、他のツールが書いたものでも解除します」と書く。確認ダイアログには
  解除する入れ替えの一覧を出す。
- **N12. Q2 の補足**: (a)`RolledBack`(書いてから元へ戻した)でも LastWriteTime は進むので、値は起動時と同じでも「再起動待ち」と出る(安全側だが
  不要な再起動を促す)。(b)値の削除(すべて解除で値が空になる)で LastWriteTime が進むかも Q2 で確かめる(進むと推測)。(c)起動時刻を
  「現在時刻 − 稼働時間」で出すと、起動後の時計合わせで数秒ずれる。比較に数秒の余裕を持たせる。
- **N13. 軸A の「不明」の `RollbackFailed`**: 設定画面を開き直すと、プロセス内でしか分からない「書き込み結果不明」は失われ、LastWriteTime 方式では
  「再起動待ち」として出る。それで足りる(安全側)ので、:57 の「書き込み結果不明」は「その場の表示だけ」と注記する。
- **N14. WinRE のパス**: オフラインの SYSTEM ハイブでは、現在の制御セットは `Select\Current` の値で決まり、`ControlSet001` とは限らない
  (多くの環境では 001 だが)。手順は「`Select` の `Current` の番号の `ControlSet00N`」と書く(Q3 で確かめる)。
