## Should-fix

### S8. 「他のツールの設定」の一覧に置く「確認つきの削除」は、今の核では書けない。ADR-230 の方針(他ツールの項目は awase が変えない)の変更でもある

- 根拠: 決定5 :97-98「図からは他ツールのエントリを `displace` しない(一覧『他のツールの設定』に確認つきの削除を置く)」、非目標 :216 も同じ。
  一方、`compute_swap_write(existing, pairs, caps_extra_ctrl)`(`scancode_pairs.rs:244-248`)は「編集後のペア集合」と Caps 追加 Ctrl しか受け取らず、
  他ツールのエントリ(Unclaimed)は**必ず保持**する(:344-349。消えるのは新規エントリと from が同じものを上書きするときの `displaced` だけ)。
  昇格側の `ApplyRequest`(`scancode_apply.rs:76-85`)にも「この他ツールのエントリを消す」を表す欄が無い。今の画面は
  「他のツールが設定している項目(awase は変更しません)」と明言している(`main.rs:5005`)。
- 問題: 段階2 は「ペアの核の上で出す」(:180-183)とし、核の変更を段階3 に寄せているが、この削除だけは段階2 で核と昇格 CLI の変更を要する。
  加えて、他ツールのエントリだけを消す操作は ADR-230 が意図的に持たなかった能力(ADR-230 決定3・決定4 の「他ツールのエントリは保持」、
  段階4 の「壊れた値の削除の操作は用意しない」)で、ADR-230 の改訂に当たる。
- 推奨修正(どちらかを決定に書く):
  - **(推奨)削除を置かない**。一覧は読み取り専用のまま(今と同じ)とし、②⑤の `Locked` の理由に「他のツールが設定しています。変えるときは
    そのツールで変更してください」と出す(「すべて解除」では他ツールの項目は消えないので、そこへは誘導しない)。:98 と非目標 :216 の「一覧の確認つきの削除」を削る。
    質問(2)への答え: ②⑤が `releasable: false` で awase に解除手段が無いのは、ADR-230 の方針(他ツールの項目は awase が変えない)と一致しており
    妥当。awase が書いたもの・awase の形(Pair/循環)のものは③④⑥⑦で必ず解除できるので、ADR-230 の「awase が書いた入れ替えを awase から解除できる」も
    保たれる。
  - **削除を置く**なら、`compute_swap_write` に「消す他ツールのエントリ」の引数を足し(値で照合。同値の複製は全部消すか、位置で消すかを決める。
    コードレビュー round1 B1 の型に注意)、`revealed` の計算に含め、`ApplyRequest` に欄を足して昇格側で「`expected` に実在したエントリだけ」を
    検査する、と決定6 と段階2 に書き、ADR-230 に改訂を追記する。

## Nit

- **N15. 状態(status)の文が古い**: :8「Opus round1 の指摘を反映済み(round2 の再確認前)」「段階1の前に Q2 … を解く」は、段階の節(:177-180、段階1 は Q2 を待たない)と
  食い違う。段階0 の見出し(:175)も「前提の解決」に Q2 を含むので、「Q2 は段階1 と並行して解き、解けたら軸A を差し替える。Q5 は段階1 の前」と書き分ける。
- **N16. 古い段階番号**: :118「段階3の試作で確かめ」は、図が段階2 に移ったので「段階2」。
- **N17. Q3 のパス**: :199「WinRE の `ControlSet001` のパス」は、決定7 :164 の `ControlSet00N`(`Select` の `Current`)にそろえる。
- **N18. ①の `releasable` の値**: :86「`releasable` は Caps 追加 Ctrl のスイッチで外す」は値を言っていない。図の上では `releasable: false`
  (解除はスイッチで行う)と書き、理由の文言に「『Caps を Ctrl としても使う』をオフにすると戻せます」と出す。
- **N19. 警告つきペアのもう片方の位置**: ③の例 `A⇄B` + 他ツールの `C→A` では、他ツールの to に現れる機能 A が出ているのは B の位置で、A の位置
  (機能 B を出す)は①〜⑦のどれにも当たらず `Editable` になる。A の位置から機能 B をドラッグすると、ドロップの規則(:104)で `A⇄B` が解かれる
  (削除なので核では通る)。規則上の矛盾は無いが、同じペアの一方が `Locked`・他方が `Editable` という見え方になる。「警告つきペアは両方の位置を
  同じ状態(`Locked{releasable: true}`)にする」か、「片方だけ」かを「入力 → 図の表示」の表で決める(③④の必須ケースの行に、両位置の期待値を書く)。
  同様に `releasable` は「恒等でない位置」にだけ意味がある(③で恒等の位置は解除するものが無い)ので、表では恒等の位置を `releasable: false` とする。
- **N20. 段階1 の保守的な文言**: 軸A の「レジストリに設定があります。再起動していなければ、まだ効いていません」は、Q2 が解けるまで再起動後もずっと出る。
  レジストリが空のとき・他ツールの設定だけのときの保守的な文言も決めておく(決定1 :60-61 の「入れ替えなし」「他のツールの設定があります」は軸A の「一致」が
  前提なので、段階1 では使えない)。

## 質問への回答のまとめ

1. 各反映は意図を満たしている(上の確認の節)。
2. `Locked`/`releasable` の新しい矛盾は無い。漏れは N18(①の値)・N19(警告つきペアの片方の位置と恒等の位置)。②⑤の `releasable: false` は ADR-230 の
   方針どおりで妥当だが、それと「一覧の確認つきの削除」(S8)は両立しないので、どちらかに決める。
3. 段階と Q2・Q3: 段階の節は整合している。残りは状態の文と段階0 の見出し(N15)だけ。Q3 は段階4 に入り、段階2 の復旧手順は(1)だけなので
   「確認できた手順だけ」と一致する。
4. 収束の判断: Blocker なし。S8 を「削除を置かない」に決めれば、段階2 も ADR の言うとおり「ペアの核の上」(核・昇格 CLI の変更なし)で出せ、
   収束とする。「削除を置く」を選ぶなら、その核の変更を ADR に書いたうえで、もう1回だけ確認したい。
