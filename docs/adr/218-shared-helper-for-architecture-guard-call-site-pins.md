# ADR-218: 呼び出し元固定ガードの重複を、共通ヘルパー 1 本で除く

## 背景

`crates/awase-windows/tests/architecture_guard.rs` は 5,916 行・`#[test]` 115 本(2026-10-02、`origin/develop`)。
その中の「ファイル → 出現数/呼び出し元の固定」型は、Opus round1 の全数確認で 16 本(同じテスト内の 2 表は 1 本と数える)。
当初案はこれを `GuardRule` 宣言テーブルにまとめるものだったが、次の理由で取り下げた。

- 数え方は「どこを数えるか(Region: ファイル全体 / `production_code_only` / `strip_any_test_module`)」×「何を数えるか(Unit: `count_real_calls` の行数 / `matches` の出現数)」の 2 軸で、
  パイロット 5 本だけで 4 通りある。532 の `platform_state.rs` の件数 2 は片方がテストモジュール内で、本番だけ数えると 1 になる。つまり件数を変えずに表へ移せない。
- 16 本中 10 本(1024・1209・1265・1896・1945・2321・3570・3633・3790・5700)は既に `src/` 全体を走査し、表に無いファイルを 0 件と期待している。「移行 PR は `Scope::Listed`」にすると、
  1209 などの検出力が黙って落ちる。「合否が変わらない」基準ではこれを検出できない。
- `tests/guard_rules.rs` を足すと、別の integration test バイナリになり、`ci.yml:47`/`:337` の `--test` 指定に載らない。`xtask-adr-evidence`(`extract_guard_expectations`)は
  architecture_guard.rs の `(".foo(", N)` を文字列走査で拾うので、表を移すと CI が赤になる。
- 試算では、コメントを残す限りパイロット 5 本で差し引き約 +12 行、16 本全体でも純減は約 200 行(ファイルの約 3.5%)。
- 例外が既に 4 種ある(ファイルごとに needle が違う 962、特定ファイル除外 2366/2613/5719、複数 needle の合計 1700、`src/` 外の走査 4554)。

一方で、重複の実体は小さく具体的である: 「`files_with_calls` を集めて sort → `expected` を作って sort → `assert_eq!`」の約 20 行が 1222〜1243 / 1268〜1289 / 1903〜1925 / 1955〜1977 の 4 か所にほぼそのまま複製されている。

## 決定

### D1: ヘルパー関数 1 本(新しい型・新ファイルなし)

`architecture_guard.rs` の中に、次の形の関数を 1 本置く。

```rust
fn assert_src_call_sites(
    needle: &str,
    region: fn(&str) -> &str,          // production_code_only / strip_any_test_module / identity
    count: fn(&str, &str) -> usize,    // count_real_calls / 出現数
    known: &[(&str, usize)],           // 既存テストの表をそのまま渡す
    why: &str,                         // 失敗時に出す ADR 参照と確認事項(既存のメッセージ)
)
```

Region と Unit は **関数ポインタで渡す**ので、2 軸の組合せを型で表さずに済む。`list_src_files()` で全ファイルを走査し、`known` に無いファイルは 0 件を期待する。
**既存テストの Scope をそのまま写す**: 既に全体走査のもの(上の 10 本)は全体走査のまま、列挙のものは列挙のまま。`Listed` から全体走査への強化は別 PR・別議論(対象は 211・532・637・4158・4355・4411 の 6 本)。

各 `#[test]` は残す。名前、doc コメント(経緯の記録)、`cargo test <name>` での個別実行、nextest の個別表示は変えない。移るのは、重複していた突き合わせブロックだけ。

### D2: 移行は「旧と新の同値」を確認してから旧を消す

移行 PR では、対象テストごとに旧ロジックと新ヘルパーで「全 src ファイル × needle の件数の地図」を計算し、`assert_eq!` で比べる使い捨てテストを一時的に置く。一致してから旧ブロックを消し、同値テストも消す。
加えて、各テストについて 1 回ずつ「該当ファイルに呼び出しを 1 行足すと落ちる」ことを手で確かめる(ミューテーション)。件数を変える移行は行わない。

### D3: 対象と対象外

- 対象: 重複ブロックが確認できる 1209・1265・1896・1945 の 4 本から始める。他は、4 本の移行後に同じ関数で書けるか見て、書けるものだけ足す(目標を先に決めない)。
- 対象外: (a) `extract_fn_body`/`extract_all_balanced_blocks` を使う構造検査(4375 の `per_fn_expectations` など)。(b) 例外つき(962 ファイル別 needle、2366/2613/5719 の除外、1700 の複数 needle、4554 の `src/` 外)。(c) **dylint が既に同じ対象を見ているもの、または ADR-161 D1 M2 で dylint へ置き換える予定のもの**(1436 の `ENTRY_POINTS`、2321、2526 など。置き換えたらテキスト一致のガードは削除する方針)。ModeKeyPassedThrough の 3686 は `lints/ime_event_guard` と二重なので、表に移すのではなく削除候補として別途検討する。
- 当初案の D3(コメントを除いて数え直す)は行わない。件数が変わる修正は本 ADR の範囲外。参考として、`InputRelay` をコメント除外で数えると `ime_controller.rs` 1→0、`open_chain.rs` 4→0、`class_names.rs` 12→9、`physical_disposition.rs` 2→1 になる。0 になる 2 エントリは否定ガードにしかならず、InputRelay ゲートの存在は 4355 の `decide_gate(` 固定が担う。別 PR で「数え直す」でなく「削除する」ことを検討する。

### D4: 中止基準

4 本の移行後、`architecture_guard.rs` の行数が増えるなら(ヘルパー追加分を含めて)、ヘルパーを撤去して終了する。固定費は約 30 行、4 本で 80 行前後の重複が消える見込み(実測は実装時)。

## 検討した代替案

- **宣言テーブル + 汎用チェッカー(当初案)**: 上の理由で取り下げ。全ルールを一覧できる以外の利点がヘルパーより小さい。
- **ルールごとに `#[test]` を生成する `macro_rules!`**: テスト名は残るが、エラー位置が悪くなる。ヘルパーで足りる。
- **何もしない**: 4 か所の複製は小さく、動いている。D4 の基準を満たせなければこれが結論。
- **dylint へ一本化**: ADR-161 D1 M2 が対象ごとに採用済み。本 ADR は dylint が見ていない件数ガードだけを扱う。

## 影響

テスト専用。ホスト(Linux)で実行できる。CI の `--test architecture_guard` 指定、`xtask-adr-evidence`、`fix-requires-evidence.md` の対象ファイル表には触れない(新ファイルを作らないため)。
