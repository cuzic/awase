# ADR-230: Scancode Map の全単射入れ替えエディタ

## 背景

「IME キーや Ctrl/Alt を自由に入れ替えたい」という要望がある(出典: 所有者経由の利用者要望。issue 番号・報告 ID は
未確認)。所有者の整理(2026-10-06): 入れ替えたいキーの範囲は **左 Ctrl・左 Alt・右 Alt・スペース・無変換・変換・かな・半角/全角(漢字)・英数/Caps**
あたりで、これらの間で全単射に入れ替えられればよい(決定2 の許可リスト)。

現状の Scancode Map 機能は `ScancodeMapPreset` の2種類(`Swap`・`CapsAsExtraCtrl`、
`crates/awase-windows/src/scancode_map.rs`)で、任意のキーの組は扱えない。

hook ベースの汎用リマップ(ADR-110)は、JIS の英数キー位置と日本語 IME の Shift ショートカットの衝突で
構造的に危険と判明して撤回済み(ADR-111 r4。直接の記録は `docs/experiments.md` エントリ17。エントリ07〜09 は
17 が参照する先の先例)。実現手段は Scancode Map(レジストリ、ドライバ層)に限る。

所有者の方針(2026-10-06): 「自由」といっても全単射(入れ替え)だけ作れればよい。

## 決定(提案)

### 決定1: 編集の単位は「入れ替えペア `A⇄B`」

- ユーザーが編集するのは、互いに素なペアの集合 `{(A1,B1), (A2,B2), ...}`。各キーは高々1つのペアにしか現れない。
- ペア `(A,B)` はレジストリ上 `A→B` と `B→A` の2エントリ。
- **保証の範囲を正しく言う**: 全単射が保証されるのは「awase が書くペア部分」であり、OS 全体の写像が全単射になるのは
  他ツールのエントリがペアのキーと交わらない場合だけ(決定3 のマージ検査が、交わるものを止めるか確認に回す)。
- **既存2プリセットの扱い**: `ScancodeMapPreset::Swap` は廃止し、`{(Caps/英数 0x003A, LCtrl 0x001D)}` の1ペアとして
  読む。`CapsAsExtraCtrl`(全単射でない)だけプリセットに残す。CLI の `"swap"` 引数は同じ exe 内なので互換を残さない
  (ADR-217)。
- **CapsAsExtraCtrl との関係は排他(キー単位)**: 有効なとき、`0x003A` と `0x001D` のどちらを含むペアも新規には作れない
  (`Caps→LCtrl` と `X⇄LCtrl` が同居すると Caps と X が両方 LCtrl を出す多対一になるため)。それ以外のペア
  (`無変換⇄左 Alt` など)は同時に使える。UI は「Caps を追加の Ctrl にする」をチェックボックスにし、オンのときは
  `0x003A`/`0x001D` をペアの候補から消す(モード単位の排他にはしない。無関係な入れ替えまで禁じる理由が無い)。

### 決定2: 選べるキーは固定の許可リスト(u16、E0 込みの1つの値で持つ)

Set 1 スキャンコードを `u16`(上位バイトが E0)で持ち、`u8 + bool` に分けない(BUG-132 はフックの
`KBDLLHOOKSTRUCT` で scan と拡張フラグが別フィールドになる層の話で、Scancode Map の u16 には当てはまらない。
引用するなら「分けて持つと同型の取り違えが起きるので1つの値で持つ」)。表は `scancode_pairs.rs`(`scancode_map.rs` の
`SCANCODE_CAPS_EISU` などを使う。`awase-vkmap` は VK→`PhysicalPos` の表でスキャンコードを持たない)に置く。

| キー | scancode | 備考 |
|---|---|---|
| 左 Ctrl | 0x001D | |
| 左 Alt / 右 Alt | 0x0038 / 0xE038 | 右 Alt は US 配列など、物理キーがある配列のみ |
| スペース | 0x0039 | 親指キーの設定とぶつかりうる(下記) |
| 無変換 / 変換 / かな | 0x007B / 0x0079 / 0x0070 | JIS 配列のみ |
| 半角/全角(漢字) | 0x0029 | JIS 配列では半角/全角、US 配列では `` ` `` の文字キー |
| 英数/Caps | 0x003A | **同じ物理キーの2つの呼び名**(JIS では英数キーが CapsLock の位置にあり、Shift+英数が CapsLock)。二重人格あり(下記) |

範囲は所有者の整理(背景)に合わせた初期値で、許可リストはデータなので表に足せば広げられる。Shift・右 Ctrl・Win・App は初期範囲に含めない
(要望が無く、組み合わせの検証対象を増やさない)。

- **配列依存は「新規作成の候補の表示」だけ**: JIS 専用キー(無変換・変換・かな・半角/全角)は JIS 配列のときだけ候補に出す
  (表示名も配列に合わせる。`0x0029` が文字キーになる US 配列では出さない。配列は config の `keyboard_model` で判定する)。
  Scancode Map はマシン全体の値で、配列は利用者ごとに違いうるので、**分類(Pair かどうか)は配列に依存させない**
  (JIS で書かれた `無変換⇄左 Alt` を US の利用者が開いても Pair として読め、解除できる)。
- **英数(0x003A)の二重人格は移動する**: `0x003A` を X と入れ替えると、X の物理位置が `0x003A` を出し、
  レイアウトドライバの「英数単独=`VK_DBE_ALPHANUMERIC`、Shift+英数=`VK_CAPITAL`」と、Shift/Ctrl/Alt+CapsLock の
  IME ショートカットが X に付いていく(ADR-111 決定1)。X が NICOLA の親指キー(config の `left_thumb_vk`/`right_thumb_vk` の実際の値から決める。既定は無変換/変換)なら、親指キーと Shift の
  同時押しで CapsLock が点灯する。**`0x003A` と親指キーのペアは、確認つき警告を出す**(禁止はしない)。
- **スペースを入れ替えるとき**: スペースは NICOLA の親指キーに設定できる(config の `left_thumb_vk`/`right_thumb_vk`)ので、スペースを
  無変換/変換などと入れ替えると、親指シフトの物理位置が動く。変換/無変換をスペースの位置に持ってくる使い方(通常の配列の
  キーボードで親指シフトを使う)が主な用途と思われるが、確認つき警告と同じ扱いで UI の説明に書く。スペースを Ctrl/Alt と入れ替えても
  押しっぱなしにはできる(通常のキー)が、IME の変換操作(スペースで変換)が入れ替え先のキーに移るのは意図どおりかを説明に書く。
- **NICOLA 親指キーとの相互作用**: awase の親指キー設定は VK(`left_thumb_vk` 等)で持つので、無変換/変換を
  入れ替えると親指シフトの物理位置が動く。UI の説明に書く。ADR-196 の学習表(キー効果)は VK 単位なので影響しない。
- **ログオン画面**: HKLM の値なのでログオン画面でも効く(ADR-111 決定3)。全単射なので打てないキーは生じず、
  Ctrl+Alt+Del も入れ替え後の位置で打てる(**推測**: Scancode Map はキーボードクラスドライバで効き、その上の win32k の
  SAS 判定は変換後の値を見るはず。未確認で、実機確認の項目)ので締め出しの危険は低い、と検討済みとして残す。入れ替え後に CapsLock が点いたままログオンすると大文字小文字が分かりにくい点だけ UI に書く。
- **押しっぱなしにできないキーの懸念は不要**: Scancode Map はキーボードクラスドライバで効き、キーボードレイアウト(JIS の
  vk 変換)より前に scancode を書き換える。入れ替えた位置のキーは、入れ替え先の scancode のキーとして OS に見える。フック
  ベースのリマップ(ADR-110)で問題になった「押下状態・Down/Up の非対称」は、この層には当てはまらない(所有者判断 2026-10-06)。
  参考の実測(JIS キーボード1台、フックで 1 秒押しっぱなしを記録): 半角/全角(0x29)・かな(0x70)も押している間 DOWN が繰り返され、
  押し続けられる。半角/全角だけは押下中に DOWN/UP が約 31 ms 周期で交互に出る(vk 0xF3/0xF4、レイアウト層の変換)が、
  Scancode Map はそれより前に効く。この機種には英数キーが無く(英数の位置を Ctrl に置き換えて使っている)、許可リストの「英数/Caps」は
  機種により物理キーが無い(候補は物理キーの有無に関わらず出す。分類には影響しない)。

### 決定3: 純粋関数(Linux でテストする)

用語: **「他ツールのエントリ」= `detect_swap_pairs(existing)` が Unclaimed と分類したもの**(書いた主体ではなく分類で定義する。
他ツールが偶然書いた許可リスト内の完全な入れ替えは、決定4 のとおり編集可能なペアとして見える)。

- `compute_swap_write(existing, pairs, caps_extra_ctrl) -> Result<WritePlan, SwapError>`。`pairs` は**編集後のペア集合の全体**
  (差分ではない)。内部で `detect_swap_pairs(existing)` を呼び、既存の Pair のうち `pairs` に無いものを削除対象にし
  (決定4 の「差分で書く」)、「他ツールのエントリ(Unclaimed)」は保持して書き込み全体を作る。`WritePlan` は
  `{entries, displaced, revealed}`(`revealed` は下記)。
- **検査は「書き込み後のエントリ列が、書き込み前より悪くならない」こと**: エントリ列として多対一・from 重複を**新たに**作らない
  (未登録のキーは自分自身を出す・from 重複でどちらが効くかは OS 依存で未確認、という実効の写像までは保証しない。下の `revealed`)。
  - ペアのキーが他ツールのエントリの **to** に現れる → `SwapError::CollidesWithForeignTarget{entry}`
    (例: 他ツールの `X→A` と `A⇄B` は X と B が両方 A を出す多対一になるため新規には止める)。
  - ペアのキーが他ツールのエントリの **from** に現れる → そのエントリは上書きで消えるので `displaced` に入れ、UI が
    「他ツールのエントリ `A→Y` を消します」と事前に確認する。
  - そのほか `SwapError`: キーの重複・許可リスト外(新規作成のみ)・自己ペア `A⇄A`・`CapsAsExtraCtrl` とのキー衝突。
  - **`displaced` は、追加するエントリと同じ値のものを含まない**(書く値が変わらないので確認は要らない)。
  - **`revealed`**: 消すペア・Caps 追加 Ctrl と同じ from を持つ、残る他ツールのエントリ。from が重複していたとき OS がどちらを
    効かせるかは未確認なので、消すと残った方が効き出しうる(Caps 追加 Ctrl を外す・ペアを外す・displaced を消す、どの操作でも)。
    書き込みを止める理由にはせず、UI が**全ての経路で**警告する(S13 の「`A→Z` が効くようになります」を一般化したもの)。
  - 消すものの照合は**値**で行い(同じ写像の複製は1つを消すなら全部消す)、残る他ツールのエントリとの多対一の検査は、
    消えるもの(消すペアと同値の複製を含む)を除いて行う。
  - **削除だけの操作は常に通る**(読んだ時点で実在した2エントリを消すだけで、多対一も from 重複も新たに作らないので、
    上の規則から導ける。ただし後述の `revealed`)。他ツールが1件足されても、awase が書いた入れ替えを awase から解除できる(現行からの後退を作らない)。
- 出力順は「既存の保持分を既存の順、ペア分を末尾・入力順」に固定する(読み戻し検証が順序込みの一致比較
  〈`verified == new_entries`〉であり、ADR-126 M13 が順序を変えるなら多重集合比較にせよと警告しているため)。
- `detect_swap_pairs(entries) -> {pairs, caps_extra_ctrl: bool, unclaimed: Vec<(Entry, Reason)>}`。**分類は配列にも許可リストにも
  依存しない**(許可リストが効くのは新規作成だけ)。分類規則は次の表で、そのまま必須のテストケースとする。

  | 入力 | 分類 |
  |---|---|
  | `A→B`, `B→A`(他と交わらない) | Pair(許可リスト外でも Pair として読む。編集・削除は可、新規作成は許可リスト内のみ) |
  | `A→B`, `B→A` だが、別のエントリと交わっている(`C→A` など) | **Pair(警告つき)**。削除は常に許す。交わっている相手のエントリは Unclaimed |
  | `0x3A→0x1D` だけ | CapsAsExtraCtrl |
  | `Caps` が採用済みペアのキーで、同値の複製または同じ from の `Caps→左 Ctrl` がある | Unclaimed(from 重複)。ペアと Caps 追加 Ctrl は排他 |
  | `A→B` だけ(上記以外) | Unclaimed |
  | `A→B`, `B→C`, `C→A`(3巡回) | Unclaimed |
  | `A→B`, `B→A` がそろい、さらに同じ from の別エントリ(`A→Z`)がある | `A⇄B` は **Pair(警告つき)**、`A→Z` は Unclaimed(理由: from 重複)。削除は `A→B`,`B→A` の2件だけを消す。UI は「削除すると `A→Z` が効くようになります」と警告する(`A→Z` は他ツールが書いた値そのもので、多対一も from 重複も新たには作らないので「悪くならない」規則と整合) |
  | 同じ from が2件(上記以外) | **重複したエントリだけ** Unclaimed(他のエントリの分類には波及させない) |
  | `A→0x0000`(無効化)・`A→A`(恒等)・`0x0000→A` | Unclaimed |

- 性質テスト(実装は、乱数による大きめの宇宙と、E0 キー・0 を含む小さな宇宙の**全列挙**〈エントリ3件以下〉の両方):
  恒等(既存のペアとプリセットをそのまま渡すと入力と同じ列)/ 削除だけは常に成功/ 指定したペアは必ず読める/
  Caps 追加 Ctrl は指定どおりに読める(ペアが `Caps⇄左 Ctrl` に読み替わる場合と、重なっていた他ツールの `Caps→左 Ctrl` が
  単独になって読める場合を除く)/ 他ツールのエントリは、上書きされたもの・消したペアやプリセットと同じ写像の複製を除いて保持/
  エントリ列として from 重複・多対一を増やさない。比べるのはエントリの集合だけで、分類の理由は比べない。ADR の初期案より弱いのは、
  削除でペアが読めるようになる・同値の複製を全部消す、という実装の挙動を許すため(その方が現実的)。固定の回帰ケース:
  Opus コードレビュー round1 の B1・S1・S2・N2〜N4。
- 既存テスト `ambiguous_third_party_entry_colliding_with_swap_reverse_value_is_not_preserved`
  (`scancode_map.rs`)は、期待値を「`Caps⇄LCtrl` のペアに読む(従来の Swap 優先判定と同じ結果)」に更新して引き継ぐ。
  黙って消える問題は決定4 の全件表示で解消する。同様に `third_party_left_ctrl_remap_to_unrelated_key_survives_caps_extra_ctrl_enable_and_disable`
  (CapsAsExtraCtrl と他ツールの `0x1D→0x99` の共存)も引き継ぐ(新しい分類でも `0x3A→0x1D` 単独 → CapsAsExtraCtrl、`0x1D→0x99` → Unclaimed で成り立つ)。
- 旧 UI の Swap → CapsAsExtraCtrl 切り替えが UAC 1回で済んだ(ADR-126 決定5)ように、新 UI でも「`Caps⇄LCtrl` ペアの削除と
  チェックボックスのオン」を、`compute_swap_write` の1回の呼び出し(1回の適用・UAC 1回)で書ける。

### 決定4: 所有の記録を持たない。レジストリを唯一の真実とし、全件を表示し、読んだ状態との差分で書く

**取り下げた案**: 「awase が書いたペアを `cache.toml` に記録する」。理由:

- ADR-126「却下した代替案」が、まさにこのマーカー方式を「Scancode Map は OS レベルで awase の設定と独立して存在し続けるので
  同期が壊れる(アンインストール後に Scancode Map だけ残る、マーカーだけ消える)」として却下済み。
- `cache.toml` は exe と同じディレクトリにある、捨ててよい学習キャッシュ(BUG-108 の案内、学習キャッシュ削除)で、
  HKLM・全ユーザー共通のレジストリ値とは寿命も範囲も合わない。ユーザーごとの Scoop ディレクトリやポータブル展開では、
  同じ PC の別ユーザーの awase が記録を持たない。
- 書き込み主体がずれる(レジストリは昇格側、`cache.toml` はどちらが書くか未定で、2つの書き込みは原子的でない)。
- 食い違ったとき(他ツール・手動 regedit・別 PC)にユーザーへ見せるのは結局「今のレジストリの中身」で、記録は判断材料を増やさない。

**採用する方式**:

1. 読み込み時に `detect_swap_pairs` で、編集可能なペアと、読み取り専用の一覧(Unclaimed とその理由)を**全件表示**する。
2. 書き込みは「読んだときのエントリ列」と「編集後のペア集合」の**差分**で計算する。削除したペアは、読んだ時点で実在した
   2エントリをそのまま消す。記憶した集合ではなく読んだ状態との差分なので、残骸も無関係なエントリの消去も起きない。
3. 他ツールが偶然許可リスト内の完全な入れ替えを書いていた場合は、編集可能なペアとして見える。見えている状態なので、
   ADR-126 の B1 型(見えない所で黙って消える)にはならない。「原理的限界」の実害は「見えない所で消えること」であり、
   全件表示で解消する。
4. 新しい永続状態・同期の失敗モード・アンインストール時の後始末は増えない。

### 決定5: 適用の流れ(ADR-111 の流れを土台に、新しい挙動を明記する)

- **昇格側への受け渡し**: CLI の列挙子1つ(`"swap"` など)から、ペア集合の列(例 `--scancode-pairs 3A-1D,7B-38`)と
  「UI が読んだエントリ列」に変える。昇格側は渡された値を信用せず、**許可リスト・自己ペア・重複を `compute_swap_write` で
  再検証**する。パース失敗は専用の終了コード。
- **比較交換(TOCTOU 対策)**: UI が読んでから UAC 承認まで時間があり、その間に他ツールや別ユーザーの awase-settings が
  値を変えうる。UI は読んだエントリ列を引数で渡し、昇格側が書く直前に読み直した値と食い違ったら、**書かずに専用の
  終了コードで戻る**(ユーザーが見て確認した差分と実際に書く差分を一致させる)。
- **承認フラグ**: UI が確認した `displaced`(他ツールの消えるエントリ)が空でないとき、昇格側は `--allow-displace` が無ければ書かない
  (UI を飛ばした呼び出しで他ツールのエントリが消えるのを防ぐ)。
- **壊れた既存値は上書きしない**: `parse_entries` は短すぎる・壊れた値を空リストにする(`scancode_map.rs`)。パースできない
  既存値があるときは、空と誤認して上書きせず、書かずに専用の終了コードで戻る(現行コードにもある穴をここで塞ぐ)。
- **読み戻し失敗時の巻き戻しは新しい挙動**(現行の `run_elevated_worker_windows` は不一致で終了コード1を返すだけで、
  元に戻さない。ADR-111 決定3 も巻き戻しは無い)。次を新規に決める: 読み戻しが一致しなければ、書く前の値へ書き戻す。
  巻き戻し用に保存するのは**書く前の生のバイト列(または「値が無かった」事実)**で、パース済みのエントリ列では復元できない
  (巻き戻しは書き戻し、元が無かったなら `delete()`)。「書き込み成功・読み戻し不一致・巻き戻し失敗」の3段目も扱い、どの結果でも**今のレジストリの中身を読み直して**画面に出す。
- **ADR-127 との整合**: ADR-127 D4 がこのセクションを例外にしたのは「ラジオを押した瞬間に UAC→即時書き込み」で
  編集途中の状態が無いからだった。ペア編集は複数操作をまとめるので、このセクション専用の編集途中の状態と「適用」ボタンが
  要り、画面共通の「適用」と並ぶ2つ目になる(ADR-127 の発端の苦情の型)。対処: **このセクションの適用ボタンは
  「入れ替えを適用(要再起動)」と明確に別名にし**、ADR-127 側で「画面共通の適用とは別の操作で、レジストリにだけ書く」例外として明文化し、未適用の編集があるときの表示、タブ移動・終了時の破棄確認を
  ADR-127 に追記する。この追記を実装の前提条件とする。
- 反映には**再起動**が要る(サインアウトでは不十分。ADR-111 決定5 の訂正を引き継ぐ。高速スタートアップでは `shutdown /s` でも
  反映されないことがあるので、UI は「再起動」を求める)。画面が表示するのは「レジストリにある設定」で「今効いている入れ替え」ではない
  ので、適用後・再起動前は「再起動後に有効」と明示する。

## 非目標

- hook ベースのリマップ(ADR-110)、アプリごとに変わる割り当て、片方向・多対一の自由なマッピング。
- GJI のキーマップ(ADR-231)。2つを組み合わせる使い方(Caps を無変換にして、無変換に IME トグルを割り当てる)は
  同じ設定画面で2段階に案内する。

## 実装の段階(提案)

1. 純粋関数と検査(`awase-windows::scancode_map`、Linux でテスト。決定3 の表とプロパティテストを必須ケースにする)。
   **実装済み(段階1、`crates/awase-windows/src/scancode_pairs.rs`)**: `detect_swap_pairs`・`compute_swap_write`・`Pair`・
   `ALLOWED_SCANCODES`。決定3 の分類表と、削除の常時許可・恒等・往復・「悪くならない」の性質テストを含む。実装で決めた細部:
   `Pair` は `(小さい scancode, 大きい scancode)` に正規化する(書き込む2エントリは `lo→hi`, `hi→lo` の順)/ 完全に同じエントリの
   複製は、1つを消すなら全部消す/ Caps 追加 Ctrl との衝突検査は新規に作る分だけ(既存の同居状態も恒等・削除は通す)/
   Caps 追加 Ctrl を新たに足すときは、他ツールの `左 Ctrl→Caps` も上書き対象にする(残すと入れ替えに読み替わるため)。

3. **実装済み(段階3)**: 昇格 CLI `--scancode-pairs <spec>`(`awase-settings` の `scancode_map_admin::run_elevated_pairs_worker`)。
   判断の核は純粋モジュール `crates/awase-windows/src/scancode_apply.rs`(`ApplyRequest` の直列化・`decide`・`read_back_matches`・
   `WorkerExit` の終了コード)。引数形式は `pairs=0038-007B;caps=0;expect=003A>001D,001D>003A;displace=0`(スキャンコードは常に4桁の16進)。
   比較交換(`expect` と書く直前の値の食い違いは `Changed` で書かない)・壊れた既存値は書かない(`ExistingCorrupt`)・
   他ツールのエントリを消すなら `displace=1` が要る(`DisplaceNotApproved`)・読み戻しが一致しなければ書く前の生のバイト列
   (無ければ削除)へ戻す(`RolledBack`/`RollbackFailed`)。ただし読み戻した値が書いた値でも元の値でもない、正しく読める値のときは、
   書き込みと読み戻しの間に他の書き手が書いたとみなして巻き戻さず `Changed` で返す(`classify_read_back`、他の書き手の変更を消さない)。長さ 0 の既存値は失うものが無いので空として扱う。

   描画と入力の反映だけの薄い接着コードにした。所有者の決定(2026-10-06): ペア行+ドロップダウン/ワンクリックボタンは
   「英数/Caps ⇄ 左 Ctrl」と「変換 ⇄ スペース」/ 「英数 / Caps を追加の Ctrl にする」はチェックボックスで残す(オンのとき Caps と左 Ctrl は
   候補から消える)/ 注意が要る組(英数と親指キー、親指キーの移動、スペース)・他ツールのエントリが消える・隠れたエントリが効き出しうる
