# ADR-248: 旧UIの Custom 表を読んで、無変換/変換の効果を予測に使う

## 背景

MS-IME「以前のバージョンの Microsoft IME を使う」互換モードの利用者が、旧UIの詳細キーカスタマイズで無変換/変換などを
カスタムしていると、v2 の awase は期待どおり動かないという報告が散発している。v1 では動いていた。
v2 は IME 設定から役割を逆算して打鍵時に IME の開閉を予測する(ADR-191・199)が、互換モードの旧UIの割り当ては
読めず(`msime_native_key_role` は互換モード ON で無変換/変換/半角全角を受動にする、`key_effect_predictor.rs:772,781`)、
読めない窓(Chrome・Windows Terminal)では IME の状態が belief とずれる。
既定の MS-IME 本体の表(`MSIME_NATIVE`、新UIの値を前提)で予測すると、カスタム内容と食い違って誤予測にもなりうる。

ADR-197 はこの表を読む案を、「コード `CE` の検出が実挙動と相関しない」として撤回した。

## 実測(2026-10-10、CI スパイク。各セル n=1)

詳細は `docs/tasks/msime-legacy-keytable-findings-2026-10-10.md`。要点:

1. `keystyle=Custom` のときだけレジストリの表が効く。NATURAL・ATOK などの名前付きスタイルの `key`/`S4key` を書き換えても挙動は変わらない
   (`IMJPUEXC.EXE setkeytemplate <Microsoft_IME|IME_Standard|ATOK|VJE|WX>` で切り替えると挙動が変わる=内蔵表)。
2. 閉じた状態で押したキーは `Custom\S4key` が決める。`key` だけを書いても閉じた状態では無反応(「直接入力モードを使用しない」の ON/OFF に依らない)。
   → ADR-197 が見た「無反応」は `S4key` が無かったため。
3. 開いた状態(入力なし)で押したキーは `Custom\key`(6列を同じコードで埋めた実測)。開いた状態で IME を閉じるコードは `D5` だけだった。
4. 「直接入力モードを使用しない」(既定 ON)では、IME の「オフ」は conv=0x10(半角英数)で IME は閉じない(BUG-185 と同じ)。
5. `SerialNo` の更新や ctfmon の再起動は効果と無関係。UI の Apply は `keystyle`・`IMEUserName`・`option2`・`SerialNo` などを書く。
6. 各テンプレートの全表は採取済み(`setkeytemplate` 出力、ATOK/VJE/WX/MS-IME2000/NATURAL)。テンプレート別の変換キーの実効果は、
   `S4key` の 変換 行の有無と一致した(Microsoft_IME・IME_Standard・WX は開く、ATOK・VJE は開かない)。

## 決定(提案)

### 決定1: ADR-197 の結論を訂正する

「表の内容は挙動と相関しない」は、`keystyle=Custom` の `S4key`/`key` を揃えた実測では成立しない。ADR-197 に訂正を追記する
(決定1〜3〈実行時警告〉の撤回は、検出対象が `CE` のみだった点で今も妥当。本 ADR は別の検出方法で再構成する)。

### 決定2: 読む範囲

互換モード ON(`NoTsf3Override2=1`、ADR-197 決定4)かつ MS-IME 本体かつ `keystyle=Custom` のときだけ、
`StyleList\Custom\S4key` と `StyleList\Custom\key` の、**修飾なしの 無変換・変換**の行を読む(第一段)。半角/全角・英数・ひらがな・カタカナは未検証のため範囲外。
`keystyle` が名前付きスタイルのときは、実測した内蔵表(決定5)を使う。それ以外・読めない・パース失敗は従来どおり(予測しない)。
レジストリは読み取り専用(awase は書かない)。

### 決定3: 表から「効果の対」を作る

行の 1 列目を「閉じた状態の効果」、2 列目以降の最初の列(第一段は 2 列目)を「開いた状態(入力なし)の効果」とする:

- 閉じた状態: `S4key` の 1 列目。行が無ければ `key` の 1 列目へはフォールバックせず「既定(`MSIME_NATIVE` の既定挙動)」とする(実測 2)。
- 開いた状態: `key` の 2 列目(実測 3)。

コード→効果は **実測した表だけ**を持つ(`{変化なし, 開く, 半角英数(閉じない), 閉じる, 開く+モード変化, 不明}`)。
実測していないコードは `不明`=予測しない。2 列目以降の列と状態(入力中・変換中)の対応は未検証のため、入力中・変換中は予測しない。

### 決定4: 予測・役割・学習への接続

- 打鍵時予測(ADR-191): `KeyEffectKeymap::for_msime_native` の再割り当て判定(`muhenkan_reassigned`/`henkan_reassigned`、`key_effect_predictor.rs:881-882`)を、
  「Custom の表が読めて効果が既知」のときは表由来の予測に置き換え、それ以外は従来どおり `None`。
- 役割(ADR-199): 「閉:開く」かつ「開:閉じる」のとき `ImeToggle`、「閉:開く」のみなら IME-ON 専用、など対から導く。互換モードでの受動化(`msime_native_key_role`)は、表を読めたときだけ解除する。
- 指紋(ADR-196): 互換モード ON かつ Custom のときだけ、読んだ行のバイト列の要約を `msime_native_keymap_fingerprint` に足す(互換モード OFF/不明の利用者の指紋は不変にし、全員の学習表を一斉に失効させない)。

### 決定5: 名前付きスタイル

`Microsoft_IME`(NATURAL)・`IME_Standard`(MS-IME2000)・`ATOK`・`VJE`・`WX` の無変換/変換の閉・開の効果を、実測した定数表として持つ(`keystyle` の名前→対)。
開いた状態の実測が無いスタイルは、その側を `不明` にする。

### 決定6: 失敗は安全側

読めない・コードが未実測・行が重複・`keystyle` が未知のいずれも `不明`。誤予測を作るくらいなら予測しない(ADR-196 の方針)。

## 非目的

- awase が表を書き換える、旧UIを操作する。
- 新UI(`KeyAssignment*`)と旧UIの同時カスタムの調停。
- 修飾付き(Ctrl/Shift)、F キー、半角/全角などの第一段外のキー。

## 代替案

- A: 互換モードでは予測を止め、学習(ADR-195/196)に任せる。実装は小さいが、利用者に学習の実行を求め、読める情報を捨てる。
- B: 本 ADR(表を読む)。表が正確ならゼロ設定で効く。誤読のリスクは決定6で抑える。
- A と B は併用できる。B が `不明` のとき A へ落ちる。

## 未検証(再検証 CI の対象)

1. n=1 の再現性(各コード・各状態を n≥3)。
2. 開いた状態の 2〜6 列と状態(入力なし・入力中・変換中)の対応。
3. 「直接入力モードを使用しない」OFF での閉・開の挙動(`key` の 1 列目が使われるか)。
4. 名前付きスタイルの開いた状態の実効果(決定5の定数表の根拠)。
5. 実機の旧UI保存で作られる `Custom` が `S4key` を含むか(UI の Advanced ダイアログの操作)。
6. 無変換・変換以外(半角/全角・英数・ひらがな・カタカナ)と、修飾付き。
7. 互換モード OFF(新UI)のとき、`keystyle=Custom` が残っていても効かないこと(誤適用の防止)。
