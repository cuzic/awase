# ADR-228: 不具合報告に旧互換 MS-IME のキー表を載せるか

## 背景と事実

- 2026-10-04 のトリアージ(`docs/bug-reports-triage.md`、`01M4323W7NQTMJHQRY0MXRGY68`/`01M432DESNKDF19G33XZT41XC1`)。報告者は旧互換モード
  (`legacy_compat_mode_enabled=true`)・`keystyle=Custom`・無変換/変換にトグル割当て。症状は「英数で未確定文字が消える」(BUG-184)と
  「OFF→ON で表示は あ なのにローマ字」(BUG-185 の疑い)。
- **調査が止まった点**: 報告者の Custom 表で英数・ひらがな・変換・無変換が何に割り当たっているかが分からない。CI の再現(`sc-offrca-r6-*`、
  run 37231070630)は別の実機(dragonflyg4)の表を使っており、報告者の表と同じかを確かめられない。再現しなかった結果が「CI の条件では起きない」
  にとどまる一因。
- 今の添付: `legacy_msime_keymap = {active_style, muhenkan_ime_on_toggle, henkan_ime_on_toggle, legacy_compat_mode_enabled}`
  (`crates/awase-windows/src/bug_report.rs::BugReportLegacyMsImeKeymapSummary`)。`StyleList\<keystyle>\key` を読む
  `msime_legacy_keymap.rs` は既にあり、無変換/変換の 2 行だけを bool に畳んでいる。
- **過去の決定(本 ADR が向き合う相手)**:
  - ADR-148(F7 追記): `StyleList\Custom` の生バイナリは、ADR-095 の送信前プレビュー(JSON をテキストで読み・削れる)が**構造的に機能しない**
    ため送らない。「個人情報だから」ではなく「ユーザーが中身を読んで削る判断ができない」が理由。
  - ADR-197 最終結論: `StyleList\<style>\key` の記述を「そのキーが実際にどう動くかの真実」とすること自体が不適切(7 パターンの実機検証で
    コード `CE` の効果が再現しなかった)。実際の効果は ADR-195/196 の学習で測る。
- 表の形式(`msime_legacy_keymap.rs`): Shift-JIS のキー名=6 個の 16 進コード、をNUL 区切りで並べた REG_BINARY。コード `CE`(1 列目=直接入力→ON)
  以外の意味は未確認。
- 今回の報告では `keymap_learn.table_file="not_learned"`(学習結果なし)で、学習による実測は使えなかった。

## 選択肢

- **A. 何もしない / 報告者に聞く**: 報告者に `StyleList\Custom\key` の書き出しを頼む。追加実装なし。ただし毎回、報告者の手間と往復が要り、
  匿名の報告(連絡先なし)では聞けない。
- **B. 構造化して添付する(本 ADR の提案)**: 有効な `keystyle` の表から、**許可リストのキー名**(英数・ひらがな・カタカナ・半角/全角・無変換・変換・
  Ctrl+SPACE 等の IME 系)の行だけを、`{key: "英数", codes: [0x97, …6 個]}` として添付する。
  - **自由文字列が入らない保証**: キー名は固定許可リスト(表にあっても許可外は捨てる)、codes は 6 個の u8 のみ。ADR-148 F7 の
    「許可リストが唯一の防壁」の構造に揃え、未知トークンを payload へ流す経路を作らない(型 doc に明記)。
  - **プレビューで読める**: キー名は日本語、codes は 16 進の固定長。ADR-148 の反対理由(読めず削れない)は「キー名は読める・値は個人情報になり得ない
    固定長の数値」で解消する(要レビュー)。
  - 機能コードの意味は送る側で解釈しない(`CE`=トグル以外は未確認)。意味づけは調査側が表と突き合わせる。
- **C. 学習(ADR-195/196)に任せる**: 表の記述ではなく、キーを実測した効果を主とする。報告の `keymap_learn` を厚くする。実効の真実に最も近いが、
  学習が走っていない環境(今回)では何も得られない。B と排他ではない。

## 提案(未確定、レビュー待ち)

B を、**診断の手がかり**としてのみ添付する(ADR-197 の「表を真実扱いしない」を守る: awase の動作・警告には配線しない)。対象は
`legacy_compat_mode_enabled=true` かつ `keystyle` が既知のときに限る。`BugReportDiagnostics` へのフィールド追加(追加のみ、
`#[serde(default)]`、`SCHEMA_VERSION` は上げない=ADR-148 と同じ)。`crates/awase-settings/src/bug_report.rs` の同型と
`services/report-worker` の型(`legacy_msime_keymap: Record<string, unknown>`)は、既存のゆるい型で受かるか確認する。

## 未解決・レビューに聞きたいこと

1. 許可リストのキー名の範囲(IME 系だけか、全キーか)。全キーなら 84 行・数 KB で足りるが、許可リスト方式の防壁が弱くなる。
2. ADR-197 が「表の内容は効果と一致しない」と実機で確認しているのに、添付して調査の役に立つか。立つ場面(今回)と、誤解を招く場面を分けられるか。
3. プレビュー UI で codes の 16 進を見せて意味が通じるか(ADR-148 の反対理由への答えとして足りるか)。
4. 新 UI(`MSIME` 直下の DWORD)側は既に bool/enum で完結しており、本 ADR の対象外でよいか。
5. これが A(聞く)より価値があるか。匿名報告の割合と、今回のような「表が無いと止まる」ケースの頻度は、台帳 95 行のうち数えられる範囲で数えておく。

## 検証計画(実装する場合)

- 単体: 実機の `key` バイナリ(ADR-197 の 84 レコード)から、許可リストの行だけが出る・許可外・壊れた行は出ない(テストは `cargo test --lib` 相当)。
- 回帰: 型 doc の「自由文字列が入らない」を、`tests/architecture_guard.rs` かテストで固定(許可外キー名を入れても payload に出ない)。
- 実機: 報告者の次の報告に含まれるかを確認。CI では `legacy_custom='true'` の構成で添付の中身を確かめる。

## 結論(2026-10-04、所有者決定): 見送り

Opus r1(全文は本リポジトリに残していない。要点のみ)の判断を採る。**案 B は実装しない。**

- **B1(再現に使えない)**: ADR-197「その他の未検証事項」のとおり、`StyleList\Custom\key` をレジストリへ直接書く方法では無変換/変換の動作が 7 パターンとも変わらなかった。
  報告者の表は GUI で作られたもので、CI の表との差(未検証)は、表の中身をそろえても消えない。
- **B2(動機の 2 件で決め手にならない)**: `01M4323W…` は英数を報告者の `keys.ime_off` で awase が消費しており、MS-IME に届くのは VK_IME_OFF(Edge)か ImmCross(秀丸)。
  BUG-185 は旧互換モード(`sc-offrca-r5-legacy-noawase`、dragonflyg4 の表)でも `1a:typed_nc` 0/10 で、表と無関係に再現済み。変換キーの 1 列目が `CE` かは既存の bool で分かる。
  調査が止まっている本当の理由は、(1) 英数の前に未確定の文字があったか、(2) OFF→ON 後の conv の実測、の 2 点で、表では答えられない。
- **再開条件**: 「表の X 行が無くて調査が止まった報告」が出て、かつ CI でレジストリに書いた表が動作を変えると確認できたとき。そのときは Opus r1 の Must(キー名は復号せず生バイトの完全一致、
  修飾子・捨てた件数・重複行の順序・`S1key` 以降の対象外、値は 16 進文字列、`legacy_msime_keymap` の中に `#[serde(default)]` で足す、チェックボックス説明文の更新、ADR-148 F7 への答えを
  「読める」ではなく「形として個人の情報が入りえないと判断できる」に書き直す)を反映してから起こし直す。
- **代わりにやること**: ①Edge/WebView2/秀丸 × 旧互換モードで ADR-221 D1 / `sc-offrca-*` を回す、②journal に OFF→ON 直後の conv を記録する、③報告者に質問する(issue #138/#446)。
