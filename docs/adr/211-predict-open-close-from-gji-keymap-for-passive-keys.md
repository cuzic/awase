# ADR-211: 受動のキーが IME を開閉する設定でも、GJI のキーマップから予測して Engine が追随する

## 背景(事実と、事実でないもの)

**所有者の要望(2026-09-30)**: 受動ポリシー(awase が IME に書かないキー)のモードずれは許容する。ただし、GJI・MS-IME の設定で「内部状態によらず IME ON」や
「トグル」になっているキーは、受動で動作しつつ、**できる限り Engine が追随する**ようにしてほしい。どういうときに追随できないかは現状を調べる。

### 現状の追随手段(コードで確認)
1. **能動(awase が書く)**: ADR-199 の「トグルの役割」のキー(半角/全角、F13〜F24、無変換/変換の単独タップ)と、awase 自身の `keys.ime_on/off`。トグルの定義は
   「DirectInput が Open **かつ全ての開状態が Close**」(決定4・決定11)。
2. **受動+表の予測(打鍵時)**: `TableKey`(13キー: BS・英数・Enter・Esc・半角/全角・変換・ひらがな・IMEOff・IMEOn・漢字・カタカナ・無変換・Space)だけ。
   学習/同梱の表は素の EDIT(IMM32)で測ったものなので、TSF の窓では誤りうる(ADR-209: 変換)。
3. **受動+観測**: 読める窓では、通過マーク(`is_followed_mode_key` = 0x15-0x1A・0xF0-0xF6・変換/無変換)のキーの後に IME を読み直して追随する。
   読めない窓(TsfNative/Imm32Unavailable)には観測の手段が無い。

### 実測(GitHub Actions、実 Chrome、GJI、awase あり、IME OFF から各キー1回。run 36701610898、1構成2回、`sc-follow-chrome-*`)
| キー | ATOK プリセット | MS-IME プリセット |
|---|---|---|
| 半角/全角、`VK_IME_ON` | 開いて追随 | 開いて追随 |
| 変換 | 開いて追随 | 開いて追随(ADR-209) |
| 無変換 | 開いて追随 | 開かない |
| ひらがな、英数 | 開かない | 開いて追随 |
| **F13** | 開かない | **IME は開くが Engine は追随しない(`か`)** |
| F14 | 開かない | 開かない |

追随に失敗したのは MS-IME プリセットの F13 だけ。GJI のプリセット(`ms-ime.tsv`)で F13 は DirectInput の `IMEOn`(F13 の開状態の行は無い)なので、
ADR-199 のトグルではなく受動になり(決定4の当たらないキーの例に F13 が挙がっている)、上の3手段のどれにも当たらない。

### 設定の読み取りだけで上表が説明できるか(一部だけ確認、残りは未確認)
`role.rs` のテスト用 TSV(Mozc の `ms-ime.tsv`/`atok.tsv` の**抜粋**)で DirectInput が `IMEOn` の行は、MS-IME: F13・半角/全角・漢字・ON、ATOK: 半角/全角・**変換・無変換**・漢字・ON。
上の実測と照らすと、**確認できたのは**: MS-IME の F13 が開く、ATOK の変換・無変換が開く、半角/全角が開く、MS-IME の無変換が(抜粋に行が無く)開かない、の4点。
**未確認**: MS-IME の英数・ひらがなが開く、ATOK の英数・ひらがなが開かない、F14 が開かない、は抜粋に行が無い/あるかを見ていないので、実際の TSV(Mozc `data/keymap/`)で確認する必要がある(実装の最初の作業)。
**食い違いの既知の例**: MS-IME の変換。TSV は `Reconvert` だが実測は開く(ADR-209 の窓別の規則の対象)。

### 事実でないもの(このADRの前提にしない)
- 「GJI の設定を読めば必ず実際の挙動が分かる」ではない。変換は TSV(`Reconvert`)と実測(開く)が食い違う。設定由来の予測は**常に**この種の食い違いを持ちうる。
- 「読める窓では追随に困らない」は実測していない(本 ADR の CI は実 Chrome だけ)。

## 決定

1. **予測の源を GJI の実効キーマップへ広げる**(awase が IME に書くことは増やさない。ADR-191 決定1・ADR-199 決定3が許す「設定の読み取り」)。
   - 対象 IME は GJI(`config1.db` が読めるとき)。Microsoft IME 本体のレジストリ割り当て(値0=IME-オン・値1=IME-オフ)は**本 ADR では扱わない**(実機で予測の効果を測っていない。下の「未検証」)。
   - 実効キーマップ: プリセット(ATOK/MS-IME/KOTOERI/MOBILE)は定数表、`session_keymap=CUSTOM` で表が空でなければ状態表(ADR-199 決定4と同じ継承規則・後勝ち)。
     `role.rs::key_role` が既に作っている評価の部品(`classify_command`・状態の継承)を再利用し、判定を1箇所にする(2箇所に手書きしない)。
   - overlay は ADR-199 と同じ扱い: `OVERLAY_HENKAN_MUHENKAN_TO_IME_ON_OFF` なら変換/無変換は予測しない、未知の overlay は全キー予測しない。
2. **予測する内容(開閉だけ。モード・段階は予測しない)**:
   - **開く**: 閉状態(DirectInput)の実効コマンドが Open(`IMEOn`・`CompositionMode*`・`InputMode*`。ADR-199 決定4・決定13。T1(c) で開くと確認済み)で、
     **かつ全ての開状態が Close ではない**キー(全ての開状態が Close なら既存のトグル=能動の対象で、`shadow_action` を持つ間はこの経路に来ない)。
   - **閉じる**: **全ての開状態(Precomposition・Composition・Conversion、継承後)の実効コマンドが Close**(`IMEOff`・`CancelAndIMEOff`)で、
     **かつ DirectInput が Open ではない**キー(方向固定の純粋な OFF キー)。開状態のうち一部だけ Close のキーは、入力の段階に依存するので予測しない
     (段階の追跡は不確実。初期範囲では安全側)。
   - 上記以外(Open でも Close でもない、未知のコマンド)は予測しない。belief が `Unknown` のときは既存の種(`kana_mode()`)を使う(ADR-209 決定2と同じ)。
3. **範囲**: 無修飾の物理キーの打鍵(ADR-199 決定5と同じ。injected・修飾付きは対象外)。初期範囲のキーは限定しない(TSV/表が引くキー名の全て。`mozc_key_vk_names` で VK に解決できるもの)。
   既に他の手段が扱うキーは除く: `shadow_action` を持つ(能動)・同期キー(`sync_direction`)・エンジンが消費した打鍵(文字キー等)。
4. **優先順位**: (a) ADR-209 の窓別の規則 → (b) 学習/同梱の表(13キー、既存) → (c) **本 ADR の設定由来の規則(表に無いキーだけ)** → (d) 打ち切り。
   表が持つ13キーには設定由来の規則を当てない(検証済みの既存の挙動を変えない)。ただし**設定由来の規則を13キーにも当てたときの答えが、同梱表・上の実測と食い違わない**ことをテストで固定する
   (食い違いは既知の例外だけ許す: MS-IME の変換)。将来13キーを設定由来へ寄せる判断の材料にする。
5. **BUG-157 の揃えを保つ**: 予測が開閉を動かしたキーの後、`desired_open` を観測へ揃える通過マークが立たないと BUG-157(明示意図が観測の直後に残る)が退行する
   (`key_effect_predictor.rs` のテストが「予測が開閉を変えるキーは通過マークの対象」を全表で固定している)。設定由来の予測が開閉を動かしたキーにも通過マークを立てる
   (対象を `is_followed_mode_key` の固定集合から「予測が開閉を動かしたキー」へ広げる。F13 等の観測の読み直しも同時に走る=読める窓では観測が予測を訂正する)。
6. **止める設定**: 新しい bool 設定(名前は実装時、既定は有効)を1つ置く。ADR-209 の設定とは別(規則の由来が違うので、片方の偽動作をもう片方ごと止めない)。
7. 新しいイベント・I/O・actuation の合流点・tuning 定数は作らない(fence は既存の `KEY_EFFECT_SETTLE_MS`)。

## 検証方針
- **単体テスト(Linux で走る `state/` と `awase-gji-config`)**: 設定由来の予測の純関数を、(i) 上の実測表の全セル(ATOK/MS-IME × ime-on・変換・無変換・英数・ひらがな・半角/全角・F13・F14)に対して、
  実際の Mozc TSV から作った定数表が、MS-IME の変換以外で実測と一致すること、(ii) 13キーで同梱表と一致すること(既知の例外を除く)、(iii) CUSTOM で「閉状態のみ IMEOn」「全開状態のみ IMEOff」「一部の開状態だけ IMEOff」「overlay」を固定。
- **CI(既存の `sc-follow-chrome-*` をそのまま合否に)**: 実装後、MS-IME プリセットの F13 が「開いて追随(`きう`)」になること。CUSTOM 表で F14=IMEOn(閉状態のみ)と F15=IMEOff(全開状態)を割り当てた構成も足す。
  awase 停止(`--no-awase`)の対照で「IME が実際に開く/閉じる」ことを確認し、予測が実挙動と食い違う構成を検出する。
- **実機(dragonflyg4)**: 実 Chrome・WT・メモ帳・Edge で F13 等を押し、偽 ON/偽 OFF が無いこと。

## 未検証(このADRの範囲外に置く)
- 読める窓(メモ帳・Firefox・Office 等)での実測。予測が観測と食い違ったとき、観測が訂正すること(`[key-effect-miss]`)。
- Microsoft IME 本体のレジストリ割り当て: 値0(IME-オン)・値1(IME-オフ)の無変換/変換は、現状は「明示値なら予測しない」(ADR-199 T12・決定C R3)。実機で効果を測るまで本 ADR に含めない。
- 窓の種類ごとに「設定どおりに開かない」窓が無いか(変換の TSV と実測の食い違いの逆パターン)。読めない窓では偽 ON を自動で直せないので、CI と実機の窓を広げて確認する。
- 第三者の IME(ATOK 本体など)は対象外。

## 非目的
awase が IME に書く範囲の拡大(ADR-191 決定1)、入力モード・入力中の段階の予測、修飾付きのキー、トグル(能動)の判定の変更(ADR-199)。

## 代替案
- **A: 学習表に F13〜F24 等を足す**: 学習は素の EDIT(IMM32)で測るので、TSF の窓で誤る(変換で実証済み、ADR-209)。学習の対象キーを増やしても同じ限界がある。
- **B: `keys.ime_detect` に手で書いてもらう**: 設定の二重管理になり、ユーザーが GJI の設定を変えたとき食い違う。既存の静的規則(VK 固定)は残るが、これを主にはしない。
- **C: 読めない窓で打鍵ごとに実 IME を読む**: 読めないのでできない。
- **D: awase が F13 等を能動に昇格する(Suppress して絶対指定で書く)**: ADR-199 が能動を「トグルの役割」に限定した所有者決定に反する(受動ポリシー)。

## リスク
1. **偽 ON/偽 OFF**: 設定(TSV)と実挙動が窓の種類で食い違うと、読めない窓で誤る(変換の TSV=`Reconvert` と実測=開く、が前例)。緩和: 設定で止められる・読める窓は観測が訂正する・CI で窓の種類ごとに合わせる。
2. **CUSTOM 表の評価の誤り**: 継承規則・後勝ちを `role.rs` と共有して1箇所にする(決定1)。
3. **BUG-157 の退行**: 通過マークの対象を広げる(決定5)。全表テストの前提が変わるので、テストを「予測が開閉を動かすキー = 通過マークの対象」へ書き換える。
