## Nice-to-have（確定の妨げにはならない）

### N1. `platform_state.rs:771` の doc コメントに `**` の対応崩れと句読点の順序ミスがある

`crates/awase-windows/src/state/platform_state.rs:770-771`:

```rust
/// `ConvOpenInference`(`DeriveMedium`枝) に効かない）、**本関数は意図的に
/// 無改造のまま据え置く**。）** `effective_open()` は
```

この doc ブロックには `**` が4つある（`**belief 由来の…`／`、**本関数は…`／
`…据え置く**`／`。）**`）。Markdown は近い順にペアリングするため、

- 1つ目と2つ目がペア → 「belief 由来の暫定ゲート（…効かない）、」が bold
- 3つ目と4つ目がペア → 「。）」だけが bold

となり、**強調したい「本関数は意図的に無改造のまま据え置く」が bold にならず、
代わりに「。）」が bold になる。** 旧版は `（…置換予定、まだ未配線）。**` で
括弧の外に閉じ `**` があり整合していたが、括弧内に新しい `**…**` を入れたことで
入れ子が壊れた。

あわせて `据え置く**。）**` は句点と閉じ括弧の順序が逆（日本語表記としては
`据え置く）。` が正）。

修正案（内側の `**` を外すのが最小）:

```rust
/// `ConvOpenInference`(`DeriveMedium`枝) に効かない）、本関数は意図的に
/// 無改造のまま据え置く）。** `effective_open()` は
```

`ime_model.rs` 側の追記（`:363-367`）は `**ただし TsfNative の…据え置かれている。**`
が独立した1組になっており、こちらは壊れていない。

### N2. ADR-132 の「次のアクション」1 には委譲の注記が無い

ADR-172「次のアクション」4 は **ADR-132 の 1 と 2 の両方**を引き継ぐと書いている
（「ADR-132「次のアクション」1・2を引き継ぐ」）。しかし `docs/adr/132-*.md` 側で
注記が入ったのは **2 だけ**（`:988-992`）で、1（`:982-984`、grep 突合せによる
内訳確定）には何も追記されていない。

ADR-132 の 1 だけを読んだ人には、そのタスクが ADR-172 側に移ったことが分からない。
2 に付けたのと同種の1行（「内訳確定は ADR-172『次のアクション』4 が引き継ぐ」）を
1 にも足すと、どちらの ADR から入っても同じ結論に着く。

## 総評

round1 で6件、round2 で3件の Blocker が出た後、**実装を強行せず「実装しない理由と、
次に触る人が同じ罠を踏まないための技術的知見」を残す形に着地させた**のは妥当な判断である。
特に:

- round2 B2 の知見（`ConvOpenInference` は `DeriveMedium` 枝で決着するため
  `most_recent_trusted()` ベースの述語では効かない、`BaseDecision` を使うこと）が
  申し送り項目6 に保存され、コード側 doc にも反映された。**捨てた設計から使える知見だけを
  抽出して残す**という、このリポジトリの `.claude/rules/experiment-logging.md` が
  求めている形になっている。
- round3 B1 の修正により、「実害が出るまで触らない」に発火条件付きの検知経路が付いた。
  これが無ければ本 ADR は「先送りの言い訳」と区別が付かなかった。

N1 は1行の整形修正なので、ADR 確定と同じコミットに含めることを推奨する。
