# ADR-248: 「キーの入れ替え」画面の分かりやすさの改善

## 背景

ADR-230 段階4で「キーの入れ替え」画面(`crates/awase-settings/src/main.rs` の `scancode_map_section`/`scancode_editor_ui`、
状態と文面は `crates/awase-windows/src/scancode_editor.rs`)を実装した。所有者が操作して「ちょっと分かりにくい」と感じた
(2026-10-10。どの操作で迷ったかの具体は未聴取)。

2026-10-10 に次の2つを調べた。
- 現状画面の要素・文言・操作の流れの読み取り(コードから。利用者の反応を見たものではない)。
- 先行事例の調査(出典付き。ユーザーレビューの一次情報は多くは集まらず、画面そのものを見ていないツールもある)。

## 現状のずれ(先行事例のベストプラクティスとの比較)

| # | 現状 | 先行事例が示す方向 |
| --- | --- | --- |
| 1 | 説明文が1ブロック5行。「再起動が必要」が、リモートデスクトップ・高速スタートアップの注意と同じ重さで並ぶ。「Scancode Map」は専門用語 | 再起動が要る方式(SharpKeys・KeyTweak)は書き込み前後で状態を明示する |
| 2 | 画面全体の「適用」と、入れ替え用の「入れ替えを適用(要再起動)」の2つ。違いは説明文末尾の1文だけ | 現在の状態と未保存の変更を分けて見せる(既存ツールでは確認できず、awase 側の工夫余地) |
| 3 | ワンクリックボタンとチェックボックスは、無効のとき理由を出さずグレーアウトする | 持っていない・使えないキーは外すか注意を出す(PowerToys FAQ) |
| 4 | 「英数/Caps ⇄ 左 Ctrl」(ペア)と「英数 / Caps を追加の Ctrl にする」(チェック)が、名前が似て同じ場所に並ぶ。動作は別(左 Ctrl が英数位置へ移る/左 Ctrl は残る) | GNOME は `swapcaps`(入れ替え)と `nocaps`(置き換え)を別の名前付き選択肢にしている |
| 5 | ドロップダウンのみ。ボタン名「英数/Caps」とドロップダウン「英数 / Caps」で表記も不揃い | 一覧と「押して指定」の併用(PowerToys・SharpKeys)。ただし押下検出は割り当て済みキーや Fn で誤判定する(SharpKeys FAQ) |
| 6 | 「元に戻す」(編集を破棄)と「読み直す」(確認なしで編集を破棄してレジストリを再読込)の違いが不明。キーボードが使えなくなったときの復旧手順は画面のどこにも無い | 元に戻す導線を目立たせる(macOS の Restore Defaults)。SharpKeys の復旧(セーフモードで削除)は作者が自己責任としており最も弱い |
| 7 | 他ツールの項目で許可リスト外のキーは `0x003A` のような16進で出る | 利用者に読めない内部表記は出さない |
| 8 | 成功後に「適用しました…再起動が必要」と「適用した変更は、再起動後に有効になります。」が重複する | 状態は1箇所で示す |

## 決定(案)

比較交換・読み戻し・昇格 CLI の骨格は変えない。変えるのは画面の構成と文面、およびペアから置換への表現の一般化(決定6)である。

1. **状態行を画面の先頭に置く。** 見出しの直下に1行、次のいずれかを出す: 「入れ替えなし」「適用済み(有効)」
   「適用済み。再起動後に有効になります」「未適用の変更があります」。「再起動が必要」は説明文から外し、この状態行で示す。
   「適用済み。再起動後に有効」は、適用に成功してから再起動するまでの間(レジストリの値と、起動時に効いている値が食い違う間)に出す。
   起動時に効いている値の取り方は未決(Q2)。
2. **「適用」を入れ替え画面の1つにする。** 画面全体の「適用」(設定ファイルの保存)との違いは、ボタンの文言と置き場所で示す。
   入れ替えのブロックは枠で囲み、その枠の中に「入れ替えを適用」を置く。説明文の「別です」の1文は不要になるので削る。
3. **「入れ替え」と「追加の Ctrl」を別の見出しに分ける。** 見出しは「キーを入れ替える(A ⇄ B)」と「Caps を Ctrl としても使う」。
   ワンクリックのボタンは前者の見出しの下へ、チェックボックスは後者へ置く。後者の補足は「元の左 Ctrl は残ります。英数キー自体は使えなくなります」を
   見出しの説明に移す。ボタン名とドロップダウンの表記は1つの表記に統一する(「英数 / Caps」)。
4. **無効の理由を、そのコントロールの隣に出す。** 他の行で使用中/Caps 追加 Ctrl がオン/US 配列で JIS 専用キー、の3条件
   (`scancode_editor.rs` の利用可否判定)ごとに短い文言を返す純粋関数にし、グレーアウトしたボタンとチェックボックスの下に小さく出す。
   理由は判定関数と同じ場所で作り、判定と文言がずれないようにする。
5. **画面上のキーボード図に、機能をドラッグ&ドロップして割り当てる(所有者提案、2026-10-10)。**
   - 図には、許可リスト(`ALLOWED_SCANCODES`)の10キーの**物理位置**だけを描く(下段と左端の一部。キーボード全体は描かない)。
     各位置は、いま**その位置で出る機能**のラベルを持つ。機能のラベルを別の位置へドロップすると、2つの位置の中身が入れ替わる。
     入れ替えた位置は色を変え、元の機能と違うことが一目で分かるようにする。もう一度ドロップして元の位置へ戻せば、その入れ替えは消える。
   - 図の位置は「キー(物理)」、中身は「機能(出力)」と、見出しで区別する(今の「A ⇄ B」は両方が同じ言葉で出て紛らわしい)。
   - クリックで2つの位置を選んで入れ替える操作も併設する(ドラッグしにくい環境の逃げ道)。
   - JIS 専用キー(無変換・変換・かな・半角/全角)は US 配列では位置ごと図から隠す。
   - キー押下の検出はしない。ADR-110 は再導入せず、無変換・変換・英数が IME に奪われるかという懸念(Q1)は不要になる。
   - 「Caps を Ctrl としても使う」は多対一で全単射ではないので、図の外のスイッチ(決定3)に置く。
   - ワンクリックの2つ(英数/Caps ⇄ 左 Ctrl、変換 ⇄ スペース)は、図の上で2つの位置を入れ替える動作のショートカットとして残す。
6. **置換を3つ以上の循環まで許す(所有者判断、2026-10-10)。** 図の操作は置換の合成なので、2回の入れ替えで3巡回(A→B、B→C、C→A)ができる。
   ペアだけに制限すると「入れ替え済みの位置には落とせない」という余計な規則が UI に要るため、核を一般化して許す。
   - 表現: 「位置 → 機能」の対応(許可リスト内の全単射)を単位にする。レジストリへは、位置と機能が違う位置ごとに1エントリを書く
     (長さ2の循環は従来の `A→B`・`B→A` の2エントリと同じ)。既存のペアは長さ2の循環として読める。
   - `scancode_pairs.rs` の `Pair`・`detect_swap_pairs`・`compute_swap_write` を置換へ一般化する。ADR-230 決定3の分類表の
     「3巡回は他ツールの項目(`NotPair`)」の行は、「許可リスト内で閉じた循環は編集できる置換として読む」に置き換える
     (許可リスト外のキーを含む循環・多対一・片方向は従来どおり他ツールの項目)。許可リストの制約(新規に作るエントリのキーのみ)・
     Caps 追加 Ctrl との衝突・他ツールの to との衝突の検査は、置換の各エントリに適用する。
   - `scancode_apply.rs` の比較交換・読み戻し・巻き戻し・`displace` は、エントリ単位で動くので変えない。`ApplyRequest` の
     `pairs=` は置換の表現(例: `perm=003A>001D,001D>003A`)へ置き換える(書式は実装時に決め、ADR-230 段階3の引数形式を改訂する)。
   - 長い循環を安全側に倒すため、書く前の確認ダイアログに、変わる位置の一覧(位置 → 機能)を必ず出す。
7. **元に戻す導線と復旧手順を整える。**
   - 「元に戻す」(編集を適用済みの状態へ戻す)の1つに寄せ、「読み直す」はエラー時と、外部で変わった疑いがあるときだけ出す。
   - 破棄を伴う操作は、未適用の編集があるときだけ確認を出す。
   - 画面の折りたたみ「困ったとき」に、復旧手順(再起動前なら「元に戻す」→適用。キーボードが使えない場合は、セーフモードで
     `HKLM\SYSTEM\CurrentControlSet\Control\Keyboard Layout` の `Scancode Map` を削除する)を書く。確認できた手順だけを書く(Q3)。
8. **内部表記を出さない。** 他ツールの項目で許可リスト外のキーも、日本語名の一覧(スキャンコード→名前の表)で引き、
   引けなければ「不明なキー(0x003A)」と書く。
9. **成功後の案内を1箇所にする。** 決定1の状態行と「今すぐ再起動…」だけにし、結果メッセージの重複を削る。
## 段階(提案)

1. 文面と構成だけの変更(決定1〜4・8・9)。`scancode_editor.rs` に状態行・無効理由の純粋関数を足し(Linux でテスト)、
   `main.rs` は描画だけを変える。ADR-230 の純粋関数・昇格 CLI は触らない。
2. 置換への一般化(決定6)。`scancode_pairs.rs`・`scancode_apply.rs` の `ApplyRequest`・`scancode_editor.rs` の状態を置換にする。
   性質テスト(悪くならない・往復・削除は常に許可)は小さい宇宙の全列挙で置換に書き直す。ADR-230 に改訂を追記する。
3. キーボード図とドラッグ&ドロップ(決定5)。2の上に載せる。egui のドラッグ&ドロップ(`dnd_drag_source`/`dnd_drop_zone`)の挙動と、
   クリック2回の併設を確かめる。
4. 元に戻す導線と復旧手順(決定7)。
5. 実機での画面確認。ADR-230 段階5の実機確認と同じ機会にまとめる(UAC・再起動が要るため)。

## 未確認(Q)

- **Q1** (決定5でキー押下の検出をやめたので不要。取り下げ。)
- **Q2** 「起動時に効いている値」の取り方。レジストリの値と効いている値の食い違いを検出できないなら、決定1の「再起動後に有効」は
  適用から再起動までを awase が覚えている間だけの表示になる(再起動を挟むと消える)。
- **Q3** 復旧手順に書くセーフモード・レジストリ削除が、日本語 Windows 11 でこの形のままで通るか(実機)。
- **Q4** ワンクリックの2つ(英数/Caps ⇄ 左 Ctrl、変換 ⇄ スペース)が実際によく求められる入れ替えかの頻度の裏取りは取れていない。
  調査で出てきた話題は、Caps を Ctrl にする系と、無変換・変換を IME オフ/オンにする系だった。
- **Q5** 所有者が実際にどこで迷ったかを聞いていない。聞いて決定の優先順位を見直す。
- **Q6** 循環の長さと、許可リストの10キーでの組合せ数(10! 通り)に対し、書き込み・読み戻し・確認ダイアログの文面が破綻しないか。
  小さい宇宙(許可リストを縮めた全列挙)で性質テストを回して確かめる。
- **Q7** 同じ from のエントリが複数あるときドライバがどちらを効かせるか(ADR-230 の未確認)。置換では from が重複しないので、
  この問題は自分の書き込みでは起きない(他ツールとの重複だけ)。

## 非目標

- 比較交換・読み戻し・巻き戻し・`displace` の意味論の変更(決定6のとおり、表現はペアから置換へ一般化するが、書き込みの骨格は保つ)。
- GJI のキーマップ(ADR-231)。
- hook ベースの入れ替え(ADR-110)、片方向・多対一の自由なマッピング。
- キーボード全体の図(許可リスト外のキーを含む図)。決定5の図は許可リストの10キーの位置だけ。
- 許可リスト外のキーを含む置換、多対一・片方向の写像。
