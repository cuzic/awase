# ADR-248: 「キーの入れ替え」画面の分かりやすさの改善

## 背景

ADR-230 段階4で「キーの入れ替え」画面(`crates/awase-settings/src/main.rs` の `scancode_map_section`/`scancode_editor_ui`、
状態と文面は `crates/awase-windows/src/scancode_editor.rs`)を実装した。所有者が操作して「ちょっと分かりにくい」と感じた
(2026-10-10。どの操作で迷ったかの具体は未聴取、Q5)。

2026-10-10 に次の2つを調べた。
- 現状画面の要素・文言・操作の流れの読み取り(コードから。利用者の反応を見たものではない)。
- 先行事例の調査(調査エージェントの要約。出典のページ原文との突き合わせは未了で、下表の右列は「示唆」であって断定ではない。
  Opus round1 が、SharpKeys の案内が「ログオフまたは再起動」だった記憶、PowerToys の doc が「割り当てられないキーの一覧」であること、
  GNOME Tweaks が `swapcaps` と `nocaps` を同じ「Ctrl の位置」グループ内に並べていることなどを指摘している)。

## 用語

「位置 P は機能 σ(P) を出す。レジストリのエントリは `(P, σ(P))`(from=押した位置のスキャンコード、to=出る機能のスキャンコード)」と定義する。
Scancode Map は連鎖しない(`A→B, B→C` で A を押すと B が出る。C にはならない。広く知られた挙動という推測で、一次資料の確認はしていない)。
図の「位置」は物理キー、「中身」は機能。ADR-230 の `Pair` は σ が長さ2の循環の場合(`A→B`, `B→A`)。

## 決定(案)

比較交換・読み戻し・昇格 CLI の骨格は変えない。変えるのは画面の構成と文面、およびペアから置換への表現の一般化(決定6)である。

1. **状態行を画面の先頭に置く。2軸を1語ずつ並べる。** 見出しの直下に1行、次の2軸を並べる。
   - 軸A「レジストリと起動時の値の関係」: 一致 / 再起動待ち / 不明(壊れた値・読み取りエラー・書き込み結果不明〈`RollbackFailed` 等。その場の表示だけで、設定画面を開き直すと LastWriteTime 方式の「再起動待ち」になる〉)。
   - 軸B「編集」: なし / 未適用あり。
   - 文言は軸の組合せ全部を純粋関数にして `scancode_editor.rs` に置き、全組合せをテストする(決定4 と同じ考え方)。
     「入れ替えなし」は、レジストリが空で軸A が一致のときだけ使う(すべて解除して適用した直後は軸A が再起動待ちなので出さない。
     他ツールのエントリだけがある場合は「他のツールの設定があります」と言う)。
   - 「再起動待ち」の判定は Q2 の実測が前提で、**Q2 が解けるまで「有効」と断定する文言は使わない**(使うなら「レジストリに設定があります。
     再起動していなければ、まだ効いていません」)。今の画面のプロセス内フラグ(`scancode_restart_pending`、`main.rs:514-515`)だけでは、
     再起動前に設定画面を閉じて開き直すと「有効」と誤表示する。
   - 説明文から「再起動が必要」を外し、状態行と適用ボタンの近くで示す。「Scancode Map」の語は説明文から外す(用語集の折りたたみへ)。
2. **入れ替えの適用を、枠で区切って画面共通の「適用」と見分ける。** 一本化はしない(ADR-127 の例外は残る)。入れ替えのブロックを枠で囲み、
   枠の中に「入れ替えを適用」を置く。説明文の「別です」の1文は枠の見出しの副題(「設定ファイルとは別に、すぐ書き込みます」)へ移す。
   代案は、「キーの入れ替え」を画面共通の「適用/キャンセル」が出ない独立したタブ(またはウィンドウ)へ移すこと。ADR-127 の例外がいらなくなるが、
   画面の構成が大きく変わるので、枠で区切る案を先に出し、まだ紛らわしいと分かってから検討する。
3. **「入れ替え」と「追加の Ctrl」を別の見出しに分ける。** 見出しは「キーの位置を入れ替える」と「Caps を Ctrl としても使う」(「A ⇄ B」は
   循環と食い違うので使わない)。ワンクリックは前者の見出しの下、チェックボックスは後者へ置く。後者の補足は
   「元の左 Ctrl は残ります。英数キー自体は使えなくなります」を見出しの説明に移す。ボタン名とドロップダウンの表記を統一する(「英数 / Caps」)。
4. **無効の理由を、そのコントロールの隣に出す。** 他の行で使用中/Caps 追加 Ctrl がオン/US 配列で JIS 専用キー、の3条件
   (`scancode_editor.rs` の利用可否判定)ごとに短い文言を返す純粋関数にし、グレーアウトしたボタンとチェックボックスの下に小さく出す。
   理由は判定関数と同じ場所で作り、判定と文言がずれないようにする。
5. **画面上のキーボード図に、機能をドラッグ&ドロップして割り当てる(所有者提案、2026-10-10)。**
   - **図の位置**: 「許可リスト(`ALLOWED_SCANCODES`、9キー。英数と Caps は1項目)∩ 現在の配列」の位置に、
     「いまの入れ替えに含まれる、許可リスト内の位置」を足したものを描く(隠すのは、何も入れ替えていない JIS 専用キーだけ)。
     US 配列で表示に戻した JIS 専用キーの位置は「戻す(解除)専用」にし、ドラッグ元にもドロップ先にもしない(`Locked{releasable: true}`)。
     US キーボードに無い物理キーへ新しく機能を割り当てると、スペースなどが打てなくなるため。配列で候補から外れるキーへの新規作成の禁止は、
     行の UI の `candidates` と同じ関数で決める。
     許可リスト外の位置を含む編集できる入れ替え(ADR-230 決定2・3 の「許可リスト外でもペアとして読む」の一般化)は、図の下に一覧で出し
     「解除」ボタンを付ける。新規に作る・変えるときだけ許可リストを当てる。
   - **位置の状態**: 位置ごとに `PositionState = Editable{function} | Locked{label, reason, releasable}` を純粋関数で決め、図は描くだけにする。
     「動かせない(ドラッグ・ドロップ不可)」と「解除できる」は別の性質で、**awase の編集できる入れ替え(警告つきを含む)に属する位置は、
     `Locked` でも `releasable: true`** とし、「この位置を戻す」(=その入れ替えを解除。核では削除なので常に通る)を出す。
     `Locked` になるのは次の位置。
     ①Caps 追加 Ctrl がオンのときの英数/Caps と左 Ctrl(`CapsExtraConflict`。`releasable` は Caps 追加 Ctrl のスイッチで外す)。
     ②他ツールのエントリの from になっている位置(`releasable: false`)。
     ③他ツールのエントリの to に現れる機能の位置(動かすと `CollidesWithForeignTarget`)。awase の `A⇄B` に他ツールの `C→A` が交わる警告つきペアなら
     `releasable: true`。
     ④from が重複している位置。awase の `A⇄B` に `A→Z` が追記された警告つきペアなら `releasable: true`。
     ⑤他ツールの片方向(`releasable: false`)。
     ⑥許可リスト外の位置を含む、編集できる入れ替え(決定6 の分類で編集できるもの)に関わる位置(`releasable: true`、解除は図の下の一覧と同じ)。
     ⑦US 配列で表示に戻した JIS 専用キーの位置(`releasable: true`)。
     `Locked` の位置にはラベルと理由(例「他のツールが設定しています」)を出す。ドラッグ中の置ける/置けないは、ドロップ後の状態に核の検査
     (`compute_swap_write` 相当)を当てた結果で決め、判定と表示を同じ関数にする。図からは他ツールのエントリを `displace` しない
     (一覧「他のツールの設定」に確認つきの削除を置く)。「入力 → 図の表示」の表(③・④の警告つきペアの2行を必須ケースに含む)を必須テストにする。
   - **行の UI との関係**: 段階2で図が行・ドロップダウンの編集 UI を**置き換える**。行の UI は撤去し、許可リスト外を含む入れ替えの一覧と「解除」、
     他ツールの設定の一覧だけ残す。決定3・4 の「行」「ドロップダウン」の記述は段階1だけのもの。
   - **ドロップの意味(核がペアの間)**: 機能 F(元の位置 h)を位置 P にドロップすると、P または h を含む既存のペアを解いてから P⇄h を作る。
     1. **ドロップは全体で1つの操作**: 解く部分(削除は常に通る)と作る部分(許可リスト・Caps 追加 Ctrl・他ツールの to の検査を受ける)を
        `compute_swap_write` の1回の計算で扱い、作る部分が検査に落ちたら解く部分も行わない(図の状態を変えない)。
     2. 落とせない位置は、`Locked` と検査に落ちる位置(許可リスト外、US 配列で候補外のキー)を除いて無い。P = h(元の位置へ戻す)は
        「この位置を戻す」と同じ意味(h を含むペアを解くだけ)と定義し、`SelfPair` のエラーにしない。
     3. **解く側の副作用を見せる**: P または h を含むペアを解くと、利用者が触っていない位置(P の元の相手、h の元の相手)が恒等に戻る。
        ドロップの最中(`dnd_hover_payload`)に「この位置も元に戻ります」と出す。解くペアが警告つきなら `revealed` の警告も出す。
   - **ドロップの意味(核が置換になった後、決定6)**: ドラッグ元の位置 s と P の中身を入れ替える(σ' = σ∘(s P))。ペアの核の間の
     「解いてから作る」とは、入れ替え済みの位置からドラッグしたときに結果が違う(前者は s が恒等に戻り、後者は s に P の機能が来る)。
     段階2で覚えた操作の結果が段階3で変わるので、段階3に進むときに所有者へ示す(決定6の費用に書く)。
   - **位置ごとの「この位置を戻す」**を付ける(2回のドロップで作った3巡回は、1つのラベルを元へ戻しても長さ2の循環が残るので、
     「元の位置へ戻せばその入れ替えは消える」とは言わない)。
   - **表示**: 入れ替えた位置は、色と文字の両方で示す(例「→ 左 Alt」を併記。色だけで示さない)。図の位置は「キー(物理)」、中身は「機能(出力)」と
     見出しで区別する。
   - **クリック2回の操作を主経路の1つにする**(ドラッグの逃げ道ではなく同等)。Tab で位置へ移れる・Space/Enter で選べる・選択中が文字でも分かる・
     Esc で取り消せる。eframe 0.31.1 は既定で accesskit が有効(確認済み)。egui 0.31.1 に `Ui::dnd_drag_source`・`dnd_drop_zone`・
     `Response::dnd_hover_payload` がある(確認済み)。置ける/置けないの描画は `dnd_hover_payload` で自前で行う。
     同じ矩形でボタンのクリックとドラッグが両立するか、確認ダイアログ中の無効な Ui でドラッグが始まらないかは未確認(段階3の試作で確かめ、
     モーダル中はドラッグ元を描かない分岐を明示的に入れる)。
   - **機種に無いキーの注意**(英数/CapsLock の位置は通常どの機種にもあるので対象にしない。ワンクリックの「英数/Caps ⇄ 左 Ctrl」が毎回注意を出して
     「読まずに押す」を作るのを避ける。ADR-230 :92-93 の「この機種には英数キーが無く」の文意は ADR-230 段階5の実機確認で確かめて直す): スペース・左 Ctrl・左 Alt の機能を、機種により無いことがある位置(右 Alt・かな。US 配列では JIS 専用キーも)へ移すときは、
     確認つきの注意(`Caution` を1つ足す)を出し、図の該当位置に「機種によっては無いキー」と注記する(ADR-230 決定2 の「打てないキーは生じない」は
     物理キーが無い位置へ移す場合に成り立たない)。
   - キー押下の検出はしない(押して指定は取り下げ。入れ替え後は入れ替え先のスキャンコードが見えて誤判定する、IME に奪われるキーがある、が理由)。
   - 「Caps を Ctrl としても使う」は多対一で全単射ではないので、図の外のスイッチ(決定3)に置き、オンのとき図の英数/Caps と左 Ctrl の位置の
     ラベルは「Ctrl」とし、`Locked` にする。
   - ワンクリックの2つ(英数/Caps ⇄ 左 Ctrl、変換 ⇄ スペース)は、図の上で2つの**位置**の中身を入れ替えるショートカットとして残す
     (機能どうしの入れ替えではない)。どちらかの位置が使用中なら無効のままにし、理由を出す(決定4)。
6. **核を置換へ一般化する(所有者判断、2026-10-10。ただし段階は図の後)。**
   - **所有者の判断**: 3つ以上の循環も許す。図の操作は置換の合成なので、2回の入れ替えで3巡回ができる。
   - **費用の比較(Opus round1 S1)**: ペアだけでも「P⇄h を作る前に、P と h を含むペアを解く」操作で禁止規則なしの図が作れる。循環を許す費用は、
     ADR-230 が Opus 3 ラウンド+コードレビュー2回で固めた核(`detect_swap_pairs` の貪欲な組み取り・値での削除・`revealed`)の書き直しと、
     コードレビュー round1 の B1(同値の複製の値削除がペアの片方を消す)と同じ型の穴の再発、ADR-230 段階5(実機確認)が未着手のままの積み上げ。
     向き(σ と σ⁻¹)が効いてくる(下の向きの固定ケース)。ドロップの意味も変わる(決定5 の2つの定義の違い。段階2で覚えた操作の結果が段階3で変わる)。このため、**図は先にペアの核の上で出し、所有者が触ってから循環の一般化を決める**。
     所有者が循環を選ぶなら進める。
   - **表現**: 「位置 → 機能」の対応(全単射)を単位にし、レジストリへは位置と機能が違う位置ごとに1エントリ(`(P, σ(P))`)を書く。
     分類は「完全な循環(from も to も重複しない閉じた鎖)は、許可リストに関係なく編集できる置換として読む」(ADR-230 の Pair の規則の一般化。
     許可リスト内に閉じた循環に限るとはしない)。許可リストの検査は、新規に作る・変えるエントリのときだけ。
   - **分類の優先順位と単位**: 循環の候補が重なるときの採り方(例 `A→B, B→A, B→C, C→A` は `A⇄B` か `A→B→C→A` か)、Caps 追加 Ctrl との順序
     (`Caps→左Ctrl, 左Ctrl→X, X→Caps` は3巡回か Caps 追加 Ctrl+他ツール2件か)を ADR-230 決定3 の表に行として足す。
     「残す」の単位は循環で、「循環の全エントリが値として一致すれば残す、1つでも変われば循環ごと消して新規に作る」。新規に作る循環にだけ
     許可リストと Caps 追加 Ctrl の検査を当てる。
   - **昇格側の検査**: `compute_*` の入口で「from が重複しない・to が重複しない・from の集合 = to の集合・固定点を含まない」を検査し、
     `SwapError::NotPermutation` を返す。昇格側は再検証でこれを必ず通す(UI の不具合で `perm=0039>001D` のような片方向が渡っても書かない)。
     `ApplyRequest.pairs: Vec<Pair>`(`scancode_apply.rs:76-85`)と `to_spec`/`from_spec`(:129-177)・`decide`(:257)は変わる。
     比較交換・読み戻し・巻き戻し・`displace`・`classify_read_back` は変えない。引数は `perm=003A>001D,001D>003A` のような形にする(実装時に決める)。
   - **必須テスト**: 小さい宇宙の全列挙で「悪くならない・削除は常に通る・往復」に加え、「書いた置換が読み戻しで同じ置換として(向き込みで)読める」。
     非対称な3巡回の固定ケース(バイト列まで)と、`cautions` の向きのケースを足す。注意書き(`CapsWithThumbKey`・`ThumbKeyMoved`・
     `ThumbKeyRestored`)は「位置 → 機能」で書き直す。
   - **確認ダイアログ**: ADR-230 段階4 の「毎回出すと読まずに押す」を避け、発火条件は今のまま(注意が要る・`displaced`・`revealed` のとき)に保つ。
     変わる位置の一覧(位置 → 機能)は、適用ボタンの直上に常時の差分表示として出す(図の色付きと同じ情報を文字でも)。
     長さ3以上の循環を含むときだけ、確認を足すかどうかを実機で決める。
7. **「すべて解除」と復旧手順を整える。**
   - **「すべて解除」を追加する**: 図を全部恒等に戻し、Caps 追加 Ctrl もオフにする。他のツールの設定(一覧に出ているもの)は残すが、入れ替えの形の設定は他のツールが書いたものでも解除する。
     確認ダイアログに、解除する入れ替えの一覧を出す。`compute_swap_write(existing, &[], false)` で
     書けるので核の変更は要らない(削除は常に通る)。これが復旧の第一手順になる。
   - 「元に戻す」は「編集を、最後に読み込んだ(適用した)状態へ戻す」の1つに寄せる。適用後は読み込み時の状態が適用後の状態になるので何も戻らない、
     と画面に書く(復旧は「すべて解除」)。
   - 「読み直す」はエラー時と、外部で変わった疑いがあるときだけ出す。疑いの検出は、タブを開いたとき・ウィンドウがフォーカスを得たときに読み直す
     (毎フレームは読まない、`main.rs:507-508`)。比較交換(`Changed`)があるので実害は小さい。
   - 画面の折りたたみ「困ったとき」に、確認できた手順だけを次の順で書く。
     (1)マウスで設定画面を開き、「すべて解除」→ 適用 → 再起動。キーが要る場面(UAC の資格情報など)は画面キーボード(`osk.exe`、サインイン画面の
     「アクセシビリティ」からも開ける)で打つ。画面キーボードが Scancode Map を通らないかは未確認(Q3)。
     (2)システムの復元。(3)回復環境(WinRE)の regedit でオフラインの SYSTEM ハイブを読み込み、`<読み込んだ名前>\ControlSet00N\Control\Keyboard Layout`(N は `Select` の `Current` の値。多くの環境では 001。Q3 で確かめる) の
     `Scancode Map` を削除する(読み込み時は `CurrentControlSet` が無い)。セーフモードは、Scancode Map が効かなくなると実機で確かめられた場合だけ載せる
     (kbdclass はセーフモードでも読み込まれるので、入れ替えは効いたままの可能性が高い、という推測。Q3)。
8. **内部表記を出さない。** 他ツールの項目で許可リスト外のキーも、名前の表で引き、引けなければ「不明なキー(0x003B)」と書く。許可リスト外の名前は
   配列で変わる(`0x0029`・`0x003A`・`0x007D` 等)ので、名前の表は `keyboard_model` 別にするか、`GetKeyNameTextW`(利用者の現在のレイアウトに依存)を
   使うかを段階1で決める。
9. **成功後の案内を1箇所にする。** 決定1の状態行と「今すぐ再起動…」だけにし、結果メッセージの重複を削る。`RollbackFailed` のときの再起動案内
   (`main.rs:3272-3276`)も、状態行の「不明」(軸A)で表せるかを確かめる。

## 段階(提案)

0. **前提の解決**: Q2(再起動待ちの判定、実機で「適用 → 再起動」と「適用 → シャットダウン → 電源オン」の2つ)と、Q5(所有者がどこで迷ったか)。
   ADR-230 段階5(実機確認)を先か同時に済ませる(積み上げる土台が未確認のまま、上に新しい核を積まない)。
1. 文面と構成だけの変更(決定1〜4・7の「元に戻す」整理・8・9)。軸A は Q2 が解けるまで保守的な文言(「レジストリに設定があります。再起動していなければ、
   まだ効いていません」)で出し、Q2 が解けたら判定に差し替える(決定2・3・4・8・9 と軸B は Q2 を待たない)。「復旧は『すべて解除』」の1文は
   「すべて解除」が出る段階2まで画面に書かない。`scancode_editor.rs` に状態行・無効理由の純粋関数を足し(Linux でテスト)、
   `main.rs` は描画だけを変える。ADR-230 の純粋関数・昇格 CLI は触らない。
2. 「すべて解除」(決定7)、キーボード図とドラッグ&ドロップ(決定5。行の UI を置き換える)。**ペアの核の上**で出す。復旧手順は、この段階では
   (1)の「すべて解除 → 適用 → 再起動」だけを出し、Q3 の確認が済んだ項目(画面キーボード・システムの復元・WinRE)を段階4の実機確認のあとで足す。
   egui の DnD の試作で、クリックとの併用・モーダル中の挙動を確かめる。所有者に触ってもらう。
3. 置換への一般化(決定6)。所有者が触って循環が要ると判断した場合に進める。ADR-230 に改訂を追記する。
4. 実機での画面確認と Q3(復旧手順の確認)。ADR-230 段階5の実機確認と同じ機会にまとめる(UAC・再起動が要るため)。

## 未確認(Q)

- **Q1** 取り下げ(決定5でキー押下の検出をやめたので不要)。
- **Q2**(段階1の前提)「起動時に効いている値」の取り方。候補は、`HKLM\SYSTEM\CurrentControlSet\Control\Keyboard Layout` キーの LastWriteTime
  (`RegQueryInfoKeyW`、非昇格の `KEY_QUERY_VALUE` で読める)とカーネルの起動時刻の比較。記録を増やさない(ADR-230 決定4 と整合)。
  同じキーの別の値の書き込みでも LastWriteTime は進むが、誤りは「再起動待ち」側(安全側)に倒れるので許容する。
  起動時刻の取り方(`GetTickCount64` がスリープ・休止中の時間を含むか、`NtQuerySystemInformation(SystemTimeOfDayInformation)` の BootTime か)と、
  高速スタートアップでの電源オンがカーネルの起動時刻を更新しない(推測)かは未確認。高速スタートアップで Scancode Map が読み直されない
  (ADR-111 決定5)ので、電源オンで再起動のつもりの利用者に「一致」と出さないことが要件。
  補足: (a)`RolledBack`(書いてから元へ戻した)でも LastWriteTime は進むので、値は起動時と同じでも「再起動待ち」と出る(安全側だが不要な再起動を促す)。
  (b)値の削除(すべて解除で値が空になる)で LastWriteTime が進むかも確かめる(進むと推測)。(c)起動時刻を「現在時刻 − 稼働時間」で出すと、
  起動後の時計合わせで数秒ずれるので、比較に数秒の余裕を持たせる。
- **Q3** 復旧手順の実機確認: セーフモードで Scancode Map が効くか、画面キーボードが Scancode Map を通らないか、WinRE の `ControlSet001` のパス、
  日本語 Windows 11 でこの形のままで通るか。
- **Q4** ワンクリックの2つ(英数/Caps ⇄ 左 Ctrl、変換 ⇄ スペース)が実際によく求められる入れ替えかの頻度の裏取りは取れていない。
  調査で出てきた話題は、Caps を Ctrl にする系と、無変換・変換を IME オフ/オンにする系だった。
- **Q5** 所有者が実際にどこで迷ったかを聞いていない。聞いて段階1の優先順位を見直す。
- **Q6** 置換の一般化(決定6)で、許可リスト9キー(US 配列では5キーで 5! = 120、JIS で 9! = 362,880 通り)の分類の曖昧さ(決定6「分類の優先順位と単位」)が
  テストで潰せるか。確認ダイアログの行は高々9行なので、文面が破綻するのは数の問題ではなく分類の曖昧さの問題。許可リストを縮めた全列挙で性質テストを回す。
- **Q7** 同じ from のエントリが複数あるときドライバがどちらを効かせるか(ADR-230 の未確認)。置換では自分の書き込みで from が重複しないので、
  他ツールとの重複でだけ問題になる。図の `Locked`(決定5 の④)がこれを避ける。

## 非目標

- 比較交換・読み戻し・巻き戻し・`displace` の意味論の変更(決定6のとおり、表現はペアから置換へ一般化するが、書き込みの骨格は保つ)。
- GJI のキーマップ(ADR-231)。ADR-230 非目標の「Caps を無変換にして、無変換に IME トグルを割り当てる」2段階の案内も ADR-231 側で行う
  (図の機能ラベルに awase 上の役割〈親指キー〉を小さく添える案は、段階2の試作で試す)。
- hook ベースの入れ替え(ADR-110)、片方向・多対一の自由なマッピング。
- キーボード全体の図(許可リスト外のキーを含む図)。決定5の図は許可リストの位置と、いまの入れ替えに含まれる許可リスト内の位置だけ(許可リスト外は図の下の一覧)。
- 他ツールのエントリを図の上で `displace` すること(一覧の確認つき削除でだけ行う)。
