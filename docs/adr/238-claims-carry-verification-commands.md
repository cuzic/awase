# ADR-238: docs・PR 本文の主張に、再確認のコマンドを添える

## 背景(実測した事実)

### 覆った主張の一覧(2026-10-06)

数え方: PR 本文・PR のコミット・develop の docs の修正コミットで、前に書いた主張を本人か Opus レビューが訂正したもの。「再確認のコマンド」列は、この ADR を書く時点(develop `1630e55e`)で実際に打って結果を確かめたもの。

**未確認**: brief が挙げた「#518 の『26 行 PASS』」は、今の #518 本文が「24 PASS・`#[ignore]` 1」になっており、訂正前の文言を `gh` から取り出せなかった(PR 本文の編集履歴は `gh pr view` に出ない)。件数に含めていない。

### 一覧から分かること

- 9 件中 8 件は、書いた時点で **1 本のコマンド**で確かめられた。否定・全称(#1・#2・#5・#7)は `git grep`、「以前から壊れていた」(#6)は `git log -S`、数値・タイトル(#4・#8・#9)は `gh pr view`。コマンドを打つ手間は数秒で、訂正のための追加コミット・レビューの往復(#5・#7 は Opus の round を 1 回ずつ使った)より安い。
- 1 件(#3)は grep では確かめられず、CI の run が要った。このような主張には「未確認。確かめる run は〜」と書くのが正しい形で、コマンドの併記は効かない。
- **squash の件名に誤りが残る**: #1(`cb581901`)と #4(`ae59ee2c`)は、本文を直しても develop の件名として残っている。`git log --grep` で後から引くと誤った主張が出てくる。
- **覆った主張は次の作業の前提になっていた**: #2 は V4(事実の型に `Instant` を入れない前提チェック)と V2 の 4 の根拠になり、#528 で取りやめになった。#5 は第 1 段階の撤去対象の選定を誤らせかけた(消しても CI が green のまま `drift_log_fired` が 0 に化ける)。

### 既にある近い規則(重複を避けるため)

- `docs/tasks/fcis-layering-tasks-2026-10-06.md` §0 の 6(CI のログで数値を確かめる)と V2 の 2(「PR の本文と数値は CI のログから写したか」)。FCIS の PR だけが対象で、否定・全称の主張は扱っていない。#8 はこの規則の対象だったが漏れた。
- メモリ(リポジトリ外)に同じ趣旨の教訓が少なくとも 4 本ある: ADR の実装状況は git log で裏取りする(ADR-163 で誤答)、PR の diff より現在の HEAD で裏取りする、Opus レビュアー自身の数値も次ラウンドで再検証する、「起きなかった」と言う前に観測経路に乗ったかを測る。いずれもエージェントの個人的なメモで、リポジトリの規約にはなっていない。

## 決定

### (1) 規約を 1 ページ置く

`.claude/rules/claims-carry-verification.md` を置く(docs-frontmatter-convention.md と同じ「ルール/なぜ/適用範囲」の形、30 行程度)。中身:

- **対象の主張**: ADR・docs・PR 本文・known-bugs・PR のタイトルに書く、次の形の主張。
  - 否定・全称: 「〜は無い」「読み手は 0」「〜だけ」「すべて〜」「以前から〜」
  - 数値: 件数・行数・PASS 数・`#[ignore]` 数
- **書き方**: 主張の直後か表の列に、確かめたコマンド 1 行と、打ったコミット(短縮ハッシュ)を書く。例: 「`output/` に `Instant` は無い(`git grep -n Instant -- crates/awase-windows/src/output`、`1630e55e`)」。コミットを書くのは、develop が動くと同じコマンドの結果が変わるため。
- **コマンド 1 本で確かめられない主張**(CI の run・実機が要るもの)は、「未確認」と書き、確かめる手段(run ID・ジョブ名)を添える。推測を断定で書かない。
- **squash マージ前**: PR のタイトルが本文の訂正に追随しているかを見る(件名は develop に残る)。
- 規約は人とレビューの約束であり、CI では検査しない。

### (2) 実装エージェントの指示と Opus レビューの観点に入れる

- fcis タスク表 §0 の 6 と V2 の 2 の「数値を CI のログから写したか」を、新しい規約への参照に置き換え、「否定・全称の主張にコマンドを添えたか」を加える(下の追記案)。
- Opus レビュー(opus-adversarial-consult)の依頼文に、「本文の否定・全称の主張と数値のうち、少なくとも 3 つを、添えられたコマンドとは別の方法(別の grep パターン・`git log -S`・`gh`)で再確認する」を 1 行入れる。#1・#5 型(読み手がコードの外にあった)は、狭い範囲のコマンドを打ち直しても見つからないため。

### (3) CI での機械検査はしない

否定・全称の文を検出する lint、主張とコマンドを宣言する表、コマンドを CI で再実行する仕組みは作らない。ADR-218〜220 で、宣言テーブル・DSL は「実害の記録に対して削減量が小さい」として見送った(PR #429)。ここでも実害は「訂正のコミットとレビューの往復」で、機構を足すほどのものではない。

## 却下した案と理由

| 案 | 理由 |
|---|---|
| 主張を検出する lint(「無い」「0 件」等の語を CI で拾う) | 日本語の否定表現は多様で誤検出が多い。例外の印が要り、ADR-218〜220 と同じ型の除外リストになる |
| 主張とコマンドの対応表を YAML で持ち CI で再実行する | 宣言テーブル化(却下済み)。コマンドは develop が動くと結果が変わるのが正しい(主張は書いた時点の事実)ので、再実行で落とすと誤検出になる |
| 全ての文に出典を付ける | 負担が大きく形骸化する。覆った 9 件は全て否定・全称・数値だったので、対象をそこに絞る |
| 何もしない(メモリの教訓のままにする) | メモリは書いたエージェントの次のセッションにしか効かず、並行する他のエージェント(このセッションだけで名前付きのものが 80 前後)には届かない。今日の 9 件は複数のエージェントにまたがる |

## 段階

| 段階 | 内容 | 撤去対象 | 検証方法 | 取りやめ条件 |
|---|---|---|---|---|
| 1 | 規約 1 ページを置く。fcis タスク表 §0 の 6・V2 の 2 の文言を規約への参照に置き換える。直近の ADR 1〜2 本(ADR-232 と本 ADR)に遡及適用を試す。#524・#530 の誤った件名は、該当する docs に注記するだけ(履歴は書き換えない) | §0 の 6・V2 の 2 の重複した文言(参照 1 行に置き換え)。純増は規約の約 30 行 | 遡及適用で、ADR-232 の否定・全称の主張のうちコマンドを添えられないものが何件あるかを数える(0 件なら規約は今の書き方の追認にすぎない、多ければ負担の見積もりになる) | 遡及適用で 1 本あたり 30 分以上かかる |
| 2 | 次の 10 PR(docs のみの PR を含む)で運用 | — | 10 PR の Opus レビュー記録とフォローアップのコミットで、「覆った主張」の件数を今日と同じ数え方で数える(`gh pr view <N> --json commits,comments`)。今日の基準: #518〜#534 の範囲と検討メモで 9 件 | 件数が減らない、またはコマンドが付いているのに覆った主張が出る(コマンドの形骸化)。その場合は規約を消し、レビューの観点(2)だけ残す |

CI で確認できる形にはならない(人とレビューの規約のため)。検証は上の `gh` による数え直しで行う。

## リスクと限界

- **コマンドの範囲が狭いと、添えても誤る**: #1・#5 は、読み手がコードの外(#1 は `docs/`、#5 は `tools/`・`.github/`)にあった型。書き手がどの範囲を探したかの記録は無く未確認だが、範囲の狭い grep を添えても同じ誤りは起きうる。規約は「コマンドを書く」ことでレビュアーが範囲の狭さに気づけるようにするだけで、防げはしない。(2)のレビューの観点(別の方法で再確認)で補う。
- **形骸化**: 主張と無関係なコマンドを貼るだけになる恐れ。段階 2 の取りやめ条件で見る。
- **CI の run・実機が要る主張(#3 型)には効かない**: 「未確認」と書かせるところまで。
- **未確認**: 今日以前の期間で同じ数え方をした場合の件数(基準が 1 日分しかない)。#518 の訂正前の文言。

## 所有者に聞くこと

1. **規約の置き場所**: (a) `.claude/rules/`(推奨。毎セッション自動で読み込まれ、実装エージェント・レビューの両方に届く。docs-frontmatter-convention.md と同じ扱い)/(b) `docs/` 配下(人には読みやすいが、エージェントは明示的に開かないと読まない)。
2. **適用範囲**: (a) 全 PR(推奨。#8・#9 は FCIS 以外の refactor PR で起きた。対象を否定・全称・数値に絞るので負担は小さい)/(b) ADR・known-bugs だけ(負担は最小だが、今日の 9 件のうち #2・#4・#8・#9 の 4 件は PR 本文・タイトルで起きており外れる)。
3. **squash の件名**: 誤った件名(#524・#530)をどう扱うか。(a) docs に注記するだけ(推奨。履歴は書き換えない)/(b) 何もしない。
